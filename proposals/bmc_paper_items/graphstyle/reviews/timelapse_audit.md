Exposure ranks are estimates from call sites and defaults, not measured user frequency. `M` means an output of an enabled timelapse/division workflow, with the active per-well intensity/motility panel ranked first because `make_mask_panel` and `make_adjusted_panel` default true. `L` covers debug paths, opt-in calcium analysis, raw movies and legacy plotting helpers. Exact-name searches found only test calls for `_make_motility_plots` and `_make_adjusted_qc_panel` in the current tree; those should not be described as the active primary report route.

Categorical slot widths and the n>20 switch apply to categorical sample comparisons, not trajectory paths, lineage structures or raw microscopy. A missing reference condition is flagged only where a comparison needs it; a lineage tree does not gain a scientifically meaningless control row. Raw images keep scientifically appropriate display transforms; the 0.6 graph-data rule is not a reason to fade the micrograph itself. There are no competing-method outline comparisons in the local creators; that rule is delegated for tracking overlays to `plot._visualize_and_save_timelapse_stack_with_tracks`.

## Main findings and migration order

1. **Active per-well infection/motility panel** (`timelapse._make_intensity_motility_panel:4090`) is the first migration target. It already uses `figure_style(theme_target())`, the shared export path, figure-data registration and consistent blue/grey infection identities. Its local children override those benefits with histogram alpha 0.5, embedding alpha 0.4, 7 pt legends, opaque endpoints, n/velocity text in axes and unconditional violins for small groups. Each panel is allocated four inches rather than deriving comparison width from its condition count. The current nested helpers duplicate plotting primitives that belong in `figures.style`.
2. **Division prediction and analysis** (`division_prediction_figure:711`, `_trajectory_figure:1840`, `_forest_figure:1902`, `_size_control_figure:1948`) already use shared roles, data registration and export, but directly construct `Figure` without a theme context. Prediction fixes canvas geometry independent of condition count, uses purple for an age-only control, mixes 0.3/0.6/1 opacity, does not switch for >20 fold points, and abbreviates both metrics. The forest plot is the explicitly rejected named-dot/horizontal-whisker form and colors its error bars. This requires a planned figure-form change, not an alpha-only patch.
3. **Photobleaching and lineage** use normal shared save functions but draw opaque lines. Photobleaching does not provide a legend for raw/fit/corrected encodings. Lineage uses `viridis`, an axes title and unstyled raw `Figure`; preserve the structural tree semantics and colorbar instead of imposing condition bars.
4. **Legacy/debug plotting** can follow the active routes. `_make_motility_plots` and `_make_adjusted_qc_panel` have source-confirmed opacity/font/layout issues but no current exact-name production call sites. `_debug_plot_merged_planes` should retain image inspection semantics while documenting normalization, using a controlled label palette and providing scale/representativeness metadata when exported as a scientific comparison.

Most of this scope has already adopted some shared plotting infrastructure. The correct change is to extend `spacr.figures.style` and route these creators through it, rather than adding another independent style module or asserting that no graph rules reached the application. In particular, many current `with figure_style(...)` blocks surround subplot creation only, then end before data artists are drawn; use the existing shared full-drawing context (`_figure_axes`) or an equivalent owner-controlled entry point. Replace old `ROLES` assignments only through a declared semantic identity policy: `ROLES['control_positive']` is purple, and current infected/uninfected colours are older blue/grey values rather than the authoritative palette.

- the dark export retained black title/ticks/labels on a dark canvas and white axes interiors; light error bars had low contrast against white;
- root saw **no clipping at the canvas boundary**.

The before images are `graphstyle/thumbnails/before_v1/division_prediction_light/before.png` and `graphstyle/thumbnails/before_v1/division_prediction_dark/before.png` relative to the published spec directory. These make the theme/geometry issues concrete for that creator. Legend clipping or mismatched colours in other functions remains unverified; source mentions of `tight_layout` are not evidence of a passing visual check.
