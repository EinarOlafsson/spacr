The accompanying `general_plot_rows.json` contains **180 function-level dispositions**: 51 creators, six renderers, 19 writers, 90 conditional wrappers, seven style/layout policies, two image helpers, one HTML image report, and four explicit non-plot exclusions. The count includes every candidate in the assigned 17-module scope plus supplemental lexical owners the broad scanner did not identify directly. `measure_hooks.py` has no plotting creator/writer in the parsed inventory or supplemental source search. `layers.py` compositors and source-PDF page rasterization are not statistical plot generation.

Exposure ranks are estimates from integration paths, not measured usage: 1 routine pipeline/Measure/Mask/QC output; 2 a selected analysis, assay, sequencing or training workflow; 3 optional simulation/diagnostics/model interpretation. An orchestration row is included to show its shared route, not counted as an independent chart implementation.

The largest routine gaps are in existing Measure and sequencing QC builders. A `figure_style(theme_target())` context already gives shared theme-aware chrome, but it does not enforce the data-mark alpha, condition-slot geometry, square plot area, semantic control role or chart form. Existing contexts must be retained and strengthened, rather than described as absent. The raw illumination QC builder lacks even that creation context, although it writes through the central save route.

Concrete repeated issues include 0.25/0.15 wound-curve opacity; strip-only viability and half-closure comparisons without the n>20 switch; 7pt viability and sequencing labels; fixed layouts without square-axis enforcement; plot-area geometry remains render-dependent; opaque lines/heatmaps; numeric results and labels inside plotting areas; caller-defined palettes; and default-coloured error bars. Saliency and Grad-CAM use the explicitly forbidden `jet` colour map. UMAP has a separate theme/palette route, a default opacity of 0.65, labels on cluster centres, and 7pt labels at its default figure size. The image-QC HTML gallery has fixed dark CSS and a separate system font.

The API should remain centered on the existing `spacr.figures.style` and `plot.save_figure`/`figure_sink` owners. These modules need semantic metadata from callers: chart kind, control/reference identity, condition order and sample counts, title/legend narrative, image-normalization specification and theme. A central export-only recolouring pass cannot reliably infer these meanings. The fallback pandas stacked-bar routes in `_replication_stacked_bars` and `_invasion_stacked_bars` should call the same builder as the ordinary branch instead of retaining separate rules.

Some source risks are explicitly **render-dependent**. No overlap or clipping is asserted from static code alone. In particular `utils.plot_grid` places key text at figure x=1.05; whether an exported file clips it depends on bounding-box handling, and a native GUI canvas differs from a tight export. Both themes need representative renders. Existing explicit square heatmap cells (`toxo.plot_gene_heatmaps`, `submodules.generate_score_heatmap.plot_multi_channel_heatmap`) are credited rather than marked noncompliant simply because their canvas is rectangular.

Image and plot roles must stay separate. Source-PDF rasterization, well-crop exports and layer compositing preserve scientific image data. They must not be changed to 60% opacity or given categorical axis spacing. Analytical overlays and montage captions need the shared image display-range, scale-bar and legend policy; image normalization must remain display-only and disclosed. The authority's late requirements also need a domain decision for the conventional hazard-ratio forest plot: it is currently a named horizontal dot/interval chart, a form the supplied broad rule rejects. Record the exception or replacement explicitly rather than silently claiming conformity.
