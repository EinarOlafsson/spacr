# 1010b — OPS and shared scientific operations

This specification examines operations implemented differently in OPS and elsewhere in spaCR at **`19a95cd7993e0ce44078c779828b91098820598f`**. It complements item 1010's exact-body inventory: matching function text is neither required nor sufficient here. The question is whether one existing numerical owner can serve both paths while keeping their actual input, population and output contracts explicit.

Evidence is **static source inspection only**. No Python, model inference, tests or numerical comparisons were run. Concrete examples below are deductions from the code, not measurements of prevalence or biological effect. All paths are relative to `spacr/` unless prefixed with `tests/`. Each proposed owner is an existing module; proposed internal interfaces are recommendations, not claims that those interfaces already exist.

Flat-field fitting/application is excluded under item 1009. Later `ops_cell_cycle.py` and `cpg_measure.py` are absent at this revision. Their later implementations must not be imported into this assessment.

## Global priority and interpretation

**The ordinal ranking below is qualitative potential OPS-result risk from static code**, ordered broadly from acquired fields and masks through population statistics to cropped/displayed outputs. It is not a measured effect size, frequency or performance ranking. “Duplicate” denotes overlapping numerical work, “shared” an existing common kernel, and “policy” an intentional difference around that kernel. A defect should be corrected directly with a focused regression and output/provenance handling, not hidden behind a compatibility flag. Deliberately different algorithms remain explicit adapters.

| Priority | Operation and classification | Main OPS consequence | Proposed existing owner |
|---|---|---|---|
| 1 — high | Acquisition axes/projection: duplicate mechanics, different policies | Different channels, timepoints, pixels or field count | `tiff_io.py` |
| 2 — high | Model resolution and segmentation preparation | Wrong effective checkpoint, different refusal or masks | `utils.py` for resolution; `object.py` for evaluation |
| 3 — high | Registration search and graph placement: independent strategies plus existing sharing | Different accepted edges, coordinates and spatial associations | `stitch_core.py` |
| 4 — high | Pairing and measurement adapters | Different object identities, cytoplasm and joined populations | `measure.py` |
| 5 — high | Reference normalization: duplicate arithmetic, distinct populations/fallbacks | Changed scores, missing features and profile distances | `batch_correction.py` |
| 6 — high | Phase/mitotic calls: different scientific models | Different phase populations and mitotic indices | `gene_measurement_compare.py` for the shared peak primitive only |
| 7 — high | Fixed-crop centroid: shared kernel, coordinate-frame inconsistency | One-pixel crop shift and inconsistent stored centre | `crops.py` |
| 8 — medium | Crop quantization, border policy and stored PNG interpretation | Different pixels or selected cells | `intensity_rescale.py`, `crop_source.py` or `crops.py`, one per operation below |
| 9 — medium/low | Feature selection, grouped fractions and streamed scaling | Saved-model or aggregation contract changes | Existing owners specified below |
| 10 — low | Native reads, crop margins, Funk features and covariance basis | Mostly already shared; unnecessary rewrites add risk | Retain `image_store.py`, `crop_store.py`, `measure.py`, `ops_tvn.py` |

These ranks describe the risk of naive substitution. Extracting a kernel while retaining its actual options and policies intends **zero change to OPS results except the named corrections**; that intention is not measured equivalence.

## 1. Image reading and plane selection

**Axes and projection.** OPS `_read_plane` (`ops_engine.py:622`, channel rule at `:575`) selects a channel and repeatedly takes the first leading entry until two dimensions remain. Sequencing, registration and decode call it (`:1098`, `:1362`, `:2817`). Phenotype `_ph_read_field` (`:4416`) instead repeatedly takes maxima and returns HWC float32 in requested stain order; masks, acquisition registration and crops consume that path (`:5609`, `:7708`, `:8837`). Both assume the last two dimensions are spatial and record missing-channel/file failures at the workflow boundary.

The generic TIFF route (`tiff_io.py:69`, `:114`, `:182`, `:198`, `:208`; caller `io.py:10566`) uses declared axes, retains separate timepoints and max-projects depth only. Conversion also makes first/selected/max Z explicit (`convert.py:2361`, `:2511`). On a ZCYX stack, first Z and max Z can differ. On TCZYX, phenotype maxima can collapse time that the converter preserves. Declared YXC `(8,8,2)` illustrates the OPS capability limit: its fallback channel axis is 0, whereas the generic reader recognizes the final C axis. These are static consequences, not measured pipeline outputs.

Use **`tiff_io.py`** for decoding-with-axes and small plane operations. Keep stain/file discovery, explicit projection/time policy, dtype and failure reporting in adapters. Do not silently replace the sequencing first-plane algorithm with max projection, or accept an unsupported layout by guessing. A supported-axis bug should be fixed; intentionally unsupported input should receive an explicit diagnosis. `pipeline_v2.py:474` is another distinct adapter: its legacy 3-D path selects the last-axis first channel, while its calibrated path requires single-channel 2-D input and enforces a pre-decode pixel budget. Those contracts cannot be substituted wholesale.

**Stored arrays and labels.** OPS merged reads (`ops_engine.py:8013`) and Measure (`measure.py:11130`) already use **`image_store.py:339`/`:376`**. Keep this raw reader owner. OPS returns CHW intensities, separate masks and ownership metadata; Measure reconstructs legacy HWC planes and checks retained NPY layout/identity. Preserve commitment, timepoint ambiguity and label-dtype checks in these envelopes.

OPS named-NPZ labels (`ops_decode.py:3708`, `ops_engine.py:4872`) must retain their requested key; `image_store.read_image` otherwise selects the first NPZ member. Foreign-mask import (`foreign.py:1133`) normalizes axes and reduces to 2-D, unlike rank-preserving OPS TIFF reads. Legacy `io.py:6871` uses image-intensity conversion to uint16, which is unsuitable as a shared label decoder; the bounded reference search found no production caller of that helper. Consolidate raw decoding in **`image_store.py`**, keeping key/plane selection explicit. Do not replace spatial tiled TIFF windows (`ops_engine.py:12018`) with eager full-array reading.

## 2. Crop extraction, margins and stored pixels

**A concrete centring inconsistency.** OPS `_ph_crop_cell` (`ops_engine.py:8656`) calls `utils._crop_center` (`utils.py:3394`) on a local window. Measure's PNG path (`measure.py:11870`) uses the same utility in field coordinates; streamed crops compute global centres (`crops.py:1298`, `:1361`). Rounding before versus after adding an odd origin is not translation-invariant under ties-to-even.

For a 16×16 field with one cell at `(7,7)` and `(8,7)`, side 4, the global row centroid is 7.5. OPS's local origin is 3, local centroid 4.5 rounds to 4, and the restored centre is 7; global rounding gives 8. A coordinate ramp therefore yields crops starting at rows 5 and 6. `_ph_crop_box` (`ops_engine.py:8698`) has the same metadata issue at margin 0: `round(0.5)+7` is 7. Its bounding-box pixels are already correctly cut; only its centre metadata differs.

Use **`crops.py`** for one global-centroid/window primitive, retaining the existing utility as an adapter. Correct the coordinate inconsistency by restoring the floating origin before rounding; preserve local-window efficiency. Do not add a flag that perpetuates the bug. Record the changed OPS crop bytes/centre metadata and ensure resume cannot mix old and corrected outputs. A focused half-integer/odd-origin regression must compare independent callers, not OPS against its own helper.

**Margins are already shared.** OPS `ops_engine.py:8867` and Measure `measure.py:11235` call **`crop_store.cut_crops` (`crop_store.py:53`)**. Equal prepared arrays, labels, margins and zero-outside flags therefore use one slice/mask implementation. Defaults intentionally differ: OPS fixed 96-square mode uses margin None and masks outside-cell pixels; Measure native margin 0 yields a variable bounding box with context (`ops_settings.py:188`; `settings.py:2153`). OPS's zero-outside setting applies to bbox mode, not fixed mode. Replacing None with 0 would change every default crop and is not deduplication.

Classifier bbox crops (`crop_source.py:285`) and previews (`measure.py:15676`) repeat rectangular slice/mask mechanics but add float32 conversion, resizing, size/area filtering, sorting, normalization or RGB narrowing. A single-object slice primitive in **`crop_store.py`** can remove that duplication without making each lookup enumerate the whole field. Keep output ordering, None behavior and optional display transforms outside it. OPS mask values 1/2 for cell/nucleus (`ops_engine.py:8718`) and Measure boolean masks remain distinct, supported store contracts.

One additional float-input distinction is concrete: classifier masking multiplies by a boolean mask, leaving an off-object NaN unchanged; `cut_crops` assigns zero and preview `_crop_channels` (`measure.py:15341`) uses `where`. This is not an effect on ordinary uint16 native crops. If the contract is zero outside the object, correct the nonfinite-background handling explicitly rather than preserve it behind a flag.

**Coordinate windows and sample selection.** OPS Image UMAP (`ops_image_umap.py:542`) rejects border-crossing windows; classifier coordinates (`crop_source.py:338`) pad partially outside windows. OPS uses crop usability before selecting representative cells (`ops_image_umap.py:867`), so changing rejection to padding changes the population. Share window-intersection mechanics in **`crop_source.py`**, preserving that policy and output dtype. Centre padding/trimming (`crop_loader.py:862`) and nearest-neighbour resizing (`crop_store.py:494`) are different requested operations.

**Quantization and PNG decoding.** OPS rounds/clips to uint16 (`ops_engine.py:8852`); streamed `MergedField` casts sliced planes (`crops.py:892`, `:1004`, conversion at `:1041`). Raw float 1.6 consequently becomes 2 versus 1. Measure's working conversion (`measure.py:5205`, `:11297`) can also rescale normalized/high-range intensities while treating labels separately. Use **`intensity_rescale.py`** for explicit resolved conversion, never infer a plate scale from a cropped subset. This is a pixel-policy decision, not flat-field fitting.

OPS Image UMAP reads PNG through skimage (`ops_image_umap.py:560`); **`crops.py:1701`** already owns raw-depth/channel decoding, while `crops.py:2438` adds historical crop-format/display interpretation. Reuse the raw decoder and appropriate recorded-order adapter, not unconditional display stretching. Exact skimage 16-bit colour behavior remains unmeasured; historical format-2 and distinct-channel fixtures are the necessary discriminating checks.

## 3. Registration and alignment

**Translation estimation and acceptance.** OPS `phase_correlate`/`register_edge` (`ops_register.py:330`, `:425`, `:476`; callers `ops_engine.py:1354`, `ops_cycles.py:111`) obtains an integer phase-correlation peak and unwraps it around an expected shift. Layout/tolerance or peak-ratio policy determines acceptance. Legacy Align `_register_pair` (`align.py:1251`) reads the nominal overlap, standardizes float32 strips and obtains both phase-normalized and unnormalized skimage candidates. It permits subpixel estimates, chooses by re-read overlap NCC and applies maximum-shift/minimum-confidence gates. Equal raw tiles can therefore produce different shifts or accepted edges: support, objective, precision and acceptance differ. No particular image effect was measured.

Use **`stitch_core.py`** as the existing registration owner, backed by OPS's FFT implementation. Its `register_strip_pair` (`:235`) already supports NCC/peak/both acceptance and subpixel refinement (`:196`, `:328`). Align's optional core route calls it (`align.py:1932`, `:1983`), but the default remains `align_engine='legacy'` (`:2983`). The core does not yet implement legacy dual-candidate search and re-read scoring. Move those operations as explicit strategies before delegating; the current core is not a proven drop-in. Keep nominal-overlap acquisition policy in adapters. Preserving OPS integer precision, unwrap, tolerance and refusal intends no changed OPS result; replacing accepted edges can move nuclei and barcode associations.

**A separate generic tile search remains.** `image_stitch._pair_shift` (`image_stitch.py:369`) uses bounded displacement/transverse-jitter search through sampled `_sliding_ncc` (`:263`), then full-resolution overlap scoring (`:325`). `_mosaic_by_correlation` (`:527`), reached by `plan_mosaic` (`:447`) and `stitch_tiles` (`:609`), does not delegate to the core. OPS instead chooses a phase-normalized strip peak within layout bounds (`ops_register.py:476`, `:552`). Shared dimensions/adjacency do not establish an equal winning displacement or confidence.

Consolidate this search under **`stitch_core.py`** as an explicit NCC strategy, keeping grid inference, arrangement, confidence aggregation and fallback reporting in the importer. A repetitive/ambiguous-overlap fixture is the discriminating case, not a successful registration of one easy image. Forcing either strategy onto the other changes its algorithm. The exact duplicate `_ncc` bodies (`align.py:1222`, `stitch_core.py:160`) belong to item 1010, not a new semantic-discrepancy count here.

**Placement from measured edges.** OPS `ops_solve.solve_placements` (`ops_solve.py:30`; caller `ops_stitch.py:278`) fits every accepted edge by least squares and pins the lowest site of each component. Generic Image Stitch (`image_stitch.py:568`) traverses from `(0,0)`, does not reconcile later loop closure, and places unvisited tiles using a mean-step grid. An inconsistent cycle is enough to produce different coordinates from identical edge measurements. Align placement already delegates (`align.py:1379`, `:1453`) to **`stitch_core.solve_positions` (`stitch_core.py:372`)**, which supports both the OPS gauge and anchored weighted solving. An isolated Align tile with nominal `(20,30)` can remain there while an OPS component is pinned to zero; that is an intentional frame policy.

Keep this existing owner. If all-edge placement is chosen to correct the importer's traversal behavior, identify the resulting coordinate/dimension change directly and retain fallback/reporting. Do not preserve wrong coordinates behind a compatibility flag. Preserve OPS component origins, site ordering, float64 arithmetic and one-thread BLAS contract during extraction.

**Lower-value paired affine arithmetic.** OPS `affine_polish` (`ops_merge.py:473`, well conversion `:623`) iterates mutual-nearest correspondences, trims residuals and can select tile-local fits in `(y,x)`. Spatial transcriptomics `_st_fit_affine`/`_st_apply_affine` (`ops_engine.py:12148`, `:12170`, callers `:12911`, `:12919`) takes already paired `(x,y)` landmarks once and returns a homogeneous matrix plus RMS. The paired least-squares substep can share **`ops_merge.py`**; complete fits cannot. Keep correspondence search, trimming, axis/matrix adapters and residual reporting local. The Spatial functions physically live in `ops_engine.py` but serve another workflow; this is not evidence of an independent module. No affine should be inverted by transposition unless its mathematical constraints justify it.

## 4. Segmentation calls and model loading

**Resolution before construction.** OPS `_cellpose_model` (`ops_engine.py:2128`) honors pinned artifacts, then passes nonempty names directly to `CellposeModel(pretrained_model=...)`. Normal Mask construction (`object.py:1714`, resolver use around `:1881`) uses **`utils._resolve_cellpose_pretrained` (`utils.py:6787`)**: existing files, model-zoo identities, supported aliases, stock-download policy and unknown-name refusal. Its contract explicitly addresses backend fallback for unrecognized names. Thus an equal requested name does not establish an equal effective checkpoint/error; no backend inference was run.

Reuse that existing resolver with the actual OPS setting key, preserving explicit pinned files, stock default, device and shared precision policy (`object.py:1451`). If an invalid-name path can silently select another model, correct it directly rather than retain it behind a switch. Valid model selection should remain unchanged; error behavior becomes deliberate and inspectable.

OPS role cache (`ops_engine.py:4610`, seeded at `:5689`) uses supplied names; pooled Mask caching (`_mask_workers.py:162`) uses resolved artifact/stat and constructor options. A role-specific pinned artifact collision is **not established** by the inspected caller configuration. Treat it as a conditional identity review, not a reported full-cache defect. If needed, share artifact-key construction in **`_mask_workers.py`**, keeping OPS multi-role lifetime and pooled-worker one-model eviction separate.

**Preparation is not interchangeable evaluation.** Phenotype segmentation (`ops_engine.py:4507`) block-averages DAPI/body planes, default factor 2, scales supplied diameters and repeats labels to original size. It uses public Cellpose normalization. Normal spatial Mask (`object.py:1978`, `:2030`) uses prepared channel batches, `normalize=False`, role thresholds, resampling and resolved-diameter provenance. Equal raw fields/weights need not produce equal masks because effective inputs/options differ.

Both already reach **`object._mask_eval` (`object.py:1470`; OPS adapter `ops_engine.py:2197`)**, which owns governed evaluation. Preserve it; keep geometry, normalization and options explicit in callers. There is no justification for changing OPS tile defaults or copying an entire Mask loop merely to share the model call. Fake-model checks can verify arguments, but cannot establish real segmentation equivalence.

**Classical object kernels are shared too.** OPS `_ph_segment_objects` (`ops_engine.py:4660`) uses `object._extract_classical_settings` (`:2944`), `_preprocess_batch` (`:2965`), `_segment_single_image` (`:3219`) and shared cleanup. Normal organelle generation (`object.py:2654`) additionally has cell-mask/preparation policies (`:2999`). Keep **`object.py`** as owner; consolidate capability/settings adapters only. Do not accidentally enable OPS's explicitly unsupported trained-UNet route or alter whole-field thresholding through tile-oriented substitution.

## 5. Intensity and morphology measurement

**One core, different prepared populations.** OPS `measure_phenotype_field` (`ops_sample.py:422`, settings at `:332`) casts HWC image to float32 and masks to int32, creates cell-minus-nucleus cytoplasm and anchors left joins on nucleus IDs. No nuclei means an empty table. Normal Measure constructs/filters role masks (`measure.py:11499`), excludes pathogen and enabled organelles from cytoplasm, and keeps role frames. Its actual calls (`:11612`, `:11621`) use the same **`measure.py:1336` morphology and `:1767` intensity owners** as OPS.

OPS disables periphery/outside features; normal Measure enables them. OPS's adapter is 2-D; the core supports spacing and 3-D branches. Equal original arrays therefore do not imply equal rows, cytoplasm or feature families. This is not evidence of two inconsistent region-property implementations. A prepared-array measurement interface in **`measure.py`** should take explicit role masks, spacing, channels and features, leaving filtering/join policy outside. Existing `_field_tables_for_check` (`:2541`) is a useful limited diagnostic precedent, not a substitute for all full-run hooks. Compare only identically prepared inputs and common enabled columns.

**Overlap mapping versus pairing.** OPS `pair_nuclei_with_cells` (`ops_sample.py:267`) assigns maximum overlap, retains one nucleus per cell, clips it, drops unpaired objects and compacts IDs. Selection uses overlap area, despite prose saying “largest nucleus.” Generic parent mapping (`measure.py:1643`) retains each child, assigns maximum-overlap nonzero parent, uses lowest-ID ties via `bincount().argmax()`, and maps no-overlap children to parent 0. Summaries (`:1666`) can retain multiple children.

Use **`measure.py`** for an overlap-assignment primitive, preserving OPS cardinality, clipping and relabeling in its adapter. For valid nonnegative integer masks, both implementations ignore background parents and choose the smallest positive parent on equal overlap; OPS's sorted encoded pairs and stable ordering establish that tie rule. The generic mapper retains no-overlap children with parent 0; OPS drops them and enforces one nucleus per cell. This is a concrete shared suboperation, not an unverified tie-policy claim. Preserve sparse-ID resource behavior; replacing whole policies would change row identity and joins. Clarify overlap-area documentation without silently changing selection to full-nucleus area.

**Funk and object summaries are already consolidated.** OPS `funk_object_features` (`ops_sample.py:372`) delegates to `measure._funk_object_columns` (`measure.py:3722`); its object summaries (`ops_sample.py:556`) delegate to `measure.py:1666`. Mass displacement (`measure.py:3501`, `:3628`), correlations (`:3696`) and form factor (`:3746`) retain **`measure.py`** as owner. Remaining naming, zero-filled absence and parent joins are adapters. Promoting an already-float32 OPS input to float64 cannot restore discarded precision; do not promise parity merely from the final dtype.

## 6. Feature normalization

**Reference location/scale is the largest arithmetic-sharing opportunity.** OPS `gene_measurement_compare.robust_z_to_controls` (`:1231`; caller `ops_engine.py:7412`) fits control cells per well. Embedding/profile aggregation `embeddings._normalise_to_controls` (`:1098`; caller `:1245`) works on control profiles; Measure profiling `sp_stats._normalize_profiles` (`:2977`; caller `:5760`) works on wells. Classifier normalization (`ops_mitotic.py:187`, `:233`, `:268`) supports full current/reference wells. Training without `reference_cells` warns and treats training rows as the full population (`:518`–`:532`), so completeness is a caller contract, not an enforced guarantee.

| Contract | Current numerical/population difference |
|---|---|
| OPS raw-feature robust z | Factor 1.4826; zero MAD or absent controls produces NaN; missing group keys are omitted; numeric coercion and same-index DataFrame output. |
| OPS mitotic classifier | Same rounded factor, infinity converted to missing, float32 output; missing categorical keys form a group. Full prediction reference takes precedence; saved training statistics are not the prediction reference. |
| Embedding/profile controls | Rounded factor; missing controls raises; a feature flat in any group is removed. Ordinary zscore uses sample SD. |
| Measure profiles | Full normal-consistency MAD factor (`sp_stats.py:463`), epsilon `1e-18`; spread and reference SD both below `tiny = 10 * finfo(float).eps` use unit scale. Zero MAD with reference SD at least tiny uses epsilon (`:3067`–`:3069`). Missing reference rows raises. |

For reference `[0,0,0,1]`, query 2, these policies respectively allow NaN, feature removal or division by `1e-18`; additional OPS profile routes use unit scale (`gene_measurement_compare.py:4047`, `ops_clusters.py:2400`). Even nondegenerate values differ slightly between rounded and full MAD multipliers. These are code-derived consequences, not newly measured scores.

Use **`batch_correction.py`**, extending existing `_center` (`:180`) and `_scale` (`:170`) for internal reference-statistics/application arithmetic. Keep reference populations, group/missing handling, multiplier, ddof, zero-scale policy, dtype and dropped-feature reporting explicit. Do not send every caller through one high-level normalizer. `normalization.py:100` concerns model-input channel statistics and is not the appropriate owner merely because of its name.

**Restored units versus dimensionless scores.** Generic batch correction (`batch_correction.py:1173`; public API `:903`) returns `(x-local_center)/local_scale*global_scale+global_center`, unlike OPS local/control scores. It is a no-op for fewer than two batches (`:1079`) and falls back to global scale for zero local scale. Share subtract/divide arithmetic in **`batch_correction.py`**, preserving restoration and population policy. Direct substitution changes distances and threshold meaning.

**Population SD and streaming.** OPS TVN uses `StandardScaler` per batch (`ops_tvn.py:114`) and direct float32 reductions (`:426`); streaming statistics (`gene_measurement_compare.py:4014`, `:4056`) use moment accumulation and a variance floor. Other profile standardization (`sp_stats.py:3076`) and embedding/profile sample SD (`embeddings.py:1123`) differ in ddof/precision/zero handling. The same **`batch_correction.py`** owner can host fit/apply arithmetic, but retain streamed accumulation order and library-defined policies. No bitwise-equivalence claim is available.

The default covariance eigenbasis is already shared: `batch_correction.spherize_features` (`:595`, import at `:696`) uses **`ops_tvn._control_basis` (`ops_tvn.py:216`)**. Explicit Brieflow reproduction retains sklearn PCA (`ops_tvn.py:182`) and is a separate choice. OPS TVN's shrinkage and CORAL are not the same outer transform as generic PCA/ZCA sphering. Preserve this owner rather than introduce another eigensolver.

## 7. Cell-cycle and mitotic operations

**Different models, not interchangeable classifiers.** OPS `gene_measurement_compare.cell_cycle_phases` (`:2171`; caller `ops_engine.py:10687`) anchors per-well non-targeting interphase log2 DNA, uses split 0.30 and an external mitotic flag. Its rule-based M flag (`gene_measurement_compare.py:1266`) uses mean-DNA robust z >3 and area robust z <=0; an alternative trained binary route is `ops_mitotic.py:578`.

Measure `_phases_by_measurements` (`measure.py:7189`; caller `:8080`) fits a constrained mixture per plate/time, can borrow pooled fits, distinguishes G1/S/G2/out-of-range states and overrides S/G2 calls as M at a G2-relative condensation ratio of at least 1.8 (`:7237`–`:7239`). The same corresponding DNA/area/mean inputs can therefore receive different calls by design. Missing anchors are also not equivalent: OPS relative DNA can remain NaN while the nonmitotic branch falls through to SG2; Measure nonfinite content becomes unknown. That missing-anchor behavior merits a focused correctness decision, not an unsupported claim of equivalence or automatic preservation as scientific intent.

**A smaller duplicated peak operation.** `gene_measurement_compare.g1_mode` (`:2153`) and `measure._dna_seed` (`:6874`, caller `:6976`) both smooth a log-DNA histogram. OPS uses fixed 120 bins/sigma 2 and the highest peak; Measure uses adaptive bins/sigma, constant handling and a lower-peak/G2-arrest correction. Use **`gene_measurement_compare.py`** for a configurable internal peak primitive, preserving public defaults and each caller's selection policy. Leave Measure's subsequent mixture model separate. Equal input can deliberately yield different anchors.

**Feature and denominator contracts.** OPS `mitotic_features` (`ops_mitotic.py:157`; training `:513`) selects named DNA/tubulin/nuclear-shape families in table order. Measure `_phase_features` (`measure.py:7304`; caller `:8108`) requires numeric features, excludes positional tokens, adds DNA/condensation values and cleans/drops columns. A varying nuclear centroid can enter OPS but not Measure. A configured name-selection primitive in **`ops_mitotic.py`** is possible, with numerical cleaning left in adapters; benefit is modest and saved feature order must remain stable.

OPS fractions (`gene_measurement_compare.py:1293`, `:1459`; `ops_mitotic.py:725`) count grouped cells/binary calls. Measure phase summaries (`measure.py:7889`, `:7947`) exclude missing calls or require joint calls, with time/infection groups; nonmissing `subG1` and `>4N` remain in denominators. One M, one G1 and one missing phase gives 1/2 when excluding the missing call versus 1/3 if an adapter explicitly encodes it as false and counts all cells. This does not claim OPS automatically performs that encoding. If shared, let **`gene_measurement_compare.py`** own generic counts with explicit valid masks, categories and keys. Preserve cell-count pooling and inferential statistics; do not equate this small common operation with shared biological definitions.

## Migration, verification and implementation order

Schema 950 is current (`settings.py:2551`); older-default folding (`:2621`, `:2707`) inserts absent historical values. Behavior-preserving extraction needs **no DEFAULT_CHANGES row, new public mode or compatibility flag**. Preserve intentional defaults: OPS robust z, split 0.3 and fixed crops; Measure robust profiling, ratio 1.8 and bbox crops. A deliberate default change needs an allocated migration row. A schema bump alone cannot preserve pixels, model features or denominator semantics. Correct confirmed bugs outright, document changed outputs and prevent incompatible resume/reuse.

First correct the global/local centroid inconsistency and unify model validation; next extract reference arithmetic and small slice/axis mechanics with explicit adapters. Preserve existing measurement/evaluation/covariance kernels. Defer broad phase-model mergers and low-value naming wrappers. Cache collision and PNG backend behavior remain conditional until their exact triggering inputs are established.

Existing tests provide preservation seams, not new passing evidence: `tests/test_ops_engine_phenotype_coverage.py:189`, `tests/test_ops_tile_batch_per_path_948.py:117`, `tests/test_ops_crop_bbox_margin_986.py:36`, `tests/test_crop_source.py:271`, `tests/test_ops_sample_phenotype_coverage.py:75`, `tests/test_ops_ownership_flatfield_funk.py:432`, `tests/test_mitotic_population_reference.py:156`, and `tests/test_cell_cycle_phase_three_ways.py:132`.

A later implementation check could use tiny deterministic inputs: a 16×16 coordinate ramp for half-integer crop centres; a small TIFF with distinct Z/T/C values for axis policies; and at most twelve table rows for finite, constant, zero-MAD and missing-control normalization. Report actual values, dtypes, columns, IDs and NaN masks; do not use tolerance-only comparisons to hide the differences under review. Fake model constructors can check resolution/options without downloads. A prepared-array measurement comparison should match masks, spacing, feature flags and column names before comparing values. These are proposed regression seams, not jobs needed or run for this documentation task. No broad pipeline, GPU, plate data or classifier training is required.
