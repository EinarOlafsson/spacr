# Duplicate-operation audit

Read-only specification, 2026-11-21. Source: [nightly `19a95cd7993e0ce44078c779828b91098820598f`](https://github.com/EinarOlafsson/spacr/tree/19a95cd7993e0ce44078c779828b91098820598f). Every file:line below refers to that revision. This audit changes no production code or settings. Existing tests are cited as evidence of intended contracts, not as newly executed checks.

Start with the crop percentile clones, NCC and the existing hash/SQL helper owners, then the OPS rotation constructor. Consolidate atomic file-publication mechanics with each caller's serialization and durability policy intact. Similar equations alone do not justify replacing scientific algorithms or workflow adapters.

## Search coverage and evidence

The completed inventory parsed **725 of 725 tracked `spacr/**/*.py` files**, examined **32,716 functions and methods**, and found **99 candidate groups: 74 spanning files and 25 confined to one file**, with **zero parse errors**. Every group has a disposition below. The accompanying manual search covers the nominated JSON writers, rotation constructors, publication/geometry call sites, crop scaling, label compaction and object-overlap calculations, including inline or renamed operations that an exact-body search misses.

The inventory ignores only function names, source positions and leading docstrings when hashing bodies. It preserves identifiers, literals and operators, records signatures/decorators separately, and groups bodies containing at least 30 AST nodes. Smaller bodies were parsed but omitted from clone groups. Identical bodies do not establish identical globals, closure state, imports, policies or results; nonidentical bodies can still implement the same operation. The ledger therefore records a semantic review of each candidate rather than 99 automatic merge instructions.

Retained I0 evidence: report SHA-256 `8618268331c6e261eda800316baf69c127466122f434757893b9457b04ff2e51`, inventory script `1bdf551ac055ce0ccfc0fe188283d77c19eba81bab778057f702003df97882eb`; job 650 exited 0 with source/input guards passing. The bounded AST-only run took **97.47 s**, used **302,702,592 bytes peak cgroup memory** (234,840 KiB maximum process RSS), and ran under one CPU, 1 GiB RAM, nice 19, CPU weight 800 and zero swap. It did not run application pipelines, Qt, numerical comparisons or tests. No performance improvement or numerical/pixel equivalence is inferred from these resource figures.

The primitive should accept a serializer callback or already prepared text/bytes. Preserve parent-creation policy, encoding/newlines, temp mode, file sync and directory sync (`none`, best effort or strict where supported). These are implementation arguments, not saved user settings. Close owned descriptors on stream-construction failure and preserve the original exception during cleanup. Retain caller locks and the detached-candidate → publication → in-memory-commit order.

Unique exclusive temps are preferable to shared fixed names, but changing the converter to `mkstemp` would normally change new-file permissions to 0600. Preserve its intended permission policy explicitly. Treat removal of leaked temps or improved exception preservation as named fixes with focused tests. A successful replace is atomic visibility, not a multi-file transaction, isolation, or confirmed power-loss durability; a strict directory-sync exception must report that bytes may already have been published.

## OPS rotation and coordinate operations

The reported name `rotation_matrix_from_degrees` is descriptive: at this base the helper is `_ph_rotation`. The same scalar-degree operation evaluates `np.radians(float(degrees))`, then the 2×2 `[[cos,-sin],[sin,cos]]` matrix. OPS coordinates are `(y,x)`; preserve `shape/2` as the field centre rather than substituting `(shape-1)/2`.

## Additional high-value families and risk/benefit order

The repository-wide pass adds several useful first steps beyond the nominated operations. NCC (15) already has the correct dependency edge; file hashing (51) has an existing infrastructure owner; SQL quoting (73) already has a shared reader import. These remove duplication with unusually small integration boundaries. Headless/GUI formatting (30, 81, 86, 87, 94), style (13, 35), role presence (28) and table presentation (5, 39, 47) provide further consistency gains if import and edge-case behavior stay unchanged.

The largest Qt repetition is job orchestration, but its value comes with a concrete migration obligation: preserve journals, figure capture, GUI-thread receivers, pending-job addressing and cancellation semantics. Prefer improving the existing JobRunner and bridge owners over creating another runner. Tiny accessibility, event, setup/domain and CLI adapters are not a reason to force unrelated classes into common inheritance. The priority below reflects maintenance benefit and contract risk, not a measured speedup.
