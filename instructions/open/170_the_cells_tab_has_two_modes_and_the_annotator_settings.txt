           167, 168 and 169.

RESTATED, BECAUSE IT WAS DESCRIBED ONCE ALREADY AND BUILT AS ONE ROUTE.

THE TWO MODES, AND WHAT THEY ARE CALLED

RENAMED TWICE ON 2026-08-19; THE SECOND IS THE ONE. First "live stream
images and stream cropped images", then -- "unify the terminology stream
images and load images. the default should always be loade images which
loades from data folder. if that fails it should always try the other."

    LOAD IMAGES     the crops already in data/    (crop_source 'png')
    STREAM IMAGES   cut from merged/ as it goes   (crop_source 'merged')

THESE ARE THE LABELS THE USER SEES. The stored values stay 'png' and
'merged', which is what `spacr.crops.resolve_crop_source` already reads, so
no settings file written before today changes meaning.

The naming and the fallback rule belong to instruction 171, which applies
them to EVERY panel that offers this choice. This file is the Cells tab's
share of it.

  1. LOAD IMAGES -- THE DEFAULT, AND THE EASY ONE.
     Needs `measurements.db` and the `data/` folder in the spaCR structure.
     Reads the crops that were exported at measure time. The user chooses
     WHICH CHANNELS of the PNG to load, whether they are normalised, and
     whether object outlines are drawn from them.

  2. STREAM IMAGES -- CUT FROM THE ARRAYS.
     Needs the `merged/` folder and the database. The user specifies which
     channels to build the picture from, AND which array the intensity
     channels are cut by -- a mask label, or object coordinates from the
     object table. COORDINATES CAN ONLY GIVE A BOUNDING BOX, and the panel
     must say so rather than offering an object-shaped cut it cannot make.

WHAT TO BUILD

A. A MODE SETTING, defaulting to LOAD IMAGES. It is the first
   control, not a consequence of what happens to be on disk.
   `resolve_montage_crop_source` already decides a route by looking at the
   folders; that stays as the ANSWER TO "what is available", and stops being
   the answer to "what did the user ask for".

   THE ANNOTATION APP HAS THE SAME DEFECT AND THE SAME FIX. Asked
   2026-08-19: "in the annotation app how do i choose to stream images from
   database or dataset". The answer today is that you do not --
   `set_annotate_default_settings` ships `crop_source='auto'`, and 'auto'
   takes the PNG folder whenever one exists. The setting is there and the
   choice is not offered, so a user with both folders cannot ask for the
   arrays without editing a settings file. Both panels get the named modes.

   AND THERE ARE TWO VOCABULARIES FOR THIS ALREADY, which is 145 exactly:

       spacr.crops.resolve_crop_source   'auto' | 'png' | 'merged'
       the training / classify settings  'pre_generated' | 'on_demand'
                                         | 'generate'

   One idea, two spellings, and this instruction must not add a third. The
   labels above are LABELS; the stored value stays the crops vocabulary, and
   folding the training one onto it is a separate, named job.

B. A SETTINGS BUTTON THAT OPENS THE ANNOTATOR'S OWN CONTROLS. Not a new
   vocabulary: `set_annotate_default_settings` already names every one of
   them, and the Cells tab should offer the same keys with the same meanings
   --

       image_type, channels, img_size, normalize_channels, percentiles,
       outline, outline_threshold_factor, outline_sigma, edge_thickness,
       edge_transparency, edge_image, object_size, crop_source

   A second set of names for the same picture is the "one vocabulary" failure
   145 is about, and here it would be two panels that disagree about what
   "normalize" means.

C. WHAT DOES NOT APPLY IS GREYED, NEVER HIDDEN (INVARIANTS 6). In saved-PNG
   mode the array/mask selectors are greyed with the reason; in live-crop
   mode the PNG channel picker is. A control that vanishes cannot tell the
   user why their mode does not offer it -- which is the same rule the
   backend selector already follows, and the same one the volcano's adjusted
   axis follows.

D. IT FALLS BACK, AND IT SAYS THAT IT DID.

   This file first said the opposite -- that a mode the folders cannot serve
   should be refused by name rather than silently falling back, because a
   silent fallback makes a user believe they are looking at a crop they are
   not. The maintainer has since asked for the fallback outright: "if that
   fails it should always try the other."

   Both are satisfied by keeping the fallback and dropping the SILENCE. The
   panel tries the other route and then states which one drew what is on
   screen. A fallback nobody can see is the problem; a fallback that names
   itself is a convenience.

HOW TO KNOW IT WORKED

* The Cells tab opens in LOAD IMAGES without being told to, and says so by
  name rather than leaving the user to infer it from 'auto'.
* The annotation app offers the same two named modes, so "stream from the
  database or from the dataset" is a choice a user can make in the panel.
* The settings window offers the annotator's controls, under the annotator's
  names, and a change to any of them changes the picture.
* Switching to STREAM IMAGES greys the PNG-only controls and enables the
  array and coordinate selectors; switching back reverses it, and nothing is
  hidden either way.
* Choosing coordinates says that the cut will be a bounding box before it is
  made.
* A screen with no `merged/` asked for STREAM IMAGES falls back to LOAD
  IMAGES and SAYS SO; it does not draw as though nothing happened.
* No settings file written before today changes meaning: the stored values are
  still 'png' and 'merged'.
