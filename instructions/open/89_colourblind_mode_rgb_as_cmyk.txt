================================================================================
A COLOURBLIND MODE FOR EVERY IMAGE SPACR SHOWS
================================================================================

Status:    not started, 2026-08-13.
Requested: 2026-08-13 - "we should have a colorblind mode that applies to
           images being shown, where RGB images are visualized as CMYK
           instead"

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Red/green is the commonest colour-vision deficiency and it is exactly the
pair fluorescence microscopy uses most: a red stain and a green stain
overlaid, judged by eye for colocalisation. For a deuteranope or protanope
that judgement is not harder, it is unavailable -- the two channels are the
same colour and the overlap is invisible.

This is the same family as PR #74 and issue #73, which are about a channel
landing in the wrong colour. Here the colour is right and the EYE cannot
separate it.

--------------------------------------------------------------------------------
WHAT WAS ASKED FOR, AND THE ONE THING TO SETTLE FIRST
--------------------------------------------------------------------------------

"RGB images are visualized as CMYK instead." The intent is clear -- swap the
primaries for a set that separates under red/green deficiency. CMY is a good
choice: cyan / magenta / yellow stay distinguishable where red / green do
not, and magenta-green is the standard accessible substitution for red-green
in microscopy figures.

WHAT NEEDS DECIDING is what the mapping IS, because "RGB as CMYK" has two
readings and they look different:

  a. CHANNEL SUBSTITUTION -- draw channel 0 in cyan, 1 in magenta, 2 in
     yellow, additively. Simple, reversible, and each channel keeps its own
     identity. This is what most "colourblind-friendly" microscopy figures
     do.
  b. A REAL RGB->CMYK COLOUR CONVERSION -- convert the composite through the
     subtractive model. This is a print transform; on a screen it mostly
     darkens and does not improve separability, and it is lossy in a way
     that would change what a user thinks they are seeing.

(a) is almost certainly what is wanted and (b) is almost certainly not, but
the request says CMYK, so ASK before building if there is any doubt.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

* A DISPLAY TRANSFORM, NEVER A DATA ONE. It applies where an image is drawn
  and nowhere else. It must not touch what is written to disk, what is
  measured, or what a model is trained on -- a crop saved in colourblind
  colours would silently become the training set.

* ONE PLACE, NOT NINE. Every viewer must get it: the Live Preview, the crop
  preview, Annotate, Make Masks, the plate/figure views and the saved
  figures. Instruction 69 is standardising exactly these surfaces on one
  contract; this belongs behind that seam rather than pasted into each. If
  69 has not landed, put it in the one function that turns an array into a
  QPixmap and route everything through it.

* A GLOBAL PREFERENCE, not a per-screen toggle. A user who needs this needs
  it everywhere, every session. It belongs beside the theme in preferences.

* PALETTE ROLES, not literals, for the same reason the class-editor bubbles
  use them -- see `chip_class` / `chip_value` in `spacr/qt/theme.py`.

* SAY SO ON SCREEN. When the mode is on, the viewer states which channel is
  drawn in which colour. A figure exported in these colours must carry it
  too, or a reader of the PDF has no way to know the mapping is not the
  usual one.

--------------------------------------------------------------------------------
WORTH DOING AT THE SAME TIME
--------------------------------------------------------------------------------

The outline colours (`OUTLINE_COLOURS` in `spacr/qt/widgets/live_preview.py`)
are green / magenta / yellow / cyan / white / red, and `auto` draws a random
colour per compartment. Random is fine for the sighted case and is exactly
wrong here: it can draw two adjacent compartments in a pair the user cannot
tell apart. Under colourblind mode `auto` should draw from a safe set.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

With the mode on, every surface that draws an image draws it in the
substituted primaries; nothing on disk changes; a test simulates deuteranope
and protanope vision over a two-channel overlay and asserts the two channels
remain distinguishable where they did not before; and the mapping is stated
on screen and in any exported figure.
