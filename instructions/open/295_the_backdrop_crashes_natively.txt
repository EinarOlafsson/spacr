295 — spaCR dies with a native crash, no Python frame

Reported 2026-08-28 ("spacr just crashed", then "crashed again").

WHAT THE LOG SHOWS (~/.spacr/logs/spacr-crash.log):

* Repeated `Fatal Python error: Segmentation fault` and `Fatal Python error:
  Aborted`, across many pids and predating the verbose-logging change.
* The two entries that captured a Python frame both read:

      spacr/qt/app.py, line 4119 in launch
      spacr/qt/__init__.py, line 350 in run
      spacr/qt/spaceout.py, line 29 in main

  with PySide6.QtOpenGLWidgets and PySide6.QtOpenGL among the loaded
  extension modules -- the GL fractal path.
* The most recent crashes wrote no Python frame at all.
* One run's ordinary log ends mid-paint inside the ambient backdrop
  (`_BufferedEngine.shade` -> `_FrameProducer.publish`) and the next line is a
  fresh process.

NOT memory: `free` showed 100 GB available and the kernel log records no OOM
kill.

TO PIN IT: rerun with faulthandler dumping ALL threads (not just the current
one) and a GL context created under a serialised lock, and record which thread
is in native code at the abort. A QPixmap or a QWidget touched off the GUI
thread aborts exactly like this; the producer thread is documented as
QImage-only, so the candidates are the GL context and anything the fractal
widgets touch during teardown.


STATUS 2026-08-28 -- MITIGATED, NOT YET DIAGNOSED.

The crashing thread has NO PYTHON FRAME: faulthandler already runs with
all_threads=True, and it reports the fault in native code -- Qt's render
thread or the GL driver -- where there is no Python stack to print and no
`except` that can run. Nothing more can be learned from the Python side.

What shipped instead is recovery, in `spacr/qt/crash_recovery.py`: a marker
written at launch and removed on a clean shutdown, so two unclean exits in
a row start spaCR without the backdrop or any GL. It is process-local and
clears itself after one clean run, so the user has nothing to undo.

STILL OPEN, and it needs the machine that crashes:
  * a NATIVE backtrace -- run under gdb, or catch SIGSEGV/SIGABRT with a
    handler that calls backtrace(3) -- to name the library and the call;
  * `glxinfo | head -20` and the driver version, since a driver bug is as
    likely as a spaCR one and the fix differs completely;
  * whether it reproduces with the backdrop off (`SPACR_NO_BACKDROP=1`),
    which would clear the backdrop and move the search elsewhere.
