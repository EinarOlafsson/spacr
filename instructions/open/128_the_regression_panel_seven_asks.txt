A. `volcano` DEFAULTS TO GENE
--------------------------------------------------------------------------------

`spacr/settings.py:1902` does `settings.setdefault('volcano', 'grna')`.

The DOCSTRING for the same setting, at settings.py:3529, already says
"'gene' (default)". So the code and its own documentation disagree, and the

the doc.

Worth checking whether anything reads `volcano` expecting 'grna' before
flipping it -- the gene table is the smaller one and is what the phenotype
and heatmap reports are keyed on, so this should be the cheaper default too.

B. "COLOUR BY" MUST OFFER condition -- AND SAY WHY WHEN IT CANNOT
--------------------------------------------------------------------------------

MEASURED FIRST, because the obvious diagnosis was wrong. On a synthetic
1,200-row table with nc/pc/other, `condition` IS offered:

    colour-by offers: [('nothing', None), ('condition (3)', 'condition')]

So the filter is not blanket-excluding it. The rule in `set_frame` is

    dtype is object/category AND 1 < distinct <= max(40, len(frame) // 20)

and the two ways a real screen falls out of it are:

  * `distinct == 1`. Every row is 'other' -- which happens when the
    negative/positive control NAMES do not match any feature, so nothing is
    labelled. `1 < 1` is False and the column vanishes.
  * the column is absent, on a table loaded from a gene/grna split CSV.

BOTH ARE SILENT TODAY, and that is the actual defect: a column the user
expects to see simply is not in the list, with nothing saying why. A
one-value `condition` is ALSO a finding -- it means the control names did not
match -- and hiding it hides that.

    So: offer it, or say why it is not offered. Never omit in silence.

C. LOPIT IN "COLOUR BY"
--------------------------------------------------------------------------------

`spacr/localisation.py` already joins a coefficient table to the TAGM/LOPIT
compartments (`of`, `present`, `mask`) and the volcano's right-click submenu
uses it. It is not a COLUMN, so the colour-by combo -- which walks
`frame.columns` -- cannot see it.

Add it as a DERIVED option. The house rule caps how it is drawn (one
compartment against grey, 26 hues is what the rule forbids), but as a
colour-by category on the interactive plot the existing categorical path
already handles it; `present()` gives the ones this screen actually has.

D. THE REGRESSION PLOT BELONGS ON THE ALL-FIGURES GRID
--------------------------------------------------------------------------------

The interactive volcano is built with `external_volcano=True` and placed by
the caller, so the grid -- which shows the run's matplotlib figures -- does
not carry it. The maintainer wants it there too.

TRAP, already written down in 121: `_FigureCell.index` is the enumerate index
over the pixmap list and `figure_activated` forwards it straight to
`FigureQueue.show_index()`, so anything inserted into that list SHIFTS EVERY
FIGURE AFTER IT. Whatever is added has to keep that mapping honest.

The house-style volcano (`figures/panels.volcano`) is already drawn and saved
by a run, so check first whether the ask is "the saved one is missing from
the grid" rather than "put the live widget on the grid" -- they are different
jobs and the first may already be a bug.

F. RIGHT-CLICK A LIVE PLOT TO CHANGE ITS TYPE
--------------------------------------------------------------------------------

"show guide support as a violin, box, bar, jitter plot".

The right-click menu already restyles (point size, colour, opacity, axis
labels, legend) and offers baselines and the re-fit. This adds the MARK.

FOLLOW THE SKILL'S RULE rather than offering four equal options: for n <= 8
per group it is individual points with a mean line, never a bar; a box plot
hides n; a violin on few points draws a distribution that is not there. So
offer them, and let the panel say when the chosen one is misleading for the
data in front of it rather than silently drawing it.

--------------------------------------------------------------------------------

A splitter size, not a fixed width -- the divider stays the user's to move.
Whatever is set has to survive a restart if the app already remembers

K. THE ADJUSTED P-VALUE BELONGS IN THE COEFFICIENTS TABLE
--------------------------------------------------------------------------------

The correction is the whole point of the multiple-testing work and the table
shows the raw p. The panel already PREFERS a corrected column when it cuts
("q_value", "adjusted_p_value", "p_value" -- in that order) so the column
exists in the frame; it is simply not surfaced as a column a reader can read
and sort.

Check what the run actually writes before assuming: `perform_regression`
sets `multiple_testing_method` on the frame, so the column NAME and the
method should both be visible -- a q with no method beside it is not
reportable.

L. THE GENE/gRNA FILTER IS GLOBAL, AND DRIVEN FROM THE TABLE TOO
--------------------------------------------------------------------------------

129 A put genes/guides/both on the VOLCANO's right-click menu. This extends
it in two directions:

  * the same gesture on the COEFFICIENTS TABLE;
  * and it filters EVERY tab -- the table, the p-histogram, the Q-Q, the

ONE PIECE OF STATE, not one per plot. The panel already owns `_level`; the

M. RESIDUAL AND HOMOGENEITY PLOTS IN THE REGRESSION MODULE TAB
--------------------------------------------------------------------------------

Requested 2026-08-17: "to the instructions list add to generate reisdual and
homogenisity plots in the regression modual tab".

Item E landed the Residuals, Scale-location and Influence tabs. This asks for
the pair a reader checks BEFORE believing a coefficient, together, in the
module's own tab:

  * RESIDUALS -- fitted against residual, which is already there.
  * HOMOGENEITY OF VARIANCE -- scale-location is the plot for it, and it is
    there, but the QUESTION it answers is not asked anywhere: is the residual
    spread constant across the fitted range? A trend in that plot is
    heteroscedasticity, and OLS standard errors are wrong when it is present
    -- which changes every p-value in the table.

So the work is not another plot. It is:

  * a VERDICT beside them. `regression_qc` already computes the statistics
    (Breusch-Pagan / White, and the residual-spread trend); the tab shows the
    picture and not the answer. Say "constant spread" or "spread grows with
    the fitted value; the standard errors above are optimistic" -- the second
    sentence is the one that changes what a reader does.
  * and the LINK to the fix: `cov_type='HC3'` is a sandwich estimator that is
    valid under heteroscedasticity, is already a supported setting, and is
    exactly what a user should reach for when this plot says so. The panel
    should name it.

DO NOT RE-DERIVE THE STATISTICS. `spacr/regression_qc.py` is 3,444 lines and
already computes them for the saved PDF; the live tab must read the same
numbers or the two will disagree about the same fit.

--------------------------------------------------------------------------------
N. THE STATSMODELS SUMMARY, AS A TAB
--------------------------------------------------------------------------------

Requested 2026-08-17: "statmodels provides a summary, please generate a tab
for the regression summary".

The model already reaches the panel -- `set_diagnostics(model, ...)` is how
the residual tabs are filled -- so this is a rendering job, not a plumbing
one. THREE THINGS IT MUST HANDLE, all of which this screen actually hits:

  * NOT EVERY BACKEND HAS ONE. `.summary()` is a statsmodels method; the
    sklearn-backed types (lasso, ridge, elasticnet, hinge) have no such
    thing, and `horseshoe` is spaCR's own. The tab says which backend was
    fitted and that it reports no summary, rather than being absent or
    empty.
  * IT IS ENORMOUS. This screen fits 827 parameters, so the coefficient
    block is 800-odd rows. Monospace, scrollable, and SELECTABLE -- the
    reason to want it is usually to paste a number into a methods section.
  * THE HEADER IS THE USEFUL PART and it is the part that scrolls away:
    R-squared, F-statistic, AIC, log-likelihood, Df Residuals, and the
    condition-number warning statsmodels appends. Keep it reachable.

AND THE ONE THING THAT MAKES IT DANGEROUS HERE. On this screen the fit is
NOT IDENTIFIABLE -- the run already says so: "610 analysed wells are being
used to estimate 827 parameters". statsmodels will still print a full
summary with a standard error and a P value for every guide, and it looks
exactly like a summary of a well-posed fit. The tab must carry the same
warning the run prints, next to the table rather than in the log above it.

A summary a reader pastes into a paper from an unidentifiable fit is the
worst outcome this panel can produce, and it is one click away.

O. THE FULL RESTYLE MENU: DIMENSIONS, CMAP, MARKER, FONT, LINES, TYPE
--------------------------------------------------------------------------------

Requested 2026-08-17: "when right clicking a graph i should also be able to
choose its dimensions the cmap of the datapoints and their shape, font size
color, line color and width (sometimes not applicable on certain graph
types). as well as graph type when applicable".

Some of this ships: point size, point colour, opacity, axis labels, font
size, grid, legend, the mark type on the grouped plots (F), the baseline, the
compartment, the effect-size cut and the p-value axis. What is NOT there:

  * FIGURE DIMENSIONS -- width and height. On the interactive plots this is
    the widget's size and the splitter's; on a SAVED figure it is the
    figsize, and those are different things. The menu must say which it is
    changing, or a user sets "dimensions" and finds the exported PDF
    unchanged.
  * A COLORMAP for the points, as opposed to the categorical palette that is
    there. A cmap is for a CONTINUOUS quantity -- colour the volcano by
    effect size or by well count -- and offering one for a nominal category
    is the mistake the house style warns about, so the menu should offer it
    only where the colouring column is numeric.
  * MARKER SHAPE.
  * FONT COLOUR (size is there; colour is only on the matplotlib dialog).
  * LINE COLOUR AND WIDTH -- the reference lines, the threshold lines, the
    trend on the Q-Q.
  * GRAPH TYPE where one makes sense. F did this for the grouped plots
    (violin/box/bar/jitter/points); the request generalises it.

"(sometimes not applicable on certain graph types)" is the design constraint
and it is the same one instruction 106 solved for settings: AN ENTRY THAT
CANNOT DO ANYTHING IS GREYED OUT AND SAYS WHY, never silently absent and
never present-but-inert. A cmap on a categorical colouring, a marker shape on
a histogram, a line width on a plot with no lines -- each should appear
disabled with a one-line reason.

DO NOT BUILD A SECOND STYLE SYSTEM. Instruction 127 finding 3 already records
that `spacr/figure_style.py` (the user's preference, general and per-graph)
and `spacr/figures/style.py` (the house style) are two systems unaware of
each other, and that a preference cannot currently reach a house-style panel.
This menu is the third place that would want the same vocabulary. Merge
first, or this becomes the reason the merge never happens.

Q. THE RIGHT-CLICK MENU IS TOO LONG, AND ONE ENTRY LIES BY DOING NOTHING
--------------------------------------------------------------------------------

Reported 2026-08-17: "there are way to many settings in the right click now
they need to be organized into dropdowns", "guide only and gene only does
nothing", "my data say 1612 gRNAs and 0 genes".

**Q1. SUBMENUS.** The menu now carries: point size, point colour, opacity,
axis labels, font size, grid, legend, reset view, export, mark type, the
p-value axis, the effect-size cut (seven methods plus a multiplier), show
genes/guides, measured-from, colour by localisation, re-fit -- plus whatever
the restyle work adds. That is well past what a flat list can carry.

Group them, and group them by WHAT THEY CHANGE rather than by type, because
that distinction is the one the menu already makes with its section headings
and it is the one that matters:

    Appearance      size, colour, opacity, font, lines, grid, legend, cmap,
                    marker shape, dimensions, aspect
    Axes            labels, limits, the p-value axis
    What is shown   genes/guides, colour by localisation
    Hit calling     the effect-size cut and its multiplier, measured-from
    Run             re-fit
    Export          ...

The last three change what the plot MEANS; the first two change how it looks.
A user reaching for "point size" must not be one slip from a re-fit, which is
why the re-fit already sits under its own heading -- submenus should preserve
that separation rather than flatten it back.

**Q2. THE GENE/GUIDE FILTER DOES NOTHING ON A PERMUTATION RUN, AND IT IS
RIGHT TO.** Diagnosed: `ml.py:3422` builds every permutation row's feature as
`'fraction:grna[' + guide + ']'`. There are no `gene_fraction:gene[...]` rows
because THE PERMUTATION TEST TESTS GUIDES -- it is a per-guide marginal
association -- and the compatibility dict writes `results.csv`,
`results_grna.csv` and `results_significant.csv` with NO `results_gene.csv`,
unlike the parametric path.

So 1612 gRNAs / 0 genes is CORRECT. "Guides only" changes nothing and "genes
only" empties the plot. That is honest and useless, and it is what
instruction 106 forbids by name: a control that cannot do anything is greyed
out and SAYS WHY, never silently inert. Grey both entries on a table with
only one level in it, with the reason.

**Q3. THE REAL QUESTION, AND IT IS THE MAINTAINER'S TO ANSWER.** Should a
permutation run have gene-level results at all? The parametric run gives
`gene_fraction:gene[244480]` at p = 2.9e-13 AND the guide-support table that
says which genes rest on a single guide. The permutation run gives neither,
so the two runs are not comparable and a user switching inference loses the
gene view without being told.

Aggregating per-guide permutation results to genes is a real statistical
choice with more than one defensible answer -- combine the per-guide P values
(Fisher, Stouffer), test the gene's guides as a SET against the same
permutation null, or report the gene only through guide agreement. They
answer different questions and one of them has to be chosen deliberately.
DO NOT PICK ONE SILENTLY.
