--------------------------------------------------------------------------------
A. `volcano` DEFAULTS TO GENE
--------------------------------------------------------------------------------

`spacr/settings.py:1902` does `settings.setdefault('volcano', 'grna')`.

The DOCSTRING for the same setting, at settings.py:3529, already says
"'gene' (default)". So the code and its own documentation disagree, and the
maintainer's request is for the documented behaviour. Change the code, not
the doc.

Worth checking whether anything reads `volcano` expecting 'grna' before
flipping it -- the gene table is the smaller one and is what the phenotype
and heatmap reports are keyed on, so this should be the cheaper default too.

--------------------------------------------------------------------------------
B. "COLOUR BY" MUST OFFER condition -- AND SAY WHY WHEN IT CANNOT
--------------------------------------------------------------------------------

MEASURED FIRST, because the obvious diagnosis was wrong. On a synthetic
1,200-row table with nc/pc/other, `condition` IS offered:

    colour-by offers: [('nothing', None), ('condition (3)', 'condition')]

So the filter is not blanket-excluding it. The rule in `set_frame` is

    dtype is object/category AND 1 < distinct <= max(40, len(frame) // 20)

and the two ways a real screen falls out of it are:

  * `distinct == 1`. Every row is 'other' -- which happens when the
    negative/positive control NAMES do not match any feature, so nothing is
    labelled. `1 < 1` is False and the column vanishes.
  * the column is absent, on a table loaded from a gene/grna split CSV.

BOTH ARE SILENT TODAY, and that is the actual defect: a column the user
expects to see simply is not in the list, with nothing saying why. A
one-value `condition` is ALSO a finding -- it means the control names did not
match -- and hiding it hides that.

    So: offer it, or say why it is not offered. Never omit in silence.

--------------------------------------------------------------------------------
C. LOPIT IN "COLOUR BY"
--------------------------------------------------------------------------------

`spacr/localisation.py` already joins a coefficient table to the TAGM/LOPIT
compartments (`of`, `present`, `mask`) and the volcano's right-click submenu
uses it. It is not a COLUMN, so the colour-by combo -- which walks
`frame.columns` -- cannot see it.

Add it as a DERIVED option. The house rule caps how it is drawn (one
compartment against grey, 26 hues is what the rule forbids), but as a
colour-by category on the interactive plot the existing categorical path
already handles it; `present()` gives the ones this screen actually has.

--------------------------------------------------------------------------------
D. THE REGRESSION PLOT BELONGS ON THE ALL-FIGURES GRID
--------------------------------------------------------------------------------

The interactive volcano is built with `external_volcano=True` and placed by
the caller, so the grid -- which shows the run's matplotlib figures -- does
not carry it. The maintainer wants it there too.

TRAP, already written down in 121: `_FigureCell.index` is the enumerate index
over the pixmap list and `figure_activated` forwards it straight to
`FigureQueue.show_index()`, so anything inserted into that list SHIFTS EVERY
FIGURE AFTER IT. Whatever is added has to keep that mapping honest.

The house-style volcano (`figures/panels.volcano`) is already drawn and saved
by a run, so check first whether the ask is "the saved one is missing from
the grid" rather than "put the live widget on the grid" -- they are different
jobs and the first may already be a bug.

--------------------------------------------------------------------------------
E. MORE DIAGNOSTIC TABS BESIDE Q-Q AND CONTROLS
--------------------------------------------------------------------------------

"in the tabs Q-Q and Controls, there should be Tabs like residuals showing
the residuals and regression controll graphs like that."

`spacr/qt/widgets/fast_plots.py` already has `ResidualPlot`, and
`spacr/regression_qc.py` has ~19 panels. The panel shows five of them. The
ask is for the residual diagnostics to be reachable live, as tabs, the way
Q-Q and Controls are.

Pick from what regression_qc already computes rather than writing new
statistics -- the module is 3,444 lines and its panels are already the ones
the run saves.

--------------------------------------------------------------------------------
F. RIGHT-CLICK A LIVE PLOT TO CHANGE ITS TYPE
--------------------------------------------------------------------------------

"show guide support as a violin, box, bar, jitter plot".

The right-click menu already restyles (point size, colour, opacity, axis
labels, legend) and offers baselines and the re-fit. This adds the MARK.

FOLLOW THE SKILL'S RULE rather than offering four equal options: for n <= 8
per group it is individual points with a mean line, never a bar; a box plot
hides n; a violin on few points draws a distribution that is not there. So
offer them, and let the panel say when the chosen one is misleading for the
data in front of it rather than silently drawing it.

--------------------------------------------------------------------------------
G. THE LEFT PANEL IS WIDER
--------------------------------------------------------------------------------

A splitter size, not a fixed width -- the divider stays the user's to move.
Whatever is set has to survive a restart if the app already remembers
splitter state, and must not fight the minimum widths the results panel
sets (`volcano.setMinimumHeight(240)`, `table.setMinimumHeight(150)` are the
existing precedent for "floors, not preferences").

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* A run that says nothing about `volcano` draws the GENE volcano.
* `condition` is in the colour-by list, or the panel says why it is not.
* LOPIT compartment is in the colour-by list on a Toxoplasma screen.
* The regression plot appears on the all-figures grid, and clicking any tile
  still opens the figure that tile shows.
* Residual diagnostics are a tab beside Q-Q and Controls.
* Right-clicking the guide-support plot offers violin / box / bar / jitter,
  and says when the choice misleads for this n.
* The left panel is wider on first open, and the divider still moves.

I. "WHERE DO I SET THE INTERCEPT?" -- IT IS BUILT AND UNDISCOVERABLE
--------------------------------------------------------------------------------

It ships (124 M, commit 2aee63e5): RIGHT-CLICK THE VOLCANO -> "Measured
from" -> "zero (no dose-response)" or "the non-targeting controls".

That the maintainer had to ask is the finding. Three separate things now live
on that one right-click menu -- the baseline, the LOPIT compartment, the
re-fit -- and two more are queued (F's mark types, A's gene/guide filter).
A menu is where a feature goes to not be found.

    So this is a DISCOVERABILITY item, not a missing feature. Options, and
    the choice must be stated: a visible control in the panel header beside
    "colour by"; or a Statistics/Model tab; or leaving it on the menu and
    saying in the caption where it was set. The caption already names the
    baseline on every panel, which is the half that works.

--------------------------------------------------------------------------------
J. RUNS BEFORE RESULTS, AND RESULTS FOLLOW THE SELECTED RUN
--------------------------------------------------------------------------------

Two changes, and the second is the substantive one.

  * tab ORDER: Runs, then Results.
  * SELECTING a run in the Runs tab points Results at THAT run -- its
    coefficient table, its figures, its diagnostics.

`_show_trial` already opens a run's folder into the results panel and the
grid, so the wiring exists; what is missing is that the Results tab is not
bound to the Runs selection, and the tab order says Results is the primary.

TRAP: the panel's `set_frame` resets the baseline, the compartment, the
gene/guide filter and the selection, deliberately -- a new table is a new
experiment. Switching runs SHOULD reset those. Switching BACK should not be
expected to restore them.

--------------------------------------------------------------------------------
K. THE ADJUSTED P-VALUE BELONGS IN THE COEFFICIENTS TABLE
--------------------------------------------------------------------------------

The correction is the whole point of the multiple-testing work and the table
shows the raw p. The panel already PREFERS a corrected column when it cuts
("q_value", "adjusted_p_value", "p_value" -- in that order) so the column
exists in the frame; it is simply not surfaced as a column a reader can read
and sort.

Check what the run actually writes before assuming: `perform_regression`
sets `multiple_testing_method` on the frame, so the column NAME and the
method should both be visible -- a q with no method beside it is not
reportable.

--------------------------------------------------------------------------------
L. THE GENE/gRNA FILTER IS GLOBAL, AND DRIVEN FROM THE TABLE TOO
--------------------------------------------------------------------------------

129 A put genes/guides/both on the VOLCANO's right-click menu. This extends
it in two directions:

  * the same gesture on the COEFFICIENTS TABLE;
  * and it filters EVERY tab -- the table, the p-histogram, the Q-Q, the
    controls, the guide support, and whatever 129 B adds.

ONE PIECE OF STATE, not one per plot. The panel already owns `_level`; the
work is that every draw path reads it and every entry point sets it. A filter
that reaches four of six tabs is worse than one that reaches none, because
the two disagree on screen at the same time.

    The Q-Q and the p-histogram are the ones to think about: filtering the
    family CHANGES THE CALIBRATION being shown. A Q-Q of the guides only is a
    different diagnostic from a Q-Q of the whole fit, and the panel must say
    which it is drawing rather than leaving the reader to assume.
