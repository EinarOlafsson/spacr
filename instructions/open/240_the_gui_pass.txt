1. EVERY WORD IN THE CHOSEN LANGUAGE            <-- BIGGEST ITEM, IN HAND
--------------------------------------------------------------------------------

WHAT IS DONE. The setup screen translates and applies the language as it
is chosen -- titles, blurbs, the step counter, the buttons and the GitHub
row all redraw, and German to Korean goes through the English source
rather than translating a translation. The Home chrome, the Demos menu and
the settings-count line follow, the last composed from translated parts
rather than from f-strings. All nine runtime catalogs and all nine API
catalogs are rebuilt; where a model left prose in English the translation
is hand-written as reviewed evidence.

A sweep of six surfaces in Swedish found 79 verified items. The 37 that
needed only a catalog row are carried: 101 exact rows in every one of the
nine catalogs, because several of the 37 name a family rather than one
caption -- the preferences tabs and their theme, mode and colour-blind
dropdowns, the four resource buttons and their row labels, the spaCR-mode
notes and warnings, the glass "press Escape to close" hint, the thirteen
live-preview compartment fields, twenty-three figure-settings form labels,
the annotate empty state and its keyboard legend, the maturity hover
sentences, the list-editor chip placeholders and the channel glosses. An
exact row is what beats the word-by-word term fallback, which is what had
been producing "Intensity Handling (all Objekt)" and "Platta Sources &
Arbetsflode".

THE CALL-SITE HALF IS DONE. Counted by DRIVING THE APPLICATION rather than
by grepping: the whole registry is opened in English and again in Swedish,
every settings category expanded, every declared preview toggled on, the
menus walked and Preferences shown, and a caption is called still-English
when the two runs render it identically AND a catalog can translate it.

    still-English captions   BEFORE   AFTER
    distinct                     94       5
    occurrences                 112      16

THE ONE CAUSE BEHIND 89 OF THE 94 was not a missing `tr()` anywhere. A
screen is translated ONCE, by `MainWindow` when it builds it, and
`spacr.qt.preview_registry` installs a module's declared preview the first
time that module is opened -- which is after the pass. The whole Plaque
analysis preview and the toggle beside the search box therefore arrived in
English and were never asked again. `AppScreen._watch_for_late_captions`
watches the two hosts a late panel lands in (`_runtime_wrap` and
`_body_splitter`) for `ChildAdded` and runs the pass over the new subtree,
deferred one turn of the event loop because a widget can be parented before
its own children exist.

THE FIVE THAT REMAINED are done, and they were the tip of a bigger one.
`auto`, `Overlay`, `Masks`, `Flows` and `All channels` are combo entries in
`spacr/qt/widgets/live_preview.py` that carried `i18nSkipItems` because
`_outline_rgb` and `_refresh_canvases` read them back BY TEXT. Each is a
caption a user reads, not a value in a settings file, so the value moved
into the entry's `itemData`, the readers moved to `currentData()`, and the
flag came off. `spacr.qt.i18n.set_translatable_items` is the seam: it fills
a dropdown with translated captions over untranslatable values and records
the English sources on the widget, so the ordinary language pass re-renders
the captions on every later change.

TWO MORE DROPDOWNS IN THE SAME FILE were not flagged and were doing exactly
what the flag existed to prevent, silently. Measured by driving the panel in
Swedish:

  * the segmentation object box rendered `cellen`, `Kärna`, `patogen` --
    and `_selected_object_types` returned `('cellen',)`, which is the key
    every `{object}_…` setting is spelled with and the key the worker looks
    its channel up by. A Swedish user's preview asked for a compartment
    spaCR does not have;
  * the intensity-threshold method rendered `medelvärde`, and
    `_compartment_settings` wrote that into
    `cell_intensity_threshold_method`, a setting that accepts `mean` or
    `percentile`.

Both carry their value in `itemData` now, and `_widget_value` reads it.

THE CAPTIONS THEMSELVES needed exact rows, because the word-by-word
fallback had read `auto` as the vehicle (`자동차`, `汽车`, `कार`), `Overlay`
as `Surprise` in French, `All channels` as the half-English `All Kanaler`,
`cell` as a spreadsheet `celda`, `nucleus` as an atomic `परमाणु`, and
`mean` as `意思`. Twenty rows in `_ROWS`, in all nine languages: the eight
outline colours, the three view modes, `All channels`, `View:`, the five
compartment names and the two threshold methods. `Ch 3` is left alone in
every language -- a word touching a digit is part of an identifier.

COUNTED BY DRIVING THE PANEL, English and again Swedish: twelve English
captions in those dropdowns before, none after; the object dropdown and the
threshold method now hand the same English values back in all nine
languages; and a language change re-renders the captions in both directions
while the user's choice survives it by value.

RE-SET BY A HANDLER, all fixed in `spacr/qt/screens/app_screen.py`. A
caption a handler writes after the pass is English for the session, and
worse: `retranslate_widget_tree` reads a caption it did not render as data
and opts that widget out of every later pass. Pressing Copy console on a
Swedish screen left the button reading "Copy console" for good. The same
shape had turned both hint strips English on the first hover -- they write
their fallback prompt back on every Leave -- and left the maturity notice,
the example-screen button and four dialog titles in English.

COMPOSED BEFORE LOOKUP, fixed by giving the catalog the sentence and
substituting after: `Copied {count} lines`, `Fetching {count} file(s)…`,
`{stages} settings are hidden by Preferences…` (whose stage names are
looked up separately and joined), and the "interactive-only" dialog that
names the module.

THE _ROWS vs _TERM_ROWS TRAP, twice, and the second was the worse one:

  * `Choose image…` had no exact row, so the word-by-word fallback found
    "image" and rendered `Choose Bild…` -- half of two languages. An exact
    row in `_ROWS` is what beats it, in all nine languages.

  * the same fallback was rewriting CODE NAMES. A word touching `_` or a
    digit is part of an identifier, not a word of prose, and translating it
    gave the database browser's own example predicate as
    `Cell_area > 1000`, the column hint as `'Kanal_1'`, and combo entries
    reading `focal_Förlust`, `get_Modell`, `positive_Kontroll` and
    `min_Cell_count`. `_term_translation` leaves a word inside an
    identifier alone now. Measured on the running application: 48 mangled
    captions came back to their real names, among them the plate-map
    tooltips (`positive_Kontroll`), the loss dropdown (`focal_Förlust`),
    the model-zoo API list (`get_Modell_weights`) and the well pattern
    example (`Platta1, Platta2, …`).

    The generated catalogs had done it too, to six bare identifiers --
    `image_path` was stored as `image_path.` in four languages,
    `png_list E-mail` in Portuguese, `RdBu_r( 빈 공간)` in Korean. 47 rows
    corrected, and `i18n_catalogs.ui_text` now answers an identifier with
    itself so a rebuild cannot reintroduce them.

QT'S OWN MENU TEXT follows the language now. `install_qt_translations` and
`QT_CATALOGS` already existed but were called once, from `run()`, so
choosing a language after launch left `&Copy`, `Select All` and `Close Tab`
in the language the application STARTED in. `retranslate_widget_tree` loads
the matching `qtbase_<lang>.qm` when the code moves, and removes the
previous translator rather than leaving it underneath -- verified for sv
and de, and verified to fall back to English for `is`, which Qt does not
ship, rather than keeping the last language that worked. On the running
application the effect is visible on the regression figure tabs, whose
close button went from "Close Tab" to "Stäng flik".

DRIVEN AGAIN AND HELD BY A TEST. Qt ships seven of the nine: sv, de, es,
zh_CN, pt (as pt_BR), ko and fr all load and translate `&Copy`; hi and is
have no `qtbase` catalog and come out English, which is the honest answer,
with no missing-file error and nothing left underneath answering for them.
`tests/qt/test_the_live_preview_dropdowns_follow_the_language.py` covers
both, hi included.

"when the user picks a language that is not english all of the text in and
outside of settings fields needs to be in the chosen language, now most of
it is still english."

INSIDE and OUTSIDE the settings fields. The setting labels and tooltips are
translated; what is not is everything around them -- buttons, group
headers, status lines, menu entries, dialog text, the console.

The catalogs exist (`spacr/qt/i18n_catalogs/`, nine languages) and `tr()` is
the seam. The work is finding every user-facing string that never goes
through it. Start by driving the app in a non-English language and reading
what is still English, rather than by grepping: a string that is translated
but never re-rendered on a language change looks identical to one that was
never translated.

5. RANK ALL, IN THE MEASUREMENTS TAB
--------------------------------------------------------------------------------

Pressing it produces thousands of lines of

    0.735573 vs 0.778142: these groups have fewer than 2 usable
    observations and cannot be tested: ['0.735573', '0.778142']

The group labels are FLOATING-POINT MEASUREMENTS. Something is grouping by
a continuous column -- so every "group" holds one observation, every
pairwise test is impossible, and the pair count is quadratic in the number
of rows. Two defects in one:

  a. the grouping column is wrong. A comparison is between CATEGORIES, and
     a column of floats is not one. Refuse it at the door and name the
     column, rather than emitting a message per pair;
  b. even when the grouping is right, one line per untestable pair is not a
     report. Say it once, with a count.

DONE. A grouping column of more than twenty values where over nine tenths
hold fewer observations than a test needs is refused by name, and the
thin groups that remain are named once in a single summary line.

7. INOTIFY -- NEEDS ONE ROOT COMMAND, WHICH SPACR MUST NOT RUN
--------------------------------------------------------------------------------

The machine's per-user inotify watch limit is exhausted: 65,536 with 65,434
in use (syncthing 45,078, VS Code 20,019). spaCR holds none, filters the
message and explains it once.

Making it never happen again is a system setting and needs root:

    echo 'fs.inotify.max_user_watches=524288' | \
        sudo tee /etc/sysctl.d/99-spacr-inotify.conf
    sudo sysctl --system

`sudo` requires a password here, so spaCR cannot and should not do it.

CLOSED. The maintainer ran it; /proc/sys/fs/inotify/max_user_watches now
reads 524288. spaCR's own filter and one-time explanation stay, because
the limit can be exhausted again on any machine.
