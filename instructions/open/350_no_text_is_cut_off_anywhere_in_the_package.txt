================================================================================
A SWEEP: EVERY PIECE OF TEXT FITS ITS BUTTON, BOX OR CONTAINER
================================================================================

Status:    not started, filed 2026-09-02.
Requested: 2026-09-02, verbatim -- "do a sweep of the entire package and make
           user that all tesxt fits within its button, box or container, and
           is not cut off at all." Reported alongside a concrete instance:
           "in annotation the loade test data tooltips do not fit in the popup
           window."
Owner:     spacr/qt -- every screen, dialog and widget.

--------------------------------------------------------------------------------
THE KNOWN INSTANCE, WHICH IS THE PLACE TO START
--------------------------------------------------------------------------------

Annotate's "Load test data" tooltips overflow their popup. That is a concrete,
reproducible case and it should be fixed and TURNED INTO THE MEASUREMENT the
rest of the sweep uses -- one instance fixed by hand teaches nothing; one
instance fixed with a check that then runs over every widget finds the others.

--------------------------------------------------------------------------------
WHY A SWEEP AND NOT A LIST
--------------------------------------------------------------------------------

Text is cut off for four different reasons and they need four different fixes,
so an audit that only records "this one is clipped" produces a list nobody can
act on:

  * the string is too long for a fixed-width control  -> the string, or a
    wrapping/eliding policy;
  * the control has a fixed size that a longer TRANSLATION overflows -> the
    layout, and it will only reproduce in one of the nine locales;
  * a font scale other than 1.0 -> instruction 04 records that the tests
    measured a font scale no user has, so a check that runs at one scale
    proves nothing about the others;
  * the container does not grow -> a layout stretch or size policy.

THE TRANSLATION CASE IS THE ONE MOST LIKELY TO BE MISSED and the most likely
to be wrong in the shipped product: German and Portuguese run materially
longer than English for the same caption, and nobody reads those screens.
Any sweep that runs only in English is a partial sweep and should say so.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. Write the check first, against the Annotate instance, so it is known to
   catch a real failure before it is trusted on anything else. For a rendered
   widget, `QFontMetrics.boundingRect` of the text against the widget's
   contents rect answers this without a screenshot.
2. Run it over every screen and dialog, at more than one font scale, in
   English AND in the longest locale.
3. Fix by category, not one control at a time, and record which of the four
   causes each fix addressed.

--------------------------------------------------------------------------------
WATCH
--------------------------------------------------------------------------------

* ELIDING IS NOT ALWAYS THE FIX. A tooltip that elides has lost the sentence
  it existed to say. Prefer wrapping or a wider container for prose; elide
  only identifiers and paths, where the head or tail is enough.
* A control that grows can push its neighbour off the screen. Assert the
  CONTAINER still fits too, or the sweep trades one clipped string for
  another.

--------------------------------------------------------------------------------
HOW IT WILL BE CHECKED
--------------------------------------------------------------------------------

* The Annotate "Load test data" tooltip fits, asserted rather than eyeballed.
* A committed check walks every screen and dialog and reports zero clipped
  strings, at the default font scale and at the largest one preferences
  offers, in English and in the longest-rendering locale.
* Each fix names which of the four causes it was.

--------------------------------------------------------------------------------
2026-09-02 — THE ANNOTATE INSTANCE, DIAGNOSED. IT IS A HARD-CODED HEIGHT.
--------------------------------------------------------------------------------

`spacr/qt/widgets/test_data_chooser.py`. The dialog has a description pane
under the route buttons that fills in as you hover, and it is built with

    self._description.setMinimumHeight(110)

with this comment above it:

    # A FIXED HEIGHT, so the dialog does not resize under the pointer as
    # the text changes length -- the buttons would move away from the
    # cursor that is hovering them.

THE INTENT IS RIGHT AND THE IMPLEMENTATION IS A GUESS. 110 is a number, not a
measurement: it was presumably enough for the descriptions that existed when
it was written. A longer route description -- or the same one at a larger font
scale, or in German -- needs more, and the pane does not grow because growing
is precisely what the comment set out to prevent.

THE FIX THAT SATISFIES BOTH GOALS is to size the pane to the LONGEST text it
can ever hold, rather than to a constant: walk `ROUTES`, take
`QFontMetrics.boundingRect` of each description wrapped to the pane's width,
and use the tallest. The dialog is then stable under the pointer AND cannot
clip, and it stays correct when a route is added or a caption is translated,
which a constant cannot.

`RESTING_TEXT` must be in that measurement too -- it is what the pane shows
before anything is hovered.

THIS IS THE MEASUREMENT THE REST OF THE SWEEP WANTS. The same
"boundingRect against the contents rect" comparison is what item 1 of WHAT TO
DO asks for, so fixing this one correctly produces the tool for the others
rather than just one fixed dialog.

AND IT IS AN INSTANCE OF CAUSE 2 AND CAUSE 3 AT ONCE, from the four listed
above: a fixed size that a longer string overflows, and a size that only holds
at one font scale. Worth noting because it means the sweep cannot be a single
pass at 1.0 in English -- the very first case found needs two of the four
dimensions to reproduce reliably.

--------------------------------------------------------------------------------
2026-09-02 — THE REPORTED CASE IS FIXED, AND THE MEASUREMENT EXISTS
--------------------------------------------------------------------------------

MEASURED FIRST, so the size of the problem is on the record: at the dialog's
own width of 260 px the three strings the pane can show need

    resting text     51 px
    Load route      153 px
    Stream route    170 px

against a pane of 110. The Stream description was losing 60 px -- most of its
second paragraph.

THE FIX REPLACES THE CONSTANT WITH A MEASUREMENT, and keeps the reason the
constant existed. `_size_the_description_pane` asks `QFontMetrics` how tall
the TALLEST of `every_description()` is at the pane's own width and sets BOTH
bounds to it: a minimum so nothing clips, and a maximum so a short description
replacing a long one cannot shrink the pane and move the buttons out from
under the pointer hovering them. It re-runs on `resizeEvent`, because a height
measured at one width clips at another and this dialog can be resized.

One line of `lineSpacing()` slack is added: `boundingRect` measures the ink,
and a descender on the last line sits below the box it reports.

THE CHECK IS THE DELIVERABLE, not the fixed dialog.
`tests/qt/test_no_caption_is_clipped.py` carries `wrapped_height(widget, text,
width)`, which is what any "is this clipped" question compares against, plus
three tests: every description fits, every description produces the SAME
height, and -- the one that stops this passing by luck -- a manufactured
overlong string IS caught. 288 records four tests that passed while exercising
nothing; that third test is what keeps this out of that set.

VERIFIED BOTH WAYS. Against current code: 3 passed. Against the pre-fix widget
with everything else identical: 2 failed, 1 passed -- so the check catches the
reported bug rather than merely agreeing with the repair. The three chooser
suites are green alongside it, 31 passed.

WHAT REMAINS IN 350, and it is the sweep rather than the tool:

  * point `wrapped_height` at every screen and dialog, not just this one;
  * run it at more than one font scale -- instruction 04 records that the
    tests once measured a font scale no user has;
  * and in the longest-rendering locale, because German and Portuguese run
    materially longer than English and nobody reads those screens.

This first case was cause 2 AND cause 3 from the list above at once -- a fixed
size a longer string overflows, and a size that only holds at one font scale.
That is the argument for the sweep being more than one pass.
