THERE ARE THREE SEPARATE DEFECTS HERE. Do not fix them as one.
--------------------------------------------------------------

(1) EVERY QT MESSAGE IS EMITTED TWICE, IN TWO DIFFERENT FORMATS.
    From the report:
        [13:29:40] spacr.qt WARNING  Qt warning: ...      <- "output" pane
        13:29:40 [WARNING] spacr.qt: Qt warning: ...      <- "ERROR" pane
    Neither matches the raw `print(f"{label}: {message}", file=sys.stderr)`
    in `_install_quiet_qt_logging` (spacr/qt/__init__.py), which emits no
    timestamp -- so BOTH are formatted log records and there is a second
    emission path that has not been identified yet. Find it before
    changing anything. `spacr/qt/logging_util.py:159` calls the package
    setup WITHOUT `stream=True`, so the root logger should have a file
    handler and no stream handler; that is worth re-checking against what
    actually runs, because the report says otherwise.

(2) A WARNING IS PRESENTED AS AN ERROR. The handler itself is correct --
    it maps QtWarningMsg to `logging.WARNING` -- so the mislabel is in
    whatever routes a stream into the console panel's ERROR pane, almost
    certainly "anything on stderr is an error". A Qt warning is not an
    error, and a pane that cries error over routine noise is a pane
    people stop reading. That is the cost: the next line in it might be
    the one that matters.

(3) THE PYSIDE WARNING ITSELF. Benign -- the module opens and works, and
    the connections are made; what fails is PySide registering a dynamic
    SLOT on the receiver for lifetime tracking. Do NOT simply add it to
    `_QT_NOISE` until (a) and (b) below are answered, because an
    untracked connection to a receiver that dies before its sender is a
    real crash shape, and this warning is the only notice of it.

WHAT TO ANSWER FIRST
--------------------
(a) WHICH PySide6 VERSION is on the reporting Mac. Ask; do not guess.
    If it is >6.11.2, reproduce by installing that version here and
    running the capture described above. If it reproduces, this is a
    PySide behaviour change and the fix is ours to adapt to.

    Construct the failure directly: connect a signal to a bound method of

    is cosmetic and can be filtered with a comment saying exactly that.
