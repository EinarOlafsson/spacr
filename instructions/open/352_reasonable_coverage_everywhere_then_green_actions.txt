THIS IS A CHANGE OF TARGET FROM 288, AND THAT IS THE POINT
--------------------------------------------------------------------------------

288 asks for 100% per module. This asks for "the highest REASONABLE coverage
-- not 100%, just everything that makes sense to test". Those are different
goals and the second is the maintainer's current one.

WHAT THE DIFFERENCE BUYS, in this repository's own measured experience:

  * 288's own file records that chasing the last items produced FOUR TESTS
    THAT PASSED WHILE EXERCISING NOTHING -- every one asserted an absence,
    which is what a function returns when it did not run. Those raise a
    number and find nothing.
  * `deep_spacr`'s remaining six arcs need a model, a data loader and a real
    epoch. That is an integration test worth having for its own sake and a
    terrible way to buy six items.
  * The 2026-08-31 audit wrongly recorded 307 sites as "unreachable by
    construction". The correction is real and useful -- an `except ImportError`
    arm is ALWAYS drivable -- but the effort went into re-deriving reachability
    rather than into finding defects.

AGAINST THAT: the coverage sweep is also what FOUND the defects in instruction
310, ninety-seven of them, because code behind a pragma has by construction
never run. So the sweep pays for itself in bugs, not in percentage.

THE READING TO WORK TO: cover what a reader would call a behaviour. Stop at
what only a line counter would call one.
