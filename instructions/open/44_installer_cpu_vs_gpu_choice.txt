Not investigated. The installers are:

They build the environment with `uv venv` (see instruction 01), so whatever
torch wheel gets installed is chosen there. Find out what it currently
installs and whether it is CUDA or CPU today -- that decides whether this is
a new choice or an existing default being made visible.

macOS has no CUDA. On Apple silicon the equivalent is MPS, and offering a
"GPU" build that cannot use one would be worse than not asking.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Cellpose segmentation and Torch classification are the two things spaCR
spends its time on, and both are one to two orders of magnitude slower on
CPU. A user who installs the CPU build without being told will conclude
that spaCR is slow rather than that they installed the wrong one -- and
that conclusion is invisible to us.

The number matters more than the adjective. MEASURE one field of
segmentation on both and put the real figure in the installer text, rather
than the word "slow".

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. Find what the installers currently pull for torch, and on which
   platforms. Report before changing.
2. Add the choice. Default to GPU where a GPU is DETECTED and to CPU where
   it is not -- a user with no NVIDIA card should not be offered a CUDA
   build as the default and then have it fail.
3. Detect rather than ask where you can: `nvidia-smi` on Linux/Windows,
   `platform.machine()` for Apple silicon. Ask only what detection cannot
   answer.
4. The explanation goes NEXT TO the choice, not in a README. One or two
   sentences with a measured ratio in them.
5. Record which was chosen somewhere the app can read, so
   `spacr.doctor` can say "this is the CPU build" when a user asks why a
   run is slow. That is the same fault reaching the user a second time,
   and the second time we can answer it.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

On a machine with an NVIDIA card, the installer defaults to GPU, and after
installing `python -c "import torch; print(torch.cuda.is_available())"`
prints True. On a machine without one it defaults to CPU, installs without
error, and the app starts.
