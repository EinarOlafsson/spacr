PART 3 -- WHAT THE TWO RELEASES COST, 2026-09-10
--------------------------------------------------------------------------------

1.5.0.5 FAILED ITS FIRST DISPATCH on a workflow defect that had been latent
since 2026-07-29. `online-installers.yml`'s `collect` job was gated on

    github.event_name == 'workflow_call' && inputs.publish_to_repository

and inside a REUSABLE workflow `github.event_name` is the CALLER's event --
`workflow_dispatch` or `push`, never 'workflow_call'. The condition could not
be true, so collect was skipped on every release, `release_commit` came back
empty, and the tag step ran `git tag -a v1.5.0.5 ""`. No tag, no release, no
DOI. v1.5.0.4 shipped only because it was cut from tutorial-deploy-20260814,
a branch predating the change. A TEST ASSERTED THE BROKEN STRING, so the fix
arrived red; both are corrected.

1.5.0.6 EXISTS BECAUSE 1.5.0.5 COULD NOT BE INSTALLED. Its wheel carried both
`cell_Signal_to_noise.gif` and `cell_signal_to_noise.gif`, and the same pair
for nucleus and pathogen. On Linux those are three files; on macOS and
Windows the filesystem folds case and the installer refuses the archive
outright. EVERY CHECK IN THE PIPELINE RUNS ON LINUX -- packaging tests, sdist
and wheel builds, twine check, the installer smoke test -- so all of them
passed on an artefact that could not be installed. The maintainer found it on
his own Mac. Two regression tests now forbid case-colliding tracked paths and
require every shipped GIF to be one the manifest names.

    THE LESSON WORTH KEEPING: a release pipeline that runs on one operating
    system cannot certify a package for three. Neither defect was a mistake
    anybody made twice; both were invisible to every automated check that
    existed.
