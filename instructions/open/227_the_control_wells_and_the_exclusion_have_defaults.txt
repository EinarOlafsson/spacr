================================================================================
THE CONTROL WELLS AND THE EXCLUSION HAVE DEFAULTS
================================================================================

Status:    filed 2026-08-21, NOT APPLIED. See the conflict below.
Requested: 2026-08-21 -- "default to c2, c1, c3 for positive, negative, mixed
           wells and to TGGT1_220950_1 for Exclude gRNAs".
Owner:     Regression settings

--------------------------------------------------------------------------------
WHAT IS ASKED
--------------------------------------------------------------------------------

    positive_control_wells   ['c2']
    negative_control_wells   ['c1']
    mixed_control_wells      ['c3']
    exclude_grnas            ['TGGT1_220950_1']

--------------------------------------------------------------------------------
AND IT CONTRADICTS A RULE THE MAINTAINER SET
--------------------------------------------------------------------------------

    2026-08-21, earlier the same day: "wahtever information you use from my
    screen any calculated coefficients need to be recalculable for users
    whou do their own screens"

That rule emptied `classifier_quality.py` of a table of four measured
sensitivities, and the reason given then applies exactly here: A CONSTANT IN
A LIBRARY BECOMES A DEFAULT THE MOMENT SOMEBODY IS IN A HURRY.

THE FOUR VALUES ARE NOT THE SAME KIND OF THING, and the decision should be
made separately for the two groups:

  * `c1` / `c2` / `c3` are a PLATE LAYOUT. Another lab using the first three
    columns for controls is plausible; another lab using them for something
    else is equally plausible, and then the run silently drops three columns
    of real data and calibrates against wells that are not controls. The
    failure is quiet and the result still looks like a result.

  * `TGGT1_220950_1` is A CONTAMINANT IN ONE LIBRARY PREP. It is not a
    convention, a control, or anything another screen would recognise. As a
    shipped default it would exclude a gRNA that, in somebody else's
    library, is a perfectly good guide -- and they would never know, because
    an excluded guide leaves no trace in the results.

`controls=['000000']` is the precedent for a domain default, and it is a
NAMING CONVENTION for a non-cutting control rather than a fact about one
plate. That is the line: conventions may be defaults, measurements from one
screen may not.

--------------------------------------------------------------------------------
WHAT TO DO INSTEAD
--------------------------------------------------------------------------------

A SETTINGS PROFILE, not a library default. spaCR already saves settings CSVs
per run and can load them; a named profile for this screen carries all four
values, applies in one action, and is visibly THIS SCREEN'S rather than
everyone's.

If the maintainer wants them as library defaults anyway, that is their call
to make with this written down -- but the two groups should still be decided
apart, because the well layout is a defensible guess and the contaminant is
not.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* The four values are applied in one action rather than typed each run.
* Nothing screen-specific is a library default, or if it is, the decision is
  recorded here with its date.
* A user who has never seen this screen gets no wells dropped and no gRNA
  excluded that they did not name.
