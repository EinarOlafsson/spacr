--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

4f16455f added settings_for_trial() and rerun_trial(), and the Parameter
Sweep screen re-runs a double-clicked row and puts its live figures in an
embedded FigureQueue. What it does NOT do is show the SET of graphs the way
the Image UMAP search does: one grid of small multiples, all of a run's
diagnostics at once.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Re-running is the expensive half and it is done. Showing one figure at a time
in a queue means the user still cannot compare a run's residual plot against
its volcano without clicking between them, which is the comparison that
decides whether a configuration is any good.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

A clicked row opens the full RegressionResultsPanel for that trial -- volcano,
table, p-values, Q-Q, controls, guide support, residuals, collinearity -- and
prefers the trial's SAVED outputs over a re-run when they are on disk, because
a saved run is instant and a re-fit is a minute.

--------------------------------------------------------------------------------
HOW TO KNOW IT IS DONE
--------------------------------------------------------------------------------

Clicking a row with saved output shows its graphs without re-fitting; clicking
one without saved output re-fits and then shows the same set.

    "actually the paramiter search should be like the main module setup just

THIS SUPERSEDES the section directly above it, which was written hours
earlier from "the run table to the top of the figure grid" and is now wrong.
Do not build it.

WHAT IT MEANS. The parameter search is NOT a bespoke screen with its own
layout. It is THE MAIN MODULE SETUP -- the same settings surface, the same
console, the same figure grid every other module screen has -- plus ONE EXTRA
TAB holding the runs.

WHY THIS IS THE BETTER ANSWER, and worth stating so it is not "simplified"
back later:

  * a user who has learned one module screen has learned this one. A second
    layout is a second thing to learn for no new capability.
  * every fix to the shared screen -- the figure grid, the console, the
    settings panel, the drop handling -- lands here for free. A bespoke
    screen collects its own copies of all of them, and they drift.
  * this repository already has that drift and is paying for it. 155 field
    tooltips (instruction 113) existed precisely because 28 hand-built
    screens each re-implemented a row.

SO THE WORK IS SMALLER THAN THE SUPERSEDED PLAN, not larger: build the runs
TAB, and take the rest from the module setup that already exists.

Clicking a run row still swaps the figures -- that part of the request is
unchanged and is the substance of this instruction. Only the furniture around
it changed.
