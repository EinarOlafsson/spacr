  PKG  THE BUILD ITSELF, and it was never on this list. Added 2026-09-07.
       Every cell of the compat matrix on `main` failed -- sdist, wheel, and
       `pip install spacr` on 3.9 through 3.14 -- with

           configuration error: `project.license` must be string

       `license = { file = "LICENSE" }` is PEP 621's table form, and
       setuptools >= 77 rejects it under PEP 639. The rejection happens while
       READING pyproject.toml, before any build step runs, which is why every
       cell failed identically and none gave a more specific error. Fixed on
       nightly in 38724e353: `license = "BSD-3-Clause"` with
       `license-files = ["LICENSE"]`, the build floor raised 64 -> 77, and the
       superseded `License :: OSI Approved :: BSD License` classifier removed.
       Nothing about the licence changed -- still BSD 3-Clause, still the same
       file, stated in the form current tools read.

       WHY IT BELONGS ON THIS SIDE OF THE LINE: 1.5.0.5 COULD NOT HAVE BEEN
       BUILT. The release would have failed at its first step with an error
       naming a licence field and not a cause, and 01 -- desktop installs that
       cannot update themselves -- is blocked on publishing exactly that
       version. main stays broken until nightly reaches it.

       WHY NOBODY SAW IT SOONER, which is the transferable part: the home
       workstation has setuptools 69.5.1, below the 77 that rejects the table
       form, so a build there succeeds and always would have. It reproduces
       only where setuptools is current. A green build on one machine was
       never evidence about the matrix.

       VERIFIED 2026-09-07, and this is the first time the fix was actually
       tested rather than reasoned about. The same objection applies to the
       FIX as to the bug: a build passing on setuptools 69 says nothing. So
       a throwaway venv was given setuptools 84.0.0 -- seven majors past the
       77 that rejects the table form -- and asked to build nightly:

         python -m build --no-isolation      sdist AND wheel, both built
         twine check dist/*                  PASSED, PASSED
         pip install <wheel>                 installs, 8 entry points resolve

       And the metadata is right, not merely present:

         Metadata-Version: 2.4
         License-Expression: BSD-3-Clause          <- the PEP 639 form
         License-File: LICENSE                     <- and the file travels
         Requires-Python: !=3.14.1,<3.16,>=3.9     <- NOT dropped

       That last line is the one the pyproject comment warns about: raising
       the floor without the SPDX string would have silently dropped
       `requires-python` from the built metadata, which is worse than the
       failure it replaced -- pip would then offer this wheel to 3.8. It is
       present and exact. `Classifier: License :: OSI Approved :: BSD
       License` is gone, as PEP 639 requires alongside the expression.

       WHAT THIS DOES AND DOES NOT PROVE. It proves 1.5.0.5 can be BUILT and
       uploaded, which is what "the release would have failed at its first
       step" was about, and it proves it on a setuptools newer than any CI
       cell is likely to have. It does NOT prove the compat matrix green: it
       ran on one interpreter, not 3.9 through 3.14, and it did not resolve
       dependencies (`--no-deps`). Those remain CI's job, and CI is 288's.

  288  GREEN CI. The stated gate, and the only ENGINEERING item still on
