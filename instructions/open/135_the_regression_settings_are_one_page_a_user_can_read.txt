--------------------------------------------------------------------------------
A. ONE COLUMN, NOT TWO: `score_column` MERGES INTO `dependent_variable`
--------------------------------------------------------------------------------

They name the same thing and a user has to guess which one is read. Keep
`dependent_variable`; retire `score_column` the way `volcano` was retired --
an old settings CSV carrying it must still load, with its value moved over and
a line saying so, not dropped in silence.

AUDIT DONE 2026-08-17, and it says the request is right, with one boundary.

IN THE REGRESSION MODULE the two are already the same thing BY CONTRACT.
settings.py:1983 is `settings.setdefault('score_column',
settings['dependent_variable'])`, and the tooltip already says out loud that
they must agree: "It must name the same measurement as dependent_variable, or
the simulated min_cell_count describes a different quantity than the one the
regression fits and wells are kept or dropped on the wrong evidence." Having
both therefore offers the user a way to make the run wrong and nothing else.

Its ONLY reader on the regression path is `minimum_cell_simulation`, which
resamples the per-object score CSV to work out how many objects a well needs
before its mean stops moving. Substituting `dependent_variable` there is
exactly what the default already does.

THE BOUNDARY: `score_column` is NOT only a regression setting. In
`interpret_vision_model` (Explain CV) and in `hit_investigation.py` the same
key names the CNN score column, default 'cv_predictions'. It stays alive
there. What is retired is the regression module's duplicate -- the panel
control and the regression default -- not the key.

--------------------------------------------------------------------------------
B. A COLUMN THAT IS NOT THERE OFFERS THE COLUMNS THAT ARE
--------------------------------------------------------------------------------

Today a missing `dependent_variable` fails somewhere inside the merge, after
the whole score table has been read, with a message naming a column the file
does not have. Instead: READ THE HEADERS AND OFFER THEM.

The same behaviour in three places, because it is the same failure:

  * `dependent_variable`, against the score CSVs.
  * `filter_column`, against the same input CSVs -- and its button is an SQL
    button today, which is wrong: the regression module's inputs are CSVs.
    Replace it with a CSV button that reads the input CSVs. Give
    `dependent_variable` the same button.
  * THE COUNT COLUMNS, which the request is right about -- they are
    HARD-CODED and have no setting at all. Find them, give them settings, and
    give those settings the same offer-what-exists behaviour.

Headless too, not only in the GUI: a run that cannot find the column should
print the columns the file HAS. A message that lists the alternatives is the
difference between a two-minute fix and a re-run.

--------------------------------------------------------------------------------
D. "IM NOT SURE I SEE A DIFERENCE WHEN I USE IT" -- BATCH CORRECTION
--------------------------------------------------------------------------------

That is a bug report, not a preference, and it must be ANSWERED WITH A
MEASUREMENT rather than an explanation. Fit one screen with
`batch_correction` off and on and compare the coefficient tables. Three
outcomes and each has a different fix:

  1. It genuinely does nothing on this data -- e.g. a SINGLE PLATE, where
     ComBat has no between-batch variance to remove. Then the control must
     SAY so and grey out, per 106.
  2. It runs and the effect is real but small. Then the run should report how
     much it moved: the shift it applied, per batch.
  3. It is silently not being applied. Then it is a bug and it is the most
     important item on this page, because every run since has been reported
     under a correction that did not happen.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* `score_column` is gone and an old CSV carrying it still loads.
* A missing dependent variable, filter column or count column prints the
  columns the file HAS, headless and in the GUI, and the GUI offers them.
* `filter_column` and `dependent_variable` have a CSV button; no SQL button
  remains in the regression module.
* The regression panel has exactly these sections, in this order: Input
  Tables, Controls & Filters, Plate & Batch Correction, Response, Model &
  Inference, Estimator Tuning, Permutation Test.
* "Additional Settings" is EMPTY for the regression module.
* Model & Inference opens with the formula box; `level` is directly under
  `regression_type`; the alpha and raw/adjusted choice are in it.
* Every Estimator Tuning control is greyed out with its reason unless its
  family is chosen, and its tooltip names that family.
* The batch-correction question has a MEASURED answer written down.
