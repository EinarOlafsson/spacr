--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

spacr/regression_diagnostics.py already has design_report(),
collinear_guide_pairs(), variance_inflation_factors(), residual_report() and
write_diagnostic_suite(). A normal run calls some of it; a sweep row records
almost none of it.

A sweep row today carries the settings, a hit count, and seconds. That is not
enough to choose between two runs: it cannot say whether a fit with more hits
had a worse-behaved residual, a rank-deficient design, or simply threw data
away.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

The point of a sweep is to CHOOSE a configuration. A row that reports "10
hits" and nothing else forces the user to open every trial folder by hand,
which is the work the sweep was supposed to remove. The nightly run showed
exactly this: min_cell_count=50 reported MORE hits than 100 while quietly
losing GRA14, and no column in the table said so.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

Every row gets, where the fit can supply it:

  FIT QUALITY        r_squared, adjusted r_squared, aic, bic, log-likelihood,
                     residual standard error, condition number
  RESIDUALS          Breusch-Pagan and White for homoscedasticity,
                     Durbin-Watson, Jarque-Bera and Shapiro for normality,
                     the residual/fitted trend slope
  DESIGN             rank, whether it is identifiable, max VIF, the number of
                     collinear guide pairs, n_wells / n_guides / n_rows
  CONTROLS           the positive control's rank, p and q; the negative
                     control's; and the separation between them. If the user
                     has named a positive control, IT is the yardstick a
                     configuration should be read against.
  CALIBRATION        genomic inflation at the median, the p-value histogram's
                     first-bin excess
  GUIDE SUPPORT      how many hits rest on a single guide

Every one of these gets a saved figure, in the trial folder AND in a normal
run's output folder. The user asked for both, and a diagnostic that only
exists during a search is one nobody looks at.

--------------------------------------------------------------------------------
HOW TO KNOW IT IS DONE
--------------------------------------------------------------------------------

Sorting the sweep table by the positive control's rank puts the best
configuration first, and every figure named above exists on disk after an
ordinary run with no sweep involved.

WHAT SHIPPED

  spacr/ml.py  _write_regression_qc(), called from regression() just before it
  returns. That is the ONLY scope where the fitted design exists, so this is
  the wiring point -- see REFUTED below. An ordinary run now writes
  <res_folder>/regression_qc/ containing one figure per available panel, the
  combined single-page regression_qc_report.pdf and the grep-able
  regression_qc_report.txt with every statistic in it.

  Panels follow the figure-format preference via
  spacr.plot.figure_output_preferences(), like every other kept spaCR figure.

  Guarded three ways: skipped on the mixed-model branch (no design matrix
  exists there), skipped when dst is falsy, and wrapped so a failing
  diagnostic can never take down a fit that already succeeded.

  COST, measured: ~5.8 s per run on a 384-row / 2-plate design (0.36 s
  without QC, 6.19 s with). Fine for a normal analysis, NOT free across a
  sweep of hundreds of trials -- roughly 10 minutes per hundred runs. That is
  why regression() takes qc=True as a parameter: whoever wires the sweep half
  should decide deliberately whether every trial folder gets all 23 panels or
  only the scalar metrics, rather than inheriting the default by accident.

  Weights are deliberately NOT forwarded to the report. build_context recovers
  them from the fitted model for the types that were actually weighted, so the
  hat diagonal, residual and scale agree; forwarding cell counts would compute
  a weighted leverage for the unweighted types (ols/lasso/ridge/elasticnet).
  The counts still reach the cell-count panel through metadata.

  spacr/regression_diagnostics.py  _finish() now closes its figure on BOTH
  paths (try/finally). See VERIFIED below.

  tests/test_regression_qc_wiring.py  13 tests, all asserting on FILES ON
  DISK rather than on a function having been called -- the defect being
  guarded is precisely that the code ran and nothing landed.

WHAT DID NOT SHIP

  The SWEEP half of this instruction. Everything above is the "normal
  analysis" half. A sweep row still carries settings, a hit count and seconds;
  the FIT QUALITY / RESIDUALS / DESIGN / CONTROLS / CALIBRATION / GUIDE
  SUPPORT columns enumerated under WHAT TO DO are not on it, and sorting the
  sweep table by the positive control's rank is therefore still not possible.
  spacr/trial_metrics.py already computes much of that list (including
  genomic_inflation at :209) and is the place to start. This instruction stays
  OPEN for that reason.

  perform_regression()'s returned dict does not carry the QC manifest. The
  files are on disk; nothing in-process hands the manifest upward.

CLAIMS CHECKED -- one refuted, one wrongly refuted

  VERIFIED  regression_qc_report has no production caller. Only tests.
  VERIFIED  plot_design_diagnostics (:283), plot_residual_diagnostics (:390),
            plot_inference_diagnostics (:489) are the real names.
  VERIFIED  Brier score, Cook's-D bubble plot, p-value histogram, QQ all
            already exist and were not rebuilt.

  REFUTED   "Wiring points are ml.py:2154, :3735, :4157." Only 2154 is usable.
            regression() returns (model, coef_df, regression_type) and DROPS
            X and y, so at :3735 and :4157 inside perform_regression there is
            no design matrix to hand the report. The hook must go inside
            regression() itself, where y/X (:2210), weights (:2240), model,
            coef_df and volcano_path all coexist.

  REFUTED   "genomic inflation is already in regression_qc.py." It is not.
            It lives in regression_diagnostics.py's QQ panel and in
            trial_metrics.py:209. regression_qc.py's QQ panel reports slope,
            intercept and quantile correlation instead.

  STANDS    "There is a plt.close leak near regression_diagnostics.py:272."
            A counter-claim that this was not real checked ml.py -- the wrong
            file. The leak was real: _finish() returned early on
            save_path=None, which is the DEFAULT of all three public
            plot_*_diagnostics functions, and those figures come from
            plt.subplots, so pyplot held every one of them alive. One leaked
            figure per call. Fixed with try/finally, and the savefig-raises
            path is now covered too.
