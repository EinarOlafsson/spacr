--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

The .deb / .dmg / .exe installers are built by PyInstaller plus CI on the
`packaging` branch. Two things are already known to be wrong with what they
produce, and both were found from the outside rather than by a build:

  * instruction 01 — every desktop install at or below 1.5.0.1 cannot
    update itself, because the installers build the environment with
    `uv venv`, which does not seed pip, and the updater shells out to
    `sys.executable -m pip`. The fix can only reach users THROUGH an
    update, so the first build that carries it matters more than usual.
  * instructions 44 and 45 add screens to the installer that have never
    been built or clicked.

Nobody in this session has produced an installer artefact and run it.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

The installer is how every non-developer gets spaCR, so a broken one is
indistinguishable from broken software. It is also the least-tested surface
in the project: the unit suite never touches it, and CI proves it BUILDS
without proving it RUNS.

New installer screens make this worse rather than better. A CPU/GPU choice
that is collected and then ignored, or a sign-in that captures a token the
app never reads, is a page that costs the user time and delivers nothing --
and neither failure is visible from the build log.
