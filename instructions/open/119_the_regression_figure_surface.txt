--------------------------------------------------------------------------------
A. THE RESULTS TABLE IS TO THE LEFT
--------------------------------------------------------------------------------

The regression screen gets a results container to the LEFT of the figure
grid.

DELIBERATELY DIFFERENT FROM THE SEARCH SCREEN, which was corrected on
2026-08-16 to be the ordinary module setup plus a RUNS TAB (116). The two are
not the same surface and should not be made one:

  * the SEARCH's runs are a TAB. They are a short list, scanned top to
    bottom, and picking one replaces the whole grid. A tab, because the
    search screen is otherwise the module setup every other screen is.
  * the REGRESSION's results are a PANEL BESIDE the figures -- one row per
    guide or gene, hundreds of rows, sorted by effect, read ALONGSIDE the
    figure it describes. Picking a row changes one point, not the view, so
    both have to be on screen at once.

One is navigation between runs; the other is reading within a run. Anyone who
"unifies" them has removed the reason for both.

--------------------------------------------------------------------------------
B. CLICK A ROW, LIGHT UP ITS POINT
--------------------------------------------------------------------------------

Clicking a results row highlights that row's datapoint in the regression
graph. This is the feature that makes the table and the figure one object
instead of two.

WHAT IT REQUIRES, and this is the part that is easy to get wrong: the row and
the point must be joined on a KEY, not on a position. A regression table
sorted by effect and a scatter drawn in input order are the same points in
two orders, and joining them by index highlights the wrong guide -- silently,
and in exactly the direction a user would not question, because SOMETHING
lights up.

The key is the guide/gene identifier the row carries. Assert it.

Highlighting should also survive a re-draw: change a setting, and the
selected point stays selected.

--------------------------------------------------------------------------------
C. THE FASTEST GRAPHING LIBRARY POSSIBLE
--------------------------------------------------------------------------------

Taken as "make it fast", not as "add a dependency". In that order:

1. FIND OUT WHAT IS ALREADY HERE. `spacr/qt/widgets/fast_plots.py` exists.
   Establish what it uses and where it is already wired before proposing
   anything new. A second plotting stack that only the regression module
   speaks is a second set of theme bugs, export bugs and DPI bugs.
2. MEASURE BEFORE SWITCHING. "Slow" has a cause (see D), and if the cause is
   a full re-render on every settings change then no library is fast enough
   to hide it. Fix the pipeline first; a faster renderer on a wasteful
   pipeline is still wasteful.
3. ONLY THEN consider a different renderer, and only for the plots whose
   point count actually justifies it -- a volcano with 800 guides does not
   need a GPU, a per-cell scatter with 300,000 does.

State what was measured. "It felt faster" is not a result.

--------------------------------------------------------------------------------
D. THE LAG, AND THE LAST REGRESSION FIGURE
--------------------------------------------------------------------------------

Two complaints, and they may not have the same cause:

  * changing settings on most graphs lags;
  * the LAST regression figure is "verry slow" -- named specifically, so
    identify WHICH figure that is before optimising anything.

The likely shape, to be confirmed rather than assumed: a settings change
re-renders the whole figure, and possibly re-fits the model behind it. A
restyle should never re-fit -- 108 says the same thing from the other side,
"without re-running anything".

PROFILE IT. Time one settings change end to end, and say where the
milliseconds go. A fix aimed at the wrong stage is the most expensive kind of
optimisation, and this repository has already spent a day on one of those.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* The regression screen shows a results table on the LEFT and a figure grid
  on the right, above the console.
* Clicking a results row highlights that guide's point, joined ON THE KEY --
  with a test that sorts the table differently from the plot order and
  asserts the right point still lights up.
* The selection survives a settings change.
* The parameter-search screen is the ordinary module setup with one extra
  tab holding the runs, and clicking a run swaps the figures.
* Figures are transparent, restyleable by right-click, savable, and click to
  fill the container.
* One settings change on the slowest regression figure is measurably faster,
  with the before and after numbers written down, and no re-fit in the path.
