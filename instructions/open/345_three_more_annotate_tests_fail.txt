WHY THE THIRD ONE MATTERS MORE THAN THE OTHER TWO
--------------------------------------------------------------------------------

An order-dependent failure in `tests/qt` has a known mechanism in this
repository and it should be checked against that mechanism BEFORE it is
assumed to be leaked global state. Instruction 288 records it: a widget built
by a fixture with no parent and returned without teardown is destroyed at a
moment nobody chose, and the same pairing can produce EITHER a segfault OR an
ordinary failure -- `test_the_issue_preview_can_diagnose.py` plus
`test_track_previews.py` failed the track test without dying.

So the first question is not "what global did the earlier test leave behind".
It is "which fixture built a widget that outlived its test". The fix shape is
already written down there and is per-fixture: stop the timer, then `close()`,
`setParent(None)`, `deleteLater()`, `processEvents()` -- stopping the timer
FIRST is load-bearing.

DO NOT add a between-tests `gc.collect()` fixture. 288 records it as measured
not to work and as forbidden by
`tests/qt/test_retained_widget_tree.py::
test_no_boundary_fixture_forces_python_collection_over_live_qt_wrappers`.
