--------------------------------------------------------------------------------
THE CONTRACT
--------------------------------------------------------------------------------

1. GITHUB ISSUES

Read every open issue against the current code. Close an issue only when its
acceptance criteria are implemented and verified, or when the issue is a
demonstrable duplicate/obsolete report with that evidence recorded. Do not
roll back a later implementation to match an older issue. An issue that needs
external information remains explicitly open rather than being declared fixed.

2. ONE GREEN COMMIT

Every required GitHub workflow and every job in those workflows must complete
successfully on the same final commit. A cancelled, skipped-by-error, stale-
branch or superseded run is not a passing badge. Local tests are diagnostics;
the GitHub run is the release evidence.

3. 100% FOR EACH MODULE

Measure statement and branch coverage per source module on a frozen worktree.
Every module reaches 100%; one heavily tested module cannot average away an
untested one. Tests exercise observable behavior and contain meaningful
assertions. Do not use ``# pragma: no cover``, omit files from configuration,
or delete reachable code merely to alter the denominator. Truly dead code may
be removed only after proving it is unreachable and unneeded.

The renewed request says "the library", so the denominator is every shipped
Python module in the distributions, not only ``spacr/`` files that happen to
be imported by the default test command. Package discovery, the coverage
inventory and the wheel/sdist contents must agree. A shipped module missing
from the inventory is a failure, not zero work hidden outside the report.

4. KEEP THE RESULT RATCHETED

CI fails when a new module lacks a coverage row, when any existing module
drops below 100%, or when a prohibited coverage exclusion appears. The report
artifact identifies uncovered lines and branches by module.

  * GitHub reports no open actionable issue for the spaCR repository, with a

  * all required workflows are green on one SHA that equals the final nightly

  * a clean frozen-worktree coverage run reports 100% statements and branches

  * the README badge resolves to the successful required workflow rather than
    a cancelled or non-required run;
  * instruction 253 may proceed only after all of the above remain true on the

THE BIGGEST SINGLE UNLOCK IS NOT MORE TESTS (2026-08-30)
---------------------------------------------------------
24% of the remaining coverage gap is in modules that import a dependency
setup.py DECLARES AS REQUIRED and this environment does not have.

`dependencies = [...]` at setup.py:167 is what `install_requires` is set from,
so these are not extras. Nine of its 60 entries are not importable here; one
(win10toast) is correctly absent because it is Windows-only. The other eight:

    pyfixest>=0.40.1,<1 ; python_version >= "3.10"
    glum>=3.1.2,<4      ; python_version >= "3.10"
    gpytorch>=1.11,<2   ; python_version >= "3.10"
    vispy>=0.14,<1.0
    umap-learn>=0.5.11,<1.0
    biopython>=1.80,<2.0
    gputil>=1.4.0,<2.0
    nvidia-ml-py>=11.450.51,<14

What their absence costs, measured against the batched run:

    total missing arcs in spacr/            5566
      in modules importing an absent dep    1328   (24%)

        598  vispy      spacr/qt/widgets/fractal_travel.py (595) is the single
                        largest gap in the package and it is a vispy widget

These are not untested because nobody wrote tests. Several DO have tests, sitting
behind `@pytest.mark.skipif(not _HAS_GLUM, ...)` and its siblings, which skip
silently and count as passes. A reader of the suite output cannot tell them
from tests that ran.

NOT DONE, AND DELIBERATELY. `pip install` of these eight would touch the user's
conda base environment: umap-learn pulls numba, gpytorch pulls linear_operator,
and both pin against numpy/scipy versions the rest of a working scientific
stack depends on. Restoring a declared dependency set is defensible; doing it
unattended to a machine somebody works on is not, and a broken numpy would cost
far more than 1328 arcs are worth. The command, for whoever decides:

    pip install 'pyfixest>=0.40.1,<1' 'glum>=3.1.2,<4' 'gpytorch>=1.11,<2' \
                'vispy>=0.14,<1.0' 'umap-learn>=0.5.11,<1.0' \
                'biopython>=1.80,<2.0' 'gputil>=1.4.0,<2.0' \
                'nvidia-ml-py>=11.450.51,<14'

Two things follow either way. Instruction 308 is about setup.py declaring every
dependency on every OS and Python; this is the other direction -- the
environment the suite runs in does not match what setup.py declares, and
nothing in CI notices. And any per-module coverage target has to say which
environment it is measured in, because on this one eight modules cannot reach
100% however many tests are written.
