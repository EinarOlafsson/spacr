--------------------------------------------------------------------------------
A. THE FIVE MODULES, END TO END
--------------------------------------------------------------------------------

 1. MASK. orig/ -> stack -> merged -> masks, on plate1's own
    gen_masks_settings.csv. Every segmentation method the settings offer,
    every object type, and the QC that follows. The masks already in the
    folder are the reference: a rerun that produces different objects is
    either a bug or a change that has to be explained.

 2. MEASURE. masks + merged -> measurements.db, on crop_measure_settings.csv.
    Every measurement family, the crop export, and png_list. The shipped
    measurements.db is the reference for column set and row count.

 3. CLASSIFY. Both halves. The tabular one on the tsg101 measurements; the
    computer-vision one on plate1's datasets/ folder. Instruction 236 drove
    a great deal of this -- what is NOT yet driven is what to spend time on:
    dataset generation from annotations rather than metadata, the
    annotation app's own path, and inference back into a database.

 4. MAP BARCODES. The reads above -> a guide count table, compared against
    the screen's own plate_N_unique_combinations.csv. Every barcode
    orientation the folder carries (the _RC files are there because the
    orientation is a real and repeated source of silent zero counts), the
    row/column primer scheme, chunking, and the QC.

 5. REGRESSION. Driven in 236 and DONE there. Re-run only what the
    measurements produced above changes.

--------------------------------------------------------------------------------
B. TESTS THAT ACTUALLY TEST
--------------------------------------------------------------------------------

 6. 100% COVERAGE FOR EVERY MODULE THAT IS NOT LEGACY OR INTERNAL-ONLY.
    Instruction 60 has the standing coverage goal and the runner note; this
    is the same target scoped to the core five first. Legacy modules and
    internal-only helpers are OUT -- name each exclusion and why, in the
    instruction, so the list is arguable rather than assumed.

 7. AND THE TESTS HAVE TO TEST THE THING. Coverage is a floor, not the
    goal. The failure mode this repo has hit repeatedly is a test that
    executes a function and asserts it did not raise --
    tests/test_test_suite_hygiene.py already refuses new ones. For each
    core module, read its existing tests and ask what a wrong answer would
    look like and whether anything would catch it.
