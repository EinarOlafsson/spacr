THE INSTALLED PACKAGE LOADS QUICKLY AND RUNS WITHIN MEASURED RESOURCE BUDGETS
================================================================================

Status:    OPEN, filed 2026-08-28. RELEASE-BLOCKING.
Owner:     packaging, startup, module loading, execution and resource cleanup.
Precedes:  253's final sweep and every 1.5.0.5 publication action.
Requested: 2026-08-28 — "make sure the pakeage loads and runs optimally"

--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Items 55, 262, 268, 282 and 284 already measured and improved startup,
module construction, lazy imports and memory policy. Their dated measurements
are evidence about those trees, not proof about the final release tree. Item
282 also records one unfinished integration: the tested cleanup policy exists,
but every live cache was not yet shown to consult it.

This is a final installed-package audit. It must exercise a wheel or sdist in
a clean environment as well as the checkout, because an editable import can
make broken packaging look healthy. "Optimally" means within explicit budgets,
with no known avoidable measured hotspot left unexplained; it does not mean an
unsupported claim of a theoretical optimum.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

A package that imports in the checkout but fails after installation is not a
working release. A package that eventually opens while blocking the event loop,
eagerly importing unused scientific stacks, or retaining unbounded caches is
not usable on the laptops, workstations and servers spaCR promises to support.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. BUILD AND INSTALL THE ACTUAL ARTIFACTS

Build the wheel and sdist from a clean frozen tree. Install them without the
checkout on ``sys.path`` in every supported Python/OS CI cell. Assert the
resolved ``spacr.__file__`` and drive the public import, command entry points,
Home screen and representative pipelines. Inventory the files in the artifacts
so packaging omissions cannot hide behind an editable installation.

2. MEASURE THE REAL USER PATH

Record cold and warm process-start-to-interactive-Home time, every registered
module's click-to-interactive time, peak RSS, GPU allocation where applicable,
and worst event-loop/frame interval. Use the in-application timing seam rather
than constructor-only or import-only proxies. Record the hardware/software
profile beside every result.

The artifact's app-key set must equal the live registry exactly. Readiness is
the first painted, enabled and usable control state, not constructor return or
the point immediately before entering the event loop.

The accepted lower-end reference budgets remain at most 5.0 seconds to an
interactive Home screen and 10.0 seconds for every module to become
interactive. During either interval there must be no event-loop stall of 500
ms or longer. Report every module individually; an average cannot hide one
unusable module.

3. LOAD HEAVY LIBRARIES AT THE OPERATION BOUNDARY

In fresh processes, assert that opening spaCR or a configuration screen does
not import training, segmentation, GPU or model stacks until the operation
that uses them runs. Preserve capabilities and errors: speed cannot be bought
by silently omitting an optional feature or reporting readiness before the
controls work.

The phase audit explicitly includes the real ``spacr.qt.run`` entry point and
``classify_merged``. Startup must not import pandas, scipy, sklearn, torch or
equivalent pipeline stacks; opening Classify must not import its training
stack, opening Mask must not import its segmentation stack, and opening
Regression must not import a fitting stack.

4. WIRE THE RESOURCE BUDGET TO REAL CACHES

Audit decoded-image, figure, merged-data, model-weight, allocator and GPU
caches. The idle timeout, cache ceiling and free-memory floor from item 282
must govern each applicable live cache, with bounded cleanup and observable
accounting. Do not claim Python extension libraries can be unloaded; release
only state that the runtime can honestly return or evict.

5. PROFILE BEFORE CHANGING CODE

Profile startup, the slowest module opens and representative pipelines. Fix
avoidable work in descending measured cost. Any hotspot responsible for at
least 10% of one accepted path must be removed, reduced, moved safely off the
GUI thread, or retained with a written correctness/complexity reason and its
measured cost. Scientific results from optimized and reference paths must
agree under the existing reproducibility tolerances.

6. KEEP THE RESULT RATCHETED

Check correctness in required CI and publish reproducible timing/resource
artifacts. Put stable structural guarantees in ordinary tests; use explicit
hardware-normalized thresholds for performance so noisy runners neither fail
randomly nor permit an unbounded regression.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

  * a clean wheel and sdist install, import and launch in every supported CI
    environment, with ``spacr.__file__`` resolving inside that installation;
  * the installed Home screen is interactive within 5.0 seconds and every
    registered module within 10.0 seconds on the documented lower-end profile;
  * the benchmark app keys equal the live registry exactly, and readiness is
    observed after first paint with usable controls rather than inferred;
  * the complete click-to-ready traces contain no event-loop stall of 500 ms
    or longer, and report cold/warm time, peak RSS and the slowest frame gap;
  * fresh-process ``sys.modules`` checks prove unused heavy dependencies are
    absent until their operation boundary;
  * every applicable live cache obeys the configured timeout, ceiling and
    headroom policy in tests using real registered entries, a controlled clock,
    measured sizes and headroom; in-use entries survive, and laptop/workstation
    profiles change the real caps while producing equivalent scientific output;
  * profiles and dispositions account for every >=10% hotspot on an accepted
    path, and the benchmark artifact names every retained cost honestly;
  * required CI contains guards for artifact contents, installed execution,
    lazy imports, resource cleanup, responsiveness and performance regression.

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

Do not promise to unload imported Python extension libraries; CPython cannot
reliably do that. Do not lower scientific quality, skip supported modules, or
precompute hidden work before timing begins to make a benchmark look faster.

2026-08-29 — INSTALLED FACADE HOTSPOT REMOVED; ITEM REMAINS OPEN
--------------------------------------------------------------------------------

An installed-wheel profile identified ``importlib.metadata`` as more than
60 percent of the cold ``import spacr`` path. The package facade now reads a
release-synchronised lightweight literal while the explicit public
``spacr.version`` module retains its metadata-backed inspection API. In clean,
dependency-free wheel environments on Python 3.12.4 (Ryzen 9 5950X), the
median cold import fell from 38.692 ms to 7.314 ms (81.1 percent), and loaded
modules fell from 160 to 77. The plugin-disable path also defers entry-point
metadata, cutting its CLI import and ``--list`` paths by 52.2 and 47.1 percent.

Portable subprocess ratchets now prove that the facade and plugin-disabled
CLI import neither scientific libraries nor distribution metadata. Release
tooling verifies and bumps ``setup.py``, ``spacr/_version.py`` and
``CITATION.cff`` together, including an installed-wheel build and bump
simulation. The normal plugin-enabled CLI deliberately retains its entry-point
scan so installed plugins remain visible in ``MODULES`` and ``--list``.

The compatibility metadata job now installs the freshly built wheel and sdist
separately, without dependencies and outside the checkout. For each artifact
it asserts that ``spacr.__file__`` is inside the isolated environment, checks
the facade literal against installed distribution metadata, and runs
``spacr-run --version`` and ``--list``. This closes the previously untested
sdist-installed facade boundary; the job still has to be green on the final
frozen release SHA.

The first real inventory audit caught an exclusion that only looked correct:
``MANIFEST.in`` split the unescaped space in
``loading_spinner_logo (1).gif`` and shipped that unreferenced 2,428,884-byte
review render in both artifacts. A single ``loading_spinner_logo*`` pattern
now excludes every unused logo variant. CI now compares both built inventories
against all tracked runtime Python and resource files, failing for either a
missing runtime file or any model/review asset that is deliberately excluded.

This closes only the non-Qt facade/CLI metadata hotspot. The item stays OPEN
for real post-paint Home readiness, all-module click-to-ready traces, event-loop
stall and RSS measurements, heavy-stack operation boundaries, cache-budget

2026-08-30 — EVERY APPLICABLE LIVE CACHE NOW OBEYS ONE BUDGET
--------------------------------------------------------------------------------

The production audit found five caches which were still outside item 282's
shared idle-time, byte-ceiling and free-headroom policy: timelapse decoded
frames, inactive derived-mask signatures, reproducible composited movie
frames, Annotate's warm Cellpose model, and CUDA allocator slack.  They now

animation LRUs already have their own hard bounds; Qt's opaque pixmap cache is
separately cleared by aggressive cleanup; displayed scientific arrays,
DataFrames and run-local models are active working state rather than caches;
and imported CPython extensions are not claimed unloadable.

Verification on the integrated tree: 15 focused live-cache tests, 140 cleanup
and accounting tests, 290 broader Annotate/timelapse/resource tests, and 12
fresh-process lazy-import tests passed in the isolated implementation lane.

87/87 passed.  The deterministic CUDA test presents two exact allocator-device

stopped at constructing ``AppScreen("measure")``.  That proxy could pass when
the public launcher, application registration, main window or first Home paint

The observation is taken before application shutdown can import cleanup code.
It also fails if Home has already imported pandas, SciPy, scikit-learn, Torch,
torchvision, Cellpose, OpenCV, IPython, pyplot or statsmodels.  The older core

2026-08-30 — RAW FRAME-GAP SUMMARIES NOW PROVE THEIR SOURCE TRACE
--------------------------------------------------------------------------------

The benchmark's independent parent validator checked that global and per-state
worst-gap fields were finite and below budget, but it still trusted those
derived values.  A worker artifact could therefore contain a raw watchdog gap
while claiming zero samples and a zero worst interval.  That contradiction was
syntactically complete enough to pass the release ratchet.

Home, Preferences and every registry-module result now record the exact start
and end of the watchdog window used for its summary.  A passing result seals on
the first observed watchdog beat after readiness, rather than on a wall-clock
sample between beats; a later legitimate beat therefore cannot span backward
into a closed window.  The parent requires that window to begin at the actual
interaction timestamp and end no earlier than readiness, rejects raw gaps past
the artifact clock, and independently recomputes the global and per-result
worst intervals, sample counts and budget verdicts.  The timestamp span, not a
rounded ``late_ms`` field, decides the 500 ms boundary.

These incompatible guarantees are worker/combined artifact schema 2.  The
hardware-report consumer rejects schema 1 instead of presenting it as current
evidence.  Missing, malformed, shifted or contradictory trace evidence now
fails closed.  Focused verification covered 34 driver contract tests, 32
production Qt readiness/controller tests and seven hardware-report consumer
tests.

This is a deterministic item 6 trace-integrity ratchet, not new performance
evidence.  No real-display timing was run while the machine was busy, and this
instruction remains OPEN for the accepted lower-end cold/warm registry traces,
RSS/GPU evidence, complete supported frozen-artifact matrix, and measured
dispositions for every hotspot responsible for at least 10 percent of an
accepted path.  No version, tag or release action was taken.
