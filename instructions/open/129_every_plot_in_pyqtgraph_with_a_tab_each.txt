--------------------------------------------------------------------------------
THE ONE ASSUMPTION, STATED RATHER THAN ASKED
--------------------------------------------------------------------------------

pyqtgraph ON SCREEN, matplotlib ON DISK. The request is about what is
GRAPHED -- the tabs and the grid the user looks at -- and the saved figures
are a different product: instruction 124 J requires an exported figure to
carry its data and its stats, the house style exists so a panel can go into
a paper, and `plot.save_figure` embeds TrueType fonts precisely so a PDF is
editable in Illustrator. pyqtgraph's exporters do not do any of that.

So a run keeps writing the matplotlib house-style figures, and the SCREEN
becomes pyqtgraph throughout. If that is wrong, it is one line to say so and
a large amount of work to discover late.

--------------------------------------------------------------------------------
A. GENE / gRNA IS A FILTER ON THE PLOT, NOT A MODE OF THE RUN
--------------------------------------------------------------------------------

Today `settings['volcano']` is 'gene' | 'grna' | 'all', chosen BEFORE the run
and baked into which table the volcano was drawn from. The maintainer wants
it on the plot: right-click, show only genes, or only guides.

This is strictly better and also cheaper: the coefficient table already
carries both -- `feature` is `gene_fraction:gene[...]` or
`fraction:grna[...]`, and `spacr.hits.gene_of` / `guide_of` already tell them
apart. No re-fit, no second table, just a mask.

    * three states: genes, guides, both. "Both" is what a screen is, so it
      stays the default.
    * the counts go in the menu, so a user picking "genes only" knows it is
      400 of 1,213 before they pick it.
    * the SELECTION must survive the filter, or the ring the user was reading
      vanishes -- the same rule the colouring and the baseline already follow.
    * the setting does not disappear. A headless run still needs to know
      which table to draw, and 125 A gates the legacy volcano on it.

--------------------------------------------------------------------------------
B. A PYQTGRAPH PANEL FOR EVERY GRAPH, EACH ITS OWN TAB
--------------------------------------------------------------------------------

What exists in pyqtgraph today (spacr/qt/widgets/fast_plots.py):

    VolcanoPlot   PValueHistogram   QQPlot   ResidualPlot
    ControlSeparation   GuideAgreementPlot   ResultsTable

What the run draws in the house style (spacr/figures/panels.py REGISTRY):

    volcano   effect_rank   effect_distribution   controls
    agreement   p_histogram   qq

THE GAP IS TWO: `effect_rank` (every gene ranked by effect, as a dot with its
interval) and `effect_distribution`. Both need a pyqtgraph twin. ResidualPlot
exists and is not on the panel at all, which is 128 E.

Beyond the seven there are the plate heatmaps, the well distributions and the
~19 regression_qc panels. DO NOT PROMISE ALL OF THEM AT ONCE. The order that
matters is: the seven the sheet already draws, then residuals, then the rest
by whether anybody reads them.

    * ONE TAB PER GRAPH, named for the graph.
    * a panel the table cannot support says why, in the tab, rather than
      being absent -- an absent tab is indistinguishable from a bug.
    * every one of them is CLICKABLE and joined on the KEY, which is
      instruction 119 B and is already the rule for the five that exist.

--------------------------------------------------------------------------------
C. THE GRID STAYS, IN PYQTGRAPH
--------------------------------------------------------------------------------

"i would still like to retain the grid to the right" and "same grid overview
but pyqtgraph versions".

Today the grid holds QPixmaps rendered from matplotlib figures. The pyqtgraph
version holds the live widgets, or thumbnails of them.

THE HARD PART, and it is not the drawing:

  * `_FigureCell.index` is the enumerate index over the pixmap list and
    `figure_activated` forwards it to `FigureQueue.show_index()`. A grid of
    live plots has to keep that mapping honest or clicking tile 4 opens
    figure 7 -- there is a test for it.
  * N live pyqtgraph widgets is N scenes, N view boxes and N sets of hover
    hit-boxes. The volcano alone is 1,213 points. Thumbnails via
    `grabFramebuffer`/`render` may be the answer, with the live widget only
    when a tile is opened -- MEASURE IT before choosing, the way the 49 ms
    redraw was measured.
  * the collapsible run sections (125 C) must keep working.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* Right-clicking the volcano offers genes / guides / both with counts, and
  picking one keeps the current selection ringed.
* Every graph the sheet draws has a pyqtgraph tab under Results.
* A tab whose panel has no data says why, in the tab.
* The grid to the right still shows every figure of the run, still opens the
  right one when a tile is clicked, and still folds by run section.
* A run still writes the matplotlib house-style figures to disk.
* The panel is not slower than it is today -- measured, not asserted.
