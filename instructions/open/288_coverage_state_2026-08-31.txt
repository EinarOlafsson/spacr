IMPORT-GUARD ARMS ARE NOT PINS: THE TECHNIQUE, AND THE CENSUS (2026-08-31)
==========================================================================

This file concluded that all 307 audited sites are unreachable by construction
and that the count "cannot fall without DELETING code". Import-guard arms were
misfiled into that set. They are conditional on the ENVIRONMENT rather than on
the source, which makes them look unreachable wherever the dependency happens
to be installed -- but a test can always make the import fail, so they are
testable items. Confirmed independently on both hosts, including on one where
the package IS installed.

THE TECHNIQUE, which is the general answer for the whole class:

    real = builtins.__import__
    def fake(module, globals=None, locals=None, fromlist=(), level=0):
        if module == name or module.startswith(name + "."):
            raise ImportError(f"blocked for the test: {name}")
        return real(module, globals, locals, fromlist, level)
    builtins.__import__ = fake        # drive the call, then restore

No uninstall, no venv, and no `sys.modules` surgery a later import can undo.
It works whether or not the package is present, which is the point: otherwise
the test passes for one reason here and another reason there.

WHERE THE LEAK IS NOT. Production is clean, measured rather than
assumed. `AmbientWidget.__init__` connects ``destroyed`` to

when the host is hidden or destroyed. That is a test-shaped lifetime, not
a user-shaped one -- a test builds a widget, shows it, and lets the name
go out of scope while pytest-qt keeps the C++ object alive.

2026-09-10 -- pytest-cov IS GONE FROM THE `spacr` ENV. USE `coverage run`.
--------------------------------------------------------------------------------

THE RECORDED TRAP NOW POINTS THE WRONG WAY. 352 says "do it in the `spacr`
conda env -- `spacr12` lacks pytest-cov and exits 4 per batch while the
wrapper reports success." Measured today, `spacr` lacks it too:

    python -c "import pytest_cov"   ModuleNotFoundError
    pip list | grep pytest          pytest, pytest-qt, pytest-randomly,
                                    pytest-timeout, pytest-xdist
    python -c "import coverage"     7.16.0

HOW IT FAILS, and it is the reason this is worth a note rather than a
one-line fix: pytest does not ignore `--cov`, it REJECTS it --

    error: unrecognized arguments: --cov=... --cov-report=term-missing

-- with usage text, no tests run, AND EXIT CODE 0 through a pipe to `tail`.
A batch wrapper that reads the pipeline's status sees success and records a
measurement that never happened. That is the same shape as the spacr12
failure the older note describes, from the opposite cause.

WHAT TO RUN INSTEAD. The plugin is a convenience; the library is the
measurement, and it needs no plugin:

    python -m coverage run --source=<dotted.module> --data-file=<path> \
        -m pytest <files> -q -p no:cacheprovider -m "not gpu"
    python -m coverage report --data-file=<path> --show-missing

`--data-file` OUTSIDE THE WORKTREE, deliberately. `.coverage` in the tree is
a binary that several sessions would write at once, and a combine over two
sessions' partial data is a number nobody can reproduce.

DO NOT INSTALL IT TO MAKE THE OLD COMMAND WORK. The env is shared with the
AF3 job and with other sessions, and a package added mid-run is a change to
their environment as well as to this one. The three-line form above is not
worse.
