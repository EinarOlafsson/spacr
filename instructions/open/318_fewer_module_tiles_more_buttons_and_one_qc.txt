--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

The Home screen shows a tile per module. Several of those modules are not
things a user sets out to do -- they are things they reach for WHILE doing
something else, and a tile for each puts them at the same level as Mask
and Regression.

Three destinations are asked for, and they are not interchangeable:

  A TILE      the user starts here. It is a job.
  A BUTTON    the user is already in the module this belongs to, and this
              opens beside it -- usually as a new tab, so the thing they
              came for stays on screen.
  A HELP ITEM the user wants to look something up. It opens the module
              exactly as it is today; only the way in changes.

--------------------------------------------------------------------------------
ONE QUESTION FOR THE MAINTAINER, ASKED IN THE REPORT
--------------------------------------------------------------------------------

  "add training runs as a button to classify (im pretty sure it only
   compares classefication models right? now cellpose models?)"

ANSWERED, from the screen itself: `train_compare` reads the epoch curves
and settings written under a model folder, and its own docstring's
example lists `maxvit_t` and `resnet50` -- the torch classifier
architectures. It has no Cellpose path: Cellpose training writes neither
the per-epoch curve files nor the settings CSV this screen diffs.

So Classify is the right host, and the button belongs there rather than
on Mask. If Cellpose training runs should ever be comparable the same
way, that is a separate item and a separate reader.

--------------------------------------------------------------------------------
WHAT MUST NOT BREAK
--------------------------------------------------------------------------------

APP KEYS ARE LOAD-BEARING and this item does not rename any of them.
`bridge.resolve_pipeline_entry`, `cli.INTERACTIVE_ONLY`,
`validate.APP_FUNCTIONS`, `dnd_handlers`,
`settings_model.resolve_default_settings` and every saved user state key
off them. A tile can be removed and a key kept: removing the tile is a
change to what Home OFFERS, not to what exists.

The same goes for the CLI. A module reachable only from a button is
still reachable from `spacr <key>` if it was before, and a user's script
must not stop working because a tile moved.

`qc_dashboard` is RENAMED IN THE DISPLAY NAME ONLY. Its key stays
`qc_dashboard`.

HOW TO KNOW IT WORKED

  * Home shows the tiles for the jobs and none of the eight satellites;
  * every removed tile's module opens from its new place, and opens the
    SAME screen it opened before;
  * every key that worked from the CLI before still works;
  * Run History clears all, selects many, and deletes or opens from a
    right-click;
  * the QC module is called QC and carries the layer viewer and the
    control charts.
