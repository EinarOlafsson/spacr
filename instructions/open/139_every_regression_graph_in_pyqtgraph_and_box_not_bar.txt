A. THE GENERATED GRAPHS MOVE TO PYQTGRAPH
--------------------------------------------------------------------------------

MEASURED 2026-08-18, matplotlib figures still produced on the regression path:

    spacr/regression_diagnostics.py    8
    spacr/toxo.py                      7
    spacr/ml.py                        5
    spacr/guide_permutation.py         1
                                      21

129 already put the interactive plots in pyqtgraph -- the volcano, the Q-Q,
the p-histogram, the control panel, the guide agreement, the effect ranking
and the three residual panels are `spacr/qt/widgets/fast_plots.py`. So the
same screen currently draws each plot TWICE, in two libraries, from two code
paths: one for the tab and one for the PDF. That is the real cost, and it is
not only duplication -- the two can and do disagree, which is how a figure in
a paper stops matching the figure on screen.

WHAT MOVING MEANS, and it needs stating because pyqtgraph is a screen library:
the generated file is a RENDER of the pyqtgraph scene, not a second drawing of
the same data. `FastPlot.snapshot` already photographs a live widget for the
grid; the export path needs the vector equivalent, at print resolution.

TWO THINGS THAT MUST NOT BE LOST, both already true of the matplotlib path:
  * every save goes through `spacr.plot.save_figure`, which honours the
    user's figure-format preference. A literal '.pdf' is a complaint this
    project has had twice.
  * a headless run writes its figures. The regression module runs from
    `spacr-run` and from a notebook with no GUI, and pyqtgraph needs a
    QApplication -- so the export has to work offscreen or say plainly that
    it cannot, per instruction 106. A run that silently stops writing
    figures when there is no display is the worst outcome here.

--------------------------------------------------------------------------------
B. A BOXPLOT WITH JITTER, NOT A BAR WITH JITTER
--------------------------------------------------------------------------------

"the bargraphs with jutter plot backgrounds should be boxplots with jutter".

THIS IS A STATISTICAL CORRECTION, not a preference, and that is why it is
worth doing rather than styling around. A bar drawn at a mean with points
behind it shows ONE number and hides the shape of the data: two groups with
the same mean and completely different spreads draw the same bar. A boxplot
shows the median, the quartiles and the whiskers, so the reader sees the
distribution the points already imply -- and the jitter stays, because the
box summarises and the points are the evidence.

WHERE IT IS: `spacrGraph` / `create_grouped_plot` in `spacr/plot.py` default
to `graph_type='bar'`, and `spacr/settings.py` defaults `graph_type` to
'jitter', 'jitter_bar' and 'violin' in three different modules. `jitter_box`
already exists as an option -- so this is largely changing which one is the
DEFAULT and making sure the box is drawn to the house rules, not writing a
new plot type.

THE STYLE IS THE ONE IN THE REPO: `spacr/figures/style.py`, which implements
`.claude/skills/apicomplexan-figures`, derived from Waldman et al. Cell 2020
and Giuliano et al. Nature Microbiology 2024 -- the Lourido-lab figures the
request names. Its rules apply here directly:
  * everything is grey except what the sentence is about; a box per group in
    a different colour is a rainbow, not an argument;
  * thin spines, small type, no gridlines;
  * the points are the data, so they carry the ink, and the box is a
    reference over them rather than a filled block competing with them.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* A regression run produces no matplotlib figure on its own path.
* Every generated figure matches the tab it corresponds to, because both come
  from one scene.
* `spacr-run regression` on a headless machine still writes its figures, or
  says why it cannot.
* Every save still honours the figure-format preference.
* A grouped comparison draws a box with jitter by default; the mean-bar is
  still reachable for anyone who wants it.
* The box obeys the house style: one highlighted group against grey.


================================================================================
C. EVERY GRAPH IS BOTH SAVED AND VISIBLE IN THE SOFTWARE
================================================================================

Requested: 2026-08-18 -- "all graphs should be sable and observable in the
           software, currently several graphs are saved but I cannot see them
           in the software"

THE CAUSE, FOUND 2026-08-18. A figure reaches the GUI by exactly ONE route:
`spacr/qt/bridge.py` installs `_capture_show`, which replaces
`matplotlib.pyplot.show` and emits every open figure through
`worker.figure_ready` when a module calls `plt.show()`.

So the rule the application actually runs on is:

    a figure is visible in spaCR if and only if somebody calls plt.show()

WHICH IS NOT THE RULE ANYBODY WROTE DOWN, and the regression module breaks it
in the largest place it could. Counted:

    spacr/ml.py                  10 plt.show()
    spacr/toxo.py                 5 plt.show()
    spacr/regression_qc.py        0 plt.show()   <- the ~19-panel QC suite
    spacr/regression_diagnostics.py  0 plt.show()

`regression_qc` writes one file per panel plus a combined
`regression_qc_report.pdf` with `fig.savefig(...)` and never shows anything.
Every one of those panels is on disk and none of them is in the application.
That is the report, exactly.

WHAT TO DO, and NOT by sprinkling `plt.show()` around:

  * A FIGURE IS REGISTERED, NOT SHOWN. `plt.show()` as the delivery mechanism
    is why this happened -- it couples "the user can see it" to a call that
    exists for a completely different reason, and a module that correctly
    saves-and-closes gets punished for it. There should be one function that
    says "here is a figure, it belongs to this run, keep it", and both the
    file and the gallery should come from it.
  * SAVED AND VISIBLE ARE THE SAME EVENT. Anything worth writing to the run
    folder is worth a tile; anything not worth a tile should not be written.
    If a panel is deliberately file-only, it says so where it is written.
  * THE QC SUITE IS THE TEST CASE. Nineteen panels plus the combined report;
    when this works, all twenty are in the gallery under the run that made
    them, and clicking one opens it.
  * THIS SURVIVES THE MOVE TO PYQTGRAPH (section A). Whatever draws the
    figure, the register-it step is the same, so do this first: it is the
    half that fixes the reported bug, and it makes the pyqtgraph move a
    change of renderer rather than a change of plumbing.

HOW TO KNOW IT WORKED: after a regression run with `regression_qc` on, the
number of figures in the gallery equals the number of image files in the run
folder, and every one of them opens.

2026-08-18 -- SECTION C IS DONE. THE ADOPTION, NOT ONLY THE MECHANISM.

WHAT SHIPPED

`spacr/figure_sink.publish` was already here and `regression_qc` already used
it; the other half of the path did not, so the reported bug was still live.
Now converted, and the whole regression path audited rather than the one file
that was named:

  * `regression_diagnostics._finish` published instead of `fig.savefig`. Its
    design, residual and inference panels were on disk and in no gallery.
  * `regression_diagnostics.write_diagnostic_suite` no longer defaults to
    `formats=("pdf", "png")`. That default was wrong twice over: each entry
    RE-RAN the whole panel, and the pair ignored the figure-format preference
    entirely, so two files (and two tiles) came out of one picture in a format
    the user had not chosen. `None` now means "the preference decides", one
    file per panel.
  * The suite's manifest is keyed by what was WRITTEN. `save_figure` rewrites
    the extension to the preference, so with PNG selected every key named a
    `.pdf` that is not there -- "saved but I cannot see it" wearing a
    different hat. Same fix in `regression_qc_report`, which recorded the
    requested path rather than `_save`'s return.
  * `ml._write_regression_sheet` published. `regression_figure.pdf` is THE
    publication figure of a run and it was written and closed in the next
    breath, so no `plt.show()` ever walked past it.
  * `ml.generate_ml_scores` publishes its four figures. `plot_permutation`,
    `plot_feature_importance` and `shap_analysis` all RETURN a figure and none
    of them shows it.

A SECOND BUG THE dpi WORK UNCOVERED. `_finish` hard-coded `dpi=200` and
applied it only when the path ended `.png`, so the resolution preference
reached none of these panels -- and a PNG written to a `.pdf` name is a file
no viewer opens. `dpi` and `fmt` default to None now, which is what lets the
preference through.

A THIRD, FOUND IN PASSING AND FIXED: `generate_ml_scores` called
`save_figure(figs[1], ...)` unconditionally, and `ml_analysis` returns
`feature_importance_fig = None` for every model without `feature_importances_`
-- logistic regression and HistGradientBoostingClassifier, two of the offered
`model_type_ml` values. `None.savefig` took the whole scoring run down after
the model had been fitted and every object scored. `publish(None, ...)` now
writes nothing, announces nothing and returns None.

ONE PICTURE, ONE TILE. There are two routes into the gallery now -- `show`
and `publish` -- and the acceptance is a COUNT, so a double is as wrong as a
miss. `qt/bridge.py` de-duplicates across both routes on `id(fig)` AND a
`_spacr_emitted` attribute, and it needs both: an id alone is reused by the
next figure after a close, and dropping THAT loses a picture; the attribute
alone outlives the run, so a figure cached across two runs would appear only
in the first. The sequence that made this necessary is real --
`generate_ml_scores` saves the plate heatmap that `plot_plates(verbose=True)`
has already shown.

ACCEPTANCE, MEASURED. On a real OLS fit through `regression_qc_report`:
19 panels + 1 combined report = 20 files on disk, 20 figures announced, under
BOTH the PNG and the PDF preference, and every file opens as the format its
name claims (checked by magic bytes, not by extension).
