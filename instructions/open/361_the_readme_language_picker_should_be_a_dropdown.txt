================================================================================
THE README'S LANGUAGE PICKER: A DROPDOWN, AND WHY IT CANNOT STAY ON THE PAGE
================================================================================

Status:    not started, filed 2026-09-02.
Requested: 2026-09-02, verbatim -- "for the readme translations on the github
           page when another language is chosen the user gets taken to a page.
           is it possible to set it up so they stay on the github nightly or
           main page and see the chosen language? and is it possible to have
           the languages in a dropdown menue instead of links side by side?"
Owner:     README.rst, docs/i18n/readme/** and whatever generates the picker.

--------------------------------------------------------------------------------
TWO QUESTIONS, TWO DIFFERENT ANSWERS
--------------------------------------------------------------------------------

A DROPDOWN: YES, and it is the ordinary way this is done. GitHub renders a
subset of HTML inside markdown, and `<details>` / `<summary>` is in it. The
nine links collapse into one control:

    <details>
      <summary>🌐 Language</summary>

      [Svenska](docs/i18n/readme/README.sv.rst) ·
      [Deutsch](...) · [Español](...) · ...
    </details>

It renders collapsed on the repository front page and expands on click, with
no scripting. Native language names, not English ones -- a reader looking for
their language is looking for "Deutsch", not "German".

STAYING ON THE SAME PAGE: NO, AND IT IS WORTH SAYING WHY SO IT IS NOT TRIED.
GitHub serves a README as static HTML. It runs no JavaScript from the file,
sets no cookie, reads no Accept-Language header and does no content
negotiation. A link to another language IS a link to another file, and the URL
changes. There is no arrangement of markdown that avoids it.

  WHAT WOULD ACTUALLY DO IT, and neither is the repo front page:
    * GitHub Pages with a small script that swaps the text in place. That is
      a different site from github.com/EinarOlafsson/spacr, so the reader is
      still taken somewhere -- just somewhere prettier.
    * A per-language branch or fork whose README is that language. Worse: it
      splits the repository.

  So the honest scope of this item is the dropdown plus making the DESTINATION
  page good: every translated README should carry the same picker, so a reader
  who lands in the wrong language is one click from the right one rather than
  needing the back button.

--------------------------------------------------------------------------------
WATCH
--------------------------------------------------------------------------------

* THE NINE TRANSLATED READMEs ARE GENERATED by
  `tools/build_documentation_i18n.py`. A picker hand-edited into them is
  overwritten by the next build -- instruction 319 records exactly that
  mistake being avoided. Put the picker in the GENERATOR.
* `README.rst` is reStructuredText, not markdown. GitHub renders RST too, but
  `<details>` is raw HTML: check it survives the RST renderer before
  committing, because GitHub's RST support is not GitHub-flavoured markdown's.
  If it does not, `.. raw:: html` is the RST way and GitHub may strip it --
  measure rather than assume.
* Instruction 316 requires the public translation claim to be honest per
  locale. A picker that offers nine languages implies nine equally good
  READMEs; three are human-reviewed and six are machine-drafted, so the
  picker or the page it lands on should say so.

--------------------------------------------------------------------------------
HOW IT WILL BE CHECKED
--------------------------------------------------------------------------------

* The repository front page shows one collapsed language control, not nine
  side-by-side links, rendered by GitHub itself (checked on the real page, not
  a local renderer).
* Every translated README carries the same control.
* The control survives a regeneration of the i18n documentation.
* This file records that staying on the same page is impossible on
  github.com, so the question is answered rather than reopened.
