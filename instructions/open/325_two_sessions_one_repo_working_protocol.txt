--------------------------------------------------------------------------------
3. COMMIT CADENCE — SMALL AND CONSTANT
--------------------------------------------------------------------------------

After EVERY finished item, without exception:

    git add -A
    git commit          (Einar's name only -- never Claude as author or
                         co-author, never a "Generated with" trailer)
    git pull --rebase
    git push

Not at the end of a session. Not when a group of things is done. Every
item. A conflict between two commits is a minute; a conflict between two
days is an afternoon, and the whole reason this section exists is that
conflicts compound while unpushed work sits.

If `git pull --rebase` reports a conflict:

  1. STOP. Do not resolve it by preference and carry on.
  2. Write what happened into section 5 of this file, in one commit of
     its own, and push that first if you can.
  3. If the conflicting hunk is in the other session's file, take THEIRS
     -- they know why it is that way. If it is in yours, take yours and
     tell them what you overwrote.
  4. If it is in a shared file, or you cannot tell, say so in section 5
     and move to the next item rather than guessing.

Never `--force` and never `--force-with-lease` on nightly. If you think
you need one, you have found something worth writing in section 5.

--------------------------------------------------------------------------------
4. REPORTING — A TABLE AFTER EVERY FINISHED TASK
--------------------------------------------------------------------------------

When you finish an item, print a table:

    item | summary (two sentences) | percent done | time left

If the item has numbered sub-items, ONE ROW PER NUMBER with its own
description -- not one row for the parent. "310: 40%" tells nobody which
six defects are left.

Percent is of the ITEM, not of your session. An item you cannot finish is
reported at its true percentage with the blocker named, not rounded up.

--------------------------------------------------------------------------------
5. HANDOFF — WRITE HERE, THE OTHER SESSION READS IT
--------------------------------------------------------------------------------

This is the channel. Append, never rewrite. Date every entry. Push it on
its own rather than bundling it with code, so the other session sees it
at their next pull rather than at their next conflict.

Use it for: a file you need that the other owns; a conflict you hit; a
premise of theirs you have invalidated; anything you changed outside your
lane and why; a measurement that changes their plan.

--------------------------------------------------------------------------------

1. A TEST ASSERTING AN ABSENCE PROVES NOTHING UNTIL YOU HAVE WATCHED IT
   FAIL. Four separate cases today: a test that passed against a
   deliberately broken source; one that refused a path which had never
   existed; two that reached a different guard than the one they named.
   Always write the positive counterpart. Always mutate the source and
