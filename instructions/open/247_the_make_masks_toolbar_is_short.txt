MAKE MASKS: THE TOOLS THAT ARE MISSING, AND THE ROW THEY BELONG IN
================================================================================

Status:    OPEN on one DECISION, not on any code. Draw, divide,
           Cellpose-SAM with its probability and flow panes, the one tool
           row and the settings toggle are in and tested, and every
           control on the settings panel has a default, a type, help and a
           place. Section 7's two defects are both fixed: the bare 2-D
           branch in `parse_cellpose4_output`, and the pre-import in
           `bridge.make_thread` that stops a worker's first
           `matplotlib.pyplot` import from segfaulting the process.
           What is left is the recrop question at the foot, which is the
           maintainer's to answer rather than work to do.
Owner:     spacr/qt/screens/make_masks.py, and spacr/spacr_cellpose.py /
           spacr/object.py for the Cellpose settings it has to offer.

Asked for: "for the make masks tool in spacr there is no: draw / divide /
cellpose sam (and settings) / cell probability and flows with cellpose."

--------------------------------------------------------------------------------
1. FOUR TOOLS THAT ARE NOT THERE
--------------------------------------------------------------------------------

The canvas has brush, erase, erase-object, magic-wand add, magic-wand
erase and zoom -- `MODE_*` in make_masks.py. These are missing:

  * DRAW -- the free-form polygon: trace an outline and it fills into one
    object. The module's own docstring already admits it: "the free-form
    polygon that fills an outline into one object ... has no control on
    this panel, so nothing here claims they exist";
  * DIVIDE -- the dividing line that splits one merged object into two.
    Same admission, same absence. This is the commonest correction a
    segmentation needs and there is no way to make it;
  * CELLPOSE SAM, with its settings, as a segmentation the screen can
    run on the open image;
  * CELL PROBABILITY AND FLOWS -- Cellpose's two intermediate outputs,
    which are what tell a user WHY a mask came out the way it did. Being
    able to see the probability map and the flow field beside the mask is
    the difference between adjusting a threshold with reason and
    adjusting it by guessing.

THE WAND IS WHERE IT IS FURTHEST AHEAD -- seventeen controls against
this screen's two, and they are not knobs for their own sake: they are
the answer to a flood that runs away down a bright seam, which is the
failure mode a wand has on this kind of image. The runaway detector, the
salvage-at-cap and the gradient taper are three different rescues for it.

Compare control by control and record the decision for each -- ported,
or deliberately not, with the reason. A table in this file, so the next
person can see what was considered.

3. THE LAYOUT: ONE ROW OF TOOLS, AND A SETTINGS BUTTON
--------------------------------------------------------------------------------

"I generally liek the layout of the Make Masks, but the tools can be in
one row on the top there can also be a settings button to toggle all the
settings."

  * the layout stays -- this is a rearrangement, not a redesign;
  * every tool in ONE ROW along the top, so the whole set is visible at
    once instead of being found;
  * a SETTINGS button that toggles the settings as a group. The canvas is
    what the screen is for, and the settings are what you touch on the
    way in and then stop looking at.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* draw traces a closed outline and yields ONE object with one label;
* divide drawn across a merged object yields two objects where there was
  one, and the labels of everything else are untouched;
* Cellpose SAM runs on the open image from this screen, with its
  settings on the panel rather than assumed;
* the probability map and the flow field can be shown beside the mask;
* every tool is in one row, asserted by reading the layout back;
* the settings button hides and shows the settings as a group and the
  canvas keeps the space.

4. THE SETTINGS COMPARISON, DECIDED
--------------------------------------------------------------------------------

Every setting the standalone tool declares in `DEFAULTS` (its line 143) and
shows in its settings dialog (its lines 740-860), against this screen, with
the decision and the reason. HAVE = this screen already had it. PORTED =
brought over in this pass. NO = deliberately left out.

AUTO-FILTER ON LOAD
  min area                HAVE  `_filter_min_area` -> mask_engine.filter_objects.
  max area                HAVE  `_filter_max_area`. spaCR is ahead here: the ids
                                it drops go in the curation ledger, so an
                                automatic filter is as traceable as a click.
  min mean intensity      HAVE  `_filter_min_int`, measured on the raw image.
  max mean intensity      HAVE  `_filter_max_int`.

DISPLAY
  contrast low percentile HAVE  `_norm_lo`.
  contrast high percentile HAVE `_norm_hi`. The standalone accepts ten decimals
                                and its own tooltip explains why that is
                                theatre: on a 4-megapixel field one pixel is
                                0.000025% of the distribution, so the
                                resolution floor is the pixel count. Six
                                decimals is already past it; there is nothing
                                to port.
  zoom speed              HAVE  `_zoom_speed`.
  stretch on well only    NO    It excludes the saturated white plate around a
                                round well from the percentile calculation. A
                                microscopy field has no plate: the failure this
                                answers cannot happen here. The general form of
                                it -- a handful of saturated pixels pinning the
                                top of the range -- is what the six-decimal
                                high percentile already answers.
  page level (>= is page) NO    The threshold for the setting above and nothing
                                else.
  mask opacity %          QUEUED  A real gap: this screen composites at a
                                hardcoded alpha=0.5. It belongs on the Display
                                card, which is not this pass's region.
  draw instance outlines  QUEUED  Also a real gap, and the better half of the
                                two: a solid fill hides the boundary the user
                                is judging. Same region, same queue.

MAGIC WAND -- seventeen against this screen's three
  relative tolerance      HAVE  `_wand_relative`.
  tolerance (% of range)  HAVE  `_wand_pct`.
  absolute: auto tolerance NO   The standalone's pre-relative default,
                                `max(4, 0.10*std*4)` -- which is 0.4*std
                                written in two steps -- kept there so its own
                                saved settings still behave. A third source of
                                tolerance is a third thing to be wrong about
                                which one is live, and the percentage
                                supersedes it on every axis: it is
                                scale-invariant, it is explainable, and it does
                                not move when the background noise does. The
                                absolute box stays for the one case it serves,
                                somebody who knows the exact grey distance.
  absolute: manual tol.   HAVE  `_wand_tol`.
  max flood px            HAVE  `_wand_max`.
  salvage flood at max    PORTED  "Keep the nearest pixels at the cap". This
                                screen already salvaged, with no way to turn it
                                off and no way to know it had happened: the old
                                wand's BFS simply stopped at the budget and
                                returned what it had reached. Ported so the
                                refusal is available -- an object truncated at
                                a budget is not the object, and a user tuning
                                tolerance needs to see that the budget was what
                                stopped it -- and so `capped` reaches the
                                ledger.
  trim directional runaway PORTED  The detector, and the master switch for the
                                group. The failure is not plaque-specific: a
                                nucleus welded to a bright fibre and a plaque
                                welded to a well rim are the same flood
                                escaping down the same kind of seam, and
                                lowering the tolerance shrinks the object
                                without closing the seam.
  runaway growth ratio    PORTED  Steers the detector.
  runaway warm-up         PORTED  Without it the detector fires on the object's
                                own growth out of the click -- one pixel
                                widening to two is a ratio of 2.0.
  runaway min baseline    PORTED  Same failure, other end: nothing is judged
                                until the object has a width worth comparing
                                against.
  runaway confirmation    PORTED  Without it one noisy scanline cuts the object
                                in half. Measured, not assumed: the test suite
                                has the scene where confirm=1 cuts and the
                                default confirm=2 does not.
  intensity border        PORTED  "Re-flood below the escape". Turns the
                                straight half-plane cut into a boundary the
                                image drew, by bisecting for the highest
                                tolerance whose flood stays put. It only helps
                                when the seam is dimmer than the object; when
                                the two are equally bright no tolerance
                                separates them, the search finds nothing and
                                the cut stands. Both cases are pinned by tests.
  intensity search steps  PORTED  Its precision. Each step is one more flood,
                                so this is precision against click latency.
  gradient-taper fallback PORTED  "Taper onto the gradient". A cut is a
                                straight line and a budget is an arc; cells are
                                neither. This is the step that puts the final
                                edge on a real intensity change.
  gradient smoothing      PORTED  Raise on speckled fields so noise is not read
                                as a boundary.
  gradient transition band PORTED How far the edge may travel. Too wide and it
                                reaches back to the seam the cut escaped.
  gradient foreground inset PORTED  What counts as unquestionably the object.

TOOLS
  brush radius            HAVE  The slider on the Brush card.
  remove-small min area   HAVE  `_min_area`, shared with Otsu detect.

WHAT THIS SCREEN HAS THAT THE STANDALONE DOES NOT
  * the wand is split into add and erase, so it corrects a mask instead of
    only building one;
  * every wand click writes a curation-ledger entry, and it now carries the
    rescue report -- which direction leaked, what tolerance the re-flood
    settled on, whether the budget stopped it, how many pixels were flooded
    and how many were kept. A mask nobody can explain is a mask nobody
    trusts.

WHERE THE CODE WENT
  * `spacr/qt/wand_rescue.py` -- new, Qt-free, holds the flood and the three
    rescues so the geometry is testable without a widget;
  * `spacr/qt/screens/make_masks.py` -- the twelve controls on the Magic wand
    card, the canvas attributes they write, and `wand_rescue_settings()`,
    which is the single place the flood reads them from;
  * `tests/qt/test_make_masks_wand_rescues.py` -- 41 tests.

MEASURED, ON REAL ARRAYS
  * the reference scene leaks: a plain flood takes 1,292 px where the object
    is 317. With the rescues on it takes 392, all 317 of the object and no
    part of the bright field;
  * with a dimmer seam the re-flood settles at tolerance 3,984 of the 6,000
    asked for and returns the object with nothing outside it;
  * on a clean object the rescues are bit-for-bit inert -- the assertion the
    defaults rest on;
  * cost per click on a 2048x2048 field: 3 ms before, 31 ms for a clean
    object, 0.8 s when a runaway is actually caught, 1.2 s in the worst case
    (a flood covering the whole frame, salvaged back to the budget). The
    uncapped first flood is what pays for the detector being able to see how
    far the leak went; a flood truncated at the budget looks like a large
    compact object, which is exactly what a leak is not.

5. CELLPOSE-SAM, DECIDED
--------------------------------------------------------------------------------

The standalone's Cellpose controls, against this screen. HAVE / PORTED / NO
as in section 4.

CELLPOSE
  Cellpose-SAM detect     PORTED  One button, in the one tool row rather than
                                in a card, so it survives the settings toggle.
                                `MakeMasksScreen.run_cellpose`.
  model combo             PORTED  Filled from `settings.cellpose_model_choices`,
                                which asks the INSTALLED Cellpose rather than a
                                literal. The standalone globs a directory of
                                training rounds and sorts production to the top;
                                spaCR has no such directory layout, and its
                                fine-tuned checkpoints are applied through Train
                                Cellpose / the model zoo, so the combo lists
                                stock weights and the name travels as item DATA.
                                Cellpose costs ~2.5 s to import, so the combo is
                                built from the fallback list and topped up after
                                the first run, when the live list is free.
  cellprob_threshold 0.0  PORTED  Cellpose's own default, on the panel.
  flow_threshold 0.4      PORTED  Cellpose's own default, on the panel.
  cp_diameter             PORTED  0 = let Cellpose work it out. The one pre-SAM
                                sizing argument Cellpose 4 still honours.
  cp_normalize            PORTED  Off only for data normalized upstream.
  cp_max_size_fraction    NO      The standalone filters it out on 4.2 anyway;
                                a fraction-of-frame ceiling duplicates the
                                Auto-filter card's max area, which is in pixels
                                and is already recorded in the ledger.
  min_size                HAVE    `_min_area`, the same box Remove-small reads.
                                One judgement, one control.
  replace / merge         HAVE    `_combine_mode`, shared with Otsu detect.
  cellprob_heatmap pane   PORTED  `cellprob_heatmap` -> magma, percentile-
                                stretched, on a tab beside the mask.
  flow RGB pane           PORTED  `flows[0]` where Cellpose renders one,
                                rebuilt from the `(2, H, W)` vectors otherwise.
  resting message         PORTED  And the tabs stay ENABLED, unlike the
                                standalone's, because a disabled tab cannot be
                                opened to read the sentence saying why it is
                                empty.
  editable cp/flow panes  NO      The standalone lets the wand and Otsu run on
                                the probability map as if it were the image.
                                Here the panes are read-only: the mask lives on
                                the canvas next door, and a second paintable
                                surface would mean two places to look for one
                                object.

WHAT eval ACTUALLY RETURNS, MEASURED ON cellpose 4.2.1.1
  `CellposeModel.eval` -> `(masks, flows, styles)`. For ONE 2-D image `flows`
  is a list of THREE arrays that are three different things:
      flows[0]  (H, W, 3) uint8    an RGB rendering of the field
      flows[1]  (2, H, W) float32  the raw dY/dX vectors
      flows[2]  (H, W)   float32   the cell-probability map (approx -12..+8)
  and `styles` is a (256,) float32 embedding. Handed a bare 2-D array, eval
  returns that flat list -- which `spacr_cellpose.parse_cellpose4_output`
  cannot read, because it takes `len(masks)` for the image count and finds the
  image HEIGHT. The field therefore goes in as a batch of one, which is the
  per-image layout that function is written for and the layout `object.py`
  already uses.

WHERE THE CODE WENT
  * `spacr/qt/screens/make_masks.py` -- `cellpose_detect`, `load_cellpose_model`
    (through `utils._resolve_cellpose_pretrained`, the pipeline's own resolver),
    `cellpose_intermediates`, `cellprob_heatmap`, `flow_rgb`, `stretch_to_uint8`,
    the `_FlowPane` panes and the Cellpose-SAM card;
  * `tests/qt/test_the_make_masks_cellpose_detect.py` -- 17 tests, one of them
    the real-weights run behind `SPACR_CELLPOSE_E2E=1`.

MEASURED, ON REAL ARRAYS
  * four discs of radius 18 (1,018 px each) on a 160x160 field came back as
    four objects of 1,024-1,048 px, both panes filled, in 50 s on a CPU;
  * a `(2, H, W)` vector field was being sliced as though it were an RGB
    picture -- `shape[2] >= 3` is true of both -- and rendered as a 2-pixel
    smear. The vector shape is now tested first;
  * filtering the eval kwargs against the signature silently dropped EVERY
    setting for an eval declared `(x, **kwargs)`: the run succeeded and the
    thresholds on the panel did nothing. A signature that names nothing is
    no longer filtered against.

--------------------------------------------------------------------------------

was read back off the built widget rather than off the source, and the
gap was not where it was expected: every control PORTED in section 4
already explained itself, and the three the wand ARRIVED with did not.

  Tolerance %             was silent    now explains that it is a
                                        percentage of this image's own
                                        range, and which way to move it.
  Tolerance (absolute)    was silent    now says it is read only while
                                        the percentage is off, and why
                                        the percentage is the default.
  Max pixels              was silent    now says it bounds click latency
                                        as well as the flood, and points
                                        at the salvage switch below it.
  Radius (brush)          was silent    now says the radius is in SCREEN
                                        pixels and is scaled by the zoom.
  Min area (objects)      was silent    now says it is the one judgement
                                        Remove-small, Otsu and
                                        Cellpose-SAM all read.

READ BACK, NOT ASSERTED IN THE SOURCE. Help does not stay where it is
written: `settings_model.retarget_field_tooltips` moves a field's tooltip
onto the label that NAMES it as the last step of `__init__`, so a source
search for `setToolTip` passes while every spin box on screen is silent.
`tests/qt/test_make_masks_settings_explain_themselves.py` walks the built
panel, asks the LAYOUT which label names each control, and fails with the
name of any control that has help in neither place. It also pins one
control to one setting: each of the twelve rescue controls is driven and
the dict the flood reads is diffed, so a control that moves two settings
or none is a failure with its own name in it.

A CAPTION SHIPPED WITHOUT ITS ROWS IS HALF-ENGLISH. `i18n.tr` falls back
to a word-by-word term match when it has no exact row, which turns a
sentence of help into mangled prose. The panel had 32 help strings and 24
of them -- everything this instruction wrote before this pass -- had no
row in any language. All 29 (the 24 plus the 5 above) are now exact rows
in all nine catalogs, with their source hashes, and the test above fails
if a new one arrives without them.

7. STILL OPEN: TWO DEFECTS, IN FILES THIS INSTRUCTION DOES NOT OWN
--------------------------------------------------------------------------------

a. `spacr/spacr_cellpose.py` -- `parse_cellpose4_output` cannot read the
   return of a single BARE 2-D eval. Cellpose 4.2 returns `flows` as a
   flat three-member list there, and the function takes `len(masks)` for
   the image count -- which on a 2-D mask is the image HEIGHT -- so
   neither the batched branch (len 4) nor the per-image branch (len == H)
   matches and a field that segmented perfectly raises
   `Unrecognized Cellpose flows format: type=<class 'list'>, len=3`.
   Reproduced. The fix is a single-image branch BEFORE the `len(masks)`
   count, because a 2-D mask is one image whatever the flows look like.
   This screen does not hit it -- `run_cellpose` hands the field in as a
   batch of one, which is the layout the function is written for -- so
   the defect is left where it is rather than worked around here.

b. A worker thread importing `matplotlib.pyplot` for the first time,
   while the GUI thread is collecting garbage, SEGFAULTS the process.
   `PipelineWorker.run` (spacr/qt/bridge.py) does that import, and any
   screen that starts a background job can trigger it: the measured case
   is this screen's `seed_folded` handing a folder to the folded Model
   Compare, whose `set_source` starts a scan. A segfault takes the whole
   pytest shard with it, so it is worth more than the one test it kills.
   The fix is a pre-import on the CALLER's thread in `bridge.make_thread`,
   guarded by `sys.modules` so it costs a dict lookup after the first
   job. Measured: the file that reliably dumps core goes 32/32 green with
   that pre-import and with nothing else changed.

NOTED, NOT BUILT: recrop
--------------------------------------------------------------------------------

The standalone's seventh mode is `recrop`, and this screen has no answer
to it. Two agents building different halves of this instruction each
arrived at it independently and each left it alone, because it is not in
what was asked for.

It is worth a decision rather than a silent drop: recrop changes the
FIELD a curator is looking at rather than the mask on it, which is a
different job from the six tools beside it -- and on a plate whose fields
were cut wrong it is the only tool that helps.

Say whether it belongs here and it goes in the row with the others.
