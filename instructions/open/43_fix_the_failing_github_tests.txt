--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

A red CI is a CI nobody reads, and a CI nobody reads is one that stops
catching the thing it was built for. It also blocks the release path: a
version bump pushed onto known-red runs produces a first result you cannot
interpret, because the pre-existing failures cannot be told from whatever
the bump broke.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. LOOK AT A REAL RUN FIRST. `gh run list --limit 10` and `gh run view
   <id> --log-failed`. Do not start from the local failures; the point of
   this task is that CI and local disagree.
2. Triage into three piles and say which is which: fails locally too
   (fix the code or the test), fails only in CI (an environment
   difference -- headless, no CUDA, no NAS, a different package
   resolution), and flaky.
3. Close instruction 03 first if the five order-dependent failures show
   up. They will make everything else unreadable.
4. Fix, one pile at a time, smallest blast radius first.
5. Whatever the cause, leave the failure LOUD if it recurs. A cell that
   times out with no output -- which is what the About-dialog modal did --
   teaches nobody what went wrong.

THE LAST ONE WAS SELF-INFLICTED and is worth recording. The docstring sweep
of instruction 63 CORRECTED that note -- the old text claimed
``png_dims[0]`` is the file's red channel, and the code says otherwise:

    resolve_png_channel_mapping({"png_dims": [0,1,2]}) -> {'r': 2, 'g': 1, 'b': 0}
    build_png_channels(...)  ->  source plane 0 lands in the file's BLUE slot

So the correction was right. But the old wording also carried a FACT the
correction dropped: that this mapping is the reverse of what ``png_dims``
reads like and is left that way ON PURPOSE, because every crop on disk was
written with it and flipping it would invalidate the models trained on those
crops. `test_png_channel_order_reversal_is_documented` exists to hold exactly
that, and it went red.

THE LESSON: a docstring can be WRONG and LOad-BEARING at the same time. When
correcting one, check what the old text was protecting before deleting it --
the test that guards it is the cheapest place to find out, and running the
suite for the file you edited would have caught this before it reached CI.
