--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

A red CI is a CI nobody reads, and a CI nobody reads is one that stops
catching the thing it was built for. It also blocks the release path: a
version bump pushed onto known-red runs produces a first result you cannot
interpret, because the pre-existing failures cannot be told from whatever
the bump broke.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. LOOK AT A REAL RUN FIRST. `gh run list --limit 10` and `gh run view
   <id> --log-failed`. Do not start from the local failures; the point of
   this task is that CI and local disagree.
2. Triage into three piles and say which is which: fails locally too
   (fix the code or the test), fails only in CI (an environment
   difference -- headless, no CUDA, no NAS, a different package
   resolution), and flaky.
3. Close instruction 03 first if the five order-dependent failures show
   up. They will make everything else unreadable.
4. Fix, one pile at a time, smallest blast radius first.
5. Whatever the cause, leave the failure LOUD if it recurs. A cell that
   times out with no output -- which is what the About-dialog modal did --
   teaches nobody what went wrong.

2026-08-08 - THREE REAL FAULTS FOUND BY READING ACTUAL RUNS

Step 1 done: `gh run view <id> --log-failed`, not local inference. All three
faults below were invisible locally, and two of them had been failing on
every CI run for as long as the code has existed.

FIXED

  1. `_SUBMODULES` was missing eight modules that exist as files --
     classify, classify_classes, crop_source, filters, merge_tables,
     model_check, surrogate, training_basis. Added by the Classify overhaul
     and the Gate Editor work; nothing added them to the lazy loader.
     User-visible as a split that reads as flakiness: `from spacr import
     filters` works, `import spacr; spacr.filters` raises AttributeError.
     This one DOES reproduce locally -- it was simply never run.

  2. `QSettings.setPath(NativeFormat, ...)` is IGNORED on macOS and
     Windows. On macOS NativeFormat is CFPreferences, on Windows the
     registry; neither is a directory. Fixed by making the two-argument
     constructor produce INI via `setDefaultFormat`.

  3. The sandbox ROOT was not resolved while the path being checked was.
     On macOS `/var` is a symlink to `/private/var`; on Windows the 8.3
     short name resolves to the long one. Both platforms reported
     "QSettings escaped the test sandbox" for settings sitting inside it --
     the guard accusing itself.
