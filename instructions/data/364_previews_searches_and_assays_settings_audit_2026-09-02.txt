lands nowhere, in a surface whose entire purpose is that what you tuned is
what runs. The scan used here is therefore: for every key a preview WRITES,
is it in the target module's defaults dict; and for every key a preview READS,
does the module produce one.

WHAT WAS CHECKED AND IS NOT A FINDING
--------------------------------------------------------------------------------

Recorded so the next reader does not re-open them.

* INVASION'S 37 AND REPLICATION'S 25 ARE CLEAN ON CONTENT. Nothing dead by
  the strict test; no duplicate pair; every tooltip matches the code that
  reads it, including the awkward ones -- `intensity_statistic` says "Default
  'mean'. Invasion starts at 'auto': it chooses periphery_95 when present,
  otherwise percentile_95, and uses mean only as a warned last resort", which
  is exactly what `_resolve_invasion_intensity_column` does. Two shared keys
  are the exception and they are the familiar shape rather than a new one:
  `level`'s tooltip spends four sentences on regression before "For proportion
  plots, the same key selects 'object', 'well', or 'plate' aggregation", and
  `cmap`'s says "Default 'inferno' for image plots and 'viridis' for plate
  heatmaps" on a form where the value is 'viridis' and neither kind of figure
  is drawn.

* THE MASK LIVE PREVIEW'S ORGANELLE COLUMN IS GATED CORRECTLY.
  `ORGANELLE_METHOD_FIELDS` is keyed by morphology and `_organelle_settings`
  writes only the group the current morphology reads, "otherwise a cell run
  would propagate a morphology and a method nothing in it reads"
  (live_preview.py:3092-3096). The comment above the table says it mirrors
  `spacr.object._extract_classical_settings` and warns that drift would offer
  a setting segmentation never reads. Only the two `_size` fields are wrong
  (Finding 1); the other 23 are right.

* THE COMMON TUNING CONTROLS ARE WRITTEN PER SELECTED OBJECT, NOT PER PRIMARY
  (live_preview.py:2977-2983), with the reason recorded: keying them off the
  primary alone "wrote `remove_background_cell` and left the nucleus channel
  with no key at all, so the segmentation worker ... silently skipped it and
  the toggle appeared to do half a job." That is the right shape.

* THE MASK PREVIEW READS `metadata_type` AND `custom_regex` OFF THE SCREEN
  rather than assuming the default (live_preview.py:2064-2078), which is what
  makes a preview of a cq1 folder group correctly. The crop preview does not
  need it (it reads merged `.npy`).

* `save_h5`-style conditionals were looked for in the assays and are not
  there. Invasion's `outside_threshold` / `outside_threshold_method` /
  `control_wells` are a genuine three-way fallback and each tooltip says which
  of the others it overrides.

* `test_cellpose_model` and `apply_cellpose_model` are API-only (in neither
  `spacr.cli.MODULES` nor `spacr.qt.app.APPS`). Their `FT` / `CP_probability`
  / `circularize` therefore have no category, and that is correct rather than
  a gap -- they render on no form. It is only Finding 7's naming point that
  applies to them.

* The hyperparameter panel's own sixteen run controls are all preview-of-the-
  search parameters rather than module settings, and every one carries a
  hand-written tooltip; ten of its tooltips name their API function. This is the
  best-documented hand-built control surface in the item and needs nothing.

WHAT IS LEFT
--------------------------------------------------------------------------------

The six core modules, Preferences, spaceout, and now the three sub-surfaces
the request named are all audited. What is not audited, and was noticed while
doing this:

  * THE MOTILITY ASSAY (55 settings). Named in the open instruction's own list
    beside recruitment and plaques, and it is a first-class module with a
    tile-less registration, a preview panel, and thirty-nine `infection_*`
    keys that are a whole sub-vocabulary of their own. It is the largest
    unaudited surface left in this item.

  * THE ACTIVATION MAPS MODULE (27). It is in `GUI_MODULE_DEFAULTS` and has a
    search space, and two of this audit's findings reached into it sideways --
    `object_type`'s tooltip is its setting, appearing on two other modules'
    forms.

  * AND ONE THING THIS AUDIT OWES THE RENAME BATCH. Finding 1 is a suffix
    substitution that missed three literals because they had no leading
    underscore. The same batch renamed `_Signal_to_noise`, and
    `Signal_to_noise` (no underscore) is still shipped by three modules
    (Finding 7). Before the next rename in this item, the check to run is:
    grep the package for the BARE suffix as a quoted string, not only for the
    underscored key. In this case that is four greps and it would have found
    all six of Finding 1's dead keys the same afternoon they were created.
