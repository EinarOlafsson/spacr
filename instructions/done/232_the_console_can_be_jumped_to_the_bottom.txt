================================================================================
THE BOTTOM OF A CONSOLE IS ONE GESTURE AWAY
================================================================================

Status:    DONE 2026-08-21.
Requested: 2026-08-21 -- "it should be possible to go to the bottom of a
           console section without having to scroll through everything".
Owner:     Qt GUI (console widget, every module that has one)

--------------------------------------------------------------------------------
WHAT IS ASKED
--------------------------------------------------------------------------------

A long run writes thousands of lines, and the line that matters is the last
one. Getting to it must not be a scroll through everything above it.

WHAT IS ENOUGH: Ctrl+End, and a visible affordance for people who do not
know it -- a jump-to-bottom control that appears when the view is scrolled
away from the end and does nothing when it is already there.

AND THE OTHER DIRECTION. If a console follows the tail by default, reading
something above must not be yanked back down by the next line written. The
two behaviours are one decision: FOLLOW WHILE AT THE BOTTOM, STOP WHEN THE
USER SCROLLS UP, and offer the way back. A console that always follows
cannot be read; one that never follows has to be chased.

EVERY MODULE THAT HAS A CONSOLE, and the rule belongs where the console is
built rather than on each screen -- see instruction 228, which is about the
same three panels and has the same reason.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* Ctrl+End reaches the last line from anywhere in the scrollback.
* The jump control is visible only when it would do something.
* Appending while scrolled up does NOT move the view; appending while at the
  bottom does.
* A test drives the scrollbar and the append, not the internal flag.
* It is true of every module's console, asserted by walking them rather than
  by naming them.

--------------------------------------------------------------------------------
DONE 2026-08-21
--------------------------------------------------------------------------------

HALF OF IT ALREADY EXISTED, which is why the item is small. `_follow_output`
and `_on_console_scrolled` already did the other direction: the view follows
the tail, scrolling up stops it, scrolling back down restores it. What was
missing was the way BACK.

Ctrl+End, and a visible control for the people who do not know it.

SHOWN ONLY WHEN IT WOULD DO SOMETHING. A button that is always there and
usually inert is furniture, and the user stops seeing it -- which is exactly
the state it is most needed in.

THE JUMP RESUMES THE FOLLOW, and the two are one decision rather than two.
A console that jumped without resuming would slide back off the end on the
very next line written, and the user would press it again.

THE SHORTCUT IS HELD on the panel. Qt keeps a bare pointer to a QShortcut,
and one that only the constructor referenced stops working as soon as the
call returns -- the same trap as the event filters in 228 and 202.

THE TOLERANCE IS SHARED. `at_the_end` uses the same few pixels
`_on_console_scrolled` does, because a scrollbar dragged to the end does not
always land exactly on maximum() and two different answers to "is this the
end" would disagree at the boundary.

ONE NOTE ON THE TEST: the headless console lays out no entries, so its
scrollbar maximum is 0 and every position IS the end. The tests set the
range directly -- the behaviour is what matters, not how the content got
tall.


--------------------------------------------------------------------------------
RE-AUDIT 2026-08-26 -- THE OTHER DIRECTION WAS NOT ACTUALLY WIRED
--------------------------------------------------------------------------------

"HALF OF IT ALREADY EXISTED" WAS THE HALF THAT WAS NOT CHECKED. The claim
above -- "the view follows the tail, scrolling up stops it" -- was true of
exactly one gesture. `_on_console_scrolled` only ever SET `_follow_output`
to True; the only thing that ever cleared it was raising a section. So a
reader who reached the middle of a log by DRAGGING THE SCROLLBAR was thrown
back to the bottom by the next line written, which is the behaviour this
item exists to prevent.

Driven, not reasoned about: with the bar at 0 of 2000, one `append_stdout`
moved the viewport to 2000.

`_on_console_scrolled` now assigns the follow from where the viewport is,
in both directions, using the same few-pixel tolerance `at_the_end` uses.
Where the viewport is answers the question the same way whichever gesture
put it there.

AND THE TWO CRITERIA THAT ASKED FOR TESTS NOW HAVE THEM. "A test drives the
scrollbar and the append, not the internal flag" -- three in
`tests/qt/test_the_console_jumps_to_the_end.py` set the bar and write a line
and assert on the resulting position. "It is true of every module's console,
asserted by walking them rather than by naming them" --
`test_every_module_console_can_be_jumped_to_the_end` in
`tests/qt/test_all_module_smoke.py` walks `spacr.qt.app.APPS` through the
real screen factory and asks every console it finds for the shortcut, the
jump and the follow rule. Thirteen of the registered modules failed it
before the fix.
