--------------------------------------------------------------------------------
THE REAL COMPLAINT
--------------------------------------------------------------------------------

143 read this as "too long". It is partly that, but the maintainer has since
said plainly: "my main problem was it dosnt look great". It is 2,438
characters of undifferentiated monospace in one colour. Nothing is emphasised,
so nothing stands out, and a formula reads exactly like a caveat.

Length is a symptom. The box is UNTYPESET.

--------------------------------------------------------------------------------
A. RICH TEXT, WHICH MEANS A DIFFERENT WIDGET
--------------------------------------------------------------------------------

The box is a `QPlainTextEdit`, which cannot do colour or weight. It becomes a
`QTextEdit` rendering HTML.

WHAT MUST SURVIVE THE CHANGE, because each was fixed at some cost:
  * read-only AND selectable -- a formula you cannot copy is a formula you
    retype into a methods section;
  * monospace for the CODE formula, through a QSS rule on the objectName. A
    `setFont` loses to the theme's global `QWidget { font-family: "Open
    Sans" }`, measured: the box reported QFontInfo family 'Open Sans' with
    fixedPitch False and was monospace in intention only;
  * the prose wraps to the box's width (138) and the code formula does not.
    Rich text makes this EASIER, not harder: prose in a normal block, the code
    formula in `<pre>`, which is per-block rather than per-widget -- so
    `explainer_width()`'s job shrinks to sizing the `<pre>`.

--------------------------------------------------------------------------------
B. THE COLOUR VOCABULARY, FROM THE THEME
--------------------------------------------------------------------------------

EVERY COLOUR COMES FROM `spacr.qt.theme.active_palette()`. Never a literal.
The box must be legible on the light theme and the dark one, and the palette
was contrast-checked against `CONTRAST_RULES` -- a hand-picked hex has not
been.

    MODEL:, LEVEL:, section headings      accent
    CANNOT, NOT, "no q value", refusals   error
    affirmations: TWO MODELS, TWO TABLES  success
    output file names (results_grna.csv)  chip_value
    body text                             fg
    secondary / the caveat sentence       fg_muted
    API links                             accent, underlined

FOUR COLOURS ON SCREEN AT ONCE IS THE CEILING, not a target. The house rule
from `spacr/figures/style.py` applies to text as much as to a figure:
everything is plain except what the sentence is about. If every heading, every
noun and every caveat is coloured, the box is a ransom note and nothing is
emphasised at all.

--------------------------------------------------------------------------------
C. THE FORMULA, TWICE
--------------------------------------------------------------------------------

"write the math symbol version then the code version if possible".

The statistical statement first, in proper notation; the patsy string second,
so it can be pasted. For example, for OLS at guide level:

    yᵢ = μ + Σ_g β_g·f_gi + ρ_r(i) + γ_c(i) + εᵢ        εᵢ ~ N(0, σ²)

    y ~ fraction:grna + rowID + columnID

and for the mixed model the random terms have to be visible as random:

    yᵢ = μ + Σ_G β_G·F_Gi + u_G + u_G:g + ρ_r(i) + γ_c(i) + εᵢ
        u_G ~ N(0, σ²_gene)   u_G:g ~ N(0, σ²_guide)   εᵢ ~ N(0, σ²)

    y ~ gene_fraction:gene + (1 | gene/grna) + rowID + columnID

USE REAL UNICODE, not LaTeX source: β σ ε μ ρ γ Σ ~ ᵢ. The box is a widget,
not a renderer, and `\beta` on screen is worse than no symbol.

THE TWO MUST AGREE. If the code line says `+ rowID + columnID`, the maths has
the ρ and γ terms; if instruction 143 turns plate position off, BOTH lose
them. A box whose two formulas disagree is worse than a box with one.

--------------------------------------------------------------------------------
D. SHORT DESCRIPTIONS, AND A LINK TO THE API
--------------------------------------------------------------------------------

"short discriptions that contain the vital information for the user and links
to APIs for the different methods".

Per model: ONE sentence on what it does, ONE on when to reach for it, and a
link. The vital information is what makes the CHOICE, not what makes the
method:

    ols           statsmodels.regression.linear_model.OLS
    wls           ...WLS
    rlm / huber   statsmodels.robust.robust_linear_model.RLM
    glm/poisson/logit/probit/quasi_binomial
                  statsmodels.genmod.generalized_linear_model.GLM
    quantile      statsmodels.regression.quantile_regression.QuantReg
    mixed         statsmodels.regression.mixed_linear_model.MixedLM
    ridge/lasso/elasticnet
                  scikit-learn linear_model
    hinge         sklearn.svm.LinearSVC
    group_lasso   spacr.group_lasso
    rra           spacr.rra  (MAGeCK alpha-RRA)
    horseshoe     spacr.power_model

LINKS OPEN IN A BROWSER (`setOpenExternalLinks(True)`) and are real URLs, not
bare module paths. A link that does not open is worse than a module name,
which at least can be searched.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* The box renders HTML; headings, negations and file names are distinguishable
  at a glance.
* Every colour is a palette token; the box is legible on both themes, checked
  by rendering under each.
* Each model shows the maths and then the code, and the two agree.
* Every model links its API and the link opens.
* The formula is still selectable and copies as one line.
* No more than four colours are in play at once.

2026-08-18 -- SHIPPED, ALL OF A TO D. Commit 24149572.

THE WIDGET DECISION, AND IT IS NOT THE ONE THE INSTRUCTION NAMES. A
`QPlainTextEdit` cannot render colour or weight at all, so the choice was
between changing the widget and faking typesetting with whitespace -- the
instruction is right that it has to change. But it is a `QTextBrowser`, not a
`QTextEdit`: QTextEdit HAS NO `setOpenExternalLinks`. Measured, not guessed --
the first attempt used QTextEdit and every existing test failed with
`AttributeError: 'QTextEdit' object has no attribute 'setOpenExternalLinks'`.
QTextBrowser is a QTextEdit subclass, so read-only, selectable, the wrap mode
and the QSS all carry over; what it adds is the one thing D needs.

WHAT SURVIVED, each checked rather than assumed:
  * read-only and selectable, and the code formula selects as ONE block --
    driven through a QTextCursor on the document, not on the HTML;
  * monospace still through a QSS rule on the objectName. The selector is
    `QTextBrowser#ModelExplainer` now;
  * the wrap pair STOPPED FIGHTING. 138 ("the prose fills the box") against
    "a formula is never broken" was unwinnable in plain text because wrapping
    is per WIDGET there. In rich text it is per BLOCK. Measured on the real
    document at text widths 280/400/620/900: the code formula is 1 line at
    every one of them and the prose reflows 6/9/6/4.

COLOUR. Every value comes from `active_palette()`; the test reads the colours
off the rendered CHARACTER FORMATS rather than out of the HTML, because Qt
rewrites the markup it is handed and a colour present in the string is not
evidence that it reaches a glyph. Vocabulary as specified: accent for headings,
MODEL:/LEVEL: and links; error for the refusal heading and its negations;
chip_value for the output file each formula writes; success for TWO MODELS, TWO
TABLES; fg and fg_muted for body and the caveat.

FOUR IS THE CEILING AND `lasso`/`both` IS THE BOX THAT REACHES IT -- accent,
chip_value, success and error at once. There is a test naming it, so a fifth
emphasis colour cannot arrive without failing. The emphasis inside prose is a
short EXPLICIT table of phrases (`_EMPHASIS`), not a rule over the text: a regex
that coloured every capitalised phrase would make the box a ransom note, which
is a smaller version of the complaint rather than a fix for it.

THE FORMULA TWICE. `maths_for(kind, plate_position=, random_row_column=)` takes
the SAME two arguments `formula_for` does and reads them the same way, which is
what makes "the two must agree" a property rather than a habit -- nine
parametrised cases hold it across three model terms and three plate states. Real
Unicode throughout (β σ ε μ ρ γ Σ ᵢ).

LINKS. `MODEL_API_LINKS` covers every name in REGRESSION_TYPES: statsmodels and
scikit-learn by page, and spaCR's own three (`group_lasso`, `rra`,
`power_model`) through `DOCS_API_BASE`, which is the same base the settings
rows' API dots use. A test walks the rendered document for the anchor rather
than trusting the markup.

A LIVE THEME SWITCH RE-INKS BOTH BOXES. The old box used NO colour precisely
because baked colours would survive a switch; re-rendering from the live palette
on `PaletteChange` is the other way to be safe, and it is the one that can be
seen. `_retheme_section_explainers` does it for the model box and the
permutation box together -- the permutation box is typeset too, because one rich
box beside one monospace dump is this same complaint one section further down.

NOT DONE HERE: 141's backend selector wants the same API links. `MODEL_API_LINKS`
and `model_api_link()` are the shared answer when somebody picks that up.
