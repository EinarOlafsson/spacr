================================================================================

Status:    DONE 2026-08-21.
Requested: 2026-08-21 -- "whenever i save a graph i want to generate a folder
           not a file. the folder should contain a pdf and a png version of
           the graph, and a csv with the data the graph is based on, and
           another csv which should show in a standardised way, statistics on
           the data, the stats will be auto generated, so chekc notmality and
           equal variance (test depends on what n is), then do the propper
           test depending on how many groups there are."
Owner:     Figures, Qt GUI (save)

--------------------------------------------------------------------------------
WHY A FOLDER
--------------------------------------------------------------------------------

A PDF ON ITS OWN CANNOT BE CHECKED. Six months later the question is always
the same -- what were the numbers, and was that difference tested -- and a
figure file answers neither. Saving the picture beside the data it was drawn
from and the test that was run on it is what makes a figure re-derivable
rather than merely re-viewable.

    <graph name>/
        <graph name>.pdf      vector, for the manuscript
        <graph name>.png      raster, for slides and Slack
        data.csv              the rows the graph was drawn from
        statistics.csv        the test, its assumptions, and its result

--------------------------------------------------------------------------------
THE STATISTICS ARE CHOSEN, NOT ASSUMED
--------------------------------------------------------------------------------

`spacr.figures.stats.compare` ALREADY DOES THIS and must be what runs here
rather than a second implementation. It checks normality and equal variance,
picks the test from the group count and those checks, and returns the
assumptions alongside the result.

REUSING IT IS THE POINT rather than a convenience: a figure whose saved
statistics disagree with the same comparison drawn on screen is worse than
one with no statistics at all.

What `statistics.csv` has to carry, because a p-value alone is not a result:

  * the groups compared, and n for each;
  * WHAT ONE OBSERVATION IS -- well, cell, guide. A test across cells when
    the replicate is the well is pseudoreplication and returns p < 1e-10 on
    noise. `compare` already takes this as `unit` and states it.
  * the normality and equal-variance checks, with which test was used for
    each and why (the choice depends on n);
  * the test chosen, and the reason it was chosen over the alternative;
  * the statistic, the p-value, and an EFFECT SIZE with its interval.

A COMPARISON THAT COULD NOT BE MADE IS NOT A COMPARISON WITH AN UNKNOWN
ANSWER. `compare` raises rather than returning NaN; the file must say the
comparison was refused and why, not leave an empty cell.

--------------------------------------------------------------------------------
WHAT NEEDS DECIDING
--------------------------------------------------------------------------------

  * A GRAPH WITH NO GROUPS -- a scatter, a histogram of one column -- has no
    test to run. It still gets a folder, a pdf, a png and its data; the
    statistics file says there is nothing to compare rather than being
    absent, since an absent file reads as a bug.
  * Where the folder goes, and what happens when it exists. Overwriting a
    folder is a bigger act than overwriting a file.
  * The data csv is the rows AFTER filtering, which is what the graph shows.
    If the filters are not recorded beside it the numbers cannot be
    reproduced -- so the settings that produced it belong in the folder too.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* Saving any graph produces the folder with all four files.
* The statistics come from `figures.stats.compare`, not a second copy.
* `statistics.csv` names the unit, both assumption checks, the test, the
  reason, the effect size and its interval.
* A graph with nothing to compare still gets every file, and the statistics
  file says why it is empty.
* The pdf and the png are the SAME figure -- rendered once, written twice.

DONE 2026-08-21
--------------------------------------------------------------------------------

`spacr/figures/bundle.py`, and `FastPlot.export_bundle` on every plot -- so
it is not a feature of one graph that the next one built will be missing.

THE STATISTICS ARE `figures.stats.compare`, called, with a test that spies
on the call so a second implementation cannot creep in later. The assumption
rows read the check's OWN `passed`, never re-derive it from the p-value:
the normality check compares the worst of k groups against a Bonferroni
threshold, and re-deriving `p >= 0.05` silently discards the correction --
which in this codebase sent 18% of four-group comparisons on normal data to
a rank test instead of 5%.

A CHECK THAT COULD NOT SEE SAYS "could not tell", not "holds". Recording an
underpowered check as a pass is the more misleading of the two.

A REFUSED COMPARISON SAYS REFUSED AND WHY. `compare` raises rather than
returning NaN, and the file carries the reason rather than an empty cell --
a comparison that could not be made is not a comparison with an unknown
answer.

NOTHING TO COMPARE IS AN ANSWER TOO. A scatter or a one-column histogram
gets all five files, and `statistics.csv` says there is nothing to compare,
because an absent file reads as a bug. `comparison_groups()` returns None on
the base class rather than guessing: inventing groups would put a p-value in
the folder for a comparison nobody made.

A SECOND SAVE SITS BESIDE THE FIRST rather than on it. Overwriting a folder
is a bigger act than overwriting a file -- a file replaced loses one thing
the user can see, a folder replaced can take an earlier save's data and
statistics with it, silently.

TWO MENU ENTRIES, AND THAT IS NOT THE 187 D DUPLICATION. "Save figure…" and
"Save figure, data and statistics…" produce DIFFERENT things: a user who
wants a png for Slack should not have to take a folder of five files.

THE PDF AND THE PNG ARE THE SAME FIGURE -- `export` called twice from
unchanged state, never a redraw between them.

THE SETTINGS GO IN THE FOLDER. The data csv is the rows AFTER filtering,
which is what the graph shows, so without the filters beside it the numbers
cannot be reproduced.
