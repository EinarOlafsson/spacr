================================================================================
THE VOLCANO'S RIGHT-CLICK MENU, AND FOUR FILTERS THAT CANNOT FIRE
================================================================================

Status:    DONE. The four filters are gone, the volcano's menu carries
           what was asked of it, and the three places that still said
           "aspect ratio" to a user now say which of the two quantities
           they mean. The fourth was worse than a stale name: the style
           row labelled "Graph shape" offers equal and auto, which is the
           axis lock, so the caption and the row's own explanation
           disagreed and there was no axis-lock row at all. Label, help
           and check moved together. The crop panel's control is a third
           quantity again -- it copies width onto height rather than
           holding a ratio -- and is named for what it does.
Owner:     spacr/qt/widgets/volcano_explorer.py and the shared graph
           right-click menu; spacr/settings.py for the four removals.

--------------------------------------------------------------------------------
1. FOUR OUTLIER FILTERS LEAVE THE REGRESSION MODULE
--------------------------------------------------------------------------------

"cell area outline mads, nucleus area outline mads, and Cell intensity
outline mads, Nucleus intensity outline mads can be removed from the
regression modual. these cannot be used because the measurements are only
merged with scores after regression."

    cell_area_outlier_mads
    nucleus_area_outlier_mads
    cell_intensity_outlier_mads
    nucleus_intensity_outlier_mads

THE REASON IS THE ORDER OF THE PIPELINE, not a preference. Each of these
excludes objects by a robust z-score on a MEASUREMENT -- area, or mean
intensity. The regression reads a score table and a count table; the
measurements are joined to the scores AFTER the fit. So at the moment
these would run there is no column to compute a median absolute deviation
over, and a filter that cannot see its own input is a control that reads
as doing something and does nothing.

They are removed from the regression panel. They stay wherever the
measurements ARE in hand -- that is where they were always meant to
apply -- and a settings file carrying them still loads, because a removed
control must not turn an old run into an error.

--------------------------------------------------------------------------------
2. WHAT THE VOLCANO'S RIGHT-CLICK MENU MUST ALSO OFFER
--------------------------------------------------------------------------------

Added to what is already on it:

  * COLOUR BY LOCALIZATION, and it is a multi-select rather than a single
    pick: "all or any combination of localizations, e.g. dense granuals
    and rhoptries 1 should be possible". Choosing two compartments
    colours the points belonging to either, so a reader can ask about a
    combination without editing the table underneath;
  * X AXIS LIMITS, and Y AXIS LIMITS;
  * X AXIS LABEL, and Y AXIS LABEL;
  * EVERY APPEARANCE SETTING -- point size, point opacity, and the rest
    of what the style already holds. The menu and the side panel must
    offer the same settings: two routes to one figure that disagree about
    what can be set is the defect this is closing.

--------------------------------------------------------------------------------
3. "ASPECT RATIO" BECOMES "GRAPH SHAPE"
--------------------------------------------------------------------------------

A ratio is a number and this is a choice of three:

    square | vertical rectangle | horizontal rectangle

Named that way in the menu, in the save dialog and in the figure
preferences, because a reader choosing how a figure sits on a page is
choosing a shape, not entering a ratio. The stored value may stay
whatever it is; the WORDS change.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* the four filters are absent from the regression panel, and a settings
  CSV that names all four still loads and runs;
* right-clicking the volcano offers colour-by-localization with two
  compartments tickable at once, and the points recolour to match;
* the axis limits and labels typed into the menu reach the drawn figure
  AND the saved file;
* the set of settings the menu offers equals the set the side panel
  offers -- asserted as a set comparison, not by eye;
* nothing anywhere says "aspect ratio" to a user.

--------------------------------------------------------------------------------
WHAT WAS DONE, AND HOW IT WAS MEASURED
--------------------------------------------------------------------------------

Section 2, in `spacr/qt/widgets/volcano_explorer.py`,
`spacr/qt/widgets/fast_plots.py` and their tests:

  * A CLOSED SET HELD IN A CONTAINER IS NOW TICKED RATHER THAN PICKED.
    `style_field_kind` gained a `multi` kind, `_add_style_entry` builds it
    as a submenu of tick boxes, and `_toggle_style_member` keeps the value
    in the OFFERED order so one combination is one value however a reader
    arrived at it. `VolcanoStyle.localizations` already existed and the
    renderer already drew several compartments; what was missing was any
    way to say so.
  * The side panel grew the ten settings the style had and it did not:
    x_lim, y_lim, background_color, control_column, color_vmin, color_vmax,
    localizations, localization_column, and -- shown but not editable, the
    same rule the menu follows -- split_y_lims and annotations. Measured:
    `panel_settings() == menu_settings() == {every field of VolcanoStyle}`,
    all 65 of them.
  * `_style_choices` asked `_controls` for 'colour_by' and 'label_by' while
    the controls and the style spell them 'color_by' and 'label_column', so
    the menu offered free text where the panel offered a picker. It is now
    read off the panel's own controls, which also gives the menu the
    marker, colormap, line-style and font pickers it never had. The strict
    xfail in tests/qt/test_cov_w2_6_volcano_explorer.py is cleared.
  * SAME SETTING, SAME WORDS. `add_style_entries` gained a `labels`
    argument and the explorer fills it from the panel's own rows, so the
    menu says "Marker: Circle" where the style stores "o" and "Line style:
    Dashed" where it stores "--". A closed set offered in two vocabularies
    is the same disagreement in a quieter form.
  * An axis limit of +/-8 typed into the menu was read back off the axes,
    off the side panel, and off the written SVG's tick labels; an axis
    label typed into the menu was read back off the axes and out of the
    file.
  * Two defects found on the way and fixed: `effect_threshold` was a plain
    spin box, so the first touch of ANY control wrote 0.0 over a threshold
    nobody had set; and `export('svg')` returned an `.svg` path while
    `save_figure` -- which keeps only PNG and PDF and corrects a file's
    extension to what it wrote -- had written a PDF beside it, so the
    caller was handed the name of a file that did not exist.

Section 3, in `spacr/qt/widgets/fast_plots.py`: the graph's own menu says
GRAPH SHAPE and offers square | horizontal rectangle | vertical rectangle
| free, and the data-unit lock is separately named "Lock axis scales (1 y
unit = n x units)". The stored names are unchanged.

--------------------------------------------------------------------------------
WHAT IS STILL OPEN
--------------------------------------------------------------------------------

Three places still say "aspect ratio" to a user, none of them in the graph
menu:

  * `spacr/qt/widgets/save_figure_dialog.py`, the `form.addRow("aspect
    ratio", self.aspect)` row. It is the DATA lock -- its own tooltip says
    "Lock one y unit to this many x units" -- so it takes the name the
    graph menu already gives that control, "lock axis scales", not "graph
    shape".
  * `spacr/qt/preferences.py`, the help for "Aspect": "The width-to-height
    ratio of each panel."
  * `spacr/qt/widgets/measure_preview.py`, the "Lock aspect ratio" row on
    the crop panel. A crop, not a graph -- rename or argue it is a
    different quantity.

And two tests still assert the words the graph menu used before the
rename, so they are red against the shipped menu:
`tests/test_a_square_is_the_canvas_not_the_data.py`, in
`test_the_canvas_shape_and_the_axis_lock_are_two_controls` ("Shape" ->
"Graph shape", and "wide"/"tall" -> "horizontal rectangle"/"vertical
rectangle") and `test_the_menu_shows_which_shape_is_in_force` ("tall" ->
"vertical rectangle").
