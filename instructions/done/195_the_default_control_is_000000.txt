--------------------------------------------------------------------------------
WHICH CONTROL IS WHICH
--------------------------------------------------------------------------------

Corrected by the maintainer: "233460 is the negative control, 000000 is the
non cutting control."

    negative_control  '233460'    a real gene, knocked out, expected to
                                  show no phenotype. CORRECT AS IT IS and
                                  this instruction does not touch it.
    positive_control  '239740'    likewise untouched.
    controls          [30 names]  the NON-CUTTING guides -- they bind and do
                                  not cut, so they are the empirical null
                                  every threshold and baseline is measured
                                  from. THIS is the setting.

The first draft of this file argued that `negative_control='233460'` was a
confident wrong answer. It is the right answer; the mistake was mine and it
is recorded here rather than quietly deleted, because a file that silently
changes its mind teaches the next reader nothing.

--------------------------------------------------------------------------------
A. THE DEFAULT IS THE GENE, NOT A LIST OF ITS GUIDES
--------------------------------------------------------------------------------

`controls` defaults to THIRTY HAND-TYPED GUIDE NAMES:

    ['000000_1', '000000_10', '000000_11', ... '000000_9']

Every one of them is a guide of `000000`. The list is what somebody found in
one screen, and it shows: `000000_2` and `000000_7` are absent, not because
those guides do not exist but because that screen did not have them. A
library with a thirty-first non-cutting guide silently loses it.

THE DEFAULT SHOULD BE `000000`. That is what the maintainer asked for, and
184 is what makes it possible: `control_names.resolve_control` reads a GENE
and selects every guide assigned to it, measured from the library in hand
rather than typed from one screen.

--------------------------------------------------------------------------------
B. AND IT DOES NOT WORK YET -- A DEFECT IN 184                    [MEASURED]
--------------------------------------------------------------------------------

Found while checking this ask against the example screen:

    resolve_control('000000', names=<the library>)
        -> ControlSpec(typed='000000', level='gene', value='000000',
                       prefix='TGGT1')          correct
    rows_for('000000', guides)
        -> "resolved to gene '000000': 0 guide(s)"        0 OF 30

The guides are `TGGT1_000000_11`. `matches()` with no gene column does

    series.str.startswith(spec.value + SEPARATOR)     # "000000_"

and the guides START WITH THE PREFIX, which the spec is carrying and the
match ignores. So a gene control never matches a library whose names keep
their organism prefix -- which is every count table `process_reads` writes.

184 recorded "ALL FOUR SPELLINGS REACH THE SAME 28 GUIDES", and that was
measured with a GENE COLUMN alongside the guides. The no-gene-column path is
the one a count table actually takes, and it was never exercised on prefixed
names.

FIX THE RESOLVER FIRST. Changing the default to `000000` on top of this
would replace thirty working guide names with a control that selects nothing
-- and selecting nothing is not loud: the thresholds fall back, the baseline
sits at zero, and the run completes.

--------------------------------------------------------------------------------
C. THE OLD LIST STILL HAS TO LOAD
--------------------------------------------------------------------------------

A settings CSV written before this change carries the thirty names, and it
must keep meaning what it meant. `resolve_controls` already takes a mixture
of genes and guides, so the two spellings coexist; what matters is that a
saved run reproduces.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* `rows_for('000000', guides)` on the example screen -- no gene column,
  prefixed names -- selects every `TGGT1_000000_*` guide, and a test asserts
  the count against the library rather than against a number typed here.
* The same call with the four spellings 184 names gives the same set.
* `controls` defaults to `['000000']`.
* A settings CSV holding the thirty old names still selects those guides.
* `negative_control` is still `233460`, deliberately, and this file says why.

--------------------------------------------------------------------------------
2026-08-21 -- DONE. AND B WAS REAL: EVERY SPELLING FAILED, NOT JUST THE GENE.
--------------------------------------------------------------------------------

MEASURED ON THE EXAMPLE SCREEN, before anything was changed:

    000000            ->  0 guides      (there are 30)
    TGGT1_000000      ->  0
    000000_11         ->  0             (there is 1)
    TGGT1_000000_11   ->  0

This file predicted the gene branch. The GUIDE branch had the same fault from
the other direction: `resolve_control` strips the measured organism prefix off
what the user TYPED -- so `TGGT1_000000_11` becomes `000000_11` -- and then
`matches` compared that stripped value against a column that still carries the
prefix. Neither spelling of either level worked on a prefixed library, which
is every count table `process_reads` writes.

Both branches take the prefix the spec is already carrying. All four spellings
now reach 30, 30, 1, 1.

WHY 184 DID NOT SEE IT. Its "all four spellings reach the same 28 guides" was
measured WITH a gene column beside the guides, which takes the `genes is not
None` branch and never touches the string comparison. The no-gene-column path
is the one a count table takes.

THE DEFAULT IS `['000000']`. The old thirty-name list still resolves --
`resolve_controls` takes a mixture of genes and guides -- and a test asserts
the two select the same guides, so a settings CSV written before this
reproduces.

`negative_control` is untouched at '233460', deliberately, and the setting's
own description now says which control is which so the next reader does not
have to be corrected the way this file's author was.

17 tests in tests/test_a_gene_control_finds_its_guides.py, one of them
against the example screen's own 30 guides.
