--------------------------------------------------------------------------------
1. A FOLDED MODULE KEEPS NO MODULE OF ITS OWN
--------------------------------------------------------------------------------

"make sure all folded in moduals dont have their own moduals (napari bridge
is in make masks for example)."

The fold work took the registry ROW away and left the SOURCE where it was.
`spacr/qt/screens/napari_bridge.py` is 373 lines that only Make Masks
reaches; the same shape applies to every screen module whose key is in some
host's `FOLDED_APPS` and in no registry row.

Sweep it rather than list it by hand: any module under
`spacr/qt/screens/` whose key is folded is a candidate. Fold the code into
its host, or -- where the host would become unreadable -- into a private
module clearly belonging to that host rather than a peer sitting beside
every real screen.

CONFIRMED FOR NAPARI, 2026-08-26: "napari bridge is in make maksks and can
be removed as a modual." It already has no registry row and is a button on
Make Masks' masthead (`make_masks.FOLD_ORDER`), so what is left is the
source sitting beside every real screen.

THERE ARE TWO FILES WITH THAT NAME AND ONLY ONE GOES.

  * `spacr/qt/screens/napari_bridge.py` -- 373 lines, the SCREEN. Reached
    from `make_masks.py:1682`, listed in `spacr/qt/__init__.py:413`, and
    driven by two test files. THIS is the module being removed: it folds
    into its host.
  * `spacr/napari_bridge.py` -- 677 lines, the LIBRARY. It STAYS. It is
    public API (`spacr/__init__.py:212`), the CLI documents
    `spacr.napari_bridge.correct_mask` by name (`cli.py:759`), and
    `qt/dnd_handlers.py:2418` routes a dropped label mask through it.
    Deleting it would take a documented entry point and a drop handler
    with it.

The same two-file shape may hold for other folds -- a screen module and a
library module under one name -- so sweep by asking which file the HOST
imports, not by name.

--------------------------------------------------------------------------------
2. MAKE MASKS IS A DATA TOOL
--------------------------------------------------------------------------------

"move make masks to data"

`make_masks` is registered under `SECTION_MODELS` ("Segmentation models").
It belongs under `Data`: it is hand curation of masks that already exist,
not a model. The sections are Core, Data, Segmentation models, Results & QC,
Explore, Assays, Design.

Moving a row between sections moves the tile on Home and its place in the
Home bands, so check both rather than only the registry.

--------------------------------------------------------------------------------
3. THE FOLD BUTTONS ARE HALF AGAIN AS BIG
--------------------------------------------------------------------------------

"the new icon buttons are verry close in the moduals make them 50% larger."

`spacr/qt/widgets/fold_strip.py`: `BUTTON_PX = 34`, `ICON_PX = 20`. Both go
up by half -- 51 and 30 -- and the gap between them has to grow with them,
because the complaint is that they read as CROWDED, and buttons that grow
while the gap stays put are more crowded, not less.

Check the masthead still lays out at a narrow window: a strip of larger
buttons is the thing most likely to push a masthead into a scroll.

--------------------------------------------------------------------------------
4. MASK GENERATION LOADS THE EXAMPLE DATA
--------------------------------------------------------------------------------

"add load example data in the same way as it is added in regression to mask
generation"

Regression has `AppScreen._install_example_data_button`, which puts a "Load
the example screen…" button at the top of a section and fills the two file
slots from `spacr.example_data`, saying where everything went rather than
filling fields silently.

Mask Generation wants the same shape, filling what a MASK run needs -- a
source folder of images rather than count and score tables. Whatever the
example set offers for segmentation is what the button should place, and if
the manifest has no images for it, that gap IS the first half of this item.
