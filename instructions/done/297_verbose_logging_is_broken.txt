297 — Verbose logging is broken

Reported 2026-08-28: "write on verbose logging (broken)".

MEASURED THE SAME DAY, through the real `apply_preferences_to_app` path.

1. YOU PAY FOR THE TRACE AND THE OUTPUT IS THROWN AWAY.

   Turning verbose on installs the profile hook, sets `spacr.trace` to
   DEBUG, and starts formatting a record for every call and every return in
   the process. The file level policy then filters DEBUG out:

       get_verbose_logging()  -> True
       spacr.trace level      -> DEBUG
       get_log_file_levels()  -> {INFO, WARNING, ERROR, CRITICAL}   <- no DEBUG

   So the records are built at full cost and discarded at the handler. The
   two settings are independent and contradict each other, and the one the
   user did not touch wins. Whatever verbose means, it cannot mean "do all
   the work and write none of it".

   Turning verbose on must make DEBUG reach the file. Either the level
   policy gains DEBUG with it, or the trace records bypass the policy --
   but the tracer must not run when nothing will be written.

2. THE TRACER STILL RAISES DURING INTERPRETER SHUTDOWN.

       Exception ignored in: <function _removeHandlerRef ...>
         File "spacr/logging_util.py", line 512, in _trace_profile
         File ".../logging/__init__.py", line 1391, in getLogger
       TypeError: 'NoneType' object is not callable

   An earlier guard checked that this module's own globals were still
   there. That is not enough: `logging`'s internals are torn down too, so
   `logging.getLogger` itself fails from inside a finaliser. The hook has
   to be uninstallable, or defended against its own dependencies vanishing.

3. IT IS STILL EXPENSIVE FOR WHAT IT SAYS.

   Twenty calls to `spacr.version.get_version()` wrote 5,520 bytes -- 276
   bytes per call, for a function that takes no arguments and returns a
   string. The paint path is excluded (294) but ordinary work is not, and
   a trail nobody can read through is not a trail.

HOW TO KNOW IT WORKED
  * with verbose on, DEBUG records reach the log file, and a test asserts
    the file grows;
  * with verbose off, the hook is not installed and nothing is formatted;
  * a process that enables verbose and exits prints no "Exception ignored
    in" from the tracer;
  * the cost per traced call is stated in the tooltip, measured not
    guessed.


FIXED 2026-08-28, points 1 and 2:

  * `get_log_file_levels` adds DEBUG while verbose is on, so the records
    the tracer builds actually reach the file. Added on READ, never stored,
    so the user's own level choice is untouched and DEBUG goes away again
    when verbose is turned off.
  * `_trace_profile` guards its whole body. Guarding this module's globals
    was not enough -- `logging`'s own are torn down too, so `getLogger`
    itself fails from inside a finaliser.

STILL OPEN: point 3, the cost. 276 bytes per traced call is too much for a
trail anyone can read, and the tooltip still does not say what verbose
costs.


FIXED 2026-08-28. All three points.

  1. `get_log_file_levels` adds DEBUG while verbose is on, so the records
     the tracer builds reach the file. Added on READ, never stored, so the
     user's own level choice is untouched.
  2. `_trace_profile` guards its whole body: `logging`'s globals are torn
     down at shutdown too, so `getLogger` itself failed inside finalisers.
  3. 276 bytes per traced call became 156. On a trace record the level is
     always DEBUG, the logger is always `spacr.trace`, and the file and line
     were this module's own tracer rather than the traced code -- three
     fields saying nothing and one actively misleading.
     `_CompactTraceFormat` gives that one logger a short format and leaves
     every other record's prefix alone.

AND THE DEFAULT WENT BACK TO OFF, which is the finding that matters most.
Measured on this machine, offscreen:

    verbose off : 3.05 s to a usable Home screen
    verbose on  : 65.28 s, with Mask still not open when the run was cut

Twenty times the startup. The tracer fires on every call and every return,
and startup is where a Python application makes the most calls it will ever
make; excluding the paint path and halving the line length took it from
unusable to merely large. A trail that exists before the bug is worth
having, which is why on-by-default was tried -- making it affordable means
NOT tracing every call. Sampling, or tracing only the module a run is in,
would do it. Until that exists the honest default is off, and the tooltip
now states both numbers so the choice can be made knowingly.
