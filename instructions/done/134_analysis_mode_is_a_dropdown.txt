================================================================================
ANALYSIS MODE IS A DROPDOWN, NOT A TEXT BOX
================================================================================

Status:    filed 2026-08-17.
Requested: 2026-08-17 -- "analasys mode should be a dropdown"

Related: 132 is the model and inference tab this sits in. 106 is the rule a
         greyed-out state has to follow.

--------------------------------------------------------------------------------
WHAT IS WRONG TODAY
--------------------------------------------------------------------------------

`analysis_mode` has exactly TWO valid values -- `regression` and
`guide_permutation` -- and both GUIs render it as a FREE-TEXT ENTRY. The combo
dispatch in `settings_spec.py` (the table around line 158, `'metadata_type'`,
`'dataset_mode'`, `'cov_type'` and the rest) does not list it, and the Qt
`settings_model.py` combo table lists `inference` and not `analysis_mode`.

So a setting whose entire domain is two strings is typed by hand, and a typo
in it is not caught until the run has read the whole database.

--------------------------------------------------------------------------------
WHAT IT SHOULD DO
--------------------------------------------------------------------------------

* A COMBO with `regression` and `guide_permutation`, default `regression`,
  in BOTH GUIs -- one entry in the shared `settings_spec` table so the Tk and
  Qt front ends cannot end up offering different lists.

* GREYED OUT WHILE `inference` IS NOT `auto`, and saying why. `inference` is
  the readable front end that SETS `analysis_mode` (settings.py ~1706:
  "'inference' selects 'analysis_mode'"), and an explicit `analysis_mode`
  overrides it. A user who picks `nonparametric` and then sees a live
  `analysis_mode` box saying `regression` is looking at two controls that
  contradict each other. Instruction 106's rule applies: greyed out with the
  reason on it, never silently inert.

* THE LABELS SHOULD READ. `guide_permutation` is what the settings key is
  called; what the dropdown shows can be the sentence the tooltip already
  has -- one guide at a time, plate-blocked Freedman-Lane permutations --
  the same way 132's model box explains what it fits.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* `analysis_mode` is a dropdown in `spacr` and in `spacr-qt`, with the same
  two entries in both.
* Choosing `nonparametric` for `inference` greys it out and says why.
* A settings CSV carrying either value still loads.

--------------------------------------------------------------------------------
2026-08-20 -- DONE. And the labels found a bug in the settings writer.
--------------------------------------------------------------------------------

A COMBO WITH TWO ENTRIES in both front ends, declared in `settings_spec`'s
`special_cases` so Tk and Qt cannot offer different lists, greyed out with the
reason whenever `inference` is choosing it -- naming which inference, and what
it selected. Two controls that contradict each other is what 106 forbids.

THE LABELS READ. The dropdown says "regression — fit every guide at once in
the chosen model" and "guide permutation — test each guide on its own,
plate-blocked", as (value, label) pairs, so the stored values are still the
keys every settings file already written uses.

AND THAT EXPOSED A REAL BUG, in a writer neither this instruction nor 171
touched. `AppScreen._apply_value` matched a combo item by `itemText` alone:

    for i in range(widget.count()):
        if widget.itemText(i) == str(val): ...

A combo built from (value, label) pairs shows the SENTENCE and stores the
KEY, so importing a settings CSV that named the key found no match, the
selection did not move, and NOTHING SAID SO -- the panel silently kept
whatever it had. It matches on `findData` first now, falling back to the text.

This was reachable before today: 171's `crop_source` is the same shape. That
key is not a combo on the screens checked here, so the round trip could not be
demonstrated on it -- but the writer was wrong for any labelled combo, and it
is fixed for all of them rather than for this one.

7 tests in tests/qt/test_analysis_mode_is_a_dropdown_that_reads.py.

--------------------------------------------------------------------------------
2026-08-25 -- RE-AUDIT: STILL TRUE, AND ONE CRITERION HAS BEEN SUPERSEDED
--------------------------------------------------------------------------------

Driven again: `settings_spec.special_cases['analysis_mode']` still declares the
same two (value, label) pairs with `regression` as the default, the Qt panel
greys it with the reason whenever `inference` is choosing it, and
`AppScreen._apply_value` still matches on `findData` before falling back to the
text, so a settings CSV naming either KEY still loads. 8 tests in
tests/qt/test_analysis_mode_is_a_dropdown_that_reads.py pass.

THE FIRST CRITERION NAMED TWO FRONT ENDS. The Tk front end has since been
deleted (`spacr` is now an alias entry point for `spacr.qt:run`), so "the same
two entries in both" is now satisfied by there being one panel rather than by
two agreeing. The shared declaration in `settings_spec` is kept anyway: it is
the reason a second surface cannot drift, and the settings writer's `findData`
fix that this instruction found applies to every labelled combo.
