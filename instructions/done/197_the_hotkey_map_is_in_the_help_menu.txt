THE HOTKEY MAP IS IN THE HELP MENU
================================================================================

Status:    DONE 2026-08-21. See the closing section.

--------------------------------------------------------------------------------
WHAT EXISTS, AND WHY IT IS NOT REACHABLE
--------------------------------------------------------------------------------

`shortcuts.show_cheat_sheet` already draws the map -- an overlay over the
window, grouped by category, dismissed on the next key. It is a good screen.

IT IS REACHABLE FROM TWO PLACES AND NEITHER IS THE HELP MENU: the `?` key,
which you have to know about, and the command palette, which you have to know
about. The Help menu is where a user who does not already know a shortcut
goes to look for one -- which is the entire population this screen is for.

    Help > Tutorial (web)
    Help > Documentation (web)
    Help > About spaCR
    Help > Check for updates…
    Help > Open log folder…

Add "Keyboard shortcuts" to that list, above the web links, because it is the
only entry that answers without a browser.

--------------------------------------------------------------------------------
A. THE MAP IS EVERY SHORTCUT, NOT THE SEVENTEEN SOMEBODY REGISTERED
--------------------------------------------------------------------------------

`SHORTCUTS` holds 17 entries. The Qt package binds 77 keys -- QShortcut,
QKeySequence, `setShortcut` -- so most of what a user can press is not on the
map, and nothing says which.

A MAP THAT IS SILENTLY PARTIAL IS WORSE THAN A SHORT ONE, because a reader
takes it for the whole list and concludes a key does not exist. The same
argument 108's restyle menu makes about being built from the style object
rather than a hand-written list: the map is generated from what is BOUND, so
a shortcut added anywhere appears without anyone remembering to add it.

Where a binding cannot be discovered automatically, it is registered
explicitly -- and a test counts the bound keys against the mapped ones and
fails when they drift, so "which is missing" is answered by the suite rather
than by reading 77 call sites.

--------------------------------------------------------------------------------
B. IT SAYS WHAT THE KEY DOES, AND WHERE IT WORKS
--------------------------------------------------------------------------------

A shortcut that only works on one screen and is listed without saying so
sends a user to press it somewhere it does nothing. Each row carries the
keys, what it does, and the scope: the whole window, the current module, or
one widget.

GROUPED THE WAY THE MENUS ARE. A flat list of forty rows is a wall; the
categories the cheat sheet already uses are the right ones.

--------------------------------------------------------------------------------
C. THE PLATFORM'S OWN SPELLING
--------------------------------------------------------------------------------

`Ctrl` is `Cmd` on macOS and Qt already knows: `QKeySequence.toString(
QKeySequence.NativeText)` prints what the user's keyboard actually has.
Writing "Ctrl+H" into a label hard-codes one platform into the help.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* Help > Keyboard shortcuts opens the map.
* Every key the application binds appears on it, and a test asserts the
  bound set equals the mapped set.
* Each row says what the key does and where it works.
* The keys are printed in the platform's own spelling.
* `?` and the command palette still reach the same screen -- one map, three
  doors, not three maps.

2026-08-21 -- DONE. AND THE MAP WAS MISSING FIFTEEN OF ITS THIRTY-THREE KEYS.
--------------------------------------------------------------------------------

Help > Keyboard shortcuts, above the web links because it is the only entry
there that answers without a browser. It opens `show_cheat_sheet` -- the same
screen `?` and the command palette open. One map, three doors.

A. THE MAP IS EVERY KEY NOW. `SHORTCUTS` held 17 and the package binds these
as well, none of which were on it:

    Ctrl+B                      the full app list
    Left / Right                previous / next image
    PageUp / PageDown           the same, for older muscle memory
    Alt+Left / Alt+Right        the same again
    B  E  W  Z                  brush, erase, magic wand, zoom
    Esc                         reset the zoom
    Ctrl+S                      save the mask
    Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z   undo and redo

THE SCAN HAD TO READ BOTH SPELLINGS. `QKeySequence("Ctrl+S")` and
`QKeySequence(Qt.Key_Left)` are both bindings, and a scan for string literals
misses the second entirely -- which is how the image navigation is bound. The
test reads the tree for both and prints them through Qt, so the comparison is
against what the card actually shows.

B. AND `SHORTCUTS` WAS DOING TWO JOBS AT ONCE, which is why adding to it
broke four tests in one run. It was both "what `install()` binds on the main
window" and "what the map shows" -- and a per-screen key does not exist until
that screen is built, so it can never be the first. Three names now:

    SHORTCUTS         what `install()` is responsible for
    SCREEN_SHORTCUTS  what a screen binds and the map still has to describe
    mapped()          both, which is what the card is drawn from

`BOUND_ELSEWHERE` names the one window-wide key something else binds:
`Ctrl+B` is set on the menu action that opens the app list, which is a real
binding and reaches the same place -- so it is on the map and is not in
`install()`'s count. A test called it unwired because it only looked for
`QShortcut`; it looks for a QAction's shortcut too now.

C. SCOPE AND SPELLING. A key that works on one screen says so in its row --
"Brush — the Make Masks screen" -- because one listed without that sends a
user to press it somewhere it does nothing. And every key is printed through
`QKeySequence.toString(NativeText)`, so `Ctrl` reads as the Command symbol on
macOS; writing "Ctrl+H" into a label hard-codes one platform into the help.

D. THE CARD HAD TO LEARN TO WRAP. One column-pair per category made it
1,640 px wide against a 1,280 px overlay the moment the map went from 17 rows
to 33. A map that runs off the screen is the same fault as one that leaves
keys out. Categories fill the width and wrap, and a test asserts the card
fits.

13 tests in tests/qt/test_the_hotkey_map_is_the_whole_map.py; 1,251 pass
across the shortcut, palette, window and menu suites.
