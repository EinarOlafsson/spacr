--------------------------------------------------------------------------------
WHAT IS ASKED
--------------------------------------------------------------------------------

The Evaluation section is one long list. Split it TWO WAYS at once:

  * BY CATEGORY -- the ordinary grouping every other section has.
  * BY ML VS CV -- a setting that only the classical-ML path reads and one
    that only the computer-vision path reads are not the same question, and
    a single list makes the user work out which of the two they are looking
    at from the name.

PREFER AN EXISTING CATEGORY. "best is if these settings can be added to
categories that already exist" -- a new heading is a new place to look, and
the panel already has headings that several of these belong under. Only
invent a heading where nothing existing fits.

THE ONE HARD RULE: A SHARED SETTING STAYS SHARED. A setting both paths read
must NOT be filed under a CV-specific or ML-specific heading. Doing so tells
the user it applies to one path when it applies to both, and they will set
it in one module and not the other. When in doubt about whether a setting is
shared, CHECK WHAT READS IT rather than guessing from its name -- that audit
is the work of this item.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* No section of the classify panel is a long undifferentiated list.
* Each moved setting's new heading is justified by what actually reads it,
  and a test asserts the ML-only and CV-only lists against the modules that
  consume them rather than against a hand-written list that can drift.
* Every setting read by BOTH paths is under a shared heading -- asserted,
  because this is the failure the item names.
* The number of NEW headings is small, and each one is there because nothing
  existing fit.
* No setting is lost in the move: the set of keys the panel renders is the
  same before and after.

--------------------------------------------------------------------------------
DONE 2026-08-21 -- AND THE AUDIT CORRECTED THE SPLIT
--------------------------------------------------------------------------------

THE AUDIT WAS THE WORK, exactly as this item says, and it overturned the
obvious answer. `classify.FAMILY_SETTINGS` is the authoritative table of
what each family reads EXCLUSIVELY, and against it only `n_top_examples` is
CV-only and only `save_to_db` is ML-only.

ELEVEN OF THE FIFTEEN ARE SHARED. The first attempt split them by what their
NAMES suggest -- `classifier_evaluation`, `evaluation_calibration`,
`evaluation_bins`, the four leakage settings, `score_threshold` all sound
like computer-vision settings -- and filed them under "Computer Vision
Evaluation". That broke this item's one hard rule on eleven settings out of
fifteen, and it broke it invisibly: every name in that heading looked right.

So the split is BY CATEGORY, with NEUTRAL headings:

  Model Evaluation   how the model is VALIDATED -- whether cross-validation
                     runs, into how many folds, grouped by what
  Evaluation Reports what is WRITTEN OUT -- the bundle, the calibration
                     curve and its bins, the score column and threshold
  Leakage Audit      whether train and test share objects

THE LEAKAGE AUDIT IS ITS OWN HEADING because it is a check on the SPLIT
rather than on the model. A reader looking for it among the metrics would
not find it, and a model scored on cells it was trained on is not scored at
all.

THE TWO EXCLUSIVES WENT TO FAMILY HEADINGS THAT ALREADY EXIST -- "best is
if these settings can be added to categories that already exist" -- so only
two headings were invented, and each because nothing existing fit.

THE TEST ASSERTS AGAINST `FAMILY_SETTINGS`, not against a hand-written list.
It checks that no SHARED setting sits under a path-named heading, that no
neutral heading NAMES a path, and that the two exclusives are exactly the
two the table says they are -- so the split and the families cannot drift
apart.

NO SETTING IS LOST AND NONE IS IN TWO PLACES, both asserted.
