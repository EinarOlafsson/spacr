2026-08-09 - REOPENED: THE BUTTON IS THERE, THE GEAR IS NOT
--------------------------------------------------------------------------------

  "if i click to the right of copy console i get the preferences but i
   cannot see the gear that should represent the button."

So the hit area and the wiring are correct and only the ICON is missing --
which is a narrower bug than it sounds and probably one of:

  * the gear glyph is not in the bundled icon set under the name the
    button asks for, so `themed_pixmap` returns None and the button
    renders empty;
  * it is being re-inked to the background colour and is invisible
    rather than absent -- check against BOTH themes, since a glyph that
    vanishes on dark may be fine on light;
  * the icon is set but the button has no visible size, so it paints into
    zero pixels.

Distinguish them before fixing: `themed_qimage` returning None is a
different bug from a correct image drawn in the wrong colour. Note the icon
cache added on 2026-08-09 stores re-inked icons on disk under
~/.spacr/icons -- if the icon was ever cached wrong it will stay wrong, so
clear that directory when testing.

--------------------------------------------------------------------------------
2026-08-09 - IT WAS NEVER MISSING. IT WAS 16px.
--------------------------------------------------------------------------------

The file listed three candidate causes -- missing glyph, wrong ink colour,
zero size -- and said to distinguish them before fixing. Measured:

    icon('settings').isNull()   False
    pixmap 24x24 isNull         False
    opaque sampled pixels       31 of 64
    colour                      #a1a6ad   (light grey, visible on dark)
    button                      44 x 38
    iconSize                    16 x 16

So none of the three. The glyph is present, painted and a perfectly
visible colour -- it is simply SMALL. `setIconSize` was never called, so it
took Qt's 16px default.

WHY THAT READS AS INVISIBLE, and why the tests never caught it: this
project ships `DEFAULT_FONT_SCALE = 1.5`, and the qt suite pins 1.0
(INVARIANTS 9). Everything beside the gear renders half again as large
while the icon stays 16px, so on the SHIPPED configuration it is a third
of its button and reads as an empty square. The suite was measuring the one
configuration in which it looks least wrong.

Fixed by sizing it with `scaled_px(18)`, so it keeps its proportion at
every zoom rather than being correct at one:

    font scale 1.0   18px in a 38px button   47% of button height
    font scale 1.5   27px in a 40px button   68%

Four tests, and the one that matters asserts the icon GROWS with the font
scale -- a fixed size would pass every other assertion here and still be
the bug.
