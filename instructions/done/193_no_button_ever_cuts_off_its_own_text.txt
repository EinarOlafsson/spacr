================================================================================
NO BUTTON EVER CUTS OFF ITS OWN TEXT
================================================================================

Status:    DONE 2026-08-21. See the closing section.
Requested: 2026-08-21 -- "some buttons like the plate button cut off the text.
           make it impossible for any button to cut of anny text."
Owner:     Qt GUI (every screen)

--------------------------------------------------------------------------------
THE REPORTED ONE, AND WHY IT IS NOT THE POINT
--------------------------------------------------------------------------------

The "Plate…" button of 185 is `setFixedWidth(58)`, chosen by eye against the
English label. Any longer string -- and every translation is a longer string
-- is elided to "Plat…" or clipped outright.

FIXING THAT ONE BUTTON IS NOT WHAT WAS ASKED. "make it impossible for ANY
button to cut of ANNY text" is a rule about the class, and a rule is worth
having because the failure is invisible to the person who wrote it: the
author sees their own label fit, and the button is only wrong in a language
they do not read or at a font size they do not use.

--------------------------------------------------------------------------------
A. THE RULE
--------------------------------------------------------------------------------

A button's width is a CONSEQUENCE of its text, never an input to it.

  * No `setFixedWidth` / `setMaximumWidth` on a button that carries a label.
    A fixed width is a promise about a string, and neither the string nor
    the font is fixed.
  * The size policy carries the text: the button's `sizeHint()` already
    accounts for the label, the icon, the padding and the current font.
    Let the layout have it.
  * WHERE A ROW GENUINELY HAS TO FIT, the label shortens, not the button --
    and shortening is a decision written in the code with the full text kept
    in the tooltip, not `Qt.ElideRight` happening silently at paint time.

TRANSLATION IS THE REAL TEST. spaCR ships localised UI; the German for a
three-word English button is routinely half again as long. A width that fits
`en` and clips `de` is the same bug reported in a language nobody on the
project reads.

--------------------------------------------------------------------------------
B. IT IS HELD BY A TEST, NOT BY REVIEW
--------------------------------------------------------------------------------

A rule that depends on the next author remembering it is not a rule. Build
every screen and, for every QPushButton on it, assert

    button.width() >= button.sizeHint().width()

and that the painted text is not elided -- `QFontMetrics.elidedText(...) ==
text` is the direct check, and it catches the case a width comparison misses
when a layout has already squeezed the button.

RUN IT IN EVERY SHIPPED LANGUAGE, or at least in the longest one: the
catalogues are in the tree, so the test can measure the worst case rather
than the one the author happens to speak.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* No button in `spacr/qt` sets a fixed or maximum width while carrying text.
* Every button on every module screen is at least as wide as its own
  `sizeHint`, in the longest shipped language.
* No button paints elided text.
* The "Plate…" button shows "Plate…" in full, and still does when the
  settings pane is dragged narrow.

--------------------------------------------------------------------------------
2026-08-21 -- DONE. SEVEN SITES, AND A CHECK THAT KNOWS WHAT A BUTTON IS.
--------------------------------------------------------------------------------

THE REPORTED ONE FIRST, AND IT WAS EXACTLY AS DESCRIBED. "Plate…" was
`setFixedWidth(58)`, measured by eye against the English. Every translation
spaCR ships is longer:

    de  'Teller...'      fr 'Plaque...'     es 'Plato...'
    is  'Plötu...'       sv 'Plåt...'       ko '플레이트 ...'

The cap is gone; the layout gets the button's own `sizeHint`, which already
accounts for the label, the icon, the padding and the current font. Measured
after: 100 px against an 80 px hint.

SIX MORE, ALL SINGLE-GLYPH CONTROLS -- the `×` that removes a class chip, a
filter clause, a graph drop zone and a pivot well, and the `?` legend toggle.
Each keeps its compact number as a FLOOR rather than a ceiling:

    setMinimumWidth(max(20, b.sizeHint().width()))
    setMaximumWidth(max(20, b.sizeHint().width()))

so the chip stays 20 px wide at the shipped font and grows instead of
clipping at a larger one. A `×` is text, and a rule that exempts it is a rule
with a hole the size of every icon-shaped label.

THE CHECK KNOWS WHAT A BUTTON IS, and getting that wrong twice is what the
first two drafts did. A scan for `setFixedWidth` across files that build
buttons flagged 14 sites, of which zero were buttons -- a panel at 330, a
progress bar at 140, a spin box at 220. The AST tracks names ASSIGNED a
`QPushButton`/`QToolButton` and flags width pins on those, which is precise
enough to have found the six real ones and quiet enough to be worth keeping.

TWO EXEMPTIONS, BOTH ARGUED:

  * a cap computed FROM `sizeHint()` is not pinning -- it is a preferred
    size with the text as its floor, which is the rule and not a breach;
  * a button with NO TEXT has nothing to cut. `QPushButton()` with no label
    is a swatch or an icon, and pinning its size is describing a picture.
    The DNA-rain colour swatch is that, and the plate maps' wells (194) are
    squares standing for physical wells.

AND THE SCREENS ARE MEASURED, NOT JUST THE SOURCE. Four module screens are
built and every visible button on them is checked two ways: at least as wide
as its own `sizeHint`, and -- the direct one, which catches what a width
comparison misses after a layout has squeezed something --
`QFontMetrics.elidedText(...) == text`. The reported button is checked
against its LONGEST translation across all nine catalogues, because the
author reads one of them.

15 tests in tests/qt/test_no_button_cuts_off_its_text.py; 1,004 pass across
the suites of every widget touched.
