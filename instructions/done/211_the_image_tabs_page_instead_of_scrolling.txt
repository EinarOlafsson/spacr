================================================================================
THE IMAGE TABS PAGE INSTEAD OF SCROLLING
================================================================================

Status:    DONE 2026-08-21.
Requested: 2026-08-21 -- "for the image tabs fit the images to fit in the
           visable part of the container, do not use scroll, use next and
           preveous page instead. and remove the cell_per_page settings. this
           will be dictated by the size of the images."
Owner:     Qt GUI (image tabs)

--------------------------------------------------------------------------------
WHAT IS ASKED
--------------------------------------------------------------------------------

The visible area is the page. Images are laid out to fit inside it, and what
does not fit goes on the next page, reached with Next and Previous. No
scrolling.

`cells_per_page` GOES AWAY -- not hidden, removed. The count is a
CONSEQUENCE of the container size and the image size, and a setting that
contradicts the geometry is a setting that produces a half-empty page or a
clipped row. Deleting it is the point of the request, and the setting's
current value has to be migrated out rather than left in the saved
preferences to confuse a later reader.

RECOMPUTE ON RESIZE. The page size is a function of the container, so the
window changing shape changes how many images fit; the page the user is
looking at must survive that -- keep the first image on the page fixed, not
the page number, or a resize teleports the reader.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* No scrollbar on the image tabs; every image on a page is fully visible.
* Next and Previous move by exactly one page, and both are disabled at the
  ends rather than wrapping silently.
* `cells_per_page` is gone from the settings, the defaults and the saved
  preferences.
* Resizing the window relays out the page and keeps the reader where they
  were.
* The page count is stated -- "page 3 of 11" -- because paging without a
  total is navigation without a map.

--------------------------------------------------------------------------------
DONE 2026-08-21
--------------------------------------------------------------------------------

`fits_on_a_page(width, height, thumb_px)` -- the count is a CONSEQUENCE of
the geometry, computed from the scroll area's viewport every time it is
asked. A cached number would be the PREVIOUS window's answer, and the window
is exactly what changes.

THE PAGE HOLDS WHOLE ROWS, asserted: a page ending mid-row is the clipped
row this replaces.

A VIEWPORT TOO SMALL FOR ONE THUMBNAIL STILL SHOWS ONE, clipped. An empty
page is indistinguishable from a well with no cells in it.

THE SCROLLBARS ARE OFF, both of them. A page that scrolls is not a page --
it is a grid with a smaller window over it, which is the thing being
replaced. Hiding the bar also makes a wrong page size VISIBLE instead of
navigable.

THE ANCHOR IS THE FIRST IMAGE, NOT THE PAGE NUMBER. The same page number is
a different set of cells once the page holds a different number of them, so
keeping it across a resize teleports the reader. `resizeEvent` reads
`first_on_page()` before the relayout and calls `show_crop()` after.

`cells_per_page` IS GONE from the settings, the tooltips and the picture
defaults -- and `picture_settings.RETIRED` carries what happened to it, so a
saved preferences blob that still names it is migrated out with a reason
rather than leaving an unexplained key for a later reader. `_per_page_of`
survives returning 0, which means "work it out from the container": a
settings CSV that still carries the number has it IGNORED rather than
honoured, because honouring a count that disagrees with the geometry is the
bug the setting was removed for.

The pager already said "page 3 of 11" and already disabled at both ends;
both are tested now rather than assumed.
