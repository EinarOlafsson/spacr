================================================================================
THE EXPLAINER TEXT FILLS THE WIDTH OF ITS BOX
================================================================================

Status:    filed 2026-08-18.
Requested: 2026-08-18, twice, once per box --

  "in model and inference in regression module the text in the text box
   should span the width of the textbox"

  "in permutation test in regression module the text in the text box should
   span the width of the textbox"

Related: 132 built the Model & Inference box. 135 asked for the Permutation
         Test one. This is one behaviour across both.

--------------------------------------------------------------------------------
WHY IT DOES NOT TODAY
--------------------------------------------------------------------------------

The text is HARD-WRAPPED before it reaches the widget.
`settings_model._wrap_block` runs `textwrap.wrap` at `_EXPLAINER_WIDTH`, and
`app_screen._install_section_explainer` then sets
`QPlainTextEdit.NoWrap` and a minimum width of that same column.

So the paragraph is a fixed number of characters wide whatever the panel is.
Widen the settings pane and the box widens with it; the text does not. The
right-hand side of the box is empty.

BOTH DECISIONS WERE MADE FOR REAL REASONS, and the fix has to keep them:

  * NoWrap is there because soft-wrapping ON TOP of a hard wrap broke every
    prose line a second time, at a different column, with no hanging indent.
    That is worse than either alone.
  * The hard wrap is there so a FORMULA pasted out of the box arrives in a
    methods section as the line it was written as, and so the text has a
    stable shape a test can assert.

--------------------------------------------------------------------------------
WHAT IT SHOULD DO
--------------------------------------------------------------------------------

PROSE WRAPS TO THE BOX. Stop hard-wrapping paragraphs; let the widget do it,
so the text reflows when the pane is resized and fills the width it is given.

FORMULAS DO NOT WRAP. They are the reason the box exists -- a formula broken
across two lines at an arbitrary column is not a formula. A formula line that
is wider than the box is reached by scrolling, or by the box growing, never by
breaking it.

That means the two need different treatment rather than one wrap mode for the
whole box: a rich-text box whose paragraphs wrap and whose formula lines sit
in a non-wrapping block is the obvious shape. Whatever is chosen, keep the box
READ-ONLY, SELECTABLE and MONOSPACE for the formulas, and keep the monospace
coming through a QSS rule on the objectName -- a `setFont` loses to the
theme's global `QWidget { font-family: "Open Sans" }` and the box renders
proportional, which was measured.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* Widening the settings pane reflows the prose; the right margin stays even.
* No paragraph is wrapped at a column narrower than the box.
* Every formula is on one line, at any pane width, and copies out as one line.
* Both boxes behave the same way -- Model & Inference and Permutation Test.

--------------------------------------------------------------------------------
2026-08-20 -- DONE, by 144's move to rich text, and now HELD BY A TEST.
--------------------------------------------------------------------------------

The two constraints were unwinnable together in plain text, where wrapping is
per WIDGET: NoWrap kept the formula on one line and left the prose hard-wrapped
at a fixed column, and turning it on broke every prose line a SECOND time at a
different column. In rich text wrapping is per BLOCK, so the prose reflows and
the `<pre>` formula does not.

MEASURED on the model box's own document, laid out at 320 / 460 / 640 / 900:
heights 820, 624, 540, 470, and `idealWidth` tracking the width given at every
one. The patsy formula is ONE line at all four and at 240 -- narrower than the
pane ever gets -- with `nonBreakableLines` set on its block.

Both boxes, not only the model one: the test walks `_section_explainers`, so
the Permutation Test box is covered by name rather than by assumption, which
is what the ask being made TWICE was about.

THREE MEASUREMENT TRAPS, written down because each one produced a wrong answer
first:
  * line counts are zero until a layout has run, and a document that has not
    been laid out reports zero for everything -- which reads as a pass;
  * `toHtml()` DOES NOT ROUND-TRIP A `<pre>`. Qt serialises it as a paragraph
    with `white-space: pre-wrap`, so a document re-parsed from that string
    wraps a formula the live one holds on one line. Measuring the string
    reported a bug that does not exist on screen -- and 144's own note
    ("1 line at every one of them") was taken on the widget, which is why it
    did not see this;
  * a document re-measured at a second width returns a STALE height: 540,
    624, 540, 470 for widths that reflow monotonically 820 -> 470 when each is
    laid out on its own clone.

5 tests in tests/qt/test_the_explainer_prose_fills_its_box.py.
