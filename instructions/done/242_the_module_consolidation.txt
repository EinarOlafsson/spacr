HOW A FOLDED MODULE APPEARS
--------------------------------------------------------------------------------

"for the modules that become buttons use the icon as the button, if they
are alph the hover light up green and beta purple just like the moduals
do."

  * the button IS the module's icon, with no text;
  * its tooltip is the module's own one-line description;
  * hovering lights it in the stage colour the TILE uses, read from
    `spacr.qt.theme.STAGE_HOVER` rather than retyped -- stable blue, beta
    magenta, alpha green-cyan. The table is the source: a button and the
    tile it replaced must light the same, and two colour tables drift.
  * the strip goes on the host's masthead, through
    `ModuleHeader.add_trailing`, right-aligned past the stretch.

WHAT THE BUTTON DOES IS THE HARD PART, AND A WINDOW IS THE LAST RESORT.

"the prefered way is to integrate the folded module into the new module.
for instance with motility and Timelapse these buttons just need to
toggle the visability of their settings categories as they share the rest
with [the host]. some new module could take space above the console or
become a tab. anything to integrate the new module naturally. All the
modules that were folded into others were folded because they fit
thematically and/or functionally with the module they were folded into,
so try to find a natural way to fold them in, if you cannot find any
other way, then do your new window idea."

So the order to try, per fold, is:

  1. THE FOLD IS ALREADY MOSTLY THE HOST. Timelapse and Motility share
     nearly every setting with mask generation; what is theirs is a few
     settings CATEGORIES. The button toggles those categories visible.
     Nothing opens, nothing is replaced -- the panel grows the section
     the module was.
  2. THE FOLD IS A VIEW ON THE HOST'S DATA -> a tab beside the host's own,
     or a panel above the console.
  3. ONLY IF NEITHER FITS -> a window over the host.

A window everywhere is the shape a fold has when nobody looked for the
seam. Look for the seam first: the modules were folded because they
belong together, and something they share is what the button should
reveal.

WHAT MUST NOT HAPPEN: a fold that loses a capability. Each entry below
names what the folded screen can do that its host cannot, and that is the
part that has to arrive with it.

1. MAKE MASKS BECOMES THE SEGMENTATION WORKBENCH
--------------------------------------------------------------------------------

Folded in, each as a button:

    Train                 the training half of Cellpose Workbench
    Mask the whole folder replaces the `cellpose_all` CLI key: run the
                          current model over every image in the folder
    Compare               Model Compare
    Model Zoo             Model Zoo
    Curate                Curate
    Open in napari        Napari Bridge

Then `train_cellpose`, `model_compare`, `model_zoo`, `curate` and

SUPERSEDES THE CELLPOSE WORKBENCH. Train Cellpose and Cellpose Masks were
merged into one "Cellpose Workbench" row earlier the same day. This asks
for the training logic in Make Masks instead, so the workbench folds in
and its row goes with the others.

TWO DEFECTS THIS FOLD MUST FIX, both verified:
  a. CURATE NEVER WRITES A MASK. There is no imwrite / save / tifffile /
     np.save anywhere in curate.py, curation_tool.py or curation.py: it
     writes a ledger asserting edits beside a file whose pixels are
     untouched, and `is_curated()` then returns True for it. Folding it
     into a screen that CAN write is the fix.
  b. `mask_engine.save_mask` does `label(mask > 0)`, relabelling every
     connected component and destroying the object ids, and writes no
     ledger. A hand-edited mask is byte-indistinguishable from a
     segmented one.

DONE, AND BOTH OF THE THINGS THAT WERE WRONG WITH IT ARE FIXED.

The folds are a `FoldStrip` on the Make Masks masthead (`FOLD_ORDER` in
`spacr/qt/screens/make_masks.py`) and every capability survived.

  a. TIMELAPSE AND MOTILITY HAVE LEFT THIS STRIP. They did not belong
     here -- "dont you see the overlapping settings with mask generation
     not make masks?" Make Masks is hand-curation of masks that exist;
     tracking a series and measuring how it moved are things mask
     generation does over one. Both are gone from `FOLD_ORDER` and from
     `make_masks.FOLD_FALLBACK`, and their one home is Mask Generation --
     see item 2 below.
  b. NO BUTTON OPENS A WINDOW ANY MORE. The folded module is a PAGE
     beside the editor: the host's own body becomes the first page of a
     `QTabWidget` (`map_barcodes.host_pages`), the module's whole screen
     becomes the next one, and the window is what a fold falls back to
     only when its host has no body to make pages out of. The module
     itself is unchanged, so nothing moved house; closing a folded page
     keeps the screen and everything it had loaded, which is more than
     the window managed. "Mask the whole folder" still points the
     applying half of the Cellpose workbench at the open folder and
     starts it; the training half opens on its own tab with its own path
     untouched.
  c. AND CLOSING THE SCREEN NOW CLOSES EVERY MODULE IT BUILT, not only
     the ones that were opened. Pointing Model Compare at the folder
     builds it and starts a load thread before any button has been
     pressed; `close_folded` walked only the panels, so that thread
     outlived its widget and the process died of it in whatever ran
     next.

Both defects are closed. `MaskCuration.save_mask` writes the labels and
the ledger together, and the Curate page carries a "Save mask" button
that calls it; `mask_engine.save_mask` already preserved the ids through
`canonical_labels` and already wrote the ledger, and `mask_io.save_mask`
now refuses an id that would wrap to background instead of casting it.

STILL OPEN HERE: the standalone Curate screen's own "Save log" button
still writes only the ledger -- `BrushPanel` needs a Save-mask control
beside it, in `spacr/qt/curation_tool.py`. And the folded rows are still
in the registry: `unregister_app` drops the key from `APP_STAGE` as well
as from `APPS`, so a folded button's maturity colour has to survive that.
`make_masks.FOLD_FALLBACK` keeps the eight this screen folds; every other
host needs the same, or `FoldStrip` needs the fallback built in.

4. CONTROL CHARTS: KEEP, AND HERE IS WHY
--------------------------------------------------------------------------------

Asked as a question -- "controll charts can potentially be added to
classify or measure, what do you think" -- so this is the answer rather
than a decision taken.

NEITHER. It is a CROSS-PLATE CAMPAIGN VIEW: one point per plate, control
limits from short-term variation (moving range / d2, S-bar / c4, or a
robust median-MR / MAD variant), a stated Phase-I baseline applied
forward, the eight Nelson / Western Electric rules with per-rule expected
false-alarm arithmetic, and a per-plate Z-factor. Classify and Measure are
both settings forms for ONE run over ONE plate folder, and folding a
campaign view into a pipeline step misfiles it.

It is also column-agnostic: Measure writes the object tables and Classify
merges its scores back into the same file, so a chart of `cell_area` and
a chart of `ml_pred` are the same screen with a different combo-box
selection. "What it charts" cannot decide the host.

If it must be folded, the host is Plate Viewer -- the other screen whose
unit is the plate rather than the object.

HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* The registry holds 36 apps -- 46 when this was written, and the count
  moves with every later fold -- and every folded key still runs from
  `spacr-run`, from chaining, and from a settings file written before the
  fold. A folded key that cannot run headless must at least ANSWER for
  itself: `spacr-run <key>` says why and where the module went, rather
  than "unknown module" and a guess at a near spelling. Swept by
  `tests/qt/test_the_folded_rows_left_the_registry.py::
  test_spacr_run_answers_for_every_folded_key`.
  (AUDIT 2026-08-26: three folded keys -- hit_list, methods_export and
  napari_bridge -- answered "unknown module 'hit_list'" and then guessed.
  They have `cli.INTERACTIVE_ONLY` entries now, each naming the Python
  route that does the same work.)
* Each button carries the folded module's icon and its description, and
  lights in the stage colour its tile used. A button that is a switch
  stays lit while its module is part of the run.
* No fold opens a window on a host that can carry a page.
* Curate writes a mask, and a hand-edited mask carries a ledger that says
  so.
* The regression volcano draws one correction family, not two.
* Nothing in the "not redundant" list lost a capability: the style file,
  the annotation join, the three export formats and the number
  verification all still work from their new homes.
