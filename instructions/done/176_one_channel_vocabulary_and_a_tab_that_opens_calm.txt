WHAT TO BUILD

A. THE MEASUREMENTS TAB OPENS ON ONE SECTION.
   Attached databases expanded, Regression / Measurement scan / Gene x
   measurement sweep folded. Four panels open at once is what "there are to
   many elements in the measurements tab" was about, and 169 gave them folds
   without changing what they start as.

   THE STORED LAYOUT STILL WINS. A user who folded databases away and opened

   override. 169 C is explicit that the arrangement persists.

B. EVERY CELL SETTING HAS HOVER HELP.
   Every key in `picture_settings.ALL_KEYS`, on the setting's NAME and not on
   the field (instruction 113), because a tooltip on a box you are typing in
   is unreachable exactly when you wanted it.

   NOT A SECOND SET OF WORDS. The annotator already documents these keys and
   `spacr.settings` already carries descriptions; a tooltip written fresh
   here would be a second answer to what "normalize" means, which is the 145
   failure this tab has already made once.

C. r, g, b -- NOT 0, 1, 2 -- IN THE REGRESSION CELL FEATURE.
   The annotation application asks which COLOUR PLANES to show and spells
   them r, g, b. The Cells tab must ask the same question the same way.

   THE TRANSLATION IS THE CODE'S JOB, NOT THE USER'S. Streaming cuts from
   source array indices, so the letters have to be resolved through the
   run's own `png_channel_mapping` at the boundary -- 'r' means "whichever
   source channel this screen put in red", not "channel 0". Guessing 0, 1, 2
   would silently reverse a screen whose mapping is not the identity.

   An index form typed by a user still works: it is unambiguous, and a
   settings CSV written before today carries it.

HOW TO KNOW IT WORKED

* Opening Measurements shows the attach table and three folded headings.
* Every control in the Cells tab's settings window has hover help, and the
  text matches what the annotation app says about the same key.
* The Cells tab's channel control reads r,g,b like the annotator's, and a
  streamed crop is cut from the source channels that mapping names.
* A screen whose png_channel_mapping is not {r:0, g:1, b:2} cuts the same
  planes the annotator would show for the same letters.

2026-08-19 -- DONE. A, B AND C.
--------------------------------------------------------------------------------

A. `MeasurementScanPanel.OPENS_EXPANDED` is "Attached databases" and the other
   three start folded. FIRST-RUN ONLY: `restore_section_layout` runs after and
   wins, so a saved arrangement still comes back (169 C).

B. Seventeen of the twenty-five picture-settings keys had no hover help at
   all. They are in `spacr.settings.tooltips` -- the table the settings window
   ALREADY reads -- and not in a new one beside it, which would have been a
   second answer to what "normalize" means. On the setting's NAME (113).

C. Colour letters are TRANSLATED, not dropped and not read positionally.
   `picture_settings._as_channel_mapping` resolves r/g/b through the screen's
   own `png_channel_mapping`, falling back to spaCR's default -- which is
   {r: 2, g: 1, b: 0}, so 'r' is source channel TWO and a positional reading
   would have reversed every streamed crop while looking entirely plausible.
   It emits a MAPPING rather than a `png_dims` list, whose positional
   convention is the legacy inverted one. A colour the user did not pick is
   blank rather than absent, because an absent key falls back to the default
   and quietly restores a plane they turned off. An index form still works.

ASK B IS CLOSED AT ZERO MISSING
--------------------------------------------------------------------------------

The three colour-plane choices -- `red_channel`, `green_channel`,
`blue_channel` -- had explanatory text in `picture_settings.STREAM_ONLY`,
which is the table that says WHY a control is greyed when crops are loaded,
and no entry in `spacr.settings.tooltips`, which is the table the settings
window reads for hover help. So the greyed reason was written and the help
was not, and the guard this instruction installed
(`test_every_cell_setting_has_hover_help`) caught it exactly as intended when
the three keys were added later.

They are in `spacr.settings.tooltips` now, beside the other streamed-crop
keys and not in a second table, and each states its default -- 2, 1 and 0,
spaCR's shipped inverted mapping -- as every setting must.
