332 — MEASURE NEEDS DOWNLOADABLE TEST DATA, LIKE MASK HAS
==========================================================

ASKED FOR (2026-09-01)
----------------------
"the measure modual should also have test data that is dowloadable from
hugginface."

WHAT THE STATE IS
-----------------
Mask Generation has example data: it downloads a plate to
`~/.cache/spacr/example_images/plate1` and fills `src` with it, which is how
a new user gets from an empty screen to a running module without owning a
microscope. Measure has no equivalent, so the first thing it asks for is a
folder the user cannot produce until they have already run Mask.

That ordering is the problem rather than the missing files. Measure consumes
what Mask produces -- images plus masks -- so "try Measure" today means "run
Mask first, successfully, on your own data". A user evaluating spaCR gives up
before reaching the module that produces the numbers.

WHAT TO DO
----------
1. Publish a Measure example set: a small plate WITH ITS MASKS, so Measure can
   run standalone. That is the difference from Mask's set and the only reason
   this is not a one-line copy -- masks are what Measure needs and what Mask's
   example does not ship.
2. Reuse the download path that already exists. `spacr/qt/hf_download.py`
   fetches Mask's example; the same mechanism, the same cache folder
   convention, the same "already downloaded" check.
3. The button belongs where Mask's is, on the Measure screen, saying what it
   will fetch and how large it is BEFORE fetching.

WATCH OUT
---------
* The example must produce a measurements.db that the DOWNSTREAM modules can
  open -- Classify, Regression and the Plate Viewer all read it. An example
  set that only satisfies Measure moves the wall one module along.
* Size it for a laptop on hotel wifi. Mask's plate is the precedent.
* `hf_download.py` is 317's file; check who holds it before editing.

HOW TO KNOW IT WORKED
---------------------
* Measure runs to completion on a clean machine with no other module run
  first, and writes a measurements.db.
* That database opens in the Plate Viewer and in Regression.
* The download is declined gracefully: no example data must never mean no
  module.

--------------------------------------------------------------------------------
DONE, 2026-09-01
--------------------------------------------------------------------------------

Published as `einarolafsson/spacr-example-measure`: sixteen merged arrays
across four wells, cut from the example plate by a real Mask run. All four
wells are kept deliberately -- well-level aggregation and between-condition
comparison are most of what Measure does after the per-object step, and a
single-well set makes neither testable.

A "Load the example measure data..." button sits beside `src` in Input &
Experiment. The arrays ship compressed (~370 MB rather than ~890 MB) and are
written back out as .npy on arrival, so the second format lives entirely
inside the downloader.

Two things had to be solved that were not in the original plan. The database
stored ABSOLUTE paths naming the machine that made it, so the published copy
stores them relative to the plate folder and the downloader makes them
absolute wherever it lands. And every example set now unpacks into ONE folder,
`~/.cache/spacr/example_data/plate1`, because `merged/`, `data/` and
`measurements/measurements.db` are parts of one plate that are needed
together.
