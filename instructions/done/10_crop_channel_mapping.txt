--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

The reported symptom: nuclei render red and parasites blue in the annotator
and in any external viewer. Cause: commit 341f4462 (2026-07-26) deliberately
moved png_dims[0] from the file's blue slot to its red slot. Channel 0 is the
405 line, so that put the nuclear stain in red. migrate_crop_folder then
rewrote existing folders into that state, so pre-07-26 data that was migrated
is reversed on disk too.

Until the crop-source parity is restored, training-tar and UMAP thumbnail
generation can disagree with the PNG folder. DO NOT run a training-data
export off this tree until it is.

--------------------------------------------------------------------------------
WHAT WAS DONE
--------------------------------------------------------------------------------

1. spacr/crops.py
   * resolve_png_channel_mapping / build_png_channels /
     png_dims_to_channel_mapping / channels_from_settings.
     DEFAULT_PNG_CHANNEL_MAPPING = {'r': 2, 'g': 1, 'b': 0}, which is
     byte-for-byte what every crop written before 2026-07-26 looks like.
   * CROP_FORMAT_DECLARED_RGB = 3 is CROP_FORMAT_CURRENT. Reversal on read
     keys off _FORMAT_IS_DECLARED_ORDER (1:True, 2:False, 3:True), because
     formats 1 and 3 hold identical bytes and `fmt != as_format` would
     reverse between them.
   * migrate_crop_folder REPAIRS format-2 folders. A legacy, format-3 or
     unmarked folder is an immediate no-op.
   * CropSpec.channels is now COLOUR order, built by channels_from_settings.
     THIS was the parity blocker: the merged source spoke list order and the
     PNG source spoke file order, so the two returned different pixels for
     the same object.
2. spacr/measure.py — crop path builds planes in file order;
   generate_object_dataset stamps its output folder.
3. spacr/settings.py — png_channel_mapping; png_dims deprecated, still
   translated.
4. spacr/qt/widgets/channel_mapping.py — three R/G/B fields, wired into
   settings_model.py at _widget_for / _read_widget / set_value_for_key.
5. skill/INVARIANTS.md gained section 13, which is the general lesson.

TWO BUGS FOUND IN MY OWN CHANGE, both by tests that would not have caught
themselves:
   * the retry-after-skip path keyed on the SOURCE format, so a folder
     finished with on_error='skip' returned `already` and never retried its
     leftovers. Measured: converted all 3 crops instead of the 1 outstanding.
   * mark-mode refused format 2 but not format 3, so marking a repaired
     folder legacy silently discarded the record that it had been repaired.

PRE-EXISTING FAILURES, CONFIRMED ON A STASHED CLEAN TREE, NOT CAUSED HERE:
   * tests/test_crops.py::test_field_cache_is_keyed_on_file_contents passes
     alone and fails in the file. An isolation leak of the INVARIANTS 5
     family. NOT diagnosed. Left failing rather than papered over.
   * tests/test_crop_dtype_boundaries.py::
     test_normalise_without_masking_uses_every_pixel was red on the clean
     tree: pytest.approx computes abs(expected - actual) and a uint16 actual
     wraps, so 16384 vs 16383 came out as 65535 and the test failed on a
     difference it was explicitly tolerating. Fixed with int(), since it sat
     in the suite being certified.
