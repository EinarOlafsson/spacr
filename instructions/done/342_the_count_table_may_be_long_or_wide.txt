--------------------------------------------------------------------------------
WHAT WAS WRONG
--------------------------------------------------------------------------------

1. THE COUNT TABLE HAD ONE ACCEPTED SHAPE. `perform_regression` assumed one
   row per (well, guide), named by `count_grna_column` and
   `count_value_column`. A count table that arrives with ONE GUIDE PER COLUMN
   -- which is what several sequencing pipelines write -- had no route in at
   all, and the failure came out of pandas rather than out of the settings.

2. PLATE WAS NOT IN THE FIXED-EFFECTS MODEL. `prepare_formula` ended with
   `+ rowID + columnID`. The same row and column labels recur on every plate,
   so those two terms cannot absorb a shift in the overall mean BETWEEN
   plates: a four-plate screen with a plate-level offset had nowhere to put
   it, and it went into the guide coefficients.

3. THE NUISANCE FILTER WAS A SUBSTRING MATCH. `process_model_coefficients`
   dropped every coefficient whose feature name merely CONTAINED "row" or
   "column", so a legitimate guide named e.g. `ROW1_sg2` was silently
   removed from the hit list.

--------------------------------------------------------------------------------
WHAT WAS DONE
--------------------------------------------------------------------------------

`spacr/regression_layout.py` -- lossless long/wide conversion, deliberately
strict: a value is never silently selected when duplicate rows disagree.
`infer_regression_layout` recognises long from the paired guide/value columns
and otherwise treats the numeric non-metadata columns as guides;
`normalise_count_table_layout` melts wide input before any filtering, so the
fraction sweep and every downstream consumer see the shape they already knew.

THREE SETTINGS, all with defaults, declared types, tooltips and categories, so
they render in the GUI and survive a settings CSV round trip:

    independent_variable_layout   auto | long | wide     default 'auto'
    wide_predictor_columns        list                   default []
    model_data_layout             long | wide            default 'long'

INPUT LAYOUT AND MODEL LAYOUT ARE TWO QUESTIONS, not one, and that is the
design decision worth keeping. A long input can be collapsed to one row per
well for a fixed-effects estimator; a wide input can be melted for the
historical formula and for the permutation paths. `ml._wide_fixed_effect_design`
builds the explicit one-row-per-well design and keeps spaCR's existing
`fraction:grna[...]` / `gene_fraction:gene[...]` feature-name contract, so
every estimator and every results consumer reads coefficients the same way.

MIXED MODELS AND FREEDMAN-LANE PERMUTATION need the long nesting
representation, so `model_data_layout='wide'` is normalised back to long for
them and the run says so rather than silently disagreeing with the setting.

PLATE IS NOW EXPLICIT: `prepare_formula` emits `+ plateID + rowID + columnID`,
and `random_row_column_effects=True` uses plate as the grouping variable with
row and column as variance components. Patsy emits no contrast column when
there is only one plate, so a single-plate screen is unchanged.

THE NUISANCE FILTER now matches the Patsy term prefix
(`^(?:plateID|rowID|columnID|screenID)\[`) instead of a substring.
