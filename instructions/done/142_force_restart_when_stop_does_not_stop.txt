================================================================================

Status:    filed 2026-08-18.
Requested: 2026-08-18 --

   its settings) then quit spacr, restart space, go back to the modual that was

Related: 140 is the long fit that makes this necessary. 114 is the search that

--------------------------------------------------------------------------------
WHY THIS EXISTS
--------------------------------------------------------------------------------

A mixed fit runs for tens of minutes to hours (instruction 140, measured), in
a worker, inside statsmodels' optimiser. There is no cooperative check inside
a REML iteration, so a stop request can be ACCEPTED and still not land -- the
thread is in C, not in Python, and it will finish its iteration whatever the
GUI wants.

So "Force stop" can fail to stop, and today the only thing left is to kill the
application from outside and lose the whole configuration.

--------------------------------------------------------------------------------
A. A THIRD BUTTON, AND ONLY AS THE LAST ONE
--------------------------------------------------------------------------------

The stop dialog gains `Force restart`, after the existing choices. It is the
most destructive option on the dialog, so it is last, and it says what it
does before it does it -- this is not a gesture anyone should make by accident.

WHAT IT DOES, in order:
  1. save the state -- which module is open and the settings it holds;
  2. quit spaCR;
  3. start spaCR again;
  4. reopen that module with those settings.

THE SAVE HAPPENS FIRST AND IS VERIFIED BEFORE ANYTHING IS KILLED. A restart
that loses the settings is worse than a stuck run, because a stuck run can at
least be waited out. If the state cannot be written, the button says so and
does NOT restart.

--------------------------------------------------------------------------------
B. EVERY RUNNING MODULE IS NAMED, NOT JUST THE ONE IN FRONT
--------------------------------------------------------------------------------

"if other moduals are currently also running warn about these and tell the
user that theire settings states will also be reloaded".

The warning NAMES them -- "Mask (running 14 min), Measure (running 2 min)" --
rather than saying "other modules are running". A user deciding whether to
lose two hours of segmentation needs to know that is what they are deciding.

Their settings are saved and reloaded too, and the dialog says that plainly,
because it changes the answer: losing the RUNS is not the same as losing the
CONFIGURATION, and only the first happens.

--------------------------------------------------------------------------------
C. WHAT IS NOT PROMISED
--------------------------------------------------------------------------------

A killed run's PARTIAL OUTPUT is whatever reached disk. The dialog must not
imply the run resumes -- it does not. It says which run folders exist and that
they hold whatever was written before the restart, so a user knows where to
look rather than assuming everything is gone or everything is fine.

spaCR already has `spacr.resume` and `spacr.checkpoint`. If a module's work IS
resumable, say so for that module specifically; do not make the claim
generally.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* The stop dialog has three buttons and Force restart is last.
* Pressing it with a wedged mixed fit returns to the same module, with the
  same settings, in a fresh process.
* The state is written and verified BEFORE anything is killed; a failure to
  write cancels the restart and says why.
* Other running modules are named individually, with how long they have run.
* The dialog says the settings come back and the runs do not.

--------------------------------------------------------------------------------
2026-08-20 -- DONE, A THROUGH C.
--------------------------------------------------------------------------------

FIRST, THE PREMISE MOVED. 140 C landed the same day: `spacr.ml` now checks
`spacr.cancellation` on every objective evaluation, so most wedged mixed fits
DO answer Stop. This is what is left for the ones that do not -- a fit
somewhere the checkpoint cannot reach -- and it is offered from the module's
Stop dialog, which is the button somebody presses when a fit will not stop.

A. THE SAVE IS FIRST AND IS VERIFIED BEFORE ANYTHING IS KILLED, and that is
   the property everything else rests on. `restart_state.save` writes,
   re-reads and PARSES the file before returning its path; it returns None
   rather than raising, because the caller's next step is to tell the user and
   NOT restart, and a raise would arrive inside a dialog handler on the way
   out of an application that is already in trouble. `force_restart` returns
   False and says "Nothing was stopped".

   The launch is checked too. If the new process will not start, this one does
   not leave -- and the state is left ON DISK deliberately, because the user
   will start spaCR themselves and should land back where they were.

   THE RUNNING INTERPRETER, not `spacr` off the PATH: a user in a conda
   environment, a checkout or a bundled build has a PATH entry that may point
   at a different installation, and coming back as a different spaCR is worse
   than not coming back.

   TAKEN, NOT READ. `take()` deletes the state as it returns it, so a crash on
   the way back up cannot leave spaCR reopening the same wedged module on
   every launch afterwards -- which would turn one bad afternoon into a
   permanently broken installation. A state older than a day is dropped for
   the same reason.

B. EVERY RUNNING MODULE IS NAMED with how long it has run -- "Mask (running
   14 min), Measure (running 2 min)" -- and the dialog says the three losses
   separately, because they are three different things a user weighs: which
   runs stop, that the SETTINGS come back, and where the partial output is.

C. THE RUNS DO NOT COME BACK and the dialog says so. The reopened module is
   NOT restarted: starting a run unasked is the opposite of what somebody who
   has just force-restarted wants. The run folders that hold whatever reached
   disk are named.

A MODULE NAMED ON THE COMMAND LINE WINS over a saved state. spaCR ignoring
what it was just told would be a worse surprise than not resuming.

FOUND ON THE WAY: `AppScreen._apply_value` is a SECOND settings writer beside
the settings model's, and it did not know about 181's auto-or-number box --
`float("auto")` raised into an `except` that left `alpha` showing 1, the one
value a penalised fit cannot use. Both writers share the spelling now.
