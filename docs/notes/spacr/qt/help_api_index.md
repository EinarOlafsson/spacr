# Notes from `spacr/qt/help_api_index.py`

`spacr/qt/help_api_index.py` is GENERATED by
`tools/build_help_search_index.py`. Do not edit it; rerun the tool.

```
python tools/build_help_search_index.py           # rewrite it
python tools/build_help_search_index.py --check   # fail if it is stale
```

## Why it is a Python module and not a data file

`find_packages` ships a `.py` under `spacr/` with no entry in `setup.py` or
`MANIFEST.in`. A `.json` or `.txt` beside it needs both, and `MANIFEST.in`
and `setup.py` are announce-before-you-touch files under
`features/325_two_sessions_one_repo_working_protocol.temp`. A generated module
costs one import — measured at 69 ms for 1.3 MB, and it happens on the index
worker, not the GUI thread.

## What is in it

| name | rows | built from |
|---|---|---|
| `API_ENTRIES` | 10,326 | `docs/source/_static/i18n/api/en.json` |
| `SETTING_CONSUMERS` | 806 | `docs/setting_consumers.json` |
| `PREFERENCE_ENTRIES` | 121 | the real Preferences dialog |

`API_ENTRIES` is every PUBLIC symbol of the manifest the published API pages
are built from — 10,326 of its 10,539, the difference being symbols with an
underscored component, which AutoAPI publishes no page for. Offering one would
be offering a link to nothing.

The summary is the first paragraph of the English docstring, squeezed onto one
line and cut at 140 characters. It is what makes a symbol findable by what it
DOES; the full docstring is read from the source at the moment a result is
opened, so nothing here has to carry it.

`SETTING_CONSUMERS` is the every-consumer list. `setting_api_targets.py`
already names ONE consumer per setting — the one a settings row links to —
and the search field promises the entry of EACH function that takes a
setting. Closures are dropped: Sphinx cannot address one.

## Regenerate it when

* the API manifest is rebuilt (`tools/build_documentation_i18n.py`), which
  happens whenever a public docstring changes — see HANDOFF §3a;
* `docs/setting_consumers.json` is rebuilt;
* a row is added to, removed from or renamed in the Preferences dialog.

The third has no other guard than this tool, so
`tests/qt/test_the_help_search_field_lands_where_it_says.py` checks every
indexed preference against the dialog that is actually built — a renamed
preference turns that test red rather than turning a search result into a
lie.
