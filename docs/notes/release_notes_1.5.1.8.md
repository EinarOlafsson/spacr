## spaCR 1.5.1.8

This release writes raw crops and records how every classifier's inputs were prepared, fixes a set of measurement problems (infinite distance columns, NaN texture values, clipped flat-field correction, dropped fields and files), adds one image-level table and a GPU memory governor, and brings several new alpha features: a per-cell export, label images from other tools, size filters that follow the image scale, and fixed crop scaling.

### Upgrading

Upgrade an existing Python environment with:

```bash
python -m pip install --upgrade "spacr==1.5.1.8"
```

Desktop installers are listed under **Assets** below.

- **Measure now writes raw crops.** Crop PNGs keep the intensities and bit depth of your images, usually 16-bit. Only the pixels outside the object are set to 0. Earlier versions stretched every crop to its own brightest and darkest pixels, which hid intensity differences between cells. The new setting `crop_intensity` controls this. `'auto'`, the default, writes raw crops unless `normalize` is set to a percentile pair such as `[1, 99]`. `'stretch'` writes the old stretched crops. Inside spaCR nothing looks different: Annotate, the montages, Classify and models you have already trained show raw crops with the old stretch, pixel for pixel. Only other programs see the raw values.
- **Viewing raw crops in Fiji.** A raw crop opened in Fiji (ImageJ) can look black, because its values use only a small part of the 16-bit range. Choose Image > Adjust > Brightness/Contrast and press Auto, or use Process > Enhance Contrast for display only. These change the view, not the file. To compare cells, set the same display range for every crop with Set in the Brightness/Contrast window, and do not apply it to the pixels.
- **Crops are flat-field corrected when illumination correction is on.** With `illumination_correction` enabled, Measure now cuts crops from the corrected field, so the crops match the measured intensities. Your raw images on disk are not changed. Crop folders record which illumination model was used.
- **Classifier checkpoints record their input transform.** Every new model stores how its crops were prepared: crop size, resize, channels, mean and standard deviation, mask mode and, where used, the crop scales and flat-field model. Testing a model refuses to run when the crops would be prepared differently. The message lists the differences. Set `preprocessing_mismatch` to `'warn'` to continue anyway. Models saved before this release load and run as before, with a warning that they carry no full record.
- **Texture and corrected intensities can change.** Small objects now get a texture value instead of NaN (item 792), and flat-field corrected intensities are no longer clipped or rounded (item 793). See Bug fixes below.

### Bug fixes

- Make Masks no longer stops when a shared GPU fills up. A batch that does not fit is shrunk, retried or run on the CPU, and with enough free memory the results are exactly as before (803 follow-up).
- OPS gene P values are calibrated (alpha OPS phenotype path). The old test compared each gene with randomly drawn non-targeting cells, but the cells of one guide share wells, fields and clonal patches, so guide medians vary much more than that. Its P values were far too small: on plate A of Funk et al. 2022 it called 4,053 of 5,049 genes hits, and 83 of 250 non-targeting guides tested as genes were hits too. The new default, `ops_pvalue_null='calibrated'`, adds the spread that non-targeting guides really show. Non-targeting guides tested as genes now come out at P < 0.05 in 3.2 to 6.0 percent of cases (5 percent is the target). `ops_pvalue_null='cell_bootstrap'` keeps the old test so older analyses can be rerun exactly. In Python, `spacr.gene_measurement_compare.bootstrap_gene_pvalues` takes `null='calibrated'` (the default, which needs the non-targeting guide table as `control_guides`) or `null='cell_bootstrap'`; a call with the old arguments now raises an error naming the two choices instead of silently returning the old numbers. The aggregate report records the centre, cell variance and between-guide variance of each tested feature (851).
- The OPS aggregate phase no longer runs out of memory on a full plate. It held the whole cell table in memory (46 GB on one Funk et al. plate); it now handles 48 feature columns at a time and a whole plate peaks at about 10 GB. The guide and gene tables are unchanged, value for value (858).
- OPS features whose control cells all have the same value are dropped with a reason instead of being kept as empty columns. On the Funk et al. plates twenty measurements were constant by construction, such as `cell_<channel>_distance_to_nucleus` (0 in 96 to 99 percent of cells, because a channel's centre of mass usually lies inside the nucleus), `euler_number` and the `*_frac_low10` fractions. The aggregate phase lists each dropped feature with its reason in `ops_feature_qc_<plate>.csv`; set `ops_feature_qc` to False to keep them (859).
- Measure no longer writes columns full of infinity for a pathogen or nucleus mask that was never made. A field with no such object gets a blank (NaN) value (799).
- XGBoost models, including multi-class ones such as the cell-cycle phase classifier, now train on computers without a GPU (794).
- Texture (homogeneity) values are always a number now. Objects narrower than the requested distance (small, mitotic or apoptotic nuclei) are measured at the widest distance that fits instead of reporting NaN. These values are not directly comparable to a large object's value at the full distance; wide objects give exactly the same values as before (792).
- Illumination correction in Measure divides by the flat field in floating point and measures that result, so bright pixels are no longer clipped at the image's bit depth. Intensities on corrected runs change slightly: there is no 0.5-count rounding, and the brightest edge pixels keep their true value, which can be above 65535. When a corrected image must stay integer (as segmentation input), it is scaled down to fit and the factor is recorded (793).
- Building documentation translations in parallel, and test runs on many cores, no longer fail when another process holds the translation-review lock. The lock now waits (SPACR_TRANSLATIONS_LOCK_TIMEOUT, default 900 s) (841).
- Zernike shape moments that are only floating-point noise (about 1e-15) are now written as exactly 0, so they no longer dominate control-scaled profiles (806).
- Plates whose names contain URL escapes such as %5F (for example PerkinElmer CellCarrier-384 exports) no longer lose all their rows in the merge, so analyze_endodyogeny finds cell_area on them (805).
- In Time mode, scrolling the wheel over another cell's object while a cell is selected now swaps the two cells' identities from that frame on, as one undoable step, instead of refusing (763).
- OpenPhenom loads under torch 2.12 and later. Its weights file is read by its real format (a torch zip archive, through the safe weights-only path) instead of by its .safetensors extension (775).
- Training a classifier no longer builds up memory. The six accuracy, loss and threshold plots saved after every epoch are closed once written (786).
- Measure with GPU acceleration gives the same skew and kurtosis as the CPU path (within 1e-9). On float32 images the CPU values are now computed at full precision and may shift slightly (788).
- Crops cut from merged fields now match the measured objects. When Measure merges cells that share a nucleus, drops objects outside the size limits or applies the uninfected rule, it saves the changed masks next to the field (merged/.spacr_measured_masks) and every spaCR crop uses them. The merged files are unchanged, so a rerun with different limits starts from the original segmentation. With only cell and nucleus masks, PNG crops now use the merged cells that were measured (774).
- Make Masks: with 3D on, object detection stops and asks you to turn off the enhancement-chain steps instead of quietly running without them; they work on 2D fields only (706).
- Raw images with upper-case or mixed-case extensions (.TIF, .Tif, .TIFF, the Cellomics default) are found and stacked. Before, they were counted and then dropped, and the run ended with "No image stacks were produced" (827).
- Plates whose file naming has no time group (ArrayScan, Cellomics) are written as plate_well_field.npy instead of plate_well_field_None.npy (existing _None files still measure), and Measure stops before the first field and names any merged .npy whose name it cannot read (837).
- measure_crop fills in its own default settings, so a minimal settings dictionary no longer raises KeyError: 'timelapse' (838).
- Measure no longer drops a field because one nucleus lies in two cells. A nucleus still spanning several cells after the usual merge goes to the cell it overlaps most, the cell and nucleus tables gain a nucleus_shared column, and the console and run log report how many nuclei were shared. An unreadable field name is reported once per field, with a hint for names ending in _None (840).
- Make Masks: a folder with a curate_status.csv opened from the folder dialog opens as its curation queue, so Skip and Save record skip and done there too (835).
- An existing install's settings file no longer carries the leftover session/last and prefs/restore_last_session entries from the removed restore-last-session feature. They are deleted automatically the first time spaCR reads the theme.
- The app no longer clears memory while you are pressing a mouse button, a dialog is open or a style change is in progress. This prevents a crash when dragging a splitter right after closing a panel. Settings panels, the AI usage check, test-data downloads and Home layout updates no longer leave leftover objects in memory.
- Parametric bar-panel statistics (one-way and Welch ANOVA, Tukey HSD, Games-Howell) no longer need the optional pingouin package. They run on scipy and give identical results.
- Feature QC and field-density reads close their database connections, so later copies of the database include every change.
- New database connections wait up to 30 s for a busy database instead of failing after 5 s.
- An SSH config with an unknown internal include marker no longer drops out of the current host block.
- spaCR checkouts no longer show the bundled plaque model as modified: a stray Git LFS rule for it was removed.

### New features

- Every image-level result lives in one table, `image`, in measurements.db: one row per imaged field, keyed by file name and plate/row/column/field. Measure records each channel's background (median and 25th percentile outside every object mask), mean, 1st/99th percentiles, saturated fraction and focus, plus each mask's object count and area fraction. The same row carries intensity rescaling, confluency, the mask stage's object counts and the image-quality screening verdicts. The older confluency, intensity_rescale and object_counts tables and the qc/ reports are still written (814).
- `model_type='custom'` builds spaCR's small CustomCellClassifier, trained from scratch, for any number of channels. Its outputs are now plain logits (772).
- Classify shows `input_statistics`. `'auto'` uses a pretrained backbone's own mean and standard deviation, and dataset-level statistics for a model trained from scratch (772).
- Test reports list `majority_class_accuracy`, the accuracy of always predicting the largest class, as a control (772).
- The stored per-plate illumination model can correct a crop on its own: IlluminationField.correct_window(window, channels, y0, x0) applies the gains for the crop's position in the field (773).
- ML scoring: list three or more classes in ml_classes (for example recruitment, no recruitment, artefact). Results get one probability column per class, and the report gives per-class precision and recall plus a confusion matrix. Two-class runs are unchanged (832).
- The Recruitment and Replication forms show every setting, in new Quality Filters, Panels & Figures and Report & QC (Panel QC for replication) sections, with table editors for panels, background filters and figures, and checked fields with examples for the dictionary settings (825).
- Pressing Run also writes a notebook to <project>/settings/<module>_run_<time>.ipynb that repeats the run with exactly the same settings and entry point (826).
- Cross-validation can hold out one value of any plate-map column per fold, for example leave-one-compound-out (cv_group_column, with the plate map in well_metadata_path) (781).
- Cross-validation can train each fold without the plates or batches of its held-out crops (cv_exclude_batch_column). With a compound grouping this is the NSCB rule (782).
- Predictions are summarised per well and, with prediction_treatment_column, per treatment (mean class probabilities, counts, predicted class). Cross-validation also reports per-treatment accuracy (784).
- Annotate can review touching objects two at a time (Setup -> Review touching pairs...): label A is outlined white and label B yellow, and keys 1/2/3 record merge, keep apart or cannot tell (833).
- Annotate count columns: with "Annotation column holds counts" on, + and - step a crop's count, # types any number, and counts of 10 and more are stored as entered (834).
- spacr.embeddings.embed_store turns a measurements database or crop array into per-cell embeddings plus per-well mean and median tables, with one fixed scale per channel. On the Embeddings screen it is the alpha "Embed and export..." action (778).
- Embeddings can be combined into one profile per treatment (cells into wells, wells into treatments, by mean or median), normalised to DMSO or another control per plate (centring, z-score, robust z-score or TVN sphering), and scored for mechanism of action by one-nearest-neighbour cosine matching under NSC and NSCB, with a 95% confidence interval and shuffled-label and majority-class control rows (spacr.embeddings.aggregate_profiles, evaluate_moa) (779).
- **Alpha:** Per-cell export. Measure can write one table with one row per cell, joining cell, cytoplasm and nucleus measurements (per_cell.parquet / per_cell.csv). It counts each cell's nuclei (Metadata_n_nuclei), leaves nucleus columns empty for cells without one, and runs Feature QC on the result. Also available as spacr.sp_stats.per_cell_table / export_per_cell (769).
- **Alpha:** Label image import. Measure can measure label images made by CellProfiler, Cellpose or ilastik: point it at the raw images and the label folders, and spaCR builds its own merged stacks first (label_import settings) (790).
- **Alpha:** Size filters that follow the image scale. With pixel_size_um set (or magnification passed), Measure's cell, nucleus and pathogen minimum sizes scale with it instead of the fixed 8000/2000/500 px meant for 40-60x. A field that loses more than half its objects to a size filter prints a warning (800).
- **Alpha:** `crop_scaling='fixed'` trains on raw crops. Each plate and channel is divided by one fixed scale taken from the training crops, then clipped, resized and normalised on the GPU. Augmentation uses flips, rotations, small shifts and a small per-channel gain. It needs raw crops (772).
- **Alpha:** `control_shuffled_labels` trains a shuffled-label control model (772).
- **Alpha:** New OPS phenotype settings. `ops_genotype_table` joins guide calls from another table, such as a later decode rule; `ops_pool_wells` pools only some wells; `ops_pool_interphase` summarises guides and genes from interphase cells only; `ops_test_features` chooses the features each gene is tested on. Runs that pool a subset of wells or only interphase cells write their tables with a `_wells-…` or `_interphase` suffix, so they do not replace the full tables. With these settings spaCR reproduces the plate A pilot analysis of Funk et al. 2022: guide and gene medians agree to within float32 rounding, and the hit set and the 20 dropped features are the same (851, 858, 859).
- **Alpha:** OPS core ownership (`ops_ownership`). Neighbouring phenotype fields overlap, so many cells are imaged twice, and the merge kept the copy whose sequencing match was closer, often the one cut by the field's edge. `'a1b'` keeps, for each sequencing nucleus, the copy from the field in which it lies deepest (on plate A of Funk et al. 2022 a different copy for 14.4 percent of linked cells); a cell without a sequencing match is owned by the field in which its own nucleus lies deepest (`'a1'` uses that rule for every cell). Each cell gets ownership flags in `ops_ownership_<well>.parquet`, and the aggregate phase pools owned cells only and leaves out cells touching their field's edge, which the new `ph_masks` phase finds from the saved masks. The default stays `'closer_match'`, so earlier analyses rerun unchanged (852).
- **Alpha:** OPS flat-field correction (`ops_flatfield`). The corners of a 20X field get about half the light of its centre. The new `ph_flatfield` phase builds one map per plate and channel from a few hundred random fields, records each map's md5 and fields, and never overwrites a map. `'analytic'` corrects the features already measured from each cell's mean gain under its mask, in about a minute per plate: on 24 plate A fields the median error of mean-type features against the exact correction fell from 6.9 to 0.1 percent; the 12 mode features cannot be corrected this way and are flagged in the report. `'exact'` divides every pixel before measuring and needs the raw images again. The default stays `'none'` (853).
- **Alpha:** Funk et al.'s features (`ops_ph_funk_features`): the mass displacement of every channel, the correlation of every channel pair in the nucleus and the cell, and the form factor of both, as Funk et al.'s own OpticalPooledScreens code defines them. On a plate A field spaCR's values agree with that code to within 1e-10 (857).
- **Alpha:** OPS drops fields that did not register (`ops_drop_failed_fields`). The merge phase compares each phenotype field's link rate with the rate an unrelated field would reach by chance (the density of sequencing nuclei under the field times the area of the merge circle). A field whose alignment re-solve failed and which links under three times chance, or any field that links under twice chance, is left out of the aggregate. `dropped_fields_<plate>.csv` lists each dropped field and why. On plate A of Funk et al. 2022 it drops field 589 of well B1 and no other. Off by default (860).
- **Alpha:** OPS drops cells with broken features (`ops_drop_nonfinite_rows`). The aggregate phase leaves out every cell with more than 1% of its features missing or infinite, as Brieflow does, and its report says how many rows that was (`dropped_nonfinite_rows`). Off by default (861).
- **Alpha:** OPS can measure Zernike shape moments (`ops_ph_zernike`). It adds degree-8 Zernike moments (`zernike_0` to `zernike_24`) of the cell and the nucleus to every phenotype cell, the same values Measure computes with mahotas. `measure_phenotype_field` takes a matching `zernike` argument. Off by default (862).
- **Alpha:** A new Make Masks setting, `mask_workers_per_gpu`, lets two or more workers share one GPU so a single-GPU computer stays busy. Each plate's GPU use is printed and saved to gpu_utilisation.json (801).
- **Alpha:** With `illumination_for_later_masks` on, a preprocess-only run applies the segmentation flat-field correction to the mask inputs, so a later masks-only run gives the same masks as one combined run (802).
- **Alpha:** A GPU memory governor for shared cards. Make Masks, GPU measurement, OPS phenotype and sequencing, and classifier training and inference check free GPU memory before each batch, shrink or wait when a batch would not fit, retry an out-of-memory batch at half size, and run an item on the CPU if even one does not fit; nothing is dropped and the run does not stop. New alpha settings gpu_memory_fraction, gpu_memory_margin_gb (1.5) and gpu_adaptive_batch (on). spaCR jobs on one machine share a GPU ledger, and the run log reports how often batches adapted. Memory caps and batch sizes are sized from what PyTorch reserves (with at least 1.5x headroom), a gpu_memory_fraction set too low is raised with a message, about 0.4 GB of CUDA context is counted per process, and PyTorch's expandable-segments allocator is turned on when you have not set PYTORCH_CUDA_ALLOC_CONF. A live [gpu] progress line appears while a GPU step adapts, a warning follows above 3% CPU fallback, GPU measurement rows record their compute_path, and gpu_fallback_policy = pause waits for GPU memory instead of using the CPU (803).
- **Alpha:** spaCR can show what tracked cells do in the frames before they divide (Timelapse > Division analysis). Each division is lined up on its last frame and compared with similar-sized cells from the same movie that are not about to divide, with a shuffled-alignment check that should show nothing. Tables, a summary and three figures go to tracks/division and open in a Division analysis panel under Track preview (771).
- **Alpha:** Division analysis results in minutes and micrometres. When the frame interval (frame_interval_s, or a time_s column in the tracks table) and pixel_size_um are known, the tables gain minute, µm and µm² columns next to the frame and pixel ones, and the figures are labelled in minutes and µm. A movie without them stays in frames and pixels, and summary.json and the figure axes say so; spaCR never guesses either value. Also available as spacr.division_analysis.calibrate_divisions (864).
- **Alpha:** Division effect sizes with intervals that resample movies. Cells from one movie are not independent, so when a run has several tracked fields, spaCR pools them into tracks/division/pooled_... and gives each Hedges' g a 95% interval that resamples whole movies (from 5 movies on; with fewer it shows it beside the usual cell interval). A single movie says the movie interval is not available. Also available as spacr.division_analysis.movie_effect_size and pool_division_movies (867).
- **Alpha:** Size control for budding yeast. A budding movie's division analysis now finds when each bud separates from its mother (the last frame the two touch in the masks, or, when the masks never show it, the point where the bud stops growing fast) and fits sizer, adder and timer slopes for that model: birth is a cell's size at separation, division is mother plus bud at the next separation. Mothers and daughters (a former bud's first cycle) are fitted separately, for area and for a sphere-equivalent volume. A bud whose separation cannot be seen is listed as not fitted with the reason; no time is made up. The buds go to buds.csv and the size-control figure is labelled as the budding model. Also available as spacr.division_analysis.add_budding_cycles, bud_contacts, budding_cytokinesis and budding_cycles (865).
- **Alpha:** Will this cell divide soon? With timelapse_division_prediction on, spaCR trains a classifier on each cell's shape, size, intensity and motion to say whether it will divide within the next N frames (timelapse_division_prediction_frames, default 5). Each tracked cell counts once (one frame per track, drawn with a fixed seed), and the model is always tested on fields it never saw, beside three controls: the same model on cell age alone, a model trained on shuffled labels, and always guessing the commoner answer. AUROC and AUPRC come with 95% intervals that resample fields (from 5 fields on; with fewer the summary says the intervals are too narrow). It runs once at the end of the timelapse run, and its results, per-fold scores, feature importances and every held-out prediction go to tracks/division/prediction_.... Needs 3 or more tracked fields. Also available as spacr.division_prediction (866).
- **Alpha:** **TVN profiles (`ops_profile_normalisation='tvn'`).** Typical variation normalisation, as Brieflow makes it, is now part of the aggregate phase. Each well is centred and scaled, a PCA keeps 99 percent of the variance, the non-targeting cells are whitened so they have the same spread in every direction, and CORAL aligns the wells. The aggregate phase writes `ops_guides_<plate>_tvn` and `ops_genes_<plate>_tvn` next to the robust z tables, which the per-gene test still uses. In Python the functions are in `spacr.ops_tvn`. (854)
  - `ops_tvn_mode='streamed'` (the default) reads one well at a time, so a whole plate or a pool of plates fits in memory. `'in_memory'` holds every cell at once, as Brieflow does. The two differ only in which cells the PCA is fitted on.
  - `ops_tvn_pca_sample` and `ops_tvn_seed` set the PCA fit sample. **This choice matters more than it looks.** The whitening gives the weakest PCA directions as much weight as the strongest, and which weak directions there are depends on the sample. On plate A of Funk et al. 2022, the streamed and in-memory fits score the same in the STRING benchmark, but their gene-to-gene similarities agree only partly (correlation about 0.8).
  - `ops_tvn_whiten_epsilon` (default 3) shrinks the weak directions instead of blowing them up. On plate A it raised the agreement between the streamed and in-memory fits from 0.81 to 0.93, while the STRING score stayed the same or rose slightly. Set it to 0 for Brieflow's TVN exactly, for example to reproduce earlier analyses. `ops_tvn_components` keeps only the leading directions; it did not help on plate A and is off by default. Fitting the PCA on ten times more cells did not make the fits agree either.
- **Alpha:** **Cluster benchmarks (`ops_cluster_benchmark`).** The aggregate phase can cluster the gene profiles the way Funk et al. and Brieflow do (PHATE, then Leiden at the resolution closest to `ops_cluster_target` clusters) and score them: the share of clusters enriched for a CORUM complex or a KEGG pathway (both the May 2025 and the current Brieflow counting), STRING precision and recall, STRING AUPRC of gene-pair similarity, and the adjusted Rand index against a published clustering (`ops_reference_clusters`). Every score comes with its controls: the same clustering on shuffled components, and k-means at the same cluster count. `ops_consensus_runs` repeats the clustering on resampled genes and guides with new seeds and resolutions, and writes every run so that co-membership probabilities can be computed (`spacr.ops_clusters.co_membership`). (855)
  - The CORUM, KEGG and STRING tables are not included; point `ops_benchmark_corum`, `ops_benchmark_kegg` and `ops_benchmark_string` at your own copies, in Brieflow's format.
  - PHATE and Leiden are optional: install them with `pip install "spacr[clustering]"`.
  - Rerun on the plate A pilot's profiles, spaCR gives the pilot's benchmark table value for value, and Funk et al.'s published clusters score 24.3 percent (CORUM) and 13.5 percent (KEGG), as Funk et al. report. Note that clustering magnifies tiny differences in the profiles: TVN profiles recomputed with other library versions give cluster counts and enrichment shares that differ by a few points, while the STRING AUPRC stays the same.
- **Alpha:** **A trained mitotic classifier (`ops_mitotic_model`).** The DNA rule that calls mitotic cells agrees only weakly with Funk et al. (per-gene mitotic index, Spearman 0.32 on plate A), and on 1,489 hand-labelled plate A cells only 55 percent of its mitotic calls are mitotic. `spacr.ops_mitotic.train_mitotic_classifier` trains a gradient-boosting classifier on DNA and tubulin features from labelled cells. It checks the classifier with cross-validation in which the cells of one well or field are never split between training and testing, next to a control with shuffled labels. `spacr.ops_mitotic.read_mitotic_labels` reads a table of labelled cells, and `sampling_weights` corrects for a label set that over-samples some cells, so the reported numbers describe the whole screen. Set `ops_mitotic_model` to the saved model and the aggregate phase uses it instead of the rule. (856)
  - On plate A, with folds by field, 93 percent of the classifier's mitotic calls are mitotic and it finds 85 percent of mitotic cells (the rule: 55 and 83 percent, weighted to the whole plate). The per-gene mitotic index then agrees with Funk et al. at Spearman 0.47 instead of 0.32.
  - spaCR ships no labels and no trained model: the classifier needs labelled cells from your own screen.
- **Alpha:** **TVN for Measure profiles (`profiling_normalization='tvn'`).** Measure's well profiles can now be normalised the way JUMP profiles are: each plate is first scaled against its negative-control wells (as `mad_robustize`), and after feature selection the kept features are whitened on the negative-control wells of all plates, so the variation the controls share no longer dominates how similar two treatments look. It needs `profiling_negative_control`. The OPS TVN, `batch_correction='tvn'` and this option now take their whitening from one shared core; `batch_correction`'s `tvn_epsilon` keeps pycytominer's 1e-6, which is a different knob from the OPS `ops_tvn_whiten_epsilon` (default 3). On JUMP Target-2 (4 plates) the mean phenotypic activity mAP of 306 compounds rose from 0.47 to 0.52, and on 3 BBBC021 plates from 0.74 to 0.80. With few control wells only the directions they span are kept (17 for 18 DMSO wells on BBBC021), so name enough negative controls. (863)
- **Alpha:** **Fetch a public dataset and check that every file arrived (`spacr.public_datasets`).** Downloads a BioImage Archive accession (such as S-BIAD394), an IDR study or a BBBC set into a folder, several files at a time. An interrupted download picks up where it stopped instead of starting again. Before and after, every file on disk is compared with the archive's own file list: files that are missing, empty, shorter or longer than the archive says, with the wrong checksum, half-written (left-over lftp or Aspera files) or broken ZIPs are listed in a table, so a bad mirror is found before an analysis starts rather than hours into it. Running it again fetches only the files that are still missing or bad. Use `python -m spacr.public_datasets --archive bia --accession S-BIAD394 --dst <folder>` or `spacr.public_datasets.fetch_dataset`; add `--check-only` to audit a mirror made with another tool. (750)
- **Alpha:** **Compare a screen with a published per-gene table (`spacr.published_reference`).** Puts spaCR's per-guide or per-gene table side by side with a published one, such as Funk et al. 2022's `vesuvius_genes.xlsx`, and says how well they agree. Guides are matched on their first 11 bases (what an optical pooled screen reads), genes on their symbol whatever its case, or on an alias when the published table lists them. A published table with one column per guide is read as one row per guide, and a guide listed under two genes counts once. Spearman and Pearson correlations come with 95% bootstrap intervals and a control row: the same correlation after the gene labels are shuffled, which shows what chance alone gives. The joined table, the agreement table, a glossary of its columns and a scatter plot are written to one folder. On plate A of Funk et al. 2022 the guide cell counts agree at Spearman 0.92 (shuffled control 0.00). Use `python -m spacr.published_reference --screen <guides table> --reference <published table> --dst <folder>` or `spacr.published_reference.compare_to_reference`. (751)
- **Alpha:** **Score profiles by mechanism of action, leaving one compound out (`spacr.moa_benchmark`).** Tells you how well a set of profiles groups compounds by how they work, scored the way the published BBBC021 benchmark (Ljosa et al. 2013) scores it, so a spaCR result can be compared with the published numbers. A held-out compound is never matched to, or trained on, the same compound at another dose. Three ways of scoring sit side by side: the nearest other treatment's mechanism, a logistic regression and XGBoost (on the CPU). Each is scored with any compound held out (NSC) and, when you name a batch column, also with treatments from the same imaging batch held out (NSCB), which removes the batch effects that flatter the first score. Every table has two control rows: the same scoring with the mechanism labels shuffled between compounds (what chance gives) and always guessing the commonest mechanism, plus a glossary of every column. On the BBBC021 CellProfiler profiles it gives exactly the reanalysis's numbers (81.6% NSC, 60.8% NSCB; shuffled control 6.6%). Use `python -m spacr.moa_benchmark --profiles <wells table> --labels <MoA table> --batch-column <batch> --dst <folder>` or `spacr.moa_benchmark.moa_benchmark`. (795)

### Other

- Profile export drops features that are broken without looking at any labels (non-finite in more than 5% of wells, larger than 500 after control normalisation, or near-constant) and writes feature_qc_dropped.csv with the reason for each. The thresholds are the new settings profiling_na_cutoff, profiling_outlier_cutoff and profiling_min_variance (807).
- The default classifier in Classify (ML) and ml_analysis is now standardised, L2-penalised logistic regression, and shrinkage LDA is a new choice. The old unscaled logistic regression is gone (its name now means the standardised pipeline); xgboost and the other models stay selectable (808).
- Make Masks: set Pixel size (µm/px), and blank cell, nucleus and pathogen diameters use real object sizes instead of the magnification formula, which made A549 cells about twice too large at 20x. Typed diameters are unchanged. The new option Estimate diameters per image measures a blank or auto diameter on each 2-D image and segments at that size (about twice as slow) (831).
- Make Masks: painting and editing on large fields is faster, because the check that remembers hand-set object IDs reads half as much data per stroke. Fields saved earlier keep their hand-set IDs when reopened (697).
- Merging touching objects (merge_pathogens=True) measures each object in its own bounding box: a 2000x2000 field with 500 objects went from about 129 s to 2.5 s with identical output (828).
- src may be a plate's merged folder as well as the plate folder. Measure uses the plate folder and says so, and the docs example shows the plate folder (839).
- Training metrics are measured during each epoch's training pass instead of a second pass over the training data, saving about one evaluation pass per epoch (the old behaviour is train_metrics_full_pass). Validation metrics are unchanged. Runs from custom loaders without a train/ folder now get class weights from the dataset's labels instead of equal weights (785).
- Embeddings: a crop folder of TIFFs is read raw, keeping 16-bit values and every channel (836).
- ChAda-ViT embeddings run each crop with its real channel count instead of ten padded slots: the same embeddings, several times faster (776).
- timm embedding backbones (resnet18 and others) receive crops resized and standardised the way the network was trained (its pretrained input size, mean and standard deviation). New Overview settings override them, or switch this off with 'none'. Embeddings from these backbones change and get a new fingerprint (777).
- CPU embedding runs as several worker processes with a few threads each (4 x 2 on 32 cores by default), with CPU workers and Threads controls on the Embeddings screen (780).
- Recruitment and replication panels are drawn in the spaCR house style, register their data and are saved through the shared figure writer. Graph titles and test names are off by default and can be switched on.
- Harmony batch correction is an optional extra: pip install "spacr[harmony]".
- The minimum supported nbconvert is now 7.16.5, the first release that works with mistune 3.1 and later.
- The tutorial capture profile records the tiled Home for every lesson except the Navigator lesson, matching the new default where new users land on the Navigator.
- The tutorial recording scripts and media now live in the spacr-tutorials repository and the einarolafsson/spacr-tutorials dataset; spaCR keeps the lesson definitions its Help and docs read, and the spaCR download is smaller.
