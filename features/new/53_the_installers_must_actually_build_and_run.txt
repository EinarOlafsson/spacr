WHAT THE STATE IS
--------------------------------------------------------------------------------

The .deb / .dmg / .exe installers are built by PyInstaller plus CI on the
`packaging` branch. Two things are already known to be wrong with what they
produce, and both were found from the outside rather than by a build:

  * instruction 01 — every desktop install at or below 1.5.0.1 cannot
    update itself, because the installers build the environment with
    `uv venv`, which does not seed pip, and the updater shells out to
    `sys.executable -m pip`. The fix can only reach users THROUGH an
    update, so the first build that carries it matters more than usual.
  * instructions 44 and 45 add screens to the installer that have never
    been built or clicked.

Nobody in this session has produced an installer artefact and run it.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

The installer is how every non-developer gets spaCR, so a broken one is
indistinguishable from broken software. It is also the least-tested surface
in the project: the unit suite never touches it, and CI proves it BUILDS
without proving it RUNS.

New installer screens make this worse rather than better. A CPU/GPU choice
that is collected and then ignored, or a sign-in that captures a token the
app never reads, is a page that costs the user time and delivers nothing --
and neither failure is visible from the build log.

2026-08-14 - COMPLETE: THREE NATIVE BUILDS, THREE CLEAN INSTALLS, THREE SMALL RUNS
--------------------------------------------------------------------------------

The installer workflow was changed from a build-only check into an installed-
application acceptance test. Final GitHub Actions run 31796262489 is green:

    Ubuntu 24.04   job 94753940669   spaCR-1.5.0.4-Linux-x86_64-Online.run
    Windows 2025   job 94753940682   spaCR-1.5.0.4-Windows-Online-Setup.exe
    macOS 15       job 94753940811   spaCR-1.5.0.4-macOS-Universal-Online.pkg

Each job builds the native artifact, installs it through the real shell,
NSIS, or macOS package path into a clean private CPython 3.12 environment,
and uploads the artifact. The CI-only package override points that online
installer at the checked-out spaCR source; public artifacts retain the normal
versioned PyPI package specification.

THE INSTALLED TEST is deliberately larger than `import spacr`. It verifies the
application icon/launcher and installation log, imports spaCR + PySide6 +
torch from the private interpreter, constructs and destroys `AppScreen` for
Measure, constructs the fresh-install consent page and checks its defaults and
warning, generates one synthetic field, runs Measure, then queries the
installed run database for `complete`, one success, zero failures, and at least
one cell. The Windows-only open-SQLite cleanup defect found by that run is now
covered by a handle-release regression test.

BACKENDS are verified from the installed environment. Linux and Windows use
CPU-only torch in the clean matrix; macOS 15 selects and exercises MPS. A
separate fresh default install on the project's RTX 3090 selected CUDA,
reported torch 2.13.0+cu132 and `torch.cuda.is_available() == True`, then passed
the same Qt/measurement smoke. Instruction 44 carries its complete profile.

THE UPDATER is exercised at the bootstrap trap's exact boundary. The native
venvs are made by `uv venv` and contain no seeded pip. From each installed
build, `spacr.updater.upgrade_command()` resolves to the private
`bootstrap/uv` (or `uv.exe`) plus `pip install --upgrade --python
<installed-python> spacr`, never `<python> -m pip`. This is instruction 01's
acceptance command run inside the installed builds, and it proves the upgrade
route no longer depends on the missing pip module. The workflow does not
replace the tested checkout with an older PyPI wheel merely to exercise a
network download; it verifies the actual command/tool/environment boundary
that caused the reported failure.

THE NEW SCREENS are not theatre. Backend choice changes uv's real
`--torch-backend`; the profile records requested, detected, and active values.
Consent choices reach the existing runtime preferences. Account setup invokes
the official gh/Claude/Codex/Gemini login flows at first launch; spaCR does not
capture a credential it cannot safely own. Report sending remains behind its
editable Send action, and network tests use mocked transports rather than
creating a permanent public fixture issue.

Failures found and fixed by the native loop included missing Linux Qt system
libraries, the correct Apple-MPS expectation, PowerShell UTF-8 BOM parsing,
an NSIS section forward reference, a localized uninstall section that erased
the new Windows install, swallowed silent-installer failures, Windows
`uv.exe` discovery, SQLite handle lifetime on Windows, and `SpaCR`/`spaCR`
artifact-case drift. The final run uploaded all three correctly named files;
manual verification is read-only, while the release workflow alone may commit
collected artifacts and README links.

Local/focused evidence around the final build: 236 consent/updater/installer
tests passed together; the installed smoke and static native contracts then
passed 65 tests. The final native jobs all passed from build through upload.

2026-08-26 - RE-AUDIT: THE FROZEN BUNDLES LAUNCHED A FRONT END THAT NO LONGER
             EXISTS
--------------------------------------------------------------------------------

The native matrix above is real and the run is still green (31796262489,
three platform jobs, all success). What it does not cover is the OTHER
installer family this file names in its first paragraph: the PyInstaller
bundles built by `packaging/build_windows.ps1` and `packaging/build_macos.sh`
through `packaging/spacr.spec`.

    spacr.spec        ENTRY = packaging/spacr_launcher.py
    spacr_launcher.py from spacr.gui import gui_app   <-- deleted with Tk

`spacr/gui.py` went with the Tk interface. The launcher's own `except`
turned that into `print("failed to import spacr: ...")` and `return 2`, so a
bundle built from this spec started, wrote a line to a console a
double-clicked app does not have, and exited without a window. Nothing
imported the file -- no console script points at it and no test touched it --
which is how it stayed wrong through the whole Tk removal.

FIXED. The launcher now calls `spacr.qt.run()`, the same function the `spacr`
console script uses, so a frozen bundle and a pip install open the same
window. The spec's Tk-era leftovers went with it: the tkagg matplotlib
backend is now qtagg, `PIL._tkinter_finder` and the `collect_data_files
("tkinter")` block are gone, and PySide6's three core modules are named as
hidden imports.

tests/test_packaging_launcher.py is new -- 4 tests, and two of them failed
against the old launcher before the change (the stubbed `spacr.qt.run` was
never reached, and the source still named `spacr.gui`). It is the only test
that covers the frozen entry point at all.

NOT DONE, and it is the same gap this file has always had: no PyInstaller
bundle was built or launched here. The fix is verified by import and by test,
not by a .app or a .exe. A build machine is what closes that.

AND THE SPEC IS NOT IN THE REPOSITORY. `.gitignore:33` is a bare `*.spec`,
written for PyInstaller's generated specs, and it swallows the hand-written
`packaging/spacr.spec` that `build_windows.ps1` and `build_macos.sh` both
invoke by name. `git check-ignore -v packaging/spacr.spec` names the rule.
So a fresh clone cannot build either bundle, and the Tk-era hidden imports
corrected above live only in this working tree.

    hiddenimports   matplotlib.backends.backend_tkagg -> _qtagg,
                    PIL._tkinter_finder dropped, PySide6.QtCore/QtGui/
                    QtWidgets added
    datas           the collect_data_files("tkinter") block dropped

NEEDS A DECISION, NOT A PATCH: narrowing the ignore rule (to `/*.spec`, or
to the build directory) and committing the spec changes what the repository
ships, so it is the coordinator's call rather than an audit's.
