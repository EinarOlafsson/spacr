--------------------------------------------------------------------------------
HOW TO WORK ONE, from what instruction 81 learned the hard way
--------------------------------------------------------------------------------

* READ THE PROSE, NOT JUST THE TRACEBACK. On auto-filed issues the title names
  the CRASH while the body often reports a DIFFERENT problem the user hit
  first. #108 was the first one checked and did exactly this.
* PATHS ARE REDACTED to `<PATH>` / `<DB>`, so the SHAPE of a path is still
  evidence -- `~<DB>` is a tilde that was never expanded.
* REPLY ON THE ISSUE saying what was done and in which commit, and close it as
  the maintainer. An issue that is a duplicate, a question, or a decision for
  the maintainer gets SAID SO on the issue rather than left open in silence.
* An auto-filed issue carries the pipeline settings and a traceback
  fingerprint, so most are reproducible without asking the reporter. #115 was
  not one of those, which is why its exact read-only failure had to be
  reconstructed before it could be fixed.
