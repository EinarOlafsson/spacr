WHAT TO DO
--------------------------------------------------------------------------------

1. Defaults and background
   - Set the spaCR flow default animation density to 25%.
   - Set the spaCR theme background to RGB (25, 25, 25), or #191919.
   - Leave the unspecified mouse-gravity default pending clarification.
   - Change defaults without overwriting existing saved user choices. Preserve
     page opacity and the distinction between main and settings backdrops.

2. Cross-platform window placement
   - Allow the spaCR window to snap right, left, down and up, and enter/leave
     full screen on Windows, Linux and macOS. Top snapping and full screen
     must both be available; do not satisfy both solely with one top action.
   - Extend N666's existing frameless-window implementation where appropriate.
     Respect each platform's compositor/window-manager behavior, monitor work
     areas, display scaling and restore geometry. Keep ordinary resizing usable.

3. Ripple settings and event handling
   - Provide a Field ripple slider; zero means off. Keep ripple control
     independent of mouse gravity and animation density. Reuse or migrate the
     existing ripple-intensity preference instead of adding competing controls.
   - Add a separate boolean preference for mouse-click ripples. Its default
     was not specified by the user; record any implementation choice explicitly.
   - When enabled and ripple intensity is nonzero, a click produces a ripple
     at the click position. A click that also triggers another ripple, such
     as closing a container, produces the container ripple only. Suppress the
     redundant click ripple for that interaction, not unrelated later clicks.
   - Preserve existing container geometry, opening/closing and edge ripples,
     including user-requested popup-origin behavior and saved settings.

4. Animation performance audit and GPU implementations
   - Audit every available animation, especially spaCR flow. Record exact
     source, hardware, display resolution/scaling, density, detail, palette,
     frame-time distribution, CPU use, GPU use and memory for CPU and GPU paths.
   - Implement a GPU-accelerated rendering path for each animation, retaining
     a usable CPU path. Build on N679 where suitable; do not assume its partial
     flow prototype covers all themes or demonstrates a speedup.
   - Request GPU acceleration by default on supported hardware. Provide the
     requested slider with an explicit off/CPU position. Define remaining
     slider semantics clearly; retain safe CPU fallback when the graphics
     context/backend is unsupported or initialization fails.
   - Measure native performance and visual/interaction agreement. Do not
     claim that enabling GPU necessarily improves every theme or resolution.

5. Dynamic animation resource policy
   - Add a boolean setting named "Dynamic animation" in Performance, on by
     default. Use translation and normal Preferences persistence/Apply/Revert.
   - When on, a CPU-heavy analysis task such as Measure pauses the animation
     entirely. A GPU analysis task such as mask generation disables decorative
     GPU acceleration and permits the CPU animation path when appropriate.
   - CPU-heavy work takes precedence when CPU and GPU tasks overlap. Track
     task start, completion, cancellation and failure, including concurrent
     jobs; one finished job must not release another job's resource guard.
   - Restore the user's selected theme/backend when blocking work finishes.
     Temporary policy overrides must not overwrite saved choices. When the
     boolean is off, disable this automatic workload policy while retaining
     hardware-capability fallback. Document how external/headless processes
     are detected and which task signals are covered.

geometry, screen under the pointer and Wayland startSystemMove kept.
Ripples: the Field ripples on/off switch became a 0-200% slider (0 = Off),
migrating a saved "off" to 0 once. New "Click ripples" switch, default ON
(user gave no default). Click ripples are committed 120 ms after release;
any container, window-edge or popup-close ripple during that click
suppresses it; drags are not clicks; later clicks are unaffected.
GPU: N679's moderngl point renderer is integrated for field, advection,
waves and Spaceout field (monochrome palettes, outside colour events).
Performance > "Animation GPU" slider: Off (CPU) / Automatic (dense 4K only,
where measured faster) / On (default). Missing moderngl, software GL,
macOS (GL 4.1 < 4.3), probe timeout or context failure fall back to CPU.
Dynamic animation (Performance, default on): run-registry jobs classify
as CPU (measure, umap, ...) or GPU (mask, cellpose, classify, ... when a GPU
exists). CPU work pauses every animation; GPU work disables decorative GPU
and pauses GPU-backed Spaceout fractals; CPU wins on overlap; state is
recomputed from all live jobs so finishing/failing/cancelled jobs release
only their own hold; nothing is written to Preferences. External/headless
processes are seen only via NVML compute processes (NVIDIA; own PID
excluded); external CPU load is not observed. Off keeps capability fallback.
Audit: tools/audit_animation_performance.py; CPU receipt for all 11
animations at 1080p/4K in data/684_animation_cpu_audit_2026-10-10
(Ryzen 9 5950X, offscreen). Aurora is the costliest (35-99 ms at 4K).
