WHAT TO BUILD
--------------------------------------------------------------------------------

0. ONE SOURCE OF TRUTH FOR THE LINKS. Before any prose: a single machine-
   readable map of every module's inputs and outputs -- what it reads (folder,
   file kind, database table/column) and what it writes -- from which the
   tutorials, the walkthroughs and the API pages are all written or checked,
   so the three "match each other" by construction and a test fails when a
   module's real inputs/outputs drift from the map. Start from what the code
   already declares (settings `src`/output folders, the tables each module
   writes to measurements.db, the preview registry, the Home registry's
   groups). The chain the maintainer names must come out of it verbatim:

     Mask generation -> masks + merged arrays
       -> Measure (reads the masks and images) -> measurements.db + crops
       -> Classify, machine learning (reads measurements.db)
       -> Classify, computer vision (reads the crops, or streams them from the
          masks)
       -> Annotate (labels crops in png_list) -> the classifiers' training data
     Map Barcodes (sequencing) -> per-well guide/gene counts
     Classify outputs + Map Barcodes outputs -> Regression -> hit list

1. TUTORIAL "spaCR screens": the pooled-screen story end to end -- what a
   spaCR screen is, and which module does each step, in order.
2. TUTORIAL "Module inputs and outputs": EVERY module, what it takes and what
   it produces, and which modules come before and after it (from part 0).
3. TUTORIAL "Image analysis modules and how they relate": Mask, Make Masks,
   Measure, Annotate, Classify, Image UMAP, Gate Editor, Align & Stitch, the
   assays (Plaque, Recruitment, Invasion, Replication), QC, Embeddings.
4. TUTORIAL "Sequencing modules and how they relate": Map Barcodes, OPS,
   Regression, Power / Design, Experiment Design, Dose-Response, Run Compare.
5. WALKTHROUGHS (the interactive ones), one per common pathway, each starting
   from the Home screen and saying which tile to press first:
     a. A spaCR screen: Mask -> Measure -> Annotate -> Classify, and
        Map Barcodes -> Regression.
     b. A high-content image analysis experiment: Mask -> Measure -> then
        Classify / Image UMAP / Gate Editor / Graph Builder / the assays.
     c. Training a segmentation model: Make Masks (curate) -> train a Cellpose
        model -> use it in Mask.
     d. OTHERS the maintainer asked us to think of -- candidates:
        - a parasite assay: Mask -> Plaque / Recruitment / Invasion /
          Replication;
        - an optical pooled screen: Align & Stitch -> OPS -> Regression;
        - importing someone else's data: Import -> Measure -> ...;
        - phenotype discovery without labels: Measure -> Embeddings /
          Image UMAP -> Gate Editor -> Annotate;
        - planning a screen before running it: Experiment Design ->
          Power / Design;
        - live-cell tracking: Mask (timelapse) -> Measure -> motility.
       Each named from the Home tiles as they read today.
6. API: each module's API page (and the Home tile's API link) states its
   inputs, its outputs, and the modules before and after it, generated from
   the part-0 map so it cannot disagree with the tutorials.
7. The three -- tutorials, walkthroughs, API -- say the same thing: a test
   (or the docs build) compares each one's stated links against the part-0
   map.

PART 5 -- THE HOME SCREEN (CLAUDE)
--------------------------------------------------------------------------------

   a. "I can click them and nothing seems to happen": reproduce a Home tile
      click on a fresh install (a module that opens slowly with no feedback,
      a single- vs double-click expectation, a tile that opens off screen or
      behind, an empty state that looks like nothing happened) and fix it so
      every tile click visibly does something at once.
   b. "Open a sample project similar to mine": a clear first-run entry on
      Home -- choose the kind of experiment (the pathways in 5a-d), get its
      example data (the existing test-data downloads) and land in its first
      module with the settings filled, with the walkthrough for that pathway
      one click away.
