CLUSTER RUNS DOWNLOAD A MISSING ZOO MODEL AUTOMATICALLY

Status:    PARTIAL — exact missing-path lookup and local-process download coalescing implemented 2026-10-14; pinned export, offline mode and remaining acceptance open.
Requested: maintainer, 2026-10-13: "when using run if the like with athe
           cluster, if a user puts in a version of a model thatisnt on the
           cluster it should be automatically downloaded. now it just fails
           with a file not found error. ... what users tend to do is make a
           settings file on their laptop computer then run spacr on the cloud
           so spacr should always look at the provided path and if it cant
           find the model and the model name is one in the spacr model zoo
           then downloade it automatically"
Owner:     Home (run / model resolution); WS (translations, tutorial capture)
Related:   spacr-run, distributed execution (N693 Export settings / Save
           settings CSV, docs/source/distributed_execution.rst),
           spacr.model_zoo (zoo keys, hf_repo_of, checksum-verified download).

--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

A settings file made on a laptop names a model by a local path (for example
~/.spacr/models/cpsam_v2_toxo_r7) or by a zoo key/version. On a cluster node
that path does not exist, and the run stops with FileNotFoundError instead of
fetching the model.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

The common workflow is: build the settings in the GUI on a laptop, export the
settings CSV, run `spacr-run <module> --settings <csv>` on a cluster or cloud
node. Every model setting then fails on the first run unless the user copies
weights by hand.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. One resolver used by every model setting at run start (Cellpose model,
   plaque/PV models, well detector, classifiers): first the given path as is;
   if it does not exist, identify the zoo entry by (a) zoo key and version,
   (b) the weights file name (e.g. cpsam_v2_toxo_r7, cpsam_plaque_r6_v4), or
   (c) a recorded sha256 in the settings, then download that exact version
   into the node's spaCR model cache with the existing checksum-verified
   download, and use it. Log one line: "<setting>: <path> not found here;
   downloaded zoo model <key> <version> (sha256 ...) to <cache path>".
2. Never substitute a different version: if the name matches no zoo entry,
   or the checksum fails, stop with a clear error naming the setting, the path
   and the zoo keys that would match, instead of FileNotFoundError.
3. Respect offline nodes: an env var / setting (e.g. SPACR_MODEL_DOWNLOAD=off)
   turns auto-download off; then the error says which file to copy where.
4. Export settings (N693) records each model setting's zoo key, version and
   sha256 next to the path, so the cluster side can resolve exactly.
5. Concurrent jobs on one node: the download is locked, so N jobs starting
   together download once.
6. Strings through tr(); docstrings into an API arrival contract (WS
   translates); a short paragraph in distributed_execution.rst.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

- Test: a settings CSV whose model path does not exist but names zoo model
  X version Y: the run downloads exactly X/Y (sha256 verified, mocked network)
  and proceeds; the log line names the setting, path, key, version and sha.
- Test: an unknown model name fails with the clear error listing candidate
  zoo keys, not FileNotFoundError.
- Test: SPACR_MODEL_DOWNLOAD=off fails with the copy-this-file message.
- Test: two processes resolving the same missing model download it once.

--------------------------------------------------------------------------------
