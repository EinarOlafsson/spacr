--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

THE MODULE IS GOOD, AND THIS FILE IS NOT A CRITICISM OF IT. It fits a
four-parameter logistic (`four_parameter_logistic(x, bottom, top,
log10_ec50, hill)`), carries the direction in the sign of the Hill slope,
offers both a Wald interval and a profile-likelihood one (`CI_WALD`,
`CI_PROFILE`), runs off the GUI thread through `JobRunner`, and -- the part
most fitters get wrong -- will say `STATUS_REFUSED` or `STATUS_UNBOUNDED`
rather than invent an EC50 the experiment does not locate. Constrained fits
and the biphasic case are already handled.

WHAT IT CANNOT SAY, verified by grep on both files 2026-09-09:

  ABSENT: selectivity index, CC50, therapeutic index
  ABSENT: Bliss, Loewe, synergy, checkerboard
  ABSENT: normalisation to plate controls (percent inhibition)
  ABSENT: pooling across replicate plates (random effects, mixed model)
  ABSENT: five-parameter / asymmetric logistic
  ABSENT: hormesis (non-monotonic response)

Each of these is a sentence a dose experiment routinely needs and this
module currently cannot produce.

PRESENT ELSEWHERE, AND THE POINT IS THAT DOSE-RESPONSE DOES NOT USE IT:
`spacr/qt/widgets/control_chart.py` already computes a per-plate Z-factor
(`zprime_frame`, when a positive and a negative control are named) and charts
it (`zprime_chart`). The Dose-Response screen neither reads it nor mentions
it. So the plate-quality number exists, on a different screen, and a user can
fit a curve on a plate the package already knows is bad.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

THE FIRST ONE IS THE IMPORTANT ONE. For an anti-parasitic compound the
number that decides whether anybody cares is not the EC50, it is the ratio
of host toxicity to parasite killing -- CC50 over EC50, the selectivity
index. A compound that kills Toxoplasma at 1 uM and the HFF monolayer at
1.2 uM is not a hit, and today spaCR will report its EC50 with a clean
confidence interval and say nothing about that.

spaCR IS UNUSUALLY WELL PLACED TO FIX THIS, which is the argument for doing
it here rather than in a spreadsheet. The module already segments host cell
and pathogen as separate object types from the same image. Host viability
and parasite burden come off ONE plate, at the SAME doses, in the same run.
Most tools computing a selectivity index are dividing two numbers from two
different experiments and hoping the conditions matched. Here they cannot
fail to match.

The rest follow from how dose plates are actually read: raw response values
are not comparable across plates until they are normalised to the controls
on each plate, replicate plates want pooling rather than three EC50s and an
eyeball, and a plate whose Z'-factor is 0.1 should not be silently fitted at
all.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

In value order. 1 and 2 are the ones worth doing; 3-5 are cheap once the
engine grows a notion of the plate.

1. SELECTIVITY INDEX. A paired fit: two response columns from the same
   `DoseResponseSpec`, one host, one pathogen, fitted independently and then
   divided, with the interval propagated rather than dropped. The ratio of
   two uncertain numbers is more uncertain than either, and a selectivity
   index quoted without its interval is the same failure this module already
   refuses to commit for EC50. If either fit is `STATUS_REFUSED` or
   `STATUS_UNBOUNDED` the index is one-sided or refused too, and says so --
   reuse the existing status vocabulary rather than inventing a second one.

2. SYNERGY, for two-compound checkerboards. Bliss independence and Loewe
   additivity over a dose grid, plus the interaction surface as a heatmap.
   New engine functions beside the 4PL; a new tab on the screen. Report the
   surface, not a single index: one number for a whole checkerboard hides
   exactly the concentration-dependent structure that makes synergy
   interesting.

3. PLATE NORMALISATION. Percent inhibition against the positive and negative
   control wells of each plate. `spacr/control_names.py` and
   `spacr/well_scope.py` already know which wells those are.

4. CONSUME THE Z'-FACTOR THAT ALREADY EXISTS -- do not rebuild it. Call
   `zprime_frame` from `spacr/qt/widgets/control_chart.py` and carry the
   result into the fit, so a plate that fails Z' reaches the fitting code
   knowing it. The engine already has the vocabulary for this: a fit on a
   failed plate should be `STATUS_REFUSED` with the Z' in its message, not a
   clean EC50 with a footnote nobody reads. Two screens computing Z' two ways
   would be worse than the gap it closes.

5. POOLED FITS ACROSS REPLICATE PLATES -- one EC50 with plate as a random
   effect, rather than three EC50s the user averages by hand.

NOT IN THIS ORDER BUT WORTH RECORDING: the five-parameter logistic (real
asymmetry exists and 4PL absorbs it into a wrong EC50) and hormesis
detection (a non-monotonic curve should be refused loudly, not fitted
monotonically). Both are engine-level and both are smaller than 1 or 2.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

THIS MODULE'S OWN STANDARD APPLIES: the useful answer is sometimes "this
experiment does not support that number", and every addition here must be
able to say it.

  * Selectivity: a plate with a known-selective compound and a known-toxic
    one. The selective compound gets an index well above 1 with an interval
    that excludes 1; the toxic one gets an index near 1, or a refusal. A
    build that hands back a clean index for the toxic compound has failed
    even if the arithmetic is right.
  * Synergy: an additive control pair must come out additive. Bliss on two
    compounds that do not interact should sit at zero across the surface;
    if it does not, the normalisation is wrong, not the biology.
  * Z' and normalisation: a deliberately bad plate must fail visibly.
  * Pooled fits: pooling three replicates of the same compound must land
    inside the three individual intervals.

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

A SINGLE SYNERGY SCORE PER COMPOUND PAIR as the headline. Rejected: it is
the number people quote and it is the number that misleads, because synergy
is usually concentration-dependent and collapsing the surface destroys the
only part worth seeing. The surface is the result; a summary may sit beside
it, never instead of it.

REPLACING THE 4PL DEFAULT WITH 5PL. Rejected: the extra parameter buys
asymmetry at the cost of stability on the short dilution series most plates
actually run. Offer it, do not default to it.

CHOU-TALALAY COMBINATION INDEX as the primary synergy method. Considered;
Bliss and Loewe are better understood, and CT's median-effect assumptions
are routinely violated by exactly the refused and unbounded curves this
module is careful about.

WHAT IT DOES. With a plate column chosen, every group's EC50 is also pooled

TWO DECISIONS, recorded so they can be reversed deliberately:

  1. POOLING NEEDS ONLY THE PLATE COLUMN, not the controls. Each plate is

THE 5PL, AND WHY log10_ec50 STILL MEANS THE EC50. `five_parameter_logistic`
is fitted in the EC50-preserving parameterisation:

    y = bottom + (top - bottom) / (1 + a*10**((L - log10 x)*h)) ** s,
    a = 2**(1/s) - 1

Written the way the 5PL usually is, the third parameter is the inflection
point and NOT the half-maximal concentration: at x = 10**c an asymmetric
curve sits 1/2**s of the way up, so a 5PL whose c is quoted as an EC50 is
wrong by a factor that grows with the asymmetry. That constant a moves the
half-maximal point back onto x = EC50 exactly. The payoff is bigger than
correctness -- every rule already in the module reads `log10_ec50` and none
of them had to learn a second meaning -- and at s = 1 the expression is the
4PL term for term, which is what makes the F test below a legitimate nested
comparison.

IT IS OFFERED AND NOT DEFAULTED TO, which is this file's own decision under
DELIBERATELY NOT DONE. `DoseResponseSpec.model` is `MODEL_4PL` unless
somebody says otherwise, the screen's new Curve picker starts there, and a
5PL fit reports an extra-sum-of-squares F test of its fifth parameter in
`asymmetry_p`. The interesting case is a LARGE p: it says the asymmetry is
inside what noise produces and the symmetric fit is the one to quote, and
the fit says so in its own caveats.

MEASURED, on a nine-point 3-fold series in triplicate built from a 5PL with
asymmetry 0.2 and a true EC50 of exactly 1.0:

    4PL  EC50 0.504, R2 0.9989, CI 0.443-0.567, nothing amiss
    5PL  EC50 0.916, asymmetry 0.250, F = 56.9 on 1 and 22 df, p = 1.6e-07

The symmetric fit does not fail on asymmetric data. It halves the answer,
confidently. That is the whole argument for having the option.

HORMESIS: BRAIN-COUSENS, AND FOUR CRITERIA RATHER THAN ONE. `hormesis`
fits `brain_cousens` -- the 4PL with a low-dose stimulation term, which IS
the 4PL when that term is zero -- and compares the two nested fits. Under
this module's Gaussian errors the extra-sum-of-squares F test on one degree
of freedom is the likelihood-ratio test written in the units already being
reported, so it is the one used; Cedergreen-Ritz-Streibig was the other
candidate and was not taken, because its extra exponent is a second weakly
identified parameter on a series that already struggles to identify one, and
Brain-Cousens nests the null exactly.

A verdict needs ALL FOUR of:

  1. a POSITIVE stimulation coefficient. A negative one makes the curve
     leave the control plateau faster than a 4PL: a shape correction, not
     stimulation. Doing the one-sided part by inspection rather than by
     halving the p value leaves the reported p conservative by about a
     factor of two, which is stated and not corrected.
  2. p < 0.05 on that F test;
  3. delta AICc >= 2, with the small-sample correction, because these are
     five- and six-parameter models on twenty-seven wells;
  4. the hump reaching 10% of the fitted response span -- THE
     MINIMUM-EFFECT THRESHOLD, and the criterion that does the most work. A
     tight assay reaches p < 0.001 on a hump worth 2% of the span, and 2% is
     a statement about the model rather than about the compound. It is
     measured against the span and not against the control, which is the
     convention in the literature, because this module normalises plates to
     percent inhibition -- where the control is 0 by construction and a
     percentage of it is meaningless.

MEASURED, on series built from `brain_cousens` with a known coefficient
(nine doses, triplicate, noise 2 on a span of 100):

    f =  40   6% of the span   p = 2e-05, dAICc +20 -> NOT hormesis: too small
    f =  80  17% of the span   hormesis, AND THE MONOTONICITY CHECK PASSES IT
    f = 200  66% of the span   hormesis, and the monotonicity check refuses it

THE MIDDLE ROW IS THE GAP NOBODY HAD NAMED. `MAX_REVERSAL` is 0.30, so a
hump worth a fifth of the response span sails through `monotonicity`, gets
fitted, and reports an EC50 of 2.1 where the underlying curve's is 1.0 --
with no warning of any kind, before today. Those fits now carry
`DoseResponseResult.hormesis` and a caveat that says the number above it is

FLAWED on one blocking ground, and it was the right call: this module's
identity is its intervals, and a model had been added without a single test
of the interval it produces.

WHAT WAS WRONG. `_profile_sse`'s 5PL branch did not attain the conditional
minimum it is defined to be. The 5PL profiles out FOUR parameters at a fixed
midpoint -- both plateaus in closed form, then slope and asymmetry -- and
those last two are strongly correlated: a flatter curve with a more extreme
exponent describes nearly the same data. The code did ONE sweep of
coordinate descent (grid, refine the slope at the best shape, refine the
shape at that slope) and stopped. Coordinate descent zig-zags across a
correlated valley; one sweep does not reach the floor.

WHY THAT MAKES AN INTERVAL TOO NARROW, WHICH IS THE WRONG DIRECTION. The
walk is allowed to spend `sse * (1 + q**2/dof)`, about 1.20 * sse at 22 df.
If the profile already reports MORE than `sse` at the point estimate, that
overshoot is subtracted from the allowance before the walk has moved.
Measured at the fitted midpoint, where the conditional minimum is by
definition the unconditional one:

      asymmetry 0.20    1.36 x sse        asymmetry 0.25    1.02 x sse
      asymmetry 0.50    1.06 x sse        worst seen        3.06 x sse

On this file's own calibration series -- the 9-point 3-fold triplicate with
asymmetry 0.20 and true EC50 1.0 -- through CI_PROFILE, which is the
default, the 95% interval covered the true EC50 in 5 of 12 draws. One draw
collapsed to a width of 0.0009 in log10, an "interval" of 0.891 to 0.892,
because the profile already sat above the threshold at the centre and the
bisection walked straight back in. An interval that excludes the truth more
often than it includes it is worse than no interval, and this one was
reached by picking the new Curve picker and pressing Fit.

THE FIX. `_profile_five_sse`: evaluate the whole 11 x 40 asymmetry-by-slope
surface for basins, then polish the best three separated cells with
Nelder-Mead in log co-ordinates, which follows the valley instead of
crossing it. Three starts rather than one because over 48 fitted series a
single descent from the best cell missed the minimum by 26% on one of them,
the grid's best cell having sat in a neighbouring basin; two attained it
everywhere measured, three is the margin. AFTER: the profile equals the
fit's own SSE to 1.00000 on all 21 series checked against an independent
reference (`curve_fit` with the midpoint fixed, multistart over slope and
asymmetry), and coverage on the calibration series is 12 of 12.

WHAT IT COSTS. About 18 ms per profile evaluation, so a 5PL fit with a
profile interval runs 410-790 ms against 10 ms for a 4PL. It is off the GUI
thread through the existing JobRunner, the 4PL default is untouched at 10
ms, and a correct interval is the reason the option exists.

THE 4PL PATH STILL DOES NOT MOVE. Re-diffed after the fix against the
pre-fix commit over twenty cases -- two models by two interval methods by
five shapes -- comparing every parameter, both ends of every interval, SSE,
R2, dof, status, lack-of-fit p and a hash of the full report text. All ten
4PL cases and all five 5PL Wald cases are byte-identical; exactly two cases
differ, both 5PL PROFILE, and both widened. On the asymmetric series the
reported EC50 interval went from 0.746-0.876, which excludes the true 1.0,
to 0.721-1.093, which contains it.

THE SECOND DEFECT: A COVARIANCE THROWN AWAY. When the five-parameter search
finds nothing better than the symmetric fit, the reported curve IS the 4PL
with the exponent pinned at 1 -- and the four parameters the symmetric fit
estimated were estimated. The code set `pcov = None`, which made
`covariance_ok` false and told the reader "the covariance matrix was not
estimable". It was estimated and then discarded. Under CI_WALD the midpoint
lost its interval too, so `bounded` went false and a cleanly bounded fit was
reported as STATUS_UNBOUNDED with `ec50=None`. `_pad_symmetric_covariance`
now widens the 4x4 block to 5x5 with a zero row and column for the pinned
exponent, rescaled by (n-4)/(n-5) because `curve_fit` scaled it on four
parameters and this fit is read on five, and the asymmetry alone reports
`(None, None)` rather than the zero-width interval those zeros would
otherwise produce. The branch is reached in the test by making the
five-parameter search return nothing; no natural series was found that
reaches it, so its reachability is still unconfirmed and its consequence is
now harmless either way.
