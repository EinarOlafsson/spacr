WHAT IS THERE TODAY (read on nightly e2f082bf8)
-----------------------------------------------

* A FONT scale exists and nothing else scales: spacr/qt/preferences.py
  FONT_SCALE_MIN = 0.10 and FONT_SCALE_MAX = 2.00 (~540-541), clamped at
  ~3625 and ~3631, with its slider at ~5504. No whole-GUI scale exists
  anywhere in spacr/qt (no QT_SCALE_FACTOR, no scale-factor preference), which
  is why widget sizes, paddings, icons and fixed pixel sizes stay put while the
  text shrinks.
* The console already collapses its own topic sections
  (spacr/qt/widgets/console_panel.py collapse_section ~1647, toggle_section
  ~1662; sections start expanded, ~1665), but the console panel itself, the
  System container and the button section under System do not auto-collapse,
  and the button section cannot collapse at all.
* The live previews the maintainer names are spacr/qt/widgets/live_preview.py
  (Mask), measure_preview.py (Measure) and the image-UMAP views
  (umap_explorer.py, umap_search_viewer.py, annotation_umap_tab.py); the same
  shape recurs in motility_preview.py, plaque_preview.py and
  timelapse_preview.py. The figures panel is figure_grid.py /
  figure_grid_view.py / figure_queue.py. Screen layout is in
  spacr/qt/screens/app_screen.py.
* Item 417 (the magnifier's second round) made Make Masks' settings
  categories collapsible; that is the nearest existing pattern to reuse.

WHAT TO BUILD
-------------

1. "GUI scale" in Preferences, beside font scale: 10% to 200%, default 100%,
   scaling every GUI element -- widget sizes, spacing, icons, fixed pixel sizes
   -- not only text. Each live preview gets its own scale slider as well.
2. When a live preview opens, it takes the whole screen height: the console,
   the System container and the button section below System auto-collapse, and
   the settings collapse to the left. The button section needs a collapse
   control it does not have today.
3. The same when figures appear: console, System and the buttons auto-collapse
   and the settings collapse to the left.
4. The user can collapse the figures panel and the live preview panel, and can
   expand anything again at any time. Auto-collapse never removes the user's
   ability to undo it.
5. Every section inside the figures and live preview containers collapses.
6. Wherever possible, every GUI element -- a figure, a table -- is
   collapsible, in every module.
7. A collapsed element locks to the BOTTOM of its container. Today the console
   collapses to the middle of its container; that is the bug this point fixes.

WHAT TO BE CAREFUL WITH
-----------------------

* A true whole-GUI scale in Qt is either a startup-time scale factor (needs a
  restart to change) or every size routed through one scaled helper (live, but
  every hard-coded pixel size must go through it). Decide which before
  building, and say in the setting which it is. The font scale and the GUI
  scale must compose, not fight: 50% GUI at 200% font is a real combination.
* Auto-collapse must not fight the user: once they expand something by hand,
  it stays expanded for that view until they leave it.
* 10% is very small. The screen must stay usable and recoverable there (the
  same survival test item 413 added for the 10% font floor).
* New captions (GUI scale, the collapse controls) are translated strings in
  nine languages: list them for the catalog lane rather than regenerating
  spacr/qt/i18n_catalogs.

DONE WHEN
---------

* At GUI scale 50% on a laptop-sized window, Mask live preview, Measure live
  preview and image UMAP show everything, and 100% looks as it does today.
* Opening a live preview or figures collapses console, System, the buttons
  and the settings, and each can be expanded again.
* Every figure and table in every module can be collapsed.
* A collapsed element sits at the bottom of its container, the console
  included.

2026-09-22 — SLICE A LANDED: THE GUI SCALE AND THE PREVIEW SCALE (point 1)
--------------------------------------------------------------------------------

Slice A is point 1 only. Points 2-7 and the drag-to-resize addendum are other
slices and are not touched here.

THE MECHANISM, DECIDED BY AN AUDIT. A live scale would have to route every
hard-coded pixel size through one helper. Counted on nightly across the 328
modules under spacr/qt: 470 setContentsMargins, 489 setSpacing, 179
setMinimumWidth/Height, 67 setMaximumWidth/Height, 74 setFixed*, 30
setMinimumSize, 56 QSize(...), 64 resize(...), 6 setIconSize -- about 1,420
geometry calls in 181 files -- plus 486 "px" literals in style-sheet text in
64 files (177 of them in theme.py). Too invasive, and every size added later
would have to remember the helper. So the GUI scale is a HYBRID:

* GUI scale (Preferences, beside Font scale; 10-200 %, default 100 %) is a
  startup-time Qt scale factor. spacr/qt/gui_scale.py writes it into
  QT_SCALE_FACTOR before the QApplication exists (called from launch() in
  spacr/qt/app.py), so Qt scales every logical pixel: widget sizes, fixed
  sizes, margins, spacing, QSS paddings, icons, pictures, text. A change
  needs a restart; the row says so, shows "N% after a restart (now M%)" and
  offers Restart now, which saves the dialog and restarts through the same
  record Force restart writes (the module and its settings come back; a run
  in progress is asked about first). At 100 % nothing is written, so a
  default launch is byte-for-byte today's.
* Font scale ("Zoom") stays live, on top. They multiply: 50 % GUI at 200 %
  font gives half-size widgets with text at its usual size on screen
  (tested in a child process: body text 26 logical px = 13 device px, a
  100 px box = 50 device px).
* A user's own QT_SCALE_FACTOR is kept (SPACR_GUI_SCALE_BASE) and a restart
  does not compound it. SPACR_GUI_SCALE=1 overrides the stored value for one
  launch; safespacr reads it as its default, 100 %.
* The window keeps its physical size at any GUI scale
  (fit_window_to_gui_scale), so the room gained goes to the content.
* matplotlib's toolbar icon engine multiplies the device ratio in twice;
  below a ratio of 1 the pan/zoom icons drew 3 px tall at 50 %.
  gui_scale.mend_matplotlib_icons() holds the engine's ratio at >= 1 (only
  when running below 100 %); measured 11 px, and no change at ratio 1 or 2.

EACH PREVIEW'S OWN SCALE, live. spacr/qt/widgets/preview_scale.py (re-exported
from preview_controls.py) is one implementation used by Mask
(live_preview.py), Measure (measure_preview.py), Plaque, Timelapse, Motility
and the three image-UMAP views (umap_explorer.py, umap_search_viewer.py,
annotation_umap_tab.py). A 10-200 % slider scales, inside that preview only:
style-sheet sizes it inherits and its widgets set (font sizes, paddings,
margins, min/max sizes, radii; border widths left alone), min/max/fixed
widget sizes, layout margins and spacing, button icon sizes, and through a
hook what the panel draws itself (Measure's crop thumbnails, the UMAP
figure's dpi). Bases are remembered per widget so it never compounds, a size
the code sets later becomes the new base, and at 100 % nothing is touched at
all. Saved per preview under prefs/preview_scale/<name>. The slider sits in
the preview card's title row beside Refresh (placed on first show) -- in the
toolbar row it raised the column's minimum and the settings column lost
68 px at 100 %. It is exempt from its own scale; double-click its value for
100 %.

SURVIVAL AT 10 %. Ctrl+Alt+0 (free in shortcuts.py; Cmd+Option+0 is not a
macOS-reserved combination) puts GUI scale, font scale and every preview
scale back to 100 % and asks to restart with Restart now as the DEFAULT
button, so Ctrl+Alt+0 then Enter recovers without reading anything. Tested
on a real MainWindow built at 10 % in a child process (the binding exists,
Preferences still opens with the row at 10, Enter restarts). Honest limit:
at 10 % Preferences itself is a ~60 px postage stamp on a 1366x768 screen --
reachable, not usable by mouse; the keyboard route is the way back.

CHECKED. At GUI 50 % on 1366x768 and 1280x800 (offscreen), Mask live
preview, Measure crop preview and image UMAP show every control, the image
canvases and the figure. At 100 % the screens pixel-compare against nightly
at ec09c3608 (slice B landed): Home identical (0 px); Mask, Measure and
image UMAP differ by 683 px each, all inside the new slider's own box.
