WHAT TO BUILD, IN THE MAINTAINER'S ORDER
-----------------------------------------

1. A readout in the image's top-left corner following the cursor: the pixel
   intensity, and for the object under the cursor its label and area. It reads
   the same numbers the filter judges by (418's mean intensity on the object's
   own channel), so a user can predict what a filter will remove.
2. Settings categories to the LEFT of the image, with a visible gap between

3. Every model the screen can use is listed even when it is not installed:
   greyed out, and clicking it installs it into the running spaCR environment
   and then makes it selectable. Same list and same behaviour in the model zoo
   button and in the Mask module. The "you can install this" sentences under
   the live magnifier go.
4. A short shortcut list to the right of the Mask / Cell probability / Flows
   views: hold Shift to move, scroll to zoom, drag to choose in magnifier
   mode, and the rest, one terse line each.
5. More Otsu settings (the existing threshold correction is the start), and
   two renames: the "classical" detector becomes "Otsu", and "Cellpose-SAM"
   becomes "Object detection".
6. Buttons: Clear (clears every object, after an OK/Cancel confirmation),
   Dilate, Shrink.
7. A Filter button and a Filter settings category holding Minimum Area,
   Maximum Area, Minimum Intensity, Maximum Intensity, all off by default.
   Clicking Filter applies the ones that are on, through 418's
   _filter_objects, and writes one red line per removed object into a text box
   in that category: which object, its area, its intensity, and which bound
   removed it.
8. Ctrl + left click splits the object under the cursor; Ctrl + right click
   removes it.

WHAT MOVES WITH IT
------------------

* Renames in 5 are not cosmetic. "classical" is a stored settings value and a
  dict key; "Cellpose-SAM" is a settings category name, a button caption and a
  tooltip. A settings file written before the rename must still load. The
  captions and every new string here (the readout, the shortcut list, the
  filter's removal lines, the new buttons) need reviewed records and a catalog
  pass, which is the catalog lane's; list them there rather than regenerating
  spacr/qt/i18n_catalogs.
* Installing from a click runs a package install inside the running
  application: it needs to say what it is doing, survive failing without
  breaking the screen, and not block the GUI thread.
* Ctrl+click edits are undoable, like the existing edits.

DONE WHEN
---------

* Hovering shows intensity and the object's area and label, and they match
  what the filter reports for the same object.
* The layout is as described, and the tooltipped sentence is gone.
* An uninstalled model is visible, greyed, installs on click, and is
  selectable afterwards, in both places.
* The shortcut list is on the screen beside the views.
* "Otsu" and "Object detection" are the names everywhere, old settings files
  still load, and Otsu has its new settings.
* Clear (with its confirmation), Dilate and Shrink work and are undoable.
* Filter applies only the bounds that are on and lists every removed object,
  one red row each.
* Ctrl + left click splits and Ctrl + right click removes, both undoable.

WHAT IS THERE TODAY (read on nightly 7c7ab705c)

  * The module draws its booleans as plain QCheckBox -- seven of them in
    spacr/qt/screens/make_masks.py -- and uses the package's slider NOWHERE.
    The slider is `Toggle` in spacr/qt/widgets/toggle.py (a QCheckBox subclass,
    so the swap is a widget change, not a signal change).
  * The magnifier paints its region in `paint` (~2653); detection runs through
    `cellpose_detect` (~1346), called from the detect button
    (`_btn_cellpose.clicked` ~4873) and from the magnifier's own paths (~1536,
    ~1589, ~5012). Otsu detect is `_btn_otsu` (~4256) with the threshold
    correction read from the Cellpose-SAM category (~1515, ~4260).

WHAT TO BUILD

  9a. Every boolean in this module becomes the package's `Toggle` slider. It is
      a QCheckBox subclass, so setChecked/isChecked and the existing signal
      wiring stay; the tests that find these controls by type are part of the
      change.
  9b. A new boolean, "Invert", in the Object detection category (the renamed
      Cellpose-SAM category of point 5 -- file it under whichever name that
      category carries when this is built).
  9c. When Invert is on, the magnifier shows the inverted image inside the
      magnification, so a dark object reads as a bright one and Otsu can take
      it.
  9d. When Invert is on and the detect button is pressed, the masks are
      generated FROM THE INVERTED IMAGE -- the inversion is what the detector
      sees, not a display trick, so it applies on the same path for
      Cellpose-SAM/Object detection and for Otsu detect.
  9e. While Invert is on, a warning is visible saying the masks are being
      generated from the inverted image.

  Open for the builder to settle, and worth settling before coding: what
  "inverted" means numerically for a 16-bit field (max - value on the image's
  own range, or on the contrast-stretched view). The readout of point 1 and the
  filter of point 7 must keep reporting the ORIGINAL intensities, or a user
  filtering by intensity would be judging inverted numbers.

ORDERING: 9b's caption sits in the category 417 populates and point 5 renames,
so it lands with or after that rename, in one catalog pass -- "Invert" and the
warning are translated strings in nine languages, like the rest.
