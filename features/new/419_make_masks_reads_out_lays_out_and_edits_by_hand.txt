WHAT IS THERE TODAY (read on nightly 7c7ab705c)

    spacr/qt/screens/make_masks.py -- and uses the package's slider NOWHERE.
    The slider is `Toggle` in spacr/qt/widgets/toggle.py (a QCheckBox subclass,

  * The magnifier paints its region in `paint` (~2653); detection runs through
    `cellpose_detect` (~1346), called from the detect button
    (`_btn_cellpose.clicked` ~4873) and from the magnifier's own paths (~1536,
    ~1589, ~5012). Otsu detect is `_btn_otsu` (~4256) with the threshold
    correction read from the Cellpose-SAM category (~1515, ~4260).

WHAT TO BUILD

  9a. Every boolean in this module becomes the package's `Toggle` slider. It is
      a QCheckBox subclass, so setChecked/isChecked and the existing signal
      wiring stay; the tests that find these controls by type are part of the
      change.
  9b. A new boolean, "Invert", in the Object detection category (the renamed
      Cellpose-SAM category of point 5 -- file it under whichever name that
      category carries when this is built).
  9c. When Invert is on, the magnifier shows the inverted image inside the
      magnification, so a dark object reads as a bright one and Otsu can take
      it.

      generated FROM THE INVERTED IMAGE -- the inversion is what the detector
      sees, not a display trick, so it applies on the same path for
      Cellpose-SAM/Object detection and for Otsu detect.
  9e. While Invert is on, a warning is visible saying the masks are being
      generated from the inverted image.

  Open for the builder to settle, and worth settling before coding: what
  "inverted" means numerically for a 16-bit field (max - value on the image's
  own range, or on the contrast-stretched view). The readout of point 1 and the
  filter of point 7 must keep reporting the ORIGINAL intensities, or a user
  filtering by intensity would be judging inverted numbers.

listed whether or not it is installed, the missing ones greyed with a

nor the Mask backend dropdown ever rests on a backend that cannot load.
What changed is the destination. Both now open the Model Zoo's install
dialog, which builds a venv under ~/.spacr/backends/<name> off the GUI
thread with progress and Cancel; spaCR's own environment is never changed.

It was not a matter of taste. Item 423 changed
model_zoo.INSTALLABLE_BACKENDS's second field from a pip extra
("spacr[samcell]") to "backend:samcell" -- the zoo's own URI for "installs
as an environment of its own" -- so model_install.backend_row's requirement
stopped being something pip can be handed. The two routes could not both
stand, and leaving this one would have run `pip install "backend:samcell"`.

Unchanged in spacr/qt/model_install.py: PackageInstall, CheckpointDownload,
_RUNNING, can_install_packages, confirm_backend_install, and the whole
QProcess/off-the-GUI-thread argument this item made, which is what the Model
Zoo dialog's own job now honours as well. Two methods of
SegmentationBackendCombo changed: offer_install (opens the dialog) and
missing (asks _backend_state, so an environment of its own counts as
installed and so does a package an older spaCR left in spaCR's own). The
seven install tests in tests/qt/test_model_install_runs_off_the_gui_thread.py
and tests/qt/test_make_masks_reads_out_lays_out_and_installs.py now drive
the dialog, and two of them assert that neither control runs pip against
spaCR's own environment.

Also: the Mask backend dropdown gained a fourth row, Cellpose 3, because it
reads INSTALLABLE_BACKENDS and item 423 added that backend. Point 3's own
list of backends is not otherwise changed.

POINT 6 -- CLEAR, DILATE, SHRINK

  * `mask_engine.dilate_objects` grows every label into background only
    (`expand_labels`), so no two objects fuse and the object count cannot
    change -- an id that has been got right keeps every measurement, track
    and crop keyed to it. `shrink_objects` erodes each object against
    everything that is not itself, background AND its neighbours, so a
    touching pair comes apart; eroding `mask > 0` as one binary would leave
    that seam alone, which is the opposite of what Shrink is for. Each object
    is eroded in its own bounding box, the way part A's `canonical_labels`
    works. Both use the Euclidean distance, so a Shrink undoes a Dilate of
    the same size on an object that had room to grow -- asserted.
  * Both are one undo step and one ledger entry carrying the step. Shrink
    says how many objects it erased, because an object thinner than twice the
    step disappears and a curator who has just lost eleven of them needs to
    be told while Undo is still the obvious thing to do.
  * Clear already existed and already confirmed; it is now captioned "Clear"
    and its question names the count about to go. The dialog is still titled
    "Clear mask".

A SEGFAULT THIS BRANCH CAUSED, AND WHAT IT ACTUALLY WAS

  * tests/qt/test_the_make_masks_segmentation_workbench.py died with SIGSEGV
    about half the time on this branch and never once on clean nightly (0 in
    16). It dies partway through, after a dozen tests, with no failing
    assertion -- inside pytest-qt's _process_events.
  * A gdb backtrace named it: QTimerInfoList::activateTimers ->
    QCoreApplication::notifyInternal2, a Qt timer delivering an event to a
    C++ object Python had already collected. Bisecting the change by feature
    found the trigger: ONE MORE SPIN BOX on the settings panel. Nightly plus
    a single bare QSpinBox crashes 1 run in 5; plus the three controls point
    6 asks for, 5 in 6.
  * So the screen was never the defect. The fixture was: it ended at
    close_folded() and left the magnifier's worker thread, its timers and the
    screen itself alive, and it was the only Make Masks fixture in the suite
    that did not close the magnifier. Closing the magnifier, closing and
    deleting the screen and draining the DeferredDelete queue is 0 crashes in
    16 runs WITH the new controls in place. The measurement is in the
    fixture's docstring, because the next person to add a timer-owning widget
    to that panel needs it.
  * Not chased further: why the panel's existing spin boxes were not already
    enough. The debt was there to be collected and any new control would have
    collected it.

  * Seven existing test files were updated -- six for the renames and the
    layout, and the workbench fixture above. One test changed for a reason
    worth recording:

    `engine.otsu_instances`, which the button reached only through
    `_otsu_instances`'s shortcut for a plain threshold. Two of the new
    settings start on, so that shortcut is no longer taken and the stub was
