    spacr/qt/screens/make_masks.py -- and uses the package's slider NOWHERE.

    correction read from the Cellpose-SAM category (~1515, ~4260).

WHAT TO BUILD

  9a. Every boolean in this module becomes the package's `Toggle` slider. It is
      a QCheckBox subclass, so setChecked/isChecked and the existing signal
      wiring stay; the tests that find these controls by type are part of the
      change.

      Cellpose-SAM category of point 5 -- file it under whichever name that
      category carries when this is built).

      magnification, so a dark object reads as a bright one and Otsu can take

2026-09-19 (later) — POINT 3 STILL STANDS; WHERE IT INSTALLS CHANGED (ITEM 423)

Decided: "Isolated env per backend! But with the addition of adding cellpose
3 and its cyto, nucleus, and cyto2 and cyto3 models. The cellpose 3 backend
will allow more models from the biomass.io to be added to the model zoo."
-- the maintainer, 2026-09-19, answering item 423's open questions, three

The gesture point 3 asked for is unchanged and is still here: every backend
listed whether or not it is installed, the missing ones greyed with a
tooltip, choosing one installs it and selects it, and neither the Mode box
nor the Mask backend dropdown ever rests on a backend that cannot load.
What changed is the destination. Both now open the Model Zoo's install
dialog, which builds a venv under ~/.spacr/backends/<name> off the GUI
thread with progress and Cancel; spaCR's own environment is never changed.

It was not a matter of taste. Item 423 changed
model_zoo.INSTALLABLE_BACKENDS's second field from a pip extra
("spacr[samcell]") to "backend:samcell" -- the zoo's own URI for "installs
as an environment of its own" -- so model_install.backend_row's requirement
stopped being something pip can be handed. The two routes could not both
stand, and leaving this one would have run `pip install "backend:samcell"`.

Unchanged in spacr/qt/model_install.py: PackageInstall, CheckpointDownload,
_RUNNING, can_install_packages, confirm_backend_install, and the whole
QProcess/off-the-GUI-thread argument this item made, which is what the Model
Zoo dialog's own job now honours as well. Two methods of
SegmentationBackendCombo changed: offer_install (opens the dialog) and
missing (asks _backend_state, so an environment of its own counts as
installed and so does a package an older spaCR left in spaCR's own). The
seven install tests in tests/qt/test_model_install_runs_off_the_gui_thread.py
and tests/qt/test_make_masks_reads_out_lays_out_and_installs.py now drive
the dialog, and two of them assert that neither control runs pip against
spaCR's own environment.

Also: the Mask backend dropdown gained a fourth row, Cellpose 3, because it
reads INSTALLABLE_BACKENDS and item 423 added that backend. Point 3's own
list of backends is not otherwise changed.

THE TWO INVERSIONS ARE ARITHMETICALLY DIFFERENT AND BOTH ARE KEPT.

Item 419 left the meaning of "inverted" open for the builder. 435 asked the
maintainer and got "1/intensity i think and then fitted to dtype i guess",
and landed `mask_engine.invert_intensity` as the dtype complement. The
obvious resolution -- delete point 9's function and use 435's -- was tried
first in this rebase AND IT IS WRONG. The measurement that reversed it:

  * 435 also rewrote the detect button's two-class path to take its level
    from `_otsu_levels`, which works on ABSOLUTE smoothed intensity and
    applies item 417's threshold correction there as a MULTIPLIER.
    Multiplying is not invariant to an offset.
  * The complement puts a 12-bit field (0..4095 in uint16) into
    61440..65535. Measured on such a field with dark objects, inverted, Otsu
    on the bright side: correction 0.8 gives ONE object over 100% of the
    frame, 1.0 gives 3 objects over 8%, 1.3 gives NOTHING. Reflecting about
    the field's own range gives 47 objects over 20%, the same 3 objects over
    8%, and 3 objects over 8%.
  * So the complement turns the threshold correction from a dial into an
    on/off switch. AT EXACTLY 1.0 THE TWO AGREE, which is why the merge
    passed every test that pinned the default and had to be caught by
    measuring rather than by running the suite.

The display inversion must be exactly reversible and nothing reads it; the
detector's must keep the field's span so a number dialled against the
picture still means what it meant. One function cannot be both.
`mask_engine.invert_for_detection` is point 9's, beside 435's
`invert_intensity`, and a new test --
test_the_two_inversions_are_not_interchangeable_under_a_correction -- pins
the difference so they are not merged again from the same reasoning.
