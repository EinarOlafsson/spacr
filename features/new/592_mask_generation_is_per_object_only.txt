MASK GENERATION IS PER-OBJECT ONLY

Status:    DONE 2026-09-28 (see the note below). Not an alpha feature: it
           reshapes existing settings and adds none.
Requested: 2026-09-28, by the maintainer, verbatim:
  "in mask generation, please make per object settings the default and only
  mode (remove the preferences toggle.)
  Advanced settings, image preprocessing, cell - remove background should be
  in the per object table as a boolean (the other objects should have the
  same)
  cell segmentation - Adjust cells - should also be added to the per object
  table as a setting but only for the cell object.
  object filtrationshould also be baked int othe per object tables as new
  rows that can be added so the user can add area filtration for one or
  several object classes or mean intensity, etcetera.
  output and storage can be merged with runtime and reliability and
  segmentation robustness into quality controll."

WHAT TO BUILD
1. Per-object settings are the only Mask generation layout; the Preferences
   toggle and the old flat layout go (settings files still load).
2. The per-object table gains a "remove background" boolean row for every
   object, and an "adjust cells" row for the cell object only.
3. Object filtration becomes addable rows in the per-object table (area,
   mean intensity, and the other filters), for one or several objects.
4. Output & storage, Runtime & reliability and Segmentation robustness merge
   into one category, "Quality control".

2026-09-28: what was built.
  1. The per-object table is Mask generation's (and Timelapse's, which
     shares its settings) only layout of the per-object settings:
     AppScreen.OBJECT_GRID_APPS, mounted on every build, drawn in front of
     "Cell Segmentation". The Preferences switch ("Per-object settings as a
     table"), get/set_object_grid_enabled, DEFAULT_OBJECT_GRID, the
     broadcast to open screens and AppScreen.apply_object_grid_preference /
     _unmount_the_object_grid are gone. Other modules (Measure) keep their
     flat form. The stored keys are unchanged, so every settings file loads;
     the retired {object}_min_area bounds still fold into object_filters and
     now show as filter rows.
  2. "Remove background" is a boolean row for every object
     (remove_background_<object>, spelled object-last, now understood by
     spacr.object_settings_table), drawn as a check box. "Adjust cells" is a
     row for the cell column only (adjust_cells). The table keeps a question
     one object asks only for these declared single-object keys.
  3. Object filtration is addable rows: "Add a filter" offers every scalar
     regionprop (area and mean intensity first); a row "Filter: <property>
     (min – max)" has a cell per segmented object (not cytoplasm), taking
     "200 – 5000", "200" (minimum only), "– 5000" (maximum only) or blank
     (off). The rows write the one object_filters mapping; a filter loaded
     from a file or typed elsewhere shows as its row. The flat
     object_filters row is hidden behind the table.
  4. Mask generation's "Quality Control" now holds the segmentation QC
     checks, Output & Storage and Runtime & Reliability; "Segmentation
     Robustness α" is nested inside it.
  5. The table's "Per-object settings" heading has its own help on hover
     and takes the module's maturity colour (beta on Timelapse).
  Tests: tests/qt/test_the_object_grid_is_the_only_mask_layout.py (replaces
  test_the_object_grid_can_be_switched_on.py); the tests that toggled the
  preference now take the table as given.

LEFT: the Timelapse layout keeps its separate Output & Storage and Runtime
& Reliability headings (the request named Mask generation); a filter row
cannot be deleted in one click -- clearing its cells removes it on the next
reload; captions for the new help texts wait for the catalog lane.
