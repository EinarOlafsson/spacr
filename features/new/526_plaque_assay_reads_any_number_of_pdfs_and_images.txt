PLAQUE ASSAY READS ANY NUMBER OF PDFS AND IMAGES

Status: DONE, 2026-09-25 (filed the same day).
Owner: agent (526 worktree). Related: 517 (drop files), 518 (mode follows the input),
524 (four views in Figure mode).

REQUEST (the maintainer, 2026-09-25, verbatim)
    "plaque assay should be able to read an arbitrary number of figures or
    images. so if i drop a file with one or 10 pdfs both should be fine.
    there might be other files in the folder, if these are not images or
    pdfs they are ignored."

WHAT IS WRONG
Dropping a folder with two PDFs reads the first and rejects the second
("Plaque Assay reads one paper at a time; 1 more PDF(s) were left out."),
shown as an ERROR. 517 left this open on purpose; it is now asked for.

WHAT TO BUILD
  * Any number of PDFs (dropped, in a dropped folder, or in src) are all read,
    one after another in the background, each paper's figures going into its
    own figure folder, and all of them shown in the preview (page/paper
    navigation), then run together.
  * Any number of images likewise, as 517 already does for images.
  * Files that are neither images nor PDFs are ignored quietly (at most one
    info line naming how many were skipped), never an error.
  * Progress says which paper of how many is being read; one failing PDF does
    not stop the others and is reported by name.

DONE WHEN
An offscreen test drops a folder with 10 PDFs plus unrelated files and sees
all 10 read (reader faked) with no error, and one real run reads the
maintainer's two Plate PDFs (or two test PDFs) end to end.


2026-09-25 -- DONE

WHAT CHANGED
- PlaqueDropHandler._take_pdfs (spacr/qt/dnd_handlers.py:1908) reads one
  PDF as before (fetch_paper) and several through the new
  PlaquePreviewPanel.fetch_papers (spacr/qt/widgets/plaque_preview.py:4587).
  The "one paper at a time" refusal is gone. check_the_src (the src path)
  calls the same _take_pdfs, so a src naming a folder of PDFs reads them all.
- fetch_papers queues the PDFs on the panel's paper JobRunner, one after
  another (_next_paper :4643, _on_batch_paper :4668, _papers_read :4679).
  Each paper goes into parent/<pdf stem> beside the first PDF (a clashing
  name from another folder becomes <folder>_<stem>). The status line says
  "Reading paper k of n: <name>…". A PDF that raises is noted by name and
  the rest are read. At the end the note gives the count and names each
  failure, src is set to the folder of papers, and the preview lists it.
  A job failure the runner itself reports also moves the batch on (:4550).
- plaque_papers.figure_folders (spacr/plaque_papers.py:3016): a folder that
  holds paper folders is read paper by paper, with its own figures first
  if it has any. images_in(src, papers=True) (plaque_preview.py:309) lists
  figures that way in Figure mode (:2960). When figures come from several
  folders the picker labels them "<paper>/<file>" (:2977).
  _analyze_plaque_figures (spacr/submodules.py:1742) measures each paper
  folder into one <src>/plaque_figures database, and
  _add_figure_summaries (:1700) adds up the counts, so the papers run
  together.
- plaque_inputs also reports a folder of paper folders as a paper input
  (_holds_papers, dnd_handlers.py:1627). A src that has already been read
  is therefore not read again when the form writes it back.
- Files that are neither images nor PDFs: PlaqueDropHandler.can_accept
  (:1800) now takes any file, and apply_all leaves such files aside with one
  console line from plaque_others (:1641, message at :1885). Dropped alone
  they are still refused with the handler's own sentence, as before.

REAL RUN
  Two small real PDFs (Plate1.pdf and Plate2.pdf, one figure page each,
  made with matplotlib) and a readme.txt in one folder, passed to the real
  PlaqueDropHandler.apply_all on an offscreen AppScreen in Figure mode. They
  were read by the real figure reader in ~/.spacr/backends/papers (this
  environment has no pdfplumber) in 4.2 s on CPU. The status showed
  "Reading paper 1 of 2: Plate1.pdf…", "Reading paper 2 of 2: Plate2.pdf…"
  and "Read 2 of 2 papers into …/Plates: 2 figures, 2 with legends.". src
  was set to …/Plates and the picker showed Plate1/page_001.png and
  Plate2/page_001.png. Each paper folder held legends.csv, page_001.png,
  paper.json and text_layer.json. The figure run (YOLO detector plus plaque
  model) was not run on these; its per-paper loop is covered by test (8).
