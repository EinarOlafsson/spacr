296 — `safespacr` starts the bare minimum

Status:    AUDITED 2026-09-15, NOT CLOSED. The item's own verification now
           runs for real and passes (a written preference kills `spacr`,
           `safespacr` gets in, re-saves it, exits, and `spacr` starts).
           Safe mode no longer imports vispy, starts the pre-warm thread,
           or reads the real store for the tour and installer consent. Two
           gaps remain, both in spacr/qt/preferences.py, each pinned by a
           strict xfail. See the last section.

Asked 2026-08-28, while spaCR was crashing on launch: "there should be a start
spacr in safe mode triggered by safespacr that turns everything it can off and
just starts the bare minimum, so settings can be changed and resaved e.g."

A console entry point `safespacr` beside `spacr` and `spaceout`. It brings up
the least that can still show and save settings, and turns OFF everything that
is not needed to do that:

* no animated backdrop, no fractal, no OpenGL of any kind -- the crash log
  points at the GL path (295), so safe mode must never create a GL context;
* no preloading, no background import thread;
* no verbose tracing, whatever the saved preference says (294);
* no GPU probe, no CUDA import;
* plain widgets, default font, no theme animation.

WHY IT MATTERS: when a saved preference is what makes spaCR die on launch,
there is currently no way in. Safe mode has to be reachable without reading
the preference that is breaking it -- so it must not load the same preferences
path that a normal start does, or it inherits the fault it exists to escape.
It reads settings, lets the user change and RE-SAVE them, and exits.

Verify by making a normal start impossible -- write a preference that crashes
it -- and asserting `safespacr` still opens and can rewrite that value.

VERDICTS

* No animated backdrop, no fractal, no OpenGL of any kind -- PARTLY.
  Nothing is built: no AmbientWidget, fractal or GL widget, and SPACR_NO_GL
  refuses a canvas (fractal_travel.py:384). vispy is no longer imported
  (__init__.py:381-383). LEFT: the backdrop MODULE is still imported, by
  apply_ambient_preferences (preferences.py:2016), before it asks whether
  the backdrop is on.
* No preloading, no background import thread -- MET (was PARTLY). The
  preloader is forced to on_demand (preferences.py:629, app.py:2550); the
  settings pre-warm thread is no longer started (app.py:5573).
* No verbose tracing (294) -- MET. Verbose log forced off
  (preferences.py:628), every other logging preference read as its default,
  SPACR_TIMING popped (safespacr.py:30). Environment-only switches
  (SPACR_WATCH_GUI_STALLS, SPACR_PAINT_DIAG, SPACR_BENCHMARK_JSON) are not
  saved preferences and were left alone.
* No GPU probe, no CUDA import -- MET. Held by
  test_safe_mode_opens_without_importing_a_gpu_runtime; measured again.
* Plain widgets, default font, no theme animation -- PARTLY. Setting
  animations and the backdrop are off, and theme and font scale read as
  defaults, but the full theme stylesheet and the bundled fonts still load
  (app.py:5496, :5500): the default LOOK, not unstyled widgets. Not changed
  here; theme.py was out of bounds.
* Must not load the same preferences path as a normal start -- MET (was
  PARTLY). The shadow covers spacr.qt.preferences (preferences.py:652-655),
  but first_run.py:60 and install_consent.py:151 read the real store
  directly. The consent timer, which is the only thing that starts either,
  is no longer started in safe mode (app.py:2606). Nothing reaches the real
  store now while safe mode starts.
* Reads settings, lets the user change and RE-SAVE them, exits -- PARTLY.
  Change, Save and exit work, proven end to end below. LEFT: the
  Preferences dialog shows the defaults, not the stored values, and Save
  writes every control (PreferencesDialog._save, preferences.py:5915). A
  safe-mode Save therefore resets every preference the user did not touch.
  Measured: a stored font_scale of 1.25 came back as 1.
* Verification -- MET, below.

The preference is the real Animation key, prefs/ambient_theme=cells. No
stored value makes an ordinary start fail offscreen: all 115 preference keys
were written as a string, a list, -99999, 1e308 and broken JSON in turn, and
`spacr` exited 0 every time. The real crash (295) is a native abort in the
GL/driver path and needs a display. So the test's own launcher aborts the
process (os.abort, no Python exception) when the backdrop for that stored
animation is built; spaCR carries no hook for it.

  spacr          exit -6 (SIGABRT) at the injected point.
  safespacr      opens; the Animation dropdown shows the default, not
                 "cells"; set to Blobs, Save, window closed; exit 0; the
                 store holds blobs.
  spacr again    exit 0, with an AmbientWidget built, so crash recovery did
                 not skip the path that died.
