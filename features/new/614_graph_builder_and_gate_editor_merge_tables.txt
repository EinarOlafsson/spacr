--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Backend that exists and is the spaCR default: spacr/merge_tables.py
(merge_tables, MergePolicy, aggregation_for/AGGREGATION_RULES, roll_up,
_apply_na_policy) with the anchors in spacr/object_roles.py (ANCHOR_COLUMN:
cell/cytoplasm on object_label, nucleus/pathogen/organelles/png_list on
cell_id; JOIN_HOW; ONE_ROW_PER_CELL). Identity = plateID,rowID,columnID,
fieldID (+object_label). Regression's Measurements tab
(measurement_scan_panel.DatabaseMergePanel) and the Gate Editor's chip
working set (_reload_working_set -> merge_tables) both use it. The
aggregation editor is the shared AggregationRulesDialog.

Graph Builder (spacr/qt/widgets/graph_builder.py) has a table picker
(GraphTablePicker) and no merge. Neither screen has a "Merge tables"
button, a popup, a customisation path for non-spaCR schemas, a preview,
or a named derived table in its dropdown.

--------------------------------------------------------------------------------
WHAT TO DO (subtasks, each tested)
--------------------------------------------------------------------------------

a. Backend (Qt-free, spacr/merge_config.py): a MergeConfig that is either
   the spaCR default (delegates to merge_tables with MergePolicy -- same
   output, regression-tested for equivalence) or a custom mapping: base
   table, per-child join keys (composite), relationship (one-to-one /
   many-to-one roll-up), join type, per-type and per-column aggregation.
   Validation before any merge: missing tables/keys, duplicate keys in the
   base, many-to-many, unmatched counts, row counts in/out. Never falls
   back to spaCR assumptions for a custom schema. Base rows are never
   multiplied. Overlapping columns are table-prefixed. IDs are not
   aggregated. Missing stays missing.
b. Derived-table registry: named results scoped to the database path
   (+ schema fingerprint), carrying their config JSON; the source tables
   are never written. Persisted per database so a reopened database can
   rebuild the merge, and never offered for a different database.
c. Popup (spacr/qt/widgets/merge_tables_dialog.py), shared theme: tick
   tables, default summary (base level, keys, joins, aggregation), per-type
   and per-column aggregation overrides, a name, a preview (row counts,
   unmatched, duplicates, first rows), Merge. A "Customize merging" button
   opens the advanced panel with the warning text, an acknowledgement
   checkbox required to apply, Cancel that restores the previous config,
   "Reset to spaCR defaults", and a visible DEFAULT/CUSTOM badge.
d. Graph Builder: the button right of GraphTablePicker; the merged name
   appears in the picker and plots.
e. Gate Editor: the button right of its table picker; the merged result
   becomes the working frame; gates export only where the merged frame
   carries the identity columns, otherwise the export says why (no
   invented object links).
f. Tests for Regression's merge unchanged, equivalence, one-to-many,
   repeated IDs across images, overlaps, missing values, incompatible
   tables, a non-spaCR database with renamed tables/columns, config scope.
