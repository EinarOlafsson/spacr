--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

The checkpoint is spacr/resources/models/toxo_plaque_cyto_e25000_X1120_Y1120
.CP_model. Measured on CPU with cellpose 4.2.1.1: CellposeModel raises
"This model does not appear to be a CP4 model. CP3 models are not compatible
with CP4."

Where Plaque loads it:
* run: spacr.submodules._resolve_plaque_model ('bundled' or the path) ->
  _plaque_cellpose_model (Plaque mode) and plaque_papers._cellpose_segmenter
  (Figure mode);
* live preview: spacr/qt/widgets/plaque_preview.py resolve_plaque_model ->
  _cellpose_model -> preview_contract.preview_cellpose_model.

The run's default was already the zoo model toxoplasma_plaque_v2
(cpsam_plaque_r5, Cellpose-SAM; settings.get_analyze_plaque_settings and
submodules.DEFAULT_PLAQUE_MODEL). The live preview was not: it spelled an
unset or empty plaque_model as 'bundled' in three places (resolve_plaque_model,
apply_settings, current_settings), so an unseeded preview -- Live never
switched on, or settings without plaque_model -- asked for the Cellpose 3
checkpoint.

Fixed:
1. Default: the preview's three 'bundled' fallbacks now use
   DEFAULT_PLAQUE_MODEL, as the run does. Docstrings that still said
   "'bundled' by default" (submodules._requested_plaque_model,
   live_preview._plaque_model_the_run_would_use) corrected.
2. The old checkpoint stays selectable ('bundled' is still the last choice
   in the model box) and now WORKS when the isolated Cellpose 3 backend is
   installed: submodules._cellpose3_plaque_backend wraps
   _segmentation_backends._RemoteBackend('cellpose3', model=<checkpoint>) in
   _Cellpose3PlaqueModel, whose eval sends one grey plane (the [0, 0]
   channels the checkpoint was trained with in the original analyze_plaques)
   and answers in CellposeModel.eval's single-image shape, flows included.
   Used by _plaque_cellpose_model, plaque_papers._cellpose_segmenter and the
   preview's _cellpose_model.
3. Without the backend, the refusal is a Cellpose3Checkpoint whose message
   names toxoplasma_plaque_v2 / v1 and says to install the Cellpose 3
   backend from the Model Zoo. The preview's _explain_model_failure now also
   reads the refusal a Cellpose3Checkpoint was raised from, so the preview
   shows the same advice instead of "Cellpose3Checkpoint: ...".

CPU check (no GPU; CUDA_VISIBLE_DEVICES='' SPACR_DEVICE=cpu), 2026-10-01:
the real bundled checkpoint loaded in the installed Cellpose 3 backend
(cellpose 3.1.1.3, ~/.spacr/backends/cellpose3), segment_plaque_image and
the Figure-mode segmenter returned a 256x256 label image plus flow picture
and cell probability in 11-16 s. The test image was synthetic and gave 0
plaques -- a plumbing check, not a quality check. Script:
/mnt/wd4tb/scratch/608/cp3_cpu.py.

Tests: tests/test_608_bundled_plaque_checkpoint_runs_through_cellpose3.py,
tests/qt/test_608_plaque_preview_defaults_to_the_zoo_model.py.

--------------------------------------------------------------------------------
DECISIONS (maintainer asleep)
--------------------------------------------------------------------------------

* The default stays toxoplasma_plaque_v2 rather than moving to
  toxoplasma_plaque_v1 (cpsam_plaque_r3), the zoo model the recorder's
  --plaque-zoo-model path downloads. Both are Cellpose-SAM; v2 has been the
  run's documented default since item 468, and switching would change every
  default count and the tooltip default claims. The fix makes the preview
  agree with the run.
* The Cellpose 3 route is used only after Cellpose 4 has refused the file
  with its CP3 message, so no Cellpose-SAM checkpoint can be sent there.
