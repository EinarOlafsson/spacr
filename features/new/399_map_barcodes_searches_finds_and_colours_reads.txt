--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Three things shipped, all on `origin/nightly`, none on `main`:

  spacr/barcode_search.py      the detection engine. `search_barcodes()`
                               reads a bounded sample of a FASTQ, scores every
                               table against it, and returns a
                               `BarcodeSearchReport`. `propose_map_barcodes_
                               settings()` turns that into settings the
                               mapping run already reads.
  spacr/qt/widgets/read_view.py  one read per row, fixed pitch, each barcode
                               type in its own theme-derived colour. It never
                               searches and never imports the engine.
  spacr/settings.py            `BarcodeEntry` and `BarcodeSet` replace the
                               three hard-coded reference settings, so a run
                               decodes an arbitrary number of barcodes rather
                               than exactly three.

THE CHANCE BASELINE IS THE POINT OF THE ENGINE. 32 eight-base barcodes match
6.98 % of reads in a 150 bp read BY CHANCE. A percentage alone therefore
proves nothing, which is why the report carries span (where the matches sit)
and seen (how many of the table appear) as well as rate. That is also what
the read view is for: 27.66 % on col_p2 looked like signal and was adapter --
span 45 bases, 12 of 24 barcodes.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Before this, a misconfigured Map Barcodes run announced itself after an hour
of mapping that produced no counts. Now it announces itself in one glance.

DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

The engine does not reverse-complement the reference tables. It was claimed
early that it must; the reads use the `primers_3` tables and row identity is
present at 98.28 %, so the claim was wrong and was retracted rather than
coded around.
