================================================================================
THE SETUP SCREEN INSTALLS THE AI PROVIDER IT OFFERS, INSTEAD OF PRINTING A LINK
================================================================================

Status:    OPEN, filed 2026-09-16. Not started.
Requested: 2026-09-16, by the maintainer, in these words:

           "in the startup spacr when the use clicks an AI provider there
           should be an aditional button, install which automatically
           downloads and installs the chosen ai provider and asks the user for
           the needed information and sets up the AI provider . so instead of
           giving the user a curl link it uses the curl link to downloade e.g.
           claude and then installs it."

Owner:     unassigned. spacr/qt/widgets/setup_slides.py (the startup slide),
           spacr/qt/ai/providers.py (what each provider knows about itself),
           spacr/qt/widgets/ai_chat_panel.py (the same hint, shown again).

WHAT IS THERE TODAY (read on nightly c6c49f6ae)
------------------------------------------------

* Each provider already knows how it would be installed and whether it is:
  ChatProvider (providers.py ~35) carries install_hint (~50), is_installed()
  (~62), is_logged_in() (~69) and status() (~79). ClaudeCliProvider (~297)
  holds the curl one-liner that item 414 made work on every system --
  cmd /c "curl -fsSL https://claude.ai/install.cmd ..." on Windows, else
  curl -fsSL https://claude.ai/install.sh | bash (~303-307). CodexCliProvider
  (~335) holds "npm install -g @openai/codex   # or brew install codex"
  (~341); GeminiCliProvider is ~367.
* The startup slide already branches on that state: setup_slides.py ~1241
  (not installed -> a mark), ~1362 (installed and logged in), ~1382-1384,
  where it reads install_hint and shows it. ai_chat_panel.py ~392-406 shows
  the same hint in a QLineEdit to copy.
* So today every path ENDS at a command the user must run somewhere else.
  This item turns that last step into a button.
* No API keys are involved: spacr/qt/ai/keys.py records that the CLI-based
  providers take none. "The needed information" is therefore the provider's
  own login (and whatever it prompts for), not a key to store.

WHAT TO BUILD
-------------

1. Clicking a provider on the startup screen offers an "Install" button
   whenever that provider is not installed.
2. The button runs the provider's own installer -- the same curl or package
   command install_hint already holds, chosen per operating system -- rather
   than showing it. One source of truth: the button and the hint must not
   drift apart.
3. It then takes the user through the provider's login, asking for whatever
   the provider needs, and leaves the provider SET UP: is_installed() and
   is_logged_in() both true, and the slide's mark turns to READY without a
   restart.
4. It says what it is doing while it runs, and a failure leaves a message the
   user can act on, not a dead button: no network, a refused download, a
   missing package manager, a cancelled login.

WHAT TO BE CAREFUL WITH
-----------------------

* This downloads and executes an installer from the network on the user's
  machine, on their click. Show what will run before running it, never run it
  unasked, and keep the command visible for the user who would rather run it
  themselves.
* It must not block the GUI thread: the install and the login are long,
  interactive processes.
* The three providers install in three different ways (curl script, curl +
  cmd on Windows, npm or brew). A provider whose install cannot be automated
  on the running system should say so and fall back to today's copyable hint.
* New captions (the button, its progress and its failures) are translated
  strings in nine languages: list them for the catalog lane rather than
  regenerating spacr/qt/i18n_catalogs.
* Item 414 (BUILT, b3f7bd6c9) is what made the Claude command work on every
  system, Windows included; this item consumes it. Item 416's updater does
  the find/delete/install dance for spaCR itself and is the nearest existing
  example of running an install from inside the app.

DONE WHEN
---------

* On a machine without the CLI, clicking the provider and pressing Install
  leaves it installed, logged in and marked READY, with no terminal used.
* The command that runs is the provider's own install_hint for that operating
  system, and there is one definition of it.
* Every failure path shows a message and leaves the screen usable.

--------------------------------------------------------------------------------
2026-09-16 — ADDED BY THE MAINTAINER: THE GITHUB CLI TOO, AND A WAY TO GET AN ACCOUNT
--------------------------------------------------------------------------------

In his words:

    "and same for the github cli, add that to and a button that links to
    generating a github account"

So the Install button above covers the GitHub CLI as well, and beside it there
is a button that takes a user who has no GitHub account to where they can make
one.

WHAT IS THERE TODAY (read on nightly 7fa5105a1)

  * The GitHub CLI is NOT a ChatProvider, so it has none of the machinery the
    AI providers have -- no install_hint, no is_installed(), no is_logged_in().
    spaCR only consumes it: spacr/qt/ai/github_auth.py reads a token with
    `gh auth token` (~84) and its docstring tells interactive users to run
    `gh auth login` themselves (~62); spacr/qt/ai/issue_report.py reports the
    CLI's version or the bare marker "not installed" (~278-286).
  * So today a user without `gh` is told it is missing and left to install and
    log in somewhere else -- the same dead end this item removes for the AI
    providers.

WHAT TO BUILD

  * Give the GitHub CLI the same three states the AI providers have -- not
    installed, installed but not logged in, ready -- and the same Install
    button, running the CLI's own installer for the running operating system.
    Either extend the provider seam to cover it or give it the same small
    interface; do not grow a second, different way of asking "is it there?".
  * After installing, take the user through `gh auth login` and leave the CLI
    logged in, so `gh auth token` answers and the issue reporter works without
    a restart.
  * Beside it, a button for a user with no GitHub account at all: it opens
    GitHub's sign-up page in the browser. Creating the account happens on
    GitHub, in the browser -- the button is the link, nothing more -- and when
    the user comes back, Install and login finish the job.
  * The cautions above apply unchanged: show the command before running it,
    never run it unasked, keep the GUI responsive, and leave an actionable
    message on every failure. The new captions are translated strings for the
    catalog lane.

DONE WHEN

  * On a machine without `gh`, Install leaves it installed and logged in, and
    spacr/qt/ai/github_auth.py gets a token without the user opening a
    terminal.
  * The account button opens GitHub's sign-up page.
  * A user who declines any step is left with a working screen and the command
    still visible.
