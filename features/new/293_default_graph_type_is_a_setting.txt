293 — The default graph type is a setting, and it governs every graph

Status: MOSTLY DONE — the mechanism is in place and the live Qt graphs consume
        it; the Matplotlib pipeline figures do not yet. Verified against the
        tree 2026-09-14.

        THE MECHANISM. `spacr.graph_types` is the chokepoint, and it is Qt-free
        so a headless render answers the same question the same way:
          - `chosen_for` (graph_types.py:240) reads the saved DEFAULT GRAPH
            TYPE for a data shape and returns "" for "nothing was chosen",
            which is a different answer from the table's own default;
          - `default_for` (:272) is `chosen_for(shape) or DEFAULTS[shape]`;
          - `start_for` (:350) is the one call a widget makes: it returns
            `(graph_type, note)`, taking the caller's OWN starting form as the
            fallback, and falling back OUT LOUD when the saved choice cannot
            be honoured;
          - `too_thin_for` (:319) with `HIDES_THE_OBSERVATIONS` (:87) and
            `MIN_N_FOR_DISTRIBUTION` (:103) is the "violin of two points"
            rule;
          - `MARKS` (:67) with `mark_for` (:290) / `type_of_mark` (:301)
            translates between the graph-type vocabulary the setting is stored
            in and the mark vocabulary the live plots draw with.

        THE CONSUMERS THAT NOW HONOUR IT.
          - `grouped_plot.PlotSpec.default_kind` — already did, through
            `default_for`. Unchanged (not this session's file).
          - `fast_plots.GroupedPlot` — Control separation and Guide agreement,
            the live regression panels. `DATA_SHAPE` (fast_plots.py:7544) says
            which saved answer applies, `starting_mark` (:7563) reads it,
            `_settle_mark` (:7595) re-reads it once the group sizes exist, and
            the two draw paths call it (:7778, :7959). `set_mark` settles the
            mark (:7642) so right-click still wins afterwards, and the
            fallback sentence goes on the plot through `mark_note` (:7677).
            With nothing chosen, `DEFAULT_MARK` is unchanged — a preference
            nobody expressed must not move existing views.
          - `measurement_compare_dialog` — the plot box opens on the saved
            choice (`_plot_to_start_on`, :713, called at :199), and keeps the
            panel's own first plot for a choice this panel cannot draw
            (`_PLOTS_OF_KIND`, :102).

Asked 2026-08-28.

In settings there is a DEFAULT GRAPH TYPE -- Bar, Jitter, Bar+Jitter, Box,
Violin, and so on -- and it decides which graph is drawn FIRST, along with
that graph's own settings.

Today Regression has most of this: it draws bar-with-jitter and the user can
right-click to change it. The right-click menu is right; the starting point is
not. The setting must dictate what is drawn from the start.

THE SAME BEHAVIOUR FOR EVERY GRAPH IN SPACR, not only Regression: the setting
chooses the initial form, and right-click still changes it afterwards.

2026-09-15 -- THE ml.py THIRD OF "WHAT STILL DOES NOT" IS DONE
--------------------------------------------------------------------------------

The note above named four holdouts and said "each is a one-line change once
its owner points it at `graph_types.start_for`". The first is done:

  * `spacr/ml.py:7306,7337,7357` -- the three regression QC figures, hardcoded
    `'graph_type':'jitter_bar'`. They now read the setting through
    `ml.qc_graph_type_and_note()`, and the fallback IS the old literal, so a
    user who has chosen nothing sees exactly the figure they saw before.

IT WAS NOT ONE LINE, AND THE REASON IS WORTH KEEPING. The two halves of spaCR
do not spell graph types the same way:

    graph_types stores        bar_jitter     box_jitter
    spacrGraph draws          jitter_bar     jitter_box

`mark_for` is the translation, and a substitution that skips it hands
matplotlib a name that `plot.py:3963`'s own error message lists as unknown.
All six types that FIT `categorical_continuous` were checked to translate to
something `spacrGraph` draws.

The shape is `categorical_continuous` for all three: one measurement grouped
by `plateID`.

EIGHT TESTS, three mutations, each caught:

    skipping mark_for        3 failed   (the vocabulary trap above)
    dropping the fallback    2 failed   (a preference nobody expressed moves
                                         an existing view)
    default_for not start_for 2 failed  (the user's choice ignored)

AND ONE OF THOSE TESTS BRIEFLY "FOUND" A DEFECT THAT WAS ITS OWN. It patched
`graph_types.chosen_for` to return "scatter" and then asserted that the QC
figures were handed `points`, which `spacrGraph` cannot draw. But the rule
"a saved choice that does not FIT the data is not a choice for it" lives
INSIDE `chosen_for`, so patching it out asserted about a state the
application cannot reach. Patching the PREFERENCE instead exercises the real
rule, and the real rule is correct: a saved `scatter` is dropped and the
figures keep their own form.

THE THREE THAT REMAIN
--------------------------------------------------------------------------------

  * `spacr/settings.py:1029,5613,5790` -- `setdefault('graph_type',
    'jitter_box')` for the pipeline figures. NOT TAKEN TONIGHT: the other
    session has settings.py open for a new key in the same window, and two
    edits to one file across two sessions is the collision this protocol
    exists to avoid. It is the same shape as the ml.py fix, with
    `fallback='jitter_box'` to hold existing behaviour.
  * `spacr/qt/widgets/graph_spec.py:455` `infer_kind` -- the Graph Builder
    infers BOX for one categorical against one continuous and never asks.
    Different in KIND from the other three: `infer_kind` answers "what kind of
    chart do these columns imply", which is a question about the DATA, while
    the setting answers "which of the fitting types do I want first". Those
    can disagree honestly, so this one needs a decision before a patch, not
    just a call site changed.
  * `spacr/plot.py` `spacrGraph` -- takes whatever it is handed, which is
    correct for a drawing primitive. It is on the list as the place the
    vocabulary lands, not as a caller to change.
