EASY MODE: A CONTENT-GUIDED HOME WITH AN ANIMATED PATH AND DROP FIELD

Status:    COMPLETE — sparse workflow navigation and cleared-input live field validated; published with this change
Requested: maintainer, 2026-10-26
Owner:     Codex integration; G1 Home UI; G2 registry/workflow mapping; G4 inference; root publication
Related:   startup options, Preferences, Home, dock, spaCR AI

REQUIRED BEHAVIOUR

1. Add an Easy mode boolean directly below spaCR AI in the Start spaCR
   window and in the appropriate Preferences section. Default: off.
   Keep the startup and Preferences choices consistent.

2. When enabled, replace Home with a simple central field where the user
   can type a file or folder path, or drop a file or folder. Accept drops
   anywhere in the Easy mode window, not only over the field.

3. Hide the dock and module icons by default in Easy mode. Let the user
   turn the dock back on while keeping Easy mode enabled.

4. Inspect the supplied file or folder and suggest appropriate spaCR
   modules and next steps based on its contents. Suggestions must open
   the relevant module with the supplied input available to that module.
   Handle invalid paths, unsupported contents and ambiguous inputs with
   clear, useful feedback.

5. Animate the area around the central field. Suggestions should appear
   with polished animations at varied, randomly chosen positions around
   the screen, while remaining readable, clickable and within the window.
   Keep the input field usable and avoid overlapping active controls.

LATEST MAINTAINER DESIGN (2026-10-26; supersedes the initial preview)

The center contains only one rounded, somewhat transparent path/search field.
Its gray placeholder is exactly "Type a path or Drop some images here ...".
Browse sits inside the far-right end as white text without button chrome.
Use Open Sans Light throughout. Remove the title, explanatory panel, Find next
steps button and local dock checkbox; keep saved dock choices in Preferences.
Keep the Easy Home backdrop dark even under the global Light theme; restore the normal module backdrop on exit without changing global theme or palette preferences.
Retain the existing dark blue dotted field colors, with only a subtle bounded
CPU gravity effect. Respect Reduce motion/off and stop hidden animation.
Suggestions may animate after input, remain readable and never overlap it.

CONTENT AND ESSENTIAL-SETTINGS EXTENSION (2026-10-26)

Accept image drops anywhere in the spaCR window. Inspect bounded, read-only
filename samples against the existing microscope/regex conventions, sibling
images, parent/master folders, image subdirectories and local metadata.
Present useful module choices with honest confidence and ambiguity guidance;
never decode full image arrays, access the network or process source images.
Suggestions emerge slowly at genuinely randomized safe coordinates from the existing field,
using stable normalized anchors per inspection and legal disjoint positions on resize,
with a tasteful icon, module name, short description and explicit Open action.
Every module opened while Easy mode is enabled starts with Essential settings
only, while preserving a clear way to expand the other settings. Ordinary-mode
defaults and saved choices remain unchanged.

SUGGESTION EMERGENCE (2026-10-26)

Each suggestion grows slowly from a point to its final rectangle, visibly
emerging from underneath the existing spaCR field. The field must gradually
part as the card expands; once it finishes, ripple from the new card's edges.
The final card sits above the field. Couple the visible geometry and local
field displacement through bounded existing effects, preserve its colors,
and skip motion when Reduce motion or animation is off. Opacity alone does
not meet this interaction contract.


GRID AND INPUT CORRECTIONS (2026-10-26; supersedes random placement)

field; reveal them sequentially from left to right. Enlarge module icons,
make each entire card clickable, and remove its separate Open button.

rounded field. Give the field a rim using spaCR's existing chasing blue
effect. Only a click on the search field triggers an Easy-mode ripple;
drops, cards and automatic emergence must not trigger ripples. Other
modules retain their normal ripple behavior.
A file or folder drop anywhere in spaCR must remain on Easy Home and
inspect there, with no module navigation before an explicit card click.
Recognize valid CQ1 TIFFs and sibling images, inspect actual parent spaCR
analysis outputs, and offer Generate Masks for the containing image folder,

matching real outputs justify them. Do not label a valid image unsupported.

an artifacts/cache database for the Database Browser suggestion.
Sample up to 100 filenames initially, distributed usefully across channels
and wells, with only a few representative image-header reads. Expand filename
sampling to at most 1,000 only when the initial sample is inconclusive;
never default to 1,000 header parses. Reserve a separate bounded parent
analysis-output budget so large raw-image folders cannot starve discovery.
Easy mode is the general spaCR entry point for every image/container format
supported by the actual import/readers and all existing metadata structures,
not a separate format whitelist. Reuse shared import capabilities and metadata
adapters for filenames, embedded metadata, siblings, bounded subfolders and
parent analysis outputs, including Zeiss, Nikon, Thermo Fisher and Leica.
Try existing microscope filename presets without decoding image arrays.
When a required reader is unavailable, offer the real Import/install route
instead of falsely declaring the input unsupported. Preserve valid source,
metadata and confirmed regex state through module handoff without asking the
user to repeat configuration.
When none validates, make the first suggestion an editable regex card with
the existing white regex icon, proposed pattern and image path underneath.
Color corresponding capture groups in both pattern and path consistently.
Editing remains native; an explicit card click validates and applies the
pattern, regenerates module suggestions, and passes the validated regex to
actual downstream module settings. No external regex file is required.
G1 owns UI/routing/closure; retained G4 owns bounded inference and real-file
regressions. Work remains isolated; root alone integrates and publishes.
