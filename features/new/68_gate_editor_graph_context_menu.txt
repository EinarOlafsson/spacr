================================================================================
GATE EDITOR: RIGHT-CLICK THE GRAPH FOR EVERYTHING YOU CAN DO TO IT
================================================================================

Status:    done 2026-08-09
Requested: 2026-08-09 — "in gate editor right clicking on the graph should give you as many options as possible to edit the graph including to save the graph."

--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

The gate editor's canvas has no context menu. Saving exists but only as the
"Save graph…" button added for instruction 50; axis choice, gate actions
and display settings are spread across the panel and a settings dialog.

`GateCanvas` (spacr/qt/widgets/gate_editor.py) extends `GraphCanvas`, which
already owns the figure and the spec, so it has everything a menu would
need to act on.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Right-clicking a plot is where people look for plot actions. Every one of
these is currently reachable, which makes this discoverability rather than
capability -- but a feature nobody finds is a feature nobody has.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. A context menu on the canvas. Candidates, most useful first:
       Save graph as…            (reuse GateEditorScreen.save_graph)
       Copy to clipboard
       Reset zoom / fit to data
       Change X / Y axis         (submenus of available columns)
       Toggle log X / log Y
       Point size, opacity       (or "Display settings…" to the dialog)
       Colour by…                (column submenu)
       Clear gates / delete gate under the cursor
       Export gated rows         (reuse export_gates)
2. Reuse the existing actions rather than reimplementing them -- the menu
   is a second route to the same code, and two routes that drift apart is
   worse than one route.
3. Act on the CLICKED point where it matters: "delete gate under the
   cursor" needs the gate hit-tested at the click position, which
   GateCanvas already does for dragging.
4. Keep it working when there is no figure yet: an empty canvas should show
   a short menu or none, never a menu whose items raise.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

Right-click the gate editor's graph: a menu appears, Save graph writes the
same file the button does, and each item either acts or is greyed with a
reason.

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

Not started. Note `_ZoomView` already consumes left-press for panning and
emits `clicked` on a release under 4px; a right-click menu must not disturb
that, and the two should be tested together.

--------------------------------------------------------------------------------
2026-08-09 - DONE
--------------------------------------------------------------------------------

Right-clicking the plot offers: Save graph, Copy image to clipboard, Reset
view, Graph settings, Export gates to the database.

Every item CALLS an existing method. The menu is a second route to the same
code, never a second implementation -- two routes that drift apart are
worse than one, and this codebase has already paid for that twice (the same
Cellpose model-type bug written into two preview panels).

THE CONTENTS ARE DATA, which is the part worth keeping.
`graph_menu_items()` returns `[(label, enabled, callback, why)]` and
`_show_graph_menu` renders it. That split exists because an offscreen Qt
CANNOT GRAB for a popup: a test that builds a real menu hangs the run, and
two probes did exactly that before the design changed. Now the contents are
testable without a display and the rendering is three lines.

Disabled items carry a reason -- "Draw a graph first." -- because a greyed
row with no explanation is a dead end that looks like a bug.

7 tests, 80 pass across the gate suites.

NOT INCLUDED, and worth stating: per-point actions such as "delete the gate
under the cursor" or axis submenus. Those need hit-testing at the click
position and a column list, and the menu is useful without them. The
existing `_ZoomView` click/drag boundary was left untouched, so panning
still works.
