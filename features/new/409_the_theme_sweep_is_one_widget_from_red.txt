================================================================================

--------------------------------------------------------------------------------
THE MARGIN, WHICH IS ONE
--------------------------------------------------------------------------------

`test_the_real_window_wears_one_theme_everywhere` samples the window's widgets
with a stride -- `hosts[::len(hosts) // 200]` -- and asks each sampled widget
whether the theme reached it.

TWO WIDGETS IN THE WINDOW ARE GENUINELY NOT REACHED, by design:

    QWidget#CentralRow      index 6 in window.findChildren(QWidget)
    QStackedWidget          index 9

and the sample is currently `hosts[::10]`. INDEX 6 AND INDEX 9 AGAINST A
STRIDE OF 10. One extra chrome widget anywhere ahead of them in the traversal
puts the stack into the sample and the test fails with

    ['QStackedWidget', 'QWidget']

which is the SAME SHAPE as the `['QComboBox']` failure that was just debugged
for a day: a test reporting "the theme did not reach this" when the theme is
working exactly as designed.

--------------------------------------------------------------------------------
WHY THOSE TWO ARE UNREACHED ON PURPOSE
--------------------------------------------------------------------------------

`MainWindow.stylesheet_roots` deliberately excludes the central widget and the
stack -- it nominates the chrome and the page that is actually showing, and
the pages that are not showing are MARKED instead and sheeted on their own
`showEvent`. That is the per-screen sheeting design and it is right.

But the central row and the stack are not marked either, so the test's
`deferred()` branch does not cover them. They are legitimately outside the
sweep and legitimately outside the exemption, which is exactly the gap a
stride can fall into.

--------------------------------------------------------------------------------
THE TWO WAYS TO FIX IT, AND WHY NEITHER IS A REVIEW FIX
--------------------------------------------------------------------------------

  * MARK THEM PRODUCT-SIDE with `_spacr_is_a_sheet_target`, so `deferred()`
    covers them and the sample may contain them harmlessly. This changes
    product behaviour -- they would then be sheeted on their own show -- and
    that is a theme decision, not a test decision.
  * GIVE THE TEST A NAMED, GUARDED EXEMPTION: these two, by objectName and
    class, with an assertion that there are exactly two and that each is the
    widget the exemption names. A bare skip-list would rot into a blindfold,
    which is the failure mode this whole test family exists to prevent.

THE SECOND IS PROBABLY RIGHT and it is still bigger than it looks, because the
exemption has to fail loudly when the design changes rather than quietly
covering a third widget that should have been swept.

--------------------------------------------------------------------------------
WHAT NOT TO DO
--------------------------------------------------------------------------------

DO NOT WIDEN THE STRIDE OR SAMPLE FEWER WIDGETS. That hides the margin instead
of removing it and makes the next failure rarer and therefore harder to
diagnose. The sample size is not the defect; the uncovered pair is.

DO NOT ASSUME A `['QStackedWidget', 'QWidget']` FAILURE IS A REGRESSION. Check
it against the WHOLE population first -- that is the lesson the combo day
bought, and this file exists so it is bought once.

--------------------------------------------------------------------------------
2026-09-19 — THE EXEMPTION, BY IDENTITY AND GUARDED THREE WAYS. THE STRIDE IS
             UNCHANGED.
--------------------------------------------------------------------------------

WHICH OF THE TWO FIXES, AND WHY. This file leaned toward the test-side
exemption, and reading the code agrees. Marking the central row and the stack
with `_spacr_is_a_sheet_target` would make them sheeted on their own show,
which changes the product to serve a test. `stylesheet_roots` leaves them out
on purpose, because sheeting the central widget would repolish every screen
in the stack, and avoiding that is the whole point of per-screen sheeting. So
the product is untouched.

MEASURED FIRST, AGAINST THE WHOLE POPULATION, as the WHAT NOT TO DO section
asks. On a real MainWindow with Mask and Measure open (2,086 hosts, stride
10), every host was probed, not just the sample. The widgets that are
neither sheeted nor deferred are exactly
[QWidget#CentralRow, QStackedWidget]. They are still at indices 6 and 9. The
full probe took 0.7 s at this size.

THE MARGIN, SHOWN RATHER THAN ARGUED. Moving the sample start through all ten
offsets of the stride gives this for HEAD's filter:

    offset 6   misses ['QWidget']          (the central row)
    offset 9   misses ['QStackedWidget']   (the stack)
    the other eight offsets miss nothing

With the exemption, all ten offsets miss nothing. A new chrome widget ahead
of these two in the traversal moves the offset, so this is the failure the
file predicted, and it can no longer happen.

WHAT THE TEST NOW HOLDS (tests/qt/test_every_widget_wears_the_current_theme.py):

  * `_unreached_by_design(window)` names the two widgets by what the window
    calls them: `window.centralWidget()` and `window._stack`. The sampled
    check excludes exactly those two objects by identity. Another
    QStackedWidget anywhere else is not covered.
  * GUARD 1, THE WHOLE WINDOW. Every host is walked up to the window. The ones
    under no widget that `stylesheet_roots()` returns and under no deferred
    page must be exactly the two named widgets. This check uses no probes,
    so it covers the whole window for the cost of the parent walks.
  * GUARD 2, THE NAMES. The central widget must be a plain QWidget named
    "CentralRow", and `_stack` must be a QStackedWidget.
  * GUARD 3, STILL UNREACHED. Each exempt widget is probed directly, and each
    must still NOT wear the sentinel. If the theme starts reaching one, the
    exemption for it is stale and the test says to remove it.
  * The closing "nothing was deferred" assertion now counts only deferred
    widgets. Before, it was `len(stale) - len(missed)`, which would have
    counted an exempt widget as deferred.

EACH GUARD PROVEN TO FIRE. The product file was restored byte-identically
after each mutation (sha256 f73052af…e405 before and after):

    stylesheet_roots returns roots + [central]    -> GUARD 1 red: outside = []
    stylesheet_roots drops its first root          -> GUARD 1 red: the menu bar,
                                                      WindowChrome and its three
                                                      buttons join the two
    CentralRow.setStyleSheet(SENTINEL) (probe)     -> GUARD 3 sees both widgets
                                                      reached

The whole file passes: 14 passed in 12.8 s, slow tests included.
