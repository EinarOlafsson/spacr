--------------------------------------------------------------------------------
WHAT EACH MODULE TAKES
--------------------------------------------------------------------------------

All three read `<src>/measurements/measurements.db`, the output of Mask then
Measure (`analyze_replication`, `analyze_invasion`, `analyze_recruitment` in
`spacr/submodules.py`). None of them segments. So an example is a slice of a
real screen's database, plus a couple of merged fields so the objects can be
looked at -- Recruitment also draws its outline overlays from `merged/`.

Built by `tools/build_assay_example_datasets.py` from local copies under
/mnt/wd4tb/spacr_testdata/assays/ (the script refuses a /nas_mnt source).

WHY THESE TWO PLATES. The THP-1 plate's own `settings/recruitment.csv` is the
file `analyze_recruitment` saves -- that screen was analysed with this module,
and its settings (channel_of_interest 1, nc=c1, pc=c2) are what ships, with
`src`, `cell_types` and `plot_nr` changed. The MTOC plate's pathogen mask is
segmented from the parasite stain and splits vacuoles into parasites, with up
to 20 objects per host cell, which is what a parasites-per-vacuole count
needs; the pv_counts stacks on /mnt/wd4tb carry vacuole masks only (one
object per vacuole) and no parasite channel, so they cannot be counted.

--------------------------------------------------------------------------------
WIRING
--------------------------------------------------------------------------------

  spacr/example_archives.py   the two sets join EXAMPLE_SETS, each with its
                              own folder (`ExampleSet.folder`), because both
                              ship `measurements/measurements.db` and the
                              shared plate already has one.
  spacr/cli_download.py       unpacks each set into its own folder.
  spacr/qt/assay_examples.py  the button and the load: cached copy used
                              as is, otherwise the shared tar worker, then
                              the shipped settings are applied and src set.
  spacr/qt/screens/app_screen.py  EXAMPLE_DATA_SECTIONS gains both modules.

--------------------------------------------------------------------------------
MEASURED
--------------------------------------------------------------------------------

Each archive unpacked, its settings read through `settings_from_pack` (none
dropped), and the module run on CPU:

  Replication  13.5 s. 3,406 pc / 3,362 nc vacuoles (spatial). 71% / 73%
               single-parasite vacuoles, 11% off the power-of-two ladder in
               both. Mann-Whitney on log2 count p = 0.0099 between the two
               screen controls -- not a replication claim.
  Recruitment  40 s. 2,026 cells in 12 wells after the merge (348 cells have
               no nucleus row in the screen's own database). Per-well
               recruitment ratio nc 5.07 +/- 0.56, pc 4.87 +/- 0.23. Two
               overlay PDFs, cells.csv, wells.csv.

Both buttons also driven headless end to end against the LIVE repositories:
click, real download into a scratch HOME, settings in the panel, the panel's
own `collect()` handed to the module -- the same numbers as above. A second
press used the cache without a request. `validate_settings` finds nothing in
either shipped settings file.
