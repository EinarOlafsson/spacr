--------------------------------------------------------------------------------
WHAT EACH MODULE TAKES
--------------------------------------------------------------------------------

All three read `<src>/measurements/measurements.db`, the output of Mask then
Measure (`analyze_replication`, `analyze_invasion`, `analyze_recruitment` in
`spacr/submodules.py`). None of them segments. So an example is a slice of a
real screen's database, plus a couple of merged fields so the objects can be
looked at -- Recruitment also draws its outline overlays from `merged/`.

to 20 objects per host cell, which is what a parasites-per-vacuole count
needs; the pv_counts stacks on /mnt/wd4tb carry vacuole masks only (one
object per vacuole) and no parasite channel, so they cannot be counted.

================================================================================
INVASION: SYNTHETIC, CLEARLY LABELLED -- BUILT 2026-09-21
================================================================================

DECIDED. Asked through the question prompt, answered verbatim: "Synthetic,
clearly labelled (Recommended)". The option read: ship the same kind of
synthetic two-colour images the module was developed on, run through
Mask/Measure so it has a real measurements.db, with the dataset card and the
button tooltip saying 'synthetic'.

WHAT THE MODULE WAS DEVELOPED ON. Not images: `tools/tutorials/authoring/
tools/prepare_invasion_tutorial_data.py` writes the tutorial's pathogen rows
straight into a database (c1 a no-primary staining control, two conditions
with a known invaded fraction). No image generator existed to reuse. So
`tools/build_invasion_example_dataset.py` renders that design as pixels with
`spacr.qt.synthetic`'s lattice, object shapes, noise and naming:

    c1 staining control (no outside stain)  c2 vehicle 70% invaded
    c3 inhibitor 35% invaded                rows A-D, 2 fields/well, 512 px
    channels: 0 nucleus, 1 cell, 2 total parasite stain, 3 outside stain
    one attached parasite in ten drawn at a quarter brightness

The tutorial's fractions (vehicle 0.40, inhibitor 0.70) had the inhibitor
RAISING invasion; these are turned the biological way round.

WHERE THIS DEPARTS FROM THE DECISION, AND WHY. The masks are the objects the
generator drew, written in the planes Mask would write; Measure is spaCR's
own and made the database. Mask with Cellpose-SAM on CPU did not finish one
plate row (6 fields) in 40 minutes: the 10-px parasites make Cellpose upscale
the pathogen channel threefold, and the machine was at load 36 on 32 cores.
A single-field probe was still running after 20 minutes. The GPU was not to
be used. `--segment` on the builder runs Mask instead; rebuild with it on a
free GPU to make the set match the decision exactly. The card, the tooltip,
the set summary and the builder all say the masks are drawn.

PUBLISHED. einarolafsson/spacr-example-invasion, spacr-example-invasion.tar,
106,915,840 bytes: 24 merged stacks, measurements.db (1,713 pathogen, 1,536
cell rows; build paths stripped), ground_truth.csv (every drawn parasite and
its state) and settings/invasion_settings.csv (outside_channel 3,
total_channel 2, stain_baseline_wells ['c1'], vehicle c2, inhibitor c3).

RUN, on the unpacked archive and again through the button against the live
repository (same numbers both ways), CPU, 21 s:
