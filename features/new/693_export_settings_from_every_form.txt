================================================================================
EXPORT SETTINGS FROM EVERY FORM
================================================================================

Status:    built 2026-10-12 (not alpha); ships in 1.5.1.5; translations of the
           new strings pending (WS)
Requested: GitHub issue EinarOlafsson/spacr #140 by @jak18015 (duplicated as
           #141 and #142): "Measure (and other screens): add 'Export
           settings…' to save the current form as a settings CSV".
Owner:     Home (build); WS (translations)
Related:   spacr-run (spacr/cli.py) and its settings loader; Distributed Jobs
           (Submit remote…); spacr.utils.save_settings / load_settings.

--------------------------------------------------------------------------------
WHAT THE STATE WAS
--------------------------------------------------------------------------------

Every module form (AppScreen) had "Import settings…" but nothing wrote the form
to disk. save_settings() runs only inside a pipeline, after file listing,
calibration, PSF and SQLite setup, so on a slow network mount the CSV came
late, and a stopped run left none. "Submit remote…" snapshots the form to
Distributed Jobs and writes no file. The workaround (get_*_settings() plus
save_settings() in a script) used defaults and lost every GUI change.

--------------------------------------------------------------------------------
WHAT WAS BUILT
--------------------------------------------------------------------------------

1. "Export settings…" right after "Import settings…" on every AppScreen form
   (one implementation in spacr/qt/screens/app_screen.py, so every module
   form, including both Cellpose workbench tabs, has it).
2. It collects the form exactly as Run does (SettingsModel.collect()), opens a
   save dialog offering <module>_settings.csv in the src folder (else the
   folder of the last imported/exported settings CSV, else home), and writes
   the file. No run starts and nothing is listed or opened.
3. spacr.cli.write_settings_file (public, the inverse of load_settings_file):
   the save_settings layout -- Key,Value header, dict order, None as an empty
   cell, str() of every value -- plus a .json copy beside it, as save_settings
   writes. Differences from save_settings: test_mode/plot are kept as the form
   has them, and a float whose str() is exponent-only (1e-05) is written
   positionally (0.00001) so the loaders read a float, not a string.
4. Paths are written exactly as shown. spacr.portable_paths has no portable
   form for settings (it re-roots crop paths in databases); cluster paths are
   changed with spacr-run --set src=... or a Distributed Jobs profile's
   dataset roots.
5. Distributed Jobs: "Save settings CSV…" beside Browse, enabled while a
   Submit remote… snapshot is loaded, writes that snapshot with the same
   function. Submit is unchanged.
6. SettingsModel.set_hidden_value: None leaves an empty-string hidden setting
   as "" (a CSV writes both as an empty cell), so the Timelapse form's hidden
   text settings round-trip exactly.
7. Docs: docs/source/distributed_execution.rst, "Settings files from the GUI".

Tests: tests/qt/test_n693_export_settings_from_every_form.py (button placement
and a non-default round trip on every AppScreen key, listing and run patched
to raise; non-GUI loaders; spacr-run measure --dry-run),
tests/qt/test_n693_distributed_jobs_saves_the_snapshot.py,
tests/test_n693_write_settings_file.py.

New English strings for WS: "Export settings…", "Export settings CSV",
"Export failed", "Saved {count} settings to {path}\n", the Export hint, "Save
settings CSV…", its tooltip, "Could not save the settings: {error}", "Saved
the settings to {path}. On the cluster run: spacr-run {module} --settings
{name}", and the docs section above.

2026-10-12 — built and pushed to nightly (Home). Round trip measured on all 23
AppScreen keys: no value drifted after Export, a fresh form and Import.
