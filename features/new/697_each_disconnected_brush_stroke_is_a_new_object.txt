================================================================================
MAKE MASKS: EACH NEW DISCONNECTED BRUSH STROKE IS A NEW OBJECT LABEL
================================================================================

Status:    new 2026-10-13
Requested: maintainer, 2026-10-13: "in make mask when using the brush tool,
           each new disconnected brush stroke should be a new object label."
Owner:     Home (build); WS (tutorial lesson 14 brush clips, translations)
Related:   Make Masks editor brush tool (spacr/qt/screens/make_masks.py),
           wand/divide/merge tools, undo stack, lesson 14 drawing clips 07-08.

--------------------------------------------------------------------------------
WHAT TO BUILD
--------------------------------------------------------------------------------

1. A brush stroke (press, drag, release) that does not touch any existing
   object paints a NEW label: the next free label id in the mask.
2. A stroke that starts on, or touches, an existing object extends that
   object (same label), as today. Decide and document the rule for a stroke
   that touches two objects: it extends the object the stroke started on and
   never merges labels silently (merge stays an explicit tool).
3. Two strokes are "disconnected" when their painted pixels share no 8-
   connected (2-D) / 26-connected (3-D) neighbour with each other or an
   existing object. Holding a modifier (e.g. Shift) continues the current
   label even across gaps, so one object can still be drawn in pieces; show
   the modifier in the hint strip and the shortcut overlay (tr()).
4. Erase never creates labels; undo/redo restore the label ids exactly.
5. 3-D volumes: the rule applies per stroke in the current slice, and a
   stroke touching the same label in the adjacent slice extends it.
6. Label colours follow the existing palette so new objects are visibly
   distinct immediately.

--------------------------------------------------------------------------------
ACCEPTANCE
--------------------------------------------------------------------------------

- Three separate strokes on empty ground give three labels; a stroke from
  inside object 5 outward stays 5; Shift-strokes across a gap stay one label.
- Undo after each case restores the previous mask byte-for-byte.
- Saved masks and the object table show the new objects; tests cover 2-D
  and 3-D.

--------------------------------------------------------------------------------
BUILT 2026-10-13 (Home, branch feat-697-brush-labels on makemasks-paint; not
pushed, ships after 1.5.1.5)
--------------------------------------------------------------------------------

THE RULE, in _MaskCanvas._begin_brush_stroke / _stamp / _end_brush_stroke:
- A stroke that starts on an object paints that object's id.
- A stroke that starts on background paints the next free id (2-D: one past
  the mask's maximum, engine.next_label; volume: the first id the volume does
  not use) until its painted pixels first touch an object, 8-connected in
  2-D and 26-connected in a volume (the sections either side of the shown one
  count); from then on the whole stroke is that object.
- Two objects touched: the stroke extends the first one it met (nearest to
  the segment start on a tie) and paints over the other's edge; it never
  merges them. Merge stays the Divide / Merge tool.
- Shift + drag with the Brush paints the current label across a gap: the
  last stroke's label on a 2-D field, the chosen object in a volume. A 2-D
  Shift piece that never reaches its object sets manual_ids, like a merge,
  so saving keeps the pieces as one id (undo restores the flag by digest).
- A binary 255 mask is numbered by connected component at the first brush
  press, as saving would, so a stroke bridging two blobs cannot merge them.
- Erase never creates labels; undo/redo restore the exact array, dtype and
  ids (MaskHistory copies, volume history for 3-D).
- In a volume, commit_plane keeps the stroke's id (replace_plane keep=) and
  selects it, so a later Shift stroke continues it.
- New objects take their colour from the existing label palette, so each is
  distinct as soon as it is painted.

DECISION FOR THE MAINTAINER: Shift + left drag used to pan from every tool.
With the Brush it now continues the label; Alt + drag pans from every tool
and Shift + drag still pans with every other tool. The existing panel row
"Shift or Alt + drag / Pan, from any tool" and the zoom-per-notch tooltip
are left word for word, because reviewed fr/pt/sv runtime records bind that
source and changing it makes the catalog build refuse them as stale; a new
row under it, "Brush: Shift + drag / Keep painting the last object across a
gap", states the exception. Rewording the pan row is for the translation
lane. Lesson 14 clips that pan with Shift while the Brush is held need
re-recording (WS).

NEW STRINGS (tr, need translating): the Brush button tooltip, shown in the
hint strip, "Each separate stroke paints a new object; a stroke that starts
on or touches an object extends it. Hold Shift to keep painting the last
object across a gap."; shortcut row "Brush: Shift + drag" and "Keep
painting the last object across a gap".
