--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

The same two features are built more than once.

LIVE VIEWS
    spacr/qt/widgets/live_preview.py        Mask -- the fullest one
    spacr/qt/widgets/timelapse_preview.py   Timelapse
    spacr/qt/widgets/measure_preview.py     Measure
    spacr/qt/widgets/motility_preview.py    Motility
    the Image UMAP explorer, which is a live view by another name

HYPERPARAMETER SEARCHES
    spacr/qt/screens/hyperparam.py :: HyperparamPanel, shared by umap,
    classify, ml_analyze and activation -- already one implementation, and
    the Gate Editor's clustering search is meant to join it (instruction 49).

Evidence they have already diverged, all found this session: both preview
panels passed `model_type=` to Cellpose 4, which accepts and IGNORES it, so
a user's own trained checkpoint was silently discarded -- the SAME bug in
two files, fixed twice. And the search panel's figure grid works in tests
while the user still sees one PNG at the end (instruction 35).

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Divergence here is not cosmetic. A bug fixed in one preview and not the
other is a bug that stays, and this has already happened: the model-type
defect was written twice and fixed twice, months apart from being
introduced.

For the user it is worse in a quieter way -- the same control means
different things in different modules, so what they learn in Mask does not
transfer to Timelapse.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. INVENTORY FIRST. For each live view: what controls does it show, what
   does the toggle say, where does the figure go, does it debounce, does it
   render off the GUI thread, does it cancel cleanly? Write the table
   before designing anything -- the common elements are whatever the table
   shows in most columns.
2. FIX THE KNOWN DEFECTS BEFORE STANDARDISING, or the standard inherits
   them: instruction 35 (search figures should stream, and be PDFs when
   preferences say so), 67 (the results table's ambiguous score column),
   51 (the gate editor console).
3. EXTRACT what is genuinely shared rather than making four things look
   alike. The Cellpose model resolution is the clearest candidate: one
   helper, called by every preview, so the next Cellpose API change is one
   fix. `spacr.utils._resolve_cellpose_pretrained` already exists and both
   panels now call it -- that is the pattern.
4. STANDARDISE THE VOCABULARY. "Live" means one thing on Mask and another
   on Image UMAP, where the same toggle opens an interactive explorer.
   Decide what the word means and use it that way everywhere, or use two
   words.
5. Make the shared parts BETTER while unifying, not merely uniform: every
   live view should say why it is not previewing when it cannot, and every
   search should show progress that reflects work done rather than trials
   started.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

A user who learns the Mask live preview can use the Timelapse and Measure
ones without relearning; a bug fixed in one is fixed in all because there
is one implementation; and the inventory table from step 1 shows no column
where one module is alone.

2026-08-13 - DONE. THE FILE'S "not started" WAS WRONG, AND THIS IS THE SEVENTH
--------------------------------------------------------------------------------

Every one of the five steps is shipped, in `spacr/qt/widgets/preview_contract.py`:

  1. INVENTORY FIRST -- the table is the module docstring, one column per live
     view, eleven rows.
  2. FIX THE DEFECTS FIRST -- 35, 51 and 67 are all in instructions/done/.
  3. EXTRACT WHAT IS SHARED -- `LivePreviewContract` owns the run guard, the
     cancellation token, the busy/idle button state and the status line;
     `preview_cellpose_model` is the one constructor, so the next Cellpose API
     change is one fix rather than the two it was last time.
  4. STANDARDISE THE VOCABULARY -- "live view" is defined; the Image UMAP
     explorer's toggle says INTERACTIVE because nothing it draws depends on a
     setting; Cancel and Stop are two words on purpose, because a user who
     presses one expecting the other loses either nothing or hours.
  5. BETTER, NOT MERELY UNIFORM -- every view says why it cannot preview
     (Measure used to return in silence), and the search reports trials SCORED
     rather than trials started.

Three of the unified rows were bugs, not taste: Measure's silent refusal,
Timelapse and Motility wiring `QThread.finished` to `deleteLater` while
dropping their own reference -- the race `bridge.make_thread` documents, which
leaves a running thread owned by nobody -- and Measure never announcing its
result at all.

THE SEAM PAID FOR ITSELF THE SAME DAY. Instruction 89 needed the colourblind
display transform on every viewer, and asked for it "behind 69's seam". It
went into `LivePreviewContract.display_primaries` and
`set_preview_status`, so all four panels state their mapping without any of
them containing the code that does it.

This file said "not started". It was the seventh instruction this week to be
