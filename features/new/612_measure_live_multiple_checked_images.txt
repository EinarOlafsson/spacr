WHAT TO DO AND HOW TO KNOW IT WORKED

Add the ability to check multiple images in Measure's Live view and display the objects from all checked images at once.

Requirements:

- Provide image checkboxes or extend the existing checked-selection interface. Multiple images must remain selected simultaneously; clicking another image must not simply replace the previous selection.
- Display the combined object set using the existing live-view presentation. Do not overlay unrelated source images as though they share one coordinate system.
- Keep each object's source image identifiable and preserve the metadata needed to retrieve its correct image and mask.
- Use the real composite identifiers where required. Repeated object IDs in different images must not collide.
- Unchecking an image must remove only its objects. Refresh selections without stale objects, duplicate entries, or dangling references.
- Preserve existing single-image behavior and applicable filters, channels, overlays, and object navigation.
- Handle empty selections, images without objects, and selection changes during loading gracefully.
- Use existing caching/lazy-loading patterns to avoid excessive memory use or interface freezes.
- Do not silently change underlying measurements or export semantics merely because the live display contains multiple images.

**Acceptance:** Test multiple images with repeated object IDs, selecting/unselecting images, an empty selection, images without objects, filters, correct source-image navigation, and reasonable loading performance.

================================================================================
MEASURE LIVE VIEW: CHECK SEVERAL IMAGES AND SEE ALL THEIR OBJECTS
================================================================================

Status:    not started (filed 2026-10-01; scoped, see below)
Requested: 2026-10-01 -- "Add the ability to check multiple images in
           Measure's Live view and display the objects from all checked
           images at once."
Owner:     1.5.1.1 implementation session (Claude)

--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

The Live view is MeasurePreviewPanel (spacr/qt/widgets/measure_preview.py).
One merged .npy is shown at a time: _fov_box is a single-select combo filled
from ImageSetSampler; _on_fov_changed -> load_array_async -> compute_crops
-> _render_grid. Crops are identified only by mask label and list index
(_CropThumb index into self._crops); _selected is a set of list indices.
There is no per-image checkbox and no multi-image grid.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

A checkable image list beside the field combo (the combo stays the
"current" image, unchanged single-image behaviour when one is checked).
Each checked image is cropped on the existing JobRunner with the same
crop settings; results are cached per (path, settings token) with a small
bound, so unchecking removes only that image's crops and re-checking is
cheap. Each crop carries its source (path, field name) and a composite key
(source, label), so repeated labels never collide; tooltips and the
selection use that key. The grid groups by image, then category. Empty
selection and objects-less images show a hint. Nothing in measurements or
export changes.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

tests/qt/test_615_measure_live_multi_image.py: two images with the same
labels give distinct keys; check/uncheck adds/removes only that image;
empty selection; an image without objects; stale results after a
selection change are dropped; filters still apply.

2026-10-01 — IMPLEMENTED AND VERIFIED
Measure Live now has an independent Checked images menu. Checked fields
contribute to one crop grid, grouped by phenotype and source filename. Each
crop retains its canonical source path and (path, object role, label) key;
repeated labels cannot collide. Double-click navigates to that exact source.
Unchecking removes only that source, and an empty selection clears the grid.
Single-field dropdown navigation retains its prior replace behavior. A new
folder starts a new selection; changing the sample retains already checked
fields. Preview selection never becomes a measurement/export selection.

One crop job runs at a time, with only the newest pending request retained.
It streams additional files through read-only NumPy mappings, shares the
existing maximum-crop budget across selected sources, and rejects stale
results and old-grid clicks. Failed sources are named without discarding
valid fields. Existing channels, object settings and filters apply to all.

Validation: final 26-check root cohort passed, including six checked-source
cases and the existing preview-edge/Measure-entry checks. Earlier relevant
cohorts passed the ordinary preview/source-loading checks and 81 additional
checks before two incidental expectation fixes. A 1280x720 rendered panel
with two fields/four crops was inspected at
/tmp/spacr-implementation-20261001/review/measure/checked-images.png.
User guide: docs/source/measure_live.rst. Shared translations, API manifest
and tutorial captures remain in N615; no native-platform claim is added.
