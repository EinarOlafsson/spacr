333 — CUSTOM PATHOGEN MODELS MUST BE AVAILABLE IN LIVE PREVIEW
===============================================================

Status:    DONE, verified 2026-09-15 against the code: the preview seeds from
           the run's own key order, names the model that ran, and states a
           fallback for a checkpoint not on disk. See the dated sections below.

ASKED FOR (2026-09-01)
----------------------
"custom pathogen models should be available in live preview via the same
model zoo mechanism"

WHAT THE STATE IS
-----------------
The model zoo now backs the settings rows: `spacr/qt/widgets/model_zoo_picker.py`
lists what spaCR knows about, downloads a checkpoint with a verified checksum,
and writes its path into the field
(`AppScreen._with_a_model_zoo_button`, `_MODEL_ZOO_KEYS`). `toxoplasma_pv_v1`
is published and registered.

LIVE PREVIEW DOES NOT USE ANY OF IT. `spacr/qt/widgets/preview_contract.py`
builds its Cellpose model through `_resolve_cellpose_pretrained(str(model_name))`
from whatever the preview was handed, so a user who has selected a zoo model
for the RUN gets stock cpsam in the PREVIEW -- and the preview is the thing
they are looking at while deciding whether the settings are right.

That is the worst shape for this defect: the preview does not fail, it
silently previews a different model than the run will use. A user tunes
diameter and thresholds against cpsam's masks and then runs with the
fine-tune, or the reverse.

WHAT TO DO
----------
1. Have the preview read the SAME setting the run reads. For pathogens that is
   `pathogen_model` (honoured end-to-end -- object.py:769-771 into
   `_resolve_cellpose_pretrained`, reached from core.py:432 on the default Mask
   path), falling back to `pathogen_model_name`.
2. Offer the zoo button on the preview's own model control, if it has one, via
   `choose_model(parent, kinds=("cellpose",))`. `kinds` is a rule rather than a
   parameter: the zoo also carries the YOLO well detector, and CellposeModel
   cannot load it.
3. A model that has not been downloaded yet must not stall the preview. Preview
   with what is available and SAY which model produced the picture -- a preview
   whose provenance is unstated is the defect above wearing a different hat.

WATCH OUT
---------
* 310 entry 39: the Mask panel renders NO pathogen model row today. Both
  `pathogen_model` and `pathogen_model_name` are offered by the settings and
  categorised under "Pathogen", and the panel builds a widget for neither,
  because that section is conditional on the run having a pathogen. Until that
  row exists there is nothing on screen for the preview to agree WITH, so 39
  is a prerequisite rather than a related item.
* Downloading 1.2 GB from a preview refresh would be an unpleasant surprise.
  Fetch on explicit request only, as the picker does.

HOW TO KNOW IT WORKED
---------------------
* Selecting a zoo model changes the preview, not only the run.
* The preview names the model it used, visibly.
* A model not yet on disk previews with a stated fallback rather than hanging
  or silently substituting.

STATUS, 2026-09-14 -- DONE
--------------------------------------------------------------------------------

WHAT THE 2026-09-01 ENTRY DID, and it was accurate as far as it went:
`spacr/settings.py:downloaded_zoo_models` puts local zoo checkpoints in the
live menu (`cellpose_live_model_menu`, settings.py:1184), and the Live
settings model row carries the "Model zoo..." button
(`live_preview.py:3915`, `LivePreviewPanel._choose_a_preview_model`, which
passes `kinds=("cellpose",)`). Point 2 of WHAT TO DO was therefore already
satisfied and is unchanged by this pass.

WHAT IT DID NOT DO, and what this pass added:

1. POINT 1 WAS NOT DONE. `apply_settings` read `settings.get("model_name")`
   and nothing else, and MASK DOES NOT DECLARE `model_name`. Measured on a
   Mask `AppScreen` built from this tree: `_settings_model.collect()` carries
   `cell_model_name`, `nucleus_model_name`, `organelle_model_name`,
   `pathogen_model_name` and `pathogen_model`, and no bare `model_name`. So
   the combo was NEVER seeded from Mask -- the exact defect the item
   describes was still live, in the read the 2026-09-01 entry did not touch.

   Now `LivePreviewPanel._seed_the_model` (live_preview.py:2626) seeds from
   `_model_the_run_would_use` (live_preview.py:1195), whose key order is the
   RUN's own, held in `_model_keys_for` (live_preview.py:1161):
   `pathogen_model` then `pathogen_model_name` then `model_name` for
   pathogens, `<object>_model_name` then `model_name` otherwise. A key
   present-but-None does not count, which is how Mask spells an unset
   `pathogen_model` and how the run tests it.

   AND THE PANEL FOLLOWS THE OBJECT SELECTOR onto that object's model --
   `_reseed_the_model_for_the_object` (live_preview.py:2667), called from
   `_on_primary_object_changed`. Without it the pathogen case never fires at
   all: the panel opens on `cell`, so a user who switches to `pathogen` to
   look at the parasites would still have been shown cpsam. A model the user
   picked by hand is never overwritten (`_model_seeded_to`).

2. POINT 3 WAS NOT DONE. Nothing on the panel said which model made the
   picture; the status line read "Found cell=12." and stopped. It now reads
   "Found cell=12.  Model: <name>." -- `_model_provenance`
   (live_preview.py:3385), used at live_preview.py:3762 -- and names the
   model that RAN rather than whatever the combo holds now, so changing the
   combo (which does not re-segment) cannot mislabel the masks. The run
   history records the same (`_snapshot_run`).

   A checkpoint that is not on this machine no longer costs the preview:
   `_checkpoint_is_missing` (live_preview.py:1219) tests exactly what
   `spacr.utils._resolve_cellpose_pretrained` RAISES on, and
   `_model_for_this_pass` (live_preview.py:3366) previews with cpsam and
   returns the clause that says so. The run still stops; the preview states
   the substitution instead of making it in silence.

3. THE ROUND TRIP, which the item does not list but which re-opens the same
   hole pointing the other way. `settings_for_propagation` wrote
   `model_name` and `<primary>_model_name` only, so a user seeded from a
   `pathogen_model` checkpoint who changed the live model and propagated
   left `pathogen_model` overriding what they had just chosen. It now writes
   `pathogen_model` back too -- but ONLY when the settings the panel holds
   already set it (live_preview.py:2464), so propagation cannot switch an
   override on for a user who never asked for one.

NOT DONE, DELIBERATELY:

1. PLAQUE ASSAY: THE DIVERGENCE WAS REAL, AND IT WAS THE DEFAULT CASE.
   The plaque run resolves `plaque_model` through
   `spacr.submodules._resolve_plaque_model` and loads the answer as
   `custom_model`, so `model_name` never reaches Cellpose. The preview
   seeded `model_name`. A user who opened Plaque Assay and touched nothing
   previewed stock cpsam against a run on the bundled plaque model.

     before  the run segments with '.../spacr/resources/models/
             toxo_plaque_cyto_e25000_X1120_Y1120.CP_model'; the preview
             holds 'cpsam'          (test_the_plaque_preview_follows_the_
                                     real_screens_default, built screen)
     after   the combo holds the resolver's own answer

   The preview CALLS THE RUN'S RESOLVER. It does not copy the resolver's
   rules. Two changes to the resolver made that possible.
   `_resolve_plaque_model(settings, fetch=True)` gained `fetch=False`, which
   takes only what is already on this machine: the package's bundled pack,
   or a zoo checkpoint at the entry's path or `~/.spacr/models/<name>`.
   Anything else raises `ModelZooMissing`, and nothing is downloaded, neither
   the bundled pack nor a zoo key. The new `_requested_plaque_model` holds
   the `'bundled'` default, so the preview can name an unresolvable request
   without restating that default.

   What the resolver cannot find comes back as the requested value. The pass
   previews with cpsam and says so on the status line. A zoo KEY is not
   path-shaped, so `_checkpoint_is_missing` could never see one was missing;
   the panel keeps the resolver's verdict instead (`_models_not_here`).

   `spacr.submodules` IS A 3.5 s IMPORT (torch, cellpose, scikit-learn),
   measured cold. The app has not paid it when the card is first shown, so
   the plaque seed runs on its own JobRunner (`_model_jobs`) and is adopted
   when it lands, unless the user picked a model meanwhile. A pass that
   starts before it lands resolves on the spot (`_settle_the_run_model`)
   rather than segment with whatever the combo held. Mask keeps its
   synchronous key read and never imports submodules.

   The panel learns whose run it previews from `_build_live_preview_card`,
   which now passes the host's `app_key` as `LivePreviewPanel(module=...)`.

2. CELLPOSE MASKS: SAME SHAPE, NOT RECORDED BEFORE.
   `identify_masks_finetune` loads `custom_model` whenever it is not None,
   and the preview read only `model_name`.
     before  "the Cellpose Masks run loads custom_model; the preview showed
             'cpsam'"
     after   `_RUN_MODEL_KEYS['cellpose_masks'] = ('custom_model',
             'model_name')`

3. THE TRACK PREVIEW (Timelapse, folded into Mask): SAME SHAPE, SECOND PANEL.
   `TimelapsePreviewPanel.apply_settings` seeded the object, the channel and
   the diameter, and never the model.
     before  "the track preview segmented with 'cpsam'" with
             `pathogen_model` set
     after   seeded through the same `_model_the_run_would_use` and the
             shared `_offer_the_run_model`

4. ORGANELLE SLOTS: RE-CHECKED, NO DIVERGENCE. The run reads slot b's model
   through `spacr.object_roles.organelle_settings_view`, which exposes
   `organelleb_model_name` as `organelle_model_name`. The panel's
   `_model_keys_for('organelleb')` reads the same key. A guard test asserts
   agreement against that function. It was green before and after, so it is
   a guard, not a fix.
   Mask cell, nucleus and pathogen were re-checked against
   `_get_object_settings` and object.py 696-697 and are unchanged.

5. THE ROUND TRIP, for both registry modules.
   * `custom_model` is written back only when the settings already set it.
     A checkpoint is written as itself, and a stock name CLEARS it: writing
     'cpsam' into `custom_model` makes the run print "Custom model not found"
     and return.
   * `plaque_model` is written back only when the user changed the model to
     a checkpoint FILE. An untouched preview would otherwise rewrite
     'bundled' as a path, and the plaque run cannot load a stock name.
   Both keys were added to their `PREVIEWS[...].propagation` maps, because
   the registry drops every name its map does not carry.

6. THE PROVENANCE CLAUSE IS TRANSLATED, WITH NO NEW CAPTION.
     before  sv: "Found cell=1.  Modell: cpsam — /models/not_downloaded_yet.pth
             is not on this machine."
     after   "Modell: cpsam — /models/not_downloaded_yet.pth: saknas."
   It is composed from `tr("Model")` (a term row) and `tr("missing")`, a
   reviewed compact `_ROWS` row that the AI panel's status already uses, so
   it resolves in all nine locales. `test_i18n_caption_ratchet.py` is green
   with no count or digest moved.

PUBLIC DOCSTRINGS: NONE MOVED. Checked with the builder's own
`public_docstrings()` and `_source_block_hashes` against `api/en.json`: 184
public symbols across submodules, live_preview, timelapse_preview,
preview_registry and app_screen, with 0 moved, 0 new and 0 gone. A
`:param module:` line in `LivePreviewPanel.__init__` WOULD have moved the
class's pinned block, because AutoAPI merges `__init__` prose into the class
entry (`_autoapi_class_doc`). It was taken out and the parameter is documented
at the attribute instead.

LEFT, deliberately:
* The track preview seeds its model in `apply_settings` only. Unlike the
  Mask panel, it does not follow its own object selector onto that object's
  model. A missing checkpoint there fails loudly ("Preview failed: ... looks
  like a checkpoint path but no file is there"); it does not fall back, since
  that panel has no provenance clause to state a fallback in.
* `pipeline_style='v2'` segments its single pass with `cell_model_name` and
  ignores `pathogen_model` (core.py, `run_v2`), while the preview reads
  per-object keys. That is a different shape, a different segmentation
  structure rather than a key the preview skipped, so it is reported and not
  changed.
* Outside the preview: the plaque run's zoo-key branch calls
  `model_zoo.fetch` on EVERY run, and fetch always downloads into a new
  versioned file. The preview's `fetch=False` finds an existing copy; the run
  never looks for one.
