================================================================================
ANNOTATE: LINK TO THE DATABASE BROWSER AT png_list
================================================================================

Status:    done - 2026-08-06, commit 69a650e2
Requested: 2026-08-06 — "there should also be a link to database browser in the annotation app that takes the user to the png_list table to see their annotations column"

--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Nothing written. The Database Browser exists (spacr/cli_database.py and its
Qt screen); the annotate screen has no route to it.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

After auto-annotating, the only way to check what landed in the table is to
leave the app and open sqlite by hand.

--------------------------------------------------------------------------------
WHAT WAS DONE
--------------------------------------------------------------------------------

A "View in database" button on the Annotate toolbar opens png_list in the
Database Browser, flushing pending annotations first - sending the user to a
table that disagrees with the grid they just left invites the conclusion
"my annotations are not being saved", which is wrong and alarming.

That needed a seam. MainWindow._on_train_requested navigated and then pushed
the seed into the target's SETTINGS MODEL; the Database Browser has none, so
the navigation happened and the seed was silently dropped. A screen can now
expose `apply_seed(dict)` and handle one itself.

DbBrowserScreen.apply_seed opens the database, selects the table, and
scrolls the annotation column into view. It deliberately does NOT sort by
it: arriving on a re-sorted table would hide which rows were just
annotated, which is the thing the user came to look at.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

Click it with a project open; the browser appears showing png_list with the
annotation column present.

--------------------------------------------------------------------------------
VERIFIED
--------------------------------------------------------------------------------

test_view_in_database_asks_for_png_list_and_flushes_first asserts the flush
happens BEFORE the signal, and that the seed carries db_path, table
'png_list' and the active annotation column.

--------------------------------------------------------------------------------
2026-08-26 -- RE-AUDIT: THE CRITERION HOLDS, THE COLUMN SCROLL DID NOT
--------------------------------------------------------------------------------

Driven rather than read: `MainWindow._on_train_requested("db_browser", seed)`
with a real png_list database. The browser opens on png_list and the
annotation column is present once the first chunk lands -- which is the
criterion above, and it holds.

WHAT DID NOT: "scrolls the annotation column into view", claimed under WHAT
WAS DONE, never happened in the app that ships. `apply_seed` runs the moment
the table is selected; the first chunk -- which is what DEFINES the column
set -- arrives afterwards on a worker thread, so `visible_columns()` was []
and the lookup returned early every time. It worked only in the tests, which
build the screen with `threaded=False` and therefore load inline.

FIXED: `DbBrowserScreen._seed_column` holds the name until `_apply_chunk`
paints the first chunk, and `_scroll_column_into_view` is the one place that
resolves it. A column this table lacks is still ignored, as before.

Regression test: tests/test_cov_8_db_browser.py ::
test_a_seed_column_is_reached_even_when_the_rows_arrive_later -- built on a
THREADED browser, since a synchronous one cannot see the defect. Confirmed
red before the change (nothing scrolled at all), green after.
