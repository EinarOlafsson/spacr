WHAT THE STATE WAS (measured on nightly 5b9207b21; v1.5.0.8 identical)
--------------------------------------------------------------------------------

The five modules involved are byte-identical between v1.5.0.8 and
5b9207b21 (`git diff --stat v1.5.0.8 origin/nightly` over live_preview.py,
preview_controls.py, app_screen.py, settings_model.py, settings_search.py
is empty), and the #120 probe gives the same answer on an extracted
v1.5.0.8 tree. Every probe below built MainWindow, opened Mask, and typed
into the field with QTest (keyClicks, then Return), under a throwaway
QSettings home.

#120. Under "All settings" typing 2 into pathogen_channel DID bring up
Pathogen Segmentation. Under "Essentials" -- the level every module opens
at until its user switches, which is where a new user is -- it never did:
Essentials for Mask was a fixed list (the inputs plus preprocess, masks,
test_mode, test_images, plot, save), so no object's segmentation was in
it. Three more faces of the same defect:
  * The object rule's pass ran AFTER the search strip, so it put rows
    Essentials excludes back on screen (resume and dry_run showed on a
    fresh Essentials form), and a committed channel was never re-judged by
    the strip unless rows happened to be waiting to be laid out.
  * With the per-object table on, the flat channel rows are hidden (the
    table answers for them) and the table's section has no form rows for
    the strip to count, so Essentials hid the table too: NO object channel
    could be set anywhere on the form.
  * Clearing a channel left "Pathogen Segmentation" on the form as a
    heading over no rows, at either level.

Maintainer's report. The Live settings dialog borrows the panel's controls
and hides each one explicitly when it closes. It re-showed only what
`_managed_widgets()` named on the next open, and that list omitted
`_pathogen_channel` and `_organelle_channel`. So the first open showed the
pathogen channel spin box; every later open showed the caption "Pathogen
channel" over an empty field, the same for Organelle channel. Neither was in
`_propagate_sources` either, so with Propagate on a pathogen channel change
reached the main form only when some other control moved. The per-object
table was incidental: it was just the only other place to set the channel.
The existing test read the row's caption, which was there both times.

#119. Driven with synthetic folders (setting src on the form, preview
open):
  * three-channel TIFFs whose names the dialect cannot read: one column
    captioned "ch " (the channel ID was the empty string), while the channel
    dropdown beside it offered Ch 0, Ch 1, Ch 2;
  * a cellvoyager folder loaded while the form said cq1: the same single
    column, and choosing cellvoyager afterwards changed nothing until
    another image load happened to miss the sampler's cache;
  * the columns were the channels of the SAMPLED fields only, so a channel
    some fields lack came and went with the random draw.
The reporter's exact folder is unknown; each of these produces the words
in the report, and all three are fixed.

--------------------------------------------------------------------------------
WHAT CHANGED
--------------------------------------------------------------------------------

spacr/qt/widgets/live_preview.py
  * LiveSettingsDialog: `_managed_widgets()` and `_propagate_sources` name
    the pathogen and organelle channel spin boxes;
    `_show_every_control_on_a_row()` shows every widget on every form row
    when the dialog opens, so a control added later cannot come back
    hidden.
  * `_set_table_columns()`: columns from the whole folder's channel IDs;
    unreadable names captioned "image"; one "ch N" column per plane when no
    file name carries a channel and the loaded image has 2-9 planes on its
    last axis. `_open_cell()` opens a cell's file only if it is not on
    screen already and selects the plane through the display-channel
    dropdown.
  * `regroup_the_folder()` (public, new): re-reads the loaded folder's file
    names off the GUI thread under the form's current naming.
spacr/qt/screens/app_screen.py
  * `_refilter_the_settings_search()` runs the search strip after every
    object pass (handed to the model as `rows_are_filtered_by`).
  * `refresh_maturity_visibility()` leaves a heading the object rule holds
    back hidden.
  * `cell_channel` commits run the in-place object pass too.
  * `_wire_live_preview_naming()`: metadata_type / custom_regex changes
    regroup the preview table after 400 ms.
spacr/qt/screens/settings_model.py
  * `SettingsWidgets.essential_keys()` adds each `<Object> Segmentation`
    category for every object whose channel names a plane (Mask only; the
    module-level `essential_keys()` and the walkthrough's count are
    unchanged).
  * `refresh_object_visibility()` records `_hidden_by_their_object` and
    calls `rows_are_filtered_by` at the end.
  * `_hide_the_headings_of_slots_the_run_lacks()` covers nucleus and
    pathogen as well as organelle slots.
spacr/qt/settings_search.py
  * `apply()` counts the per-object table's section by the keys it answers
    for; `_grid_section()` follows the table being mounted or taken down by
    Preferences after the strip was built.
Reasons for each are in docs/notes/spacr/qt/... under the same paths.

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

  * The walkthrough's "N settings, not M" still counts the static
    essentials. The segmentation rows that follow a channel are not
    settings a module "cannot run without", which is what that sentence
    claims.
  * `load_source_payload` still enumerates on the worker with the default
    dialect, so a folder opened under another naming is scanned a second
    time on the GUI thread. The answer is right; the cost is paid twice.
  * A (C, H, W) TIFF is still read as channels-last everywhere in the
    preview; the plane-column cap of nine keeps a mis-read axis from
    becoming a thousand columns, but the preview does not reorder it.
  * Propagate writes every channel spin box's value, including the
    panel's own defaults (nucleus 1, pathogen 2) for a user who never set
    them. Not asked, and it changes what a run segments; worth its own item.
  * macOS AppleDouble files ("._name.tif") match the cellvoyager pattern
    with plate "._name" and would add rows that fail to load. Not seen in
    the report and not measured on a Mac; recorded only.
