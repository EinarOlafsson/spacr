WHAT IS THERE TODAY (read from the code on nightly 884eacaab)
-------------------------------------------------------------

Per object (cell, nucleus, pathogen, organelle) the Mask module carries:

  {obj}_min_area, {obj}_max_area          KEEP. The model for the new pair.
  {obj}_remove_border_objects             keep
  {obj}_perimeter_fraction                keep (perimeter merge; not asked)
  {obj}_minimum_area_to_split             REMOVE (default 100)
  {obj}_min_watershed_distance            REMOVE (default 10)
  {obj}_intensity_threshold               REMOVE (default None)
  {obj}_intensity_merge                   REMOVE (default False)
  {obj}_intensity_split                   REMOVE (default False)

  * Defaults: spacr/settings.py ~1099-1124 (and organelle_min_area ~1663);
    types ~3568-3592; categories "Cell" / "Nucleus" / "Pathogen" ~4723-4727,
    each listing all five.
  * Pipeline: spacr/object.py merge_split_filter_masks (~110-205) reads every
    key above and calls spacr.utils._process_single_fov_in_memory (~805),
    which runs merge_split_objects (~877): _split_by_watershed (~648), the
    boundary-intensity merge (~585-646), then
    _filter_objects(label_img, intensity_img, min_area, max_area,
    remove_border) (~726). _filter_objects already receives the intensity
    image and ignores it -- its docstring records that the old
    intensity-percentile band was removed in 391.
  * Live Preview: COMPARTMENT_FIELDS (live_preview.py ~228-238) holds the rows
    "Min area (px²)", "Max area (px²)", "Minimum area to split", "Minimum
    watershed distance", "Perimeter fraction", "Intensity threshold",
    "Intensity merge", "Intensity split", "Remove border objects". The live
    filter (~893-921) reads {obj}_min_area / {obj}_max_area (with
    {obj}_min_size / {obj}_max_size as a fallback) and calls _filter_objects.
    ~3175-3198 records that the two upper-bound filters disagree on what
    switches a bound off (max_area > 0 vs max_size is not None).

2026-09-15 — SHARED FILTER CHECKPOINT, NOT FEATURE COMPLETION
----------------------------------------------------------

_filter_objects now accepts keyword-only min_intensity/max_intensity, with
zero disabling each side and equality retained. It computes float64 object
means on the supplied own-channel plane (not a percentile quota). Missing
or mismatched planes and nonfinite object means are refused when filtering
is active; nonfinite background is irrelevant. Existing area and border
filters still compose with it. No existing caller enables the new bounds
yet, and the five old settings/code paths have NOT been removed in this
checkpoint.

Evidence: tests/test_mask_mean_intensity_bounds.py was red on the parent
(17 failures, unsupported keyword), then 18/18 passed after the overlap case
was added. Per-function coverage on this source is 58/58 statements and
36/36 branches, with no exclusions. Five in-memory source mutations were
rejected: inclusive rejection at either bound, maximum instead of mean,
disabled intensity filtering, and silently accepting a nonfinite mean.
The 37 existing tests in test_cov_utils_labels_mergesplit.py also passed.

The remaining wiring cannot just forward today's intensity_images: the v1
NPZs and v2 segmentation batch hold normalized data, whereas Live Preview's
_image holds original values. Raw stack planes must feed the shared filter
in both runs, independently of display/segmentation normalization. Preview
also has a correct _channel_for_object selector, but _obj_channel currently
ignores it for pathogen and organelles. Reuse that selector rather than
creating another role/channel table. Preserve organelle-slot settings and
batch padding/resume filename alignment in the tests of the next slice.
