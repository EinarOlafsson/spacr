WHAT CHANGED (spacr/io.py; after review also one call in spacr/core.py)
--------------------------------------------------------------------------------

  1. Atomic writes. _replace_atomically writes into a hidden sibling named
     .spacr_tmp_* / .spacr_npz_* ... .partial, flushes and fsyncs it, then
     os.replaces it into place. _save_array_atomic, _save_npz_atomic and a
     new _savez_atomic use it. Every stack/*.npy and archive write listed
     above goes through them. The sibling ends in .partial, not .npy or
     .npz, so a sibling left by a SIGKILL is never listed as a field.
     _sweep_partial_writes removes such siblings from stack/ and masks/.
     spacr/checkpoint.py was read, not touched. Its _atomic_json is the
     same pattern for JSON.
  2. Checks before reuse. _set_aside_damaged_stacks checks each
     stack/*.npy by header and length (resume.validate_merged_field, with a
     memory-map fallback). _inspect_normalized_archive opens each
     masks/*.npz's zip directory, checks each member's extent, reads the
     data.npy header and reads filenames.npy, and never inflates pixels. A
     damaged file is renamed to <name>.damaged, and the log says how many
     and which, with the reason for each.
  3. Rebuild, not just skip. _resume_normalized_archives runs the masks/
     shortcut:
       - it builds a missing or damaged stack again from orig/ when the raw
         images are there (_rebuild_stacks_from_raw);
       - it normalises the stack/ fields that no whole archive lists into
         new archives numbered after the old ones (only_fields and
         first_batch_index on _concatenate_and_normalize_impl);
       - an illumination-corrected or timelapse set with a gap is rebuilt
         whole from stack/, because it is published, or named, as a set;
       - nothing is added to a set made with a different number of
         channels than these settings select; the log says so;
       - a damaged archive with neither stack/ nor raw images to rebuild
         from is a FileNotFoundError that names the file.
  4. A processed folder resumes. _rename_and_organize_image_files reads raw
     images from src and src/orig/ and builds only the fields stack/ lacks.
     If stack/ holds fields but none of their names is one these images make
     (an older spaCR, or channel folders), it adds nothing, so nothing is
     doubled. When it read no field it creates, moves and deletes nothing.
     A deletion with save_original_images off removes only an image whose
     field has a stack.
  5. Test mode. It never takes the plate's masks/ shortcut. On a plate with
     no raw images left it copies a sample of the plate's whole stack/*.npy
     into test/stack/ (_sample_stacks_for_test_mode, seed 42 as
     _run_test_mode uses).
  6. The error, when nothing can be built (_no_stacks_error), keeps its
     first sentence and then says which case it is: a folder spaCR already
     processed, with what each output folder holds and what that leaves; a
     test mode that found nothing to sample; or image files that match no
     filename pattern, with the pattern. The plates hint is kept for a
     folder that holds only sub-folders.

The reasons are in docs/notes/spacr/io.md, section "A re-run trusts nothing a
killed run left".
