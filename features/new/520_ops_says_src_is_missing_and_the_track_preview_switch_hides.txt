OPS SAYS "src is missing" ON A RUN THAT SUCCEEDS, AND MASK'S TRACK PREVIEW SWITCH HIDES

Status: FIXED 2026-09-25, both parts, with tests; awaiting merge to nightly.
Owner: unassigned. Found by the docs session while recording the OPS and
Timelapse tutorials.

WHAT IS WRONG
  1. An OPS run prints "[settings] ERROR [src]: src is missing" to the
     console even when the run succeeds. A false error in front of the user
     (and in a tutorial recording).
  2. In Mask, once Plot figures appear, the Track preview switch collapses
     out of view.

WHAT TO BUILD
  1. Find which settings check reports src missing for OPS (OPS may take its
     inputs from other keys, or src is filled after the check runs) and make
     the check match what OPS actually reads; no error on a successful run,
     a real error when the input is genuinely missing.
  2. Keep the Track preview switch visible when the figures panel opens
     (layout minimums, or the switch belongs in a row that does not fold).

DONE WHEN
An OPS run with valid inputs logs no src error (and one with no input still
does), and an offscreen test shows the Track preview switch visible and
clickable after figures appear in Mask.

2026-09-25 -- FIXED (both parts)

  1. THE FALSE "src is missing". The GUI bridge wraps every pipeline entry
     so it prints spacr.validate.validate_settings() problems before the run
     (spacr/qt/bridge.py:1438). validate._check_src() asks for the app's
     source key, which is "src" unless ALT_SRC_KEYS names another one, so
     for OPS it reported "src is missing from the settings."
     (spacr/validate.py:664). run_ops never reads src: its input is
     genotype_source (spacr/ops_engine.py, run_ops docstring and first
     lines), and the OPS settings have no src key at all. So the error
     fired on every OPS run, including every one that succeeded.
     Fix: ALT_SRC_KEYS maps "ops" to "genotype_source"
     (spacr/validate.py:163), with its own fix text (spacr/validate.py:654).
     The generic source checks now apply to the folder OPS really reads: an
     unset, left-out, nonexistent or file-not-folder genotype_source is
     still an ERROR; a real folder is silent. chaining.source_key("ops")
     now answers genotype_source too; ports has no OPS spec, so nothing
     changes there.

  2. THE TRACK PREVIEW SWITCH. The Timelapse fold attaches its preview with
     preview_registry.attach_folded(), whose toggle went into the settings
     search strip or, when there was none, into the Actions BODY
     (_insert_above_actions). Plot figures is a focus pane: when its card
     shows, the runtime splitter collapses the console, System, the Actions
     body and the settings column (AppScreen.adopt_runtime_pane). Both
     homes of the toggle fold away, so the switch vanished (measured
     offscreen: Actions pane 816x253 -> 1228x26, _actions_body hidden,
     toggle.isVisible() False). The Actions HEADING row survives the
     collapse and already holds Mask's own Live switch.
     Fix: _attach() takes in_heading, and attach_folded() passes True, so a
     folded preview's toggle goes into _actions_heading_row
     (spacr/qt/preview_registry.py:385, :395, :456). Registry previews of a
     screen's own key keep their old placement.
