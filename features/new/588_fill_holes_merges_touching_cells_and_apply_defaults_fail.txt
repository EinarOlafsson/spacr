FILLING HOLES MERGES TOUCHING CELLS, AND APPLY'S DEFAULT CHANNELS/PERCENTILES FAIL

Status: DONE, 2026-09-26. See the closing note.
Was: OPEN, filed 2026-09-26.
Owner: unassigned. Found by the docs session while recording the Train
Cellpose tutorial (evidence: /mnt/firecuda2/codex/scratch-docs/status/t19.md,
/mnt/firecuda2/codex/scratch-docs/t19/gpu_run4.log).

WHAT IS WRONG
  1. spacr.utils.fill_holes_in_mask runs ndimage.label on the LABEL image, so
     objects that touch are merged into one. Apply's fill_in defaults to
     True, so batch masks came out as a few giant objects per field (8/4/6
     objects where the preview showed 74 cells). Wrong numbers, silently.
  2. Apply with DEFAULT settings (channels [0,0], percentiles None) prints
     numpy "Mean of empty slice" warnings with site-packages paths and gives
     5/4/7 objects against 78 in the preview; with channels [0] and
     percentiles [2,99] it is fine.

WHAT TO BUILD
  1. Fill holes per object (each label filled on its own, e.g. binary_fill_holes
     per label via find_objects/regionprops slices), never relabelling, so
     touching objects keep their ids; keep it fast on large fields. Check every
     other caller of fill_holes_in_mask / similar helpers for the same bug.
  2. Find why Apply's defaults differ from the preview's (channel list and
     normalisation percentiles) and make Apply use the same effective
     settings as the preview when the user has not set them; no empty-slice
     warnings; Apply and preview give the same object counts on the same field.
  3. Re-check Mask generation's own post-processing for the same merge bug.

DONE WHEN
A field with touching cells keeps every object after fill_in (test with a
synthetic two-touching-cells mask and a real field); Apply with defaults gives
the preview's object count on the tutorial's fields; no numpy warnings.


2026-09-26 -- FIXED (4639c2d06, merged with nightly)
----------------------------------------------------
CAUSES
  1. spacr.utils.fill_holes_in_mask labelled the mask afresh with
     ndimage.label(mask) and filled each connected component. Every pair of
     touching cells is one component, so it became one object. The same
     "fill the foreground, then label" pattern was in Make Masks' Fill holes
     button (mask_engine.fill_holes, default mode: binary_fill_holes then
     label), and object._postprocess_masks renumbered with label(mask > 0).
     mask_engine._fill_label_holes (secondary-object propagation and Fill
     holes in exact-id mode) did keep ids but scanned the whole field once
     per label.
  2. Apply (spacr_cellpose.identify_masks_finetune) with its defaults
     channels [0,0] and percentiles None did not segment what the preview
     segments. The preview hands Cellpose ONE raw plane and lets it
     normalise per image (eval normalize=True). Apply stacked channel 0 twice
     on a multi-channel image and, without percentiles, ran the set-wide
     search in io._load_normalized_images_and_labels, which averages four
     fixed channel slots; the empty ones are np.mean([]), which is the
     "Mean of empty slice" warning with site-packages paths. Apply then
     called eval(normalize=False) on that rescaled image.

EVERY CALL SITE, ONE HELPER: spacr.qt.mask_engine.fill_label_holes
  Each label is filled inside its own find_objects box and written only
  onto background, smallest box first (so a nested ring owns its hole), and
  never relabelled. Exact, and 0.14 s on 2000 x 2000 with 400 touching
  ringed objects (the old fill_in returned 1 object there).
  - spacr.utils.fill_holes_in_mask -> fill_label_holes (Apply's fill_in;
    its only caller is identify_masks_finetune).
  - mask_engine.fill_holes (Make Masks' Fill holes): both modes now use it;
    a single-valued brush mask is still numbered by connectivity first
    (canonical_labels) because it carries no ids.
  - mask_engine propagate (secondary objects, fill_holes=True) -> the same
    helper, now box-local instead of whole-field per label.
  - object._postprocess_masks renumbers by lookup table, not label(mask>0).
  - Checked and left alone: object._segment_irregular's remove_small_holes,
    mask_engine._finish_region_binary and the Otsu/threshold paths, the
    annotate_engine outline mask and diameter.py all fill a BINARY
    foreground before any object exists, so nothing can merge there.
    Plaque Assay no longer reads fill_in (it segments via
    plaque.segment_plaque_image).
  Apply: new spacr_cellpose._apply_input_settings. A repeated channel index
  is kept once ([0,0] -> [0]); with no explicit [low, high] pair the loader
  returns the image unscaled (new rescale=False) and eval runs with
  normalize=True, i.e. exactly the preview's input. An explicit pair keeps
  the old path. The loader's percentile search now averages only the
  channel slots that were filled, so no empty-slice warning anywhere.
  fill_in and percentiles help text updated; notebooks 08/09/10/13 rebuilt.
