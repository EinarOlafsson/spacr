WHERE DINOv3 COMES FROM. Cellpose 4.2.1.1 (PyPI's latest, and the one spaCR
already installs) is the release with Cellpose-DINO: cellpose/vit.py builds
CPDINO from `dinov3.hub.backbones` (dinov3_vitl16 / dinov3_vitb16, built with
pretrained=False; the whole network comes from the checkpoint) and prints
"run `pip install git+https://github.com/facebookresearch/dinov3`" when it
cannot. dinov3 is NOT on PyPI (pypi.org/pypi/dinov3/json: 404, 2026-09-25).
The backend installs the GitHub archive of one pinned commit, so no git is
needed and every install builds the same package:
  dinov3 @ https://github.com/facebookresearch/dinov3/archive/
           6876159a11b4df116f30f667f8c9888617df0751.zip   (main, 2026-09-25)
dinov3's setup.py says python_requires>=3.11, so the spec's range is 3.11-3.14.

LICENCE. DINOv3's code AND weights are Meta's "DINO Materials" under the DINOv3
License (LICENSE.md, 19 Aug 2025) -- not open source. It needs no click-through
here ("by using or distributing ... you agree"), allows use, copying,
modification and redistribution with the licence attached, requires that a
publication using the results acknowledge DINOv3, and forbids military/
weapons/nuclear/espionage uses and sanctioned parties. The Cellpose-DINO
checkpoints are DINOv3 fine-tuned by the Cellpose authors (HF mouseland/
cellpose-sam, not gated, card says bsd-3-clause; bioimage.io says BSD-3-Clause),
so the DINOv3 terms reach them too. Respected as follows: spaCR redistributes
nothing -- dinov3 comes from Meta's GitHub, each checkpoint from the URL its
bioimage.io row names -- and the licence is said BEFORE installing: the
backend's licence_note (Model Zoo backend card, install dialog) and every
Cellpose-DINO row's card carry it. Nothing forbids the install or the use.

ONE MORE ROW. spacr.object._prefixed_model_route (503's table) gained
('cellpose_dino', _cellpose_dino_choice, _cellpose_dino_masks). Every
caller of the table -- pipeline_v2.stream_masks_from_stack, the Live
preview's _segment_multi / _backend_preview_pass and the Timelapse
preview's segment_frame -- now sends cellpose_dino:<path> to the
Cellpose-DINO backend with no change of its own (pipeline_v2.py and core.py
untouched). A prefix now wins over segmentation_backend in the table, as it
does in V1 (cellpose_dino: in a segmentation_backend=cellpose3 run goes to
DINO); a bare name under segmentation_backend=cellpose3 still goes to
Cellpose 3.

_cellpose_dino_masks (object.py, next to _cellpose3_masks) makes V1's
Cellpose-SAM call and nothing else: x = the images (a 2-D plane gets a
channel axis of 1), batch_size = number of images, normalize False,
channel_axis -1, min_size, progress True, diameter =
_eval_diameter(<obj>_diameter) (blank -> None, as V1), the object's flow
and cellprob thresholds, resample = object_type != 'pathogen' (what
settings._get_object_settings sets). It returns (masks, flows[, cell
probability]) through parse_cellpose4_output, so the Live preview's Flows
and Cell probability views fill as they do for cellpose3:. The
default_diameter / batch_size arguments are taken for the table's shared
signature and not used -- V1 and v2 send Cellpose-SAM one batch of all
images, and the calls must be the same for v2 == V1.
