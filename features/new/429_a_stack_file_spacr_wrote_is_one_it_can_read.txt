WHAT THE FILE WAS
-----------------

Not an object array. The #117 log names it one stage before the crash:

    [concatenate_and_normalize] FAILED .../test/stack/._test_N06_5_1.npy
    (stage load_npy): ValueError: This file contains pickled (object) data.

`._test_N06_5_1.npy` is an AppleDouble sidecar. macOS writes `._<name>`
beside a file that carries extended attributes when the volume cannot store
them natively: exFAT, FAT and many SMB shares, which is what /Volumes/jk-ummi
is. The sidecar keeps the ending of the file it shadows. np.load reads any
file that is neither .npy magic nor a zip as a pickle, and with
allow_pickle=False it refuses with exactly this message. The file that
crashed object.py:790 was `masks/._stack_0_norm.npz`, the sidecar of the
normalised archive: the log shows the cell pass finish the real archive
("Found 134.0 cell/FOV") and then fail.

WHO WROTE IT: macOS, beside the files spaCR wrote on that volume. The log
shows it for stack/ (above), implies it for masks/ (below), and shows it for
the test-mode copies: "All files: 8" in test/ for four
tiffs, and four "WARNING: A file with the same name already exists at
location .../orig/._W0318F0005T0001Z000C1.tif" lines, where moving each tiff
into orig/ had already carried its sidecar along.

MEASURED, 2026-09-19, numpy 2.5.2 in the spacr env:
  * what concatenate_and_normalize writes loads with allow_pickle=False:
    data is float32, filenames is a <U array. Masks are written as uint16 by
    _save_array_atomic. Nothing in the Mask path writes an object array.
  * np.load on a 4096-byte AppleDouble header: the #121 ValueError, word for
    word.
  * np.load(..., allow_pickle=True) on it: UnpicklingError "Failed to
    interpret file ... as a pickle".

DECISION ON allow_pickle: none, not even for spaCR's own files. It would not
have fixed this (it trades one error for another), and it would let any file
dropped into a plate folder run code when spaCR lists the folder. Convert on
read is not needed either: the files 1.5.0.8 wrote are plain arrays and load
unchanged. The writer was never at fault; the readers were.

WHY THIS PATH AND THIS PLATFORM: only macOS makes sidecars, only on such
volumes, and the Mask path re-lists its own output folders four times
(stack/, masks/, each *_mask_stack/, merged/) with
`os.listdir(...) if name.endswith('.npy'/'.npz')`. The raw-image listing in
io._rename_and_organize_image_files already skipped dot-files, which is why
the raw tiffs' sidecars never failed; nothing after it did.
concatenate_and_normalize met the sidecar first but loads inside a per-item
RunLedger, so it only logged "RUN INCOMPLETE - 1 of 2 items failed".
generate_cellpose_masks_sam loads with no ledger around it, so it raised and
on_error=stop ended the run.

WHAT CHANGED
------------

spacr/io.py gains `_listdir_visible(folder)`: os.listdir without names that
start with a dot, in os.listdir order. Every dot-file, not only `._`: the
atomic writers name their temporaries `.spacr_tmp_*.npy` and
`.spacr_npz_*.npz`, and a killed run leaves one behind with a data ending.
spaCR never names a field with a leading dot.

37 listing sites in 20 functions go through it or filter inline:

  io.py      _rename_and_organize_image_files (the old inline filter goes;
             the orig/ move and delete loops skip sidecars, which ends the

             _concatenate_and_normalize_impl (both branches),
             _create_movies_from_npy_per_channel, preprocess_img_data (its
             "Found N tif files" count no longer includes sidecars),
             _load_and_concatenate_arrays
  object.py  generate_cellpose_masks_sam (the #121 line),
             generate_cellpose_masks, generate_organelle_masks_sam
  core.py    _overlay_candidates, the test-mode examples_to_plot count
  utils.py   check_mask_folder, _run_test_mode, adjust_cell_masks (would
             have been the next crash: the reporter runs all three objects
             with adjust_cells on), cleanup_pipeline_folders
  plot.py    plot_arrays (test mode samples stack/ at random; with one field
             and one sidecar it was a coin toss between the field and an
             "Error:" line)
  seg_qc.py  _iter_masks, inline because seg_qc is tested to import no
             torch and spacr.io imports it. Measured on the old code: one
             good mask plus its sidecar scored "FAIL - 1 of 2 fields failed

  illumination.py  _merged_files, inline for the same import reason.
             Reached from the Mask run when segmentation illumination

Reasons are in docs/notes/spacr/io.md (_listdir_visible), with pointers in
object.md and seg_qc.md. No public docstring changed, so nothing is owed to
the catalogs.

THE REPORTER'S PROPOSAL, on #121: a module that replaces os.listdir,
os.scandir and shutil.rmtree for the whole process. Not taken: it changes
what every library in the process sees (Cellpose, torch, matplotlib), and it
had to special-case rmtree because rmtree cannot empty a directory whose
entries it is not shown. Filtering at spaCR's own listings leaves everything
else alone, and each of the 20 functions is pinned by a test.

2026-09-19, after review -- two things the review caught, both fixed
here. (1) The refusal above leaves the plate part-converted: the

2026-09-24 — Automatic conversion refuses an already converted folder
Resolved the trailing rerun hazard with a preflight refusal: a canonical
plate/well TIFF already present stops convert_to_yokogawa before any image,
rename log or run-status artifact is written. This applies with or without
a prior log, including CZI A/Z names and multi-letter rows. Existing code
already skipped plate-prefixed plain TIFFs, but still reassigned raw inputs,
could overwrite an existing well and replaced the provenance log on reruns.
Read converted images with metadata_type='cellvoyager'; retry raw conversion
in a separate folder containing the original inputs. The regex-failure
message now explains this refusal instead of claiming outputs are reread.
Seven real-file regressions failed before; 49 conversion checks now pass,
including byte-for-byte preservation of inputs/output/logs on refusal.
The previously listed streamed-dataset prefix and importer temporary-file
hazards remain separate follow-ups; this does not close those gaps.

2026-09-24 — Streamed crops no longer substitute prefix-neighbour fields
Resolved the recorded _stack_for hazard: field1 no longer matches field10,
empty stems match nothing, and multiple suffixed candidates are ambiguous
rather than choosing the first timepoint. Exact identifier/acquisition-well
spellings take priority. A single underscore-delimited legacy suffix still
works. Missing/ambiguous crops use the existing missing/trouble report.
Nine regressions fail before (including two real streaming paths that wrote
field10's object for field1); 49 stream/crop/channel checks now pass.

2026-09-24 — Importer scratch arrays no longer look like finished fields
external_masks._save_npy now delegates to the existing atomic NumPy writer:
hidden unique .partial sibling, flush/fsync, then replacement. Ordinary
save/replace failures clean scratch and retain the previous destination;
a killed writer can leave a partial, but never a new visible .npy field.
Three regressions fail before (visible temporary array and two leftover
failure paths); 61 import/rollback/partial-sweep/Qt import checks pass.
No public signature change. This completes the three runtime hazards
recorded at the end of the September19 review. Docs handoff is in #325.

2026-09-24 — Preserve provenance after the images move into orig/
Extended the automatic-conversion preflight to retain a previous rename log
even when converted TIFFs have already moved out of the top-level folder.
Without this, a rerun erased the mapping and its run-status record, or
replaced it with mappings for newly added inputs. Two real conversion/archive
regressions reproduced that loss. The log now triggers refusal before writes,
with the same separate-raw-folder/cellvoyager guidance. All 51 conversion
checks pass (32.09s); all existing data/log bytes remain intact on refusal.
