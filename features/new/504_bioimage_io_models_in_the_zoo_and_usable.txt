WHAT CHANGED.
  * spacr/model_zoo.py. bioimageio_entries() builds a row per Cellpose model
    in bioimage.io's collection: Cellpose 3 packages (CellPoseWrapper /
    CPnetBioImageIO) as `cellpose3` rows, Cellpose-SAM and Cellpose-DINO as
    `cellpose` rows. EVERY runnable row now downloads the weights file itself
    (the SAM rows used to point at the bioimage.io web page, so Download
    fetched HTML), checked against the manifest's SHA-256, named after the
    model (cellpose_cyto3.pth, cellpose_sam, ...), with its licence, its
    authors, and what it was trained on (the manifest's training_data, as a
    DOI link when it is one, then its description). The package's own run
    settings (flow_threshold=0.7 for OC1 Project 6, ...) are reported in a
    note and not used: spaCR runs it with the object's Mask generation
    settings, as it runs cyto3.
  * Rows spaCR cannot run carry a first note starting "spaCR cannot run this
    model: " and no download URI: a Cellpose-DINO model without dinov3, a
    weights file under 1 MB (the stand-in above), and any other model tagged
    Cellpose whose network is neither Cellpose 3's nor Cellpose-SAM's.
    _bioimageio_cannot_run(entry) returns that sentence.
  * The cache. A collection over 24 h old used to mean NO rows offline,
    which is one reason the category was empty; it is now listed as it is
    and refreshed in the background. The refresh also measures each weights
    file with a one-byte ranged GET (hypha answers HEAD with 405) and keeps
    the sizes in ~/.spacr/bioimageio_weight_sizes.json, which is how the
    stand-in is refused before anyone downloads it. fetch() refuses a
    bioimage.io Cellpose download under 1 MB as well.
  * The Use text 503 left: `_CELLPOSE3_USE` no longer says to set
    segmentation_backend; it says the model runs through the Cellpose 3
    backend exactly as a stock Cellpose 3 model does, and that Use this model
    writes cellpose3:<its path>. SAM rows say Use writes their path.
  * Downloads resume. hypha dropped two of three 1.2 GB Cellpose-SAM
    downloads part-way ("Response ended prematurely", chunked, no
    Content-Length). open_uri now resumes with Range from the last byte
    received when the server answers 206 at that offset, up to five times;
    the SHA-256 check covers the joined file. The next 1.22 GB download
    (sneaky-panda) completed and verified.
  * spacr/qt/widgets/model_zoo_picker.py. A cannot-run row's Status cell reads
    "spaCR cannot run this", its card and the status line give the reason,
    and Download and Use stay grey. The bioimage.io warm-up used to run only
    when the community catalogue was stale and never redrew the table; it now
    runs on every opening and redraws when bioimage.io's rows change.
  * spacr/qt/screens/make_masks.py. The Model zoo… button asks for Cellpose
    3 rows too, and a `cellpose3:<name or path>` it returns is listed as
    "Cellpose 3 · <file>"; load_cellpose_model() hands such a value to
    _backend_model(), the Mode box's Cellpose 3 loader, instead of Cellpose
    4 (which would load the checkpoint and segment nonsense).

A BIOIMAGE.IO CELLPOSE 3 MODEL BEHAVES EXACTLY LIKE A STOCK ONE. Measured on
the run above with _load_backend and the backend's eval wrapped: stock
cellpose3:cyto3 and bioimage.io cellpose3:<cellpose_cyto3.pth> went through
the same backend, were handed the same image (sha256 prefix eaa575e48abaf055)
and the same keywords (batch_size 8, channel_axis -1, min_size 0, diameter
44.0, flow_threshold 0.4, cellprob_threshold 0, resample True, augment False,
normalize {normalize: True, percentile: [1, 99]}), and wrote the same mask
(sha256 54a8645ced23f294...). The one difference is inside the worker: a
Cellpose 3 NAME is built as models.Cellpose(model_type=...), which carries
Cellpose's size model, and a checkpoint as models.CellposeModel
(pretrained_model=...), which has none -- as in Cellpose 3 itself. It shows
only with cellpose3_size_model on (diameter 0): the stock model estimates a
diameter and a checkpoint runs at the diameter it was trained at. Off, the
default, the two are the same computation, as the identical masks show.
Likewise bioimage.io Cellpose-SAM and stock cpsam_v2: CellposeModel built
with pretrained_model=<path> vs 'cpsam_v2', same eval keywords, same mask
(sha256 2fc2cb3073be11af...).
