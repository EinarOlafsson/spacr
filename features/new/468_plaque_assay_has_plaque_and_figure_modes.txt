WHAT WAS BUILT
--------------------------------------------------------------------------------

spacr/qt/widgets/plaque_preview.py -- PlaquePreviewPanel replaces the Mask
LivePreviewPanel on the Plaque Assay screen. It answers load_source_async,
apply_settings, set_propagate_callback and settings_for_propagation, so the
Live switch, the src autoload, the first-show prime and item 464's Refresh
button drive it unchanged.

THE SWITCH. A two-button Plaque | Figure control is the first widget on the
settings column and a second one sits at the top of the preview. The form's
plaque_mode control is the one source of truth: both switches write it and
both follow it (a loaded settings file moves them). The plaque_mode row is
hidden because the switch speaks for it. Plaque mode hides figure_detector,
figure_imgsz, figure_confidence, figure_read_text and confirm_annotations;
Figure mode hides well_detection, well_confidence and well_pad. Rows are
hidden, not dropped (SettingsWidgets.hide_the_rows_the_mode_leaves_out, the
same mechanism the object grid uses), so collect() still carries the values.

PLAQUE MODE. Image picker over src (prev/next, wrapping), plaque model box
(zoo plaque models, 'bundled' with a sentence saying what it is, a path via
Browse), diameter / flow threshold / cell probability. Run preview segments
one image off the GUI thread and draws the outlines, with count and mean
area. A zoo model that is not on this machine is stated, never fetched, and
a Download button offers it (CheckpointDownload). "Use these settings"
writes diameter, flow_threshold, CP_prob, plaque_mode and -- only if the
user changed it -- plaque_model back into the form.

FIGURE MODE. Same picker over the figures. Run preview runs the detector at
every size in figure_imgsz (spacr.plaque_papers.find_plaque_regions), reads
the text (read_words + reread_around), segments each crop, draws numbered
boxes (green OK, orange not) with outlines inside, and fills the review
table: #, panel, label text, legend passage, condition (editable), source /
strength, plaque count, OK. Saved reviews in figure_annotations.csv are
applied when a figure is previewed again. Save annotations merges this
figure's rows into figure_annotations.csv (write_annotation_overrides), which
the run reads.

LEGEND. legends.csv is used when it has the figure. When a panel letter was
read and no legend is known, a box says so, with "Paste the figure legend, or
annotate by hand": a pasted legend re-annotates at once and is saved into
legends.csv; Annotate by hand puts the cursor in the first condition cell.

CONFIRM. With confirm_annotations on, unreviewed rows start unticked and a
bold notice says the run measures ONLY rows ticked OK and saved. With it
off, rows start ticked, because the run measures them; unticking one and
saving leaves it out of the run either way (apply_overrides skips
approved=False).

OPTIONAL PACKAGES. Without ultralytics / RapidOCR Figure mode shows
    Figure mode needs ultralytics and RapidOCR ... pip install "spacr[papers]"
with an Install button (PackageInstall after confirm_backend_install), and
Run preview refuses with the same sentence. Detected with find_spec, so the
check never imports ultralytics (trap 3g).

A FINDING FOR THE RUN SIDE
--------------------------------------------------------------------------------

THE PLAQUE RUN'S LOADER ERASES AN 8-BIT CROP. identify_masks_finetune with
normalize=True calls _load_normalized_images_and_labels with the plaque
defaults (background=200, Signal_to_noise=10). On malnio__2.tif every pixel
comes back 1.0 -- min = max = 1.0, std 0, for channels [0,0], None and
[0,1,2] alike -- and the first preview built to mirror that loader found 0
plaques in 858 s. The preview therefore segments the image as it is, with
the tuned diameter and thresholds (plaque_preview.segment_plaque_image), and
found 67. The Plaque-mode run should segment the same way, or the preview
and the run disagree.

Figure mode segments each crop as plaque_papers._cellpose_segmenter does
(model.eval(crop), model defaults). If the Figure run starts passing the
tuned diameter/flow/cellprob, switch figure_pass to segment_plaque_image.

--------------------------------------------------------------------------------
FIGURE MODE, PER WELL (the second request above)
--------------------------------------------------------------------------------

* Run preview in Figure mode detects the wells and reads the text only
  (detect_figure); nothing is segmented.
* A well is selected by clicking its box on the figure (the click is mapped
  through the scaled picture, _ImageView.image_point; the smallest box under
  the point wins, region_at), by selecting its row in the Wells table, or by
  selecting one of its plaques in the Plaques table. The selected box is
  drawn in cyan, its row is selected, and its crop is shown to the RIGHT of
  the figure with "Well n · panel · condition".
* Plaque preview segments the selected well with the Plaque settings
  (segment_well -> spacr.plaque.segment_plaque_image, off the GUI thread),
  draws the outlines on the crop and on the figure, and fills that row's
  Plaques and Mean area columns.
* Find plaques in all wells does every well, one job after another, with
  "Finding plaques in well n (k of N)…" and Cancel (which drops the queue
  and the answer in flight).
* The table area is two tabs: Wells, and Plaques (n) -- one row per plaque:
  well, panel, condition, plaque id, area px, ratio to the panel median
  (over every segmented well of that panel, as the run's
  area_vs_panel_median), ratio to the well median, perimeter, equivalent
  diameter, eccentricity, solidity, centroid y/x -- the run's per_plaque
  columns (plaque_rows).
* Figure settings… (detector, sizes, confidence, read text, confirm
  annotations) and Plaque settings… (plaque model, diameter, flow, cell
  probability) are two pop-ups. Plaque mode keeps its four controls inline.

FROM A PAPER (item 424's "auto gather the figure ledgend")
--------------------------------------------------------------------------------

Figure mode has a "From a paper…" button. Its dialog takes a DOI, PMID or
PMC id (or a PDF via PDF…) and the folder to put the paper's folder in
(default: the current src). spacr.plaque_papers.fetch_paper_to_folder runs
off the GUI thread into <folder>/<paper_folder_name(reference)>, the button
reads "Fetching…" meanwhile, and when it lands the form's src is set to the
new folder (the registry's propagation map now carries src), the figures load
as any folder does, and a note says "<paper>: N figures, M with legends
(licence …), in <path>". The legends go to legends.csv, which the preview
already keys, so a fetched figure asks for no legend.

40 s; "9 figures, 9 with legends (licence cc by)"; form src set to
<out>/10.1371_journal.ppat.1011009; picker holds the 9 figures
(ppat.1011009.g001.jpg ... g009.jpg), plus legends.csv and paper.json.

ONE SETTINGS WINDOW (the third request above)
--------------------------------------------------------------------------------

The preview has ONE "Settings…" button, in both modes, and no inline row of
controls any more. It opens PlaqueSettingsDialog, a QDialog with two tabs:
"Figure" (detector, inference sizes, confidence, read the text, confirm
annotations) and "Plaque detection" (plaque model with Browse, diameter,
flow threshold, cell probability). In Plaque mode the Figure tab is hidden
and the window opens on Plaque detection; flipping the switch while it is
open shows or hides the tab. The controls are the panel's own, lent to the
window while it is open and handed back hidden when it closes, so values
survive and the next pass reads them.

WHERE THE LOOK COMES FROM: nothing is styled here. Being a QDialog is what
gets it spacr.qt.widgets.glass -- the application-wide filter
(install_glass_everywhere, installed at startup in spacr/qt/app.py) that
gives every QDialog the SetupCard behind it: frameless, rounded corners
(CARD_RADIUS), the translucent body and the travelling rim. The two QFrame
pop-ups it replaces were not QDialogs, which is why they looked different.
The same treatment is on Measure's CropSettingsDialog and Mask's
LiveSettingsDialog.

Checked offscreen in dark and light, composited over the screen, beside
Measure's crop settings as the reference: frameless, glassed, 496 x 298.

--------------------------------------------------------------------------------
TEXT DETECTION TAB (the fourth request above)
--------------------------------------------------------------------------------

The settings window has a third tab, "Text detection", between Figure and
Plaque detection, hidden in Plaque mode like the Figure tab. One control per
declared setting, each carrying the setting's own tooltip from
spacr.settings.tooltips:

    text_use_above / _left / _below        check boxes
    text_reach_above / _left / _below      spin boxes, image sizes
    text_panel_reach                       spin box
    text_min_confidence                    spin box, 0-1
    text_ignore                            line edit, comma-separated regexes
    text_order                             editable combo of the orders
    text_separator                         line edit
    text_reread, text_reread_scale         check box, spin box

TUNING IS IMMEDIATE. Every change except the two reread settings re-runs
annotate_regions(..., options=TextOptions) on the regions and words already
cached from the last Run preview -- no YOLO, no OCR -- and refreshes the
Wells table, the Plaques tab's conditions and the well title. The two reread
settings cannot apply to words already read, so they say "press Run preview
to read the figure again"; detect_figure then rereads at text_reread_scale,
or not at all when text_reread is off. The controls are seeded from the form
by apply_settings, written back by Use these settings (the thirteen names are
in the registry's propagation map), and the form hides them in Plaque mode
(FIGURE_ONLY_KEYS). Re-proposing replaces unsaved edits in the Condition
column with the new proposal; saved reviews are re-applied from
figure_annotations.csv as before.

Tested with faked words: the default "WT / +ATc" becomes "+ATc / WT" with
order left,above; "+ATc | WT" with separator " | "; "WT" with the row label
off; "+ATc" when ^WT$ is ignored and when the header is out of reach; a word
scoring 0.4 drops out at minimum confidence 0.5; panel reach 0 loses the
panel letter; and the figure is read exactly once throughout.

BUG, 2026-09-21: A FIELD OVER THE MODE LABEL UNTIL SETTINGS WAS OPENED

Reported on c63dfe309: "when i start live preview in plaque assay i get a
field that covers the mode to the left of the plaque and figure button in the

QDoubleSpinBoxes _spin made (diameter, flow, cell probability, confidence)
were parented to the panel and in no layout, so they painted at its (0, 0)
until the Settings window, handing them back, hid them. The same class of
defect Mask's live preview had three times (0bdf151be, "95 widgets at
(0, 0)"), fixed the same way: _spin parents to the hidden holder, and
PlaquePreviewPanel._stow_free_widgets moves any child in no layout into it
at construction. The test (Settings never opened, both modes) fails with the
fix removed -- four visible spin boxes -- and passes with it.
