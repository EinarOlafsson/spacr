--------------------------------------------------------------------------------
THE PARTS, AS ASKED
--------------------------------------------------------------------------------

  1. BOX SIZE: the maximum is no longer 512 (spacr/qt/screens/make_masks.py
     _MAGNIFIER_SIZE_RANGE = (32, 512)); it can go as high as the open image
     is high or wide.
  2. COLLAPSIBLE SETTINGS CATEGORIES in Make Masks, the way the core
     applications fold theirs.
  3. CELLPOSE MODELS: with Cellpose chosen, every Cellpose model in the model
     zoo can be picked, and there is a Model zoo button for Cellpose.
  4. THRESHOLDS: the flow threshold and the cell-probability threshold the
     detection uses can be chosen.
  5. CLICK-AND-DRAG: pressing and pulling keeps generating and applying new
     objects, merging the objects the cursor passes over.
  6. WHAT IS SAVED: an option between saving every object in the zoom area and
     saving only the objects touching the mouse -- so non-centred objects can
     be turned off, and dragging over an object selects and merges all of its
     frames into one object over the centre of the ROI.
  7. OTSU: controls over the Otsu threshold (threshold correction).
  8. SHIFT + SCROLL increases or decreases the box size.
  9. THE EXISTING CELLPOSE-SAM SETTINGS CATEGORY applies to magnifier detection
     when Cellpose is on, and gains the Otsu settings.
 10. OTHER MODELS "if you can": a live YOLO, or DINOCell (spaCR already has
     DINOCell and SAMCell behind `segmentation_backend`, items 404/405).

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

  * The box can be set to the image's full height/width, by field and by
    Shift+scroll, and stops there.
  * Every Make Masks settings category folds and unfolds, and remembers it, as
    the core applications' do.
  * With Cellpose on, the model list is the model zoo's Cellpose models, the
    Model zoo button opens the zoo, and the flow / cell-probability / Otsu
    values set in the Cellpose-SAM category are the ones the magnifier's
    detection actually uses (a test checks the values reach the call).
  * A press-and-drag across cells produces merged objects along the path, as one
    undo step; with "only objects touching the mouse", objects away from the
    cursor are not saved, and dragging over one object merges its pieces into a
    single object centred on the ROI.
  * DINOCell (and SAMCell) are selectable detectors where installed, with a
    clear message where not; YOLO is either added or recorded here with why not.
  * New labels and tooltips are translated in all nine languages.

WHAT EACH PART DOES NOW

  1. BOX SIZE. The Size box's range is (32, 512) only while no field is open.
     When a field opens, the canvas calls _LiveMagnifier.forget() with the new
     field in place, which emits size_range_changed; the range becomes (32,
     the field's LONGER side) -- the box is square -- and a size past it is
     clamped, in the box and in the magnifier. A field smaller than 32 px
     lowers the floor with it, so the range is never empty.
  2. COLLAPSIBLE CATEGORIES. All seven categories (Brush, Magic wand, Display,
     Auto-filter objects, Object operations, Cellpose-SAM, Live magnifier) are
     the core applications' own spacr.qt.widgets.section.Section: SectionCard,
     the chevron SectionHeader with the uppercase translated title, a click
     that folds the body. They START OPEN, unlike a core module's -- this is the
     editor's tool column, used between strokes -- and what the user folds is
     remembered through preferences.set_section_layout("make_masks/settings")
     and restored next visit; unfolding is remembered too.
  3. CELLPOSE MODELS. The Cellpose-SAM Model box lists the installed Cellpose
     (cpsam first) and every Cellpose entry in the model zoo, read without
     waiting on the network. A zoo model on this machine is listed by its zoo
     key and carries its path; one not downloaded is greyed out, with no path
     -- a combo box is not where a gigabyte download should start. The zoo's
     YOLO well detector is not listed. "Model zoo…" beside the box opens the
     same picker as the live preview's, restricted to kinds=("cellpose",),
     rebuilds the zoo rows (so a model just downloaded becomes selectable) and
     selects the pick.
  4. THRESHOLDS. The flow threshold and cell-probability threshold are the
     Cellpose-SAM category's existing boxes (defaults FLOW_THRESHOLD 0.4 and
     CELLPROB_THRESHOLD 0.0; ranges 0-10 and -12..12, which hold Cellpose's
     own GUI ranges), and they are now what the magnifier's Cellpose call gets.
  7. OTSU. "Otsu threshold correction" (0.10-5.00, default 1.00) in the
     Cellpose-SAM category: a threshold correction factor in CellProfiler's
     sense -- Otsu's level is multiplied by it. Otsu detect applies it through
     mask_engine._otsu_instances (dark objects are measured on the inverted
     image, so above 1 is stricter on either side; exactly 1 is otsu_instances
     itself). The magnifier's Classical mode applies it to its Otsu cut
     (_classical_region_labels(correction=)). A region that is not two clear
     populations is cut at its noise floor, which is not Otsu's level, and the
     correction does not apply there; the tooltip says so.
  8. SHIFT + SCROLL. With the magnifier on, Shift + wheel over the canvas steps
     the size by the canvas's Zoom per notch (at least 1 px), clamped to the
     range, and the Size box follows. It never zooms the view or the box. A
     sideways notch counts, for platforms that send Shift + wheel
     horizontally. Plain wheel, and any wheel with the magnifier off, is as
     item 407 left it. Built in wheelEvent.
  9. ONE SOURCE OF TRUTH. The magnifier reads the Cellpose-SAM category's
     model, flow threshold, cell probability, diameter and normalization, and
     the Otsu correction, through _magnifier_context; _MagnifierRequest carries
     them; the Cellpose segmenter passes them to cellpose_detect exactly as
     Cellpose-SAM detect does. The old FLOW_THRESHOLD constant and
     "-sensitivity" are gone from that call. The magnifier's Sensitivity is now
     the Classical mode's only, and is greyed out in any other mode. Changing
     any of these discards whole-image objects and re-segments. A sentence in
     the category says which magnifier mode reads which setting, and ledger
     entries record the thresholds, model, diameter and correction.
 10. OTHER MODELS. DINOCell and SAMCell are Mode choices wherever their
     packages are installed; where not, the Live magnifier category shows a
     line per missing model naming its extra (pip install "spacr[dinocell]" /
     "spacr[samcell]"). Both run through spacr._segmentation_backends
     ._load_backend -- the loader segmentation_backend uses -- built once per
     process, and their eval answers cellpose_detect's call, so DINOCell gets
     the category's cell probability and SAMCell uses its own thresholds. One
     that is installed but cannot build falls back to Classical, and the
     status line carries the backend's own message naming the extra.

YOLO: NOT ADDED, AND WHY

  * There are no weights to run. The zoo's only YOLO,
    yolo_welldetect_v3.pt, is a box DETECTOR of plate wells: no masks, not
    cells. Ultralytics' stock -seg checkpoints are trained on COCO classes
    (person, car, ...) and do not segment cells or vacuoles, so a live YOLO
    mode today would be a choice that finds nothing useful.
  * The dependency is feasible as an optional extra -- ultralytics is already
    spacr[plaque], imported function-locally by spacr/plaque.py, and absent
    from the dev environment -- but it is AGPL-3.0 against spaCR's BSD-3, a
    reason not to lean on it further for a mode with no model.
  * When a cell instance-segmentation YOLO checkpoint exists in the zoo, it is
    one segmenter in _MAGNIFIER_SEGMENTERS plus a find_spec("ultralytics")
    offer, the same shape as DINOCell and SAMCell.
