WHAT THE STATE WAS
--------------------------------------------------------------------------------

The Import module (app key 'foreign', spacr/qt/screens/foreign.py over
spacr/foreign.py) found plate, well and field from FOLDERS only
(spacr.convert.scan's layouts) and channel/z/t from a handful of filename
tokens. The nineteen filename conventions Mask offers as `metadata_type`
(spacr.regex_infer._METADATA_CONVENTIONS) were not reachable from Import at
all, so an Opera Phenix or ArrayScan export imported as one well of unrelated
fields. There was no test data for Import.

WHAT WAS BUILT (2026-09-21)
--------------------------------------------------------------------------------

THE IMPORTER (spacr/convert.py, spacr/foreign.py, spacr/regex_infer.py).
convert.scan and foreign.plan_import take metadata_type / custom_regex. Each
name is matched with the SAME pattern Mask uses (regex_infer._metadata_match),
and three things Mask leaves to the user are done here:
  - vendor well spellings: CQ1 index over 24 columns (W0097 = E01), Harmony
    r05c01, Leica U00--V04 (U = column, V = row, zero-based), IN Cell 'E - 01';
  - zero-based axes, from regex_infer._METADATA_ZERO_BASED (ArrayScan f/d,
    EVOS d, Micro-Manager, the Leica exports, ScanR Z/T);
  - the field numbers a name states are KEPT (F009 stays field 9) when every
    field of a well has one and none repeats; otherwise 1..N as before.
A name that breaks the chosen convention is reported unreadable, not guessed.
A container that holds the channel / z / t axis itself wins over the name.
Masks pair on (well, field) when the plate key differs between the image and
mask folders (a convention with no plate group).

THE DATA: tools/build_import_example.py (build / verify / pack). Wells E01,
E02 x fields 9, 10 x channels 1-3 of toxo_mito plate1, raw TIFFs cut to 896 px
(the window keeping most whole cells; cut objects removed), masks from the
Mask run's merged arrays, cell measurements of exactly the remaining cells.
22 generated variants (17 vendor conventions + custom + folders + CZI +
OME-TIFF + ImageJ stack) and 2 CC BY 4.0 samples (ND2 by Maxime Woringer;
LIF by Sean Warren and Michael Goelzer, downloads.openmicroscopy.org).

VERIFIED on the published archive (downloaded back, byte-identical, 24/24
pass tools/build_import_example.py verify); every import-route variant also
run through foreign.run_import, and the 22 merged arrays are pixel-identical
to each other (rank-numbered variants mapped back). ND2 converts 1 plane,
the LIF samples 88.

THE BUTTON: "Load test data..." on the Import screen, spacr/qt/import_demo.py.
Driven for real headless: fetched the published archive through the Qt
worker, filled the screen for zeiss_czi and previewed 4 fields, 36/36 rows;
a second press opened from the cache in about a second.

FOUND AND FIXED ON THE WAY

    readlif release has: every LIF scanned as unreadable. Now LifFile /

    dimensions. tests/test_convert.py's double carried the fake API and is
    now strict.
  - regex_infer's Leica Matrix Screener text said U is the well row; the
    reference parser it cites (leicaexperiment) compares u with well_column.

FOUND AND NOT FIXED
  - nd2reader reads the RGB brightfield ND2 samples on the OME server
    (zenodo-10277961, zenodo-12734440) as a (2048, 4319) plane and fails on
    zenodo-17186598 with division by zero; spaCR's ND2 path inherits both.
  - The Import screen merges one plane per channel, so a time series (all the
    small CC BY LIF samples are) cannot go through it; those go through the
    Format Converter instead.
