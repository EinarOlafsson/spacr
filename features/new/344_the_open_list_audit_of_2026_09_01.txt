--------------------------------------------------------------------------------
WHERE THE NUMBERS NOW LIVE
--------------------------------------------------------------------------------

In `tools/build_instruction_index.py`, in the `STAGE` table, so
`instructions/00_INDEX.txt` carries a percentage on every open row and CI's
`--check` keeps it honest. That file's own docstring already explains why the
index is generated and not written: it went nine days stale once, and an index
that disagrees with the folder is worse than none because it is believed.

A percentage in STAGE is a hand-maintained number. It is right on the day it
is written and decays like any other. RE-AUDIT BEFORE TRUSTING IT, and the
cheapest way to do that is the one used here.

--------------------------------------------------------------------------------
THE METHOD, BECAUSE IT COST TWO HOURS AND SHOULD COST LESS NEXT TIME
--------------------------------------------------------------------------------

1. `git log --oneline --since=<date> --grep="\bNNN\b" -E` for every open
   number. Work that shipped without its file being updated shows up here
   immediately, and this is what found 319, 327, 330 and 336. It is the
   single highest-yield step.
2. Then grep the CODE for the thing the file says is missing. A commit
   message is a claim; `MAX_ORGANELLES = 26` is a fact.
3. Then RUN the tests the file names. 306 and 341 both turned on this, in
   opposite directions.
4. Only then read the trailing notes.

The repository's standing warning -- the header often says "not started" when
it is done -- is now measured at five of twenty-three in one sweep.
