--------------------------------------------------------------------------------
REQUIREMENTS
--------------------------------------------------------------------------------

1. Inventory spaCR-owned application copies, private runtimes, bundle/package
   metadata and launchers on each supported OS. Install the requested version;
   inherited package pins, cached wheels and offline bundles must not silently
   install another version. Preserve N627's no-downgrade contract.
2. Before success, verify the actual import version, module path, interpreter
   and executable used by the desktop launcher and restarted application.
   Installer exit 0, registry/plist display versions and isolated import probes
   alone cannot establish the launched version.
3. Stage and validate before retiring the working application. On failure
   retain/restore its runtime and launchers. Then remove obsolete spaCR-owned
   application code and launchers. Do not erase unrelated Python/Conda
   environments, packages, projects, outputs, models or preferences.
4. Preserve caches, downloaded data and nonessential temporary files by default.
   A separate default-off GUI cleanup choice shows each folder's path, contents
   and size. Automatically remove only identified spaCR-owned staging or
   interrupted-install artifacts needed for replacement. Do not conflate app
   replacement with whole-root deletion; retain macOS rollback backups safely.
5. macOS consent, dependency, administrator, retry and cleanup choices stay in
   the installer/progress window throughout first-user runtime setup. No helper
   opens Terminal for questions after .pkg closes. Cancellation/failure leaves
   a clear usable state. Use GUI choices on other desktop platforms too.
6. Cover in-app update and each shipped installer: Windows NSIS/PowerShell,
   macOS online .pkg/app launcher and frozen app, Linux online/frozen .deb and
   launchers. Discover stale custom/all-users launchers safely. Do not claim
   RPM app support merely because dnf dependencies exist.
7. User strings use tr(); Work receives final strings/behavior for tutorial 04.
   Publish required repairs with their owning checks; release acceptance stays open.

--------------------------------------------------------------------------------
ACCEPTANCE
--------------------------------------------------------------------------------

- Native old-to-new upgrade and same-version reinstall through in-app and each
  desktop installer: reopened version/module/executable match the request;
  obsolete spaCR application code and launchers are gone.
- Newer runtime is not silently downgraded. Stable/nightly choices, overrides,
  offline/cached wheels and interrupted locks cannot yield wrong-version success.
- Default upgrade preserves caches, models, outputs, preferences and configured
  folders nested inside an installation root. Optional cleanup removes only
  selected folders. Required reinstall temp cleanup is narrowly scoped.
- Missing dependencies, permissions, disk exhaustion, import failure and
  cancellation preserve a working previous installation or verified rollback.
- macOS first install and update require no Terminal answers. Native acceptance
  exercises the actual installer and desktop launch, not just its helper.
- Repeated installs are idempotent; owning contracts exercise wrong-version
  detection, preservation, rollback and launcher resolution.

2026-10-14 — HOME PRIVATE STAGED-RUNTIME REPLACEMENT COMPONENT
--------------------------------------------------------------------------------

Implemented on the Home updater/installer lane; not native installer acceptance.
Windows and Unix online helpers stage dependencies and verify the actual imported
spaCR code, distribution version, private interpreter and prefix before replacing
the existing runtime. A published-runtime verification failure restores its prior
runtime. The helper waits for a verified replacement before retiring other copies
or restarting. Desktop and restart commands use the same isolated interpreter
mode as the identity probe, preventing current-directory/PYTHONPATH shadow copies.
Pinned pip upgrades reject an older target before invoking the package tool; the
existing macOS unpinned adapter retains its no-downgrade floor and verifies actual
code identity after installation.

Default retirement preserves declared data/cache/model locations, known data
folders nested inside installation roots, and unknown user folders. Current-root
launchers are retained during staging. Offline test data is not overwritten. A
configured user-data location inside the retiring Python environment causes a
refusal before replacement, rather than destructive relocation. No real user
installation or data was modified by the validation.

Finite owning cohort: 292 PASS, actual exit 0, including real private temporary
runtime/installer-CLI identity probes, wrong imported code/version/owner/prefix,
no-downgrade, nested data retention and isolated-launch commands. The native-C
launcher argument fixture ran on Linux; this is not native macOS acceptance.
Fatal Ruff and Unix shell syntax passed. Normal English API regeneration/audit
passed for 13,418 symbols. The normal scoped generator regenerated exactly
three changed API entries in all nine locales and validated each current block
(actual exit 0). Semantic review caught and corrected an initial German/Spanish
MT inversion of cache preservation. All 27 rewritten locale paragraphs now have
exact-source AI technical reviews (Codex; no human/native-speaker signoff).
Unchanged review blocks were rebound to their actual index and rewritten blocks
retired in place, retaining original reviews. Unrelated catalog/model-input
records and existing review debt were unchanged.
