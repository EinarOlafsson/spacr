3D MAKE MASKS WITH SHARED ANCHOR AND SURFACE EDITING
================================================================================

Status:    OPEN 2026-10-10 — implemented and published with nine-language captions and API pages; only the maintainer's hands-on desktop check is left
Requested: 2026-10-08
Owner:     Home/root CPU mask editing lane; workstation API/docs/translations/tutorials
Depends:   N672 validated gate anchor and surface editing logic

WHAT THE STATE IS

After the Gate Editor anchor and surface logic is implemented, the user wants the same interaction model in Make Masks to draw and modify 3D masks.

WHAT TO DO

Add a 3D mode to Make Masks in which users can draw masks, rotate the view and edit their volume using the same validated anchor and surface logic as N672. Provide evenly spaced anchors on every edge and surface, including the depth axis, an Anchor density setting, and a separate anchor visibility toggle.

Allow users to select multiple surfaces and move their associated anchors together using dragging or the mouse wheel. Keep shared anchors connected, distinguish view rotation from editing, and allow nonuniform depth deformation rather than only extruding a 2D outline.

Apply edited geometry to the actual mask voxels and preserve the original image shape, axis order, voxel spacing and object label identity. Define supported volumetric input and output through the existing Make Masks paths. Preserve existing 2D drawing and bounding-box annotation behavior. Save/load, undo/redo and invalid-geometry handling must follow the shared gate editing behavior where applicable. Reuse existing modules and do not add a new module under spacr/.

HOW TO KNOW IT WORKED

Use a small synthetic 3D image with independently known expected voxels. Draw and edit a mask in each axis after rotating the view; verify anchor density and visibility, individual anchors, multi-surface wheel/drag movement, nonuniform depth, voxel membership, object labels, anisotropic spacing, save/load and undo/redo. Run focused capped CPU/Qt checks and the relevant existing 2D mask and bounding-box regressions. Do not require GPU jobs or alter the workstation-owned livecell/cellposeTIME processes.

2026-10-16 — Maintainer review: "much better, now speed". Turning, zooming
and panning must feel instant, like napari (30-60 fps while dragging); the
view "still looks 2-dimensional". Built (Claude, spacr-d7 worktree):
- GPU volume renderer. Stack: VisPy gloo (OpenGL), already a core spaCR
  dependency and already run under PySide6 by the fractal backdrop; pygfx/
  wgpu and moderngl are not installed in the shipped environment (moderngl
  is only the optional flow-gpu extra), so no new dependency. The renderer
  (spacr.layers.GLVolumeRenderer) ray-marches every channel layer in a
  fragment shader (MIP, Attenuated MIP, Translucent, Average, MinIP; colour,
  opacity, contrast) and lays the masks over it (Surface or Translucent),
  then writes the object ID nearest the viewer per pixel for picking. It
  takes the SAME VolumeRays as the CPU renderer, so the camera, anchors,
  slice plane, Paint/Erase and Pick are unchanged and aligned. It draws
  into an offscreen Qt OpenGL context (_GLVolumeContext) on the GUI thread
  and the frame is shown under the matplotlib axes as before. Offscreen
  (EGL, RTX 3090): a 900x800 frame with 400 samples per ray in 8-10 ms;
  the True 3D drag loop (camera change, GPU frame, both matplotlib draws)
  at 16.7 ms per frame, 60 fps, against about 0.06-0.8 s per CPU frame.
  GPU and CPU frames agree within 2/255 per channel on every rendering,
  finish and magnifier setting, and pick the same objects.
- Render backend list: Auto, OpenGL, CPU (software). Vulkan, Metal and
  Direct3D need wgpu, which spaCR does not ship, so they are not offered.
  Auto uses OpenGL when a desktop GL context can be made and a test frame
  draws, and refuses software rasterisers (llvmpipe etc.); otherwise, or
  when a GPU frame fails, it draws on the CPU and logs one line ("GPU
  rendering is unavailable (...); drawing on the CPU."), also shown under
  the view. The choice is saved (preferences.get/set_volume_view).
- "Render at full resolution" is replaced by a Render scale slider, 1-100 %
  of full resolution along each axis (spacr.layers.render_scale: 50 % =
  every 2nd voxel along X, Y and Z into half-size pixels). While the view
  moves it draws coarser (CPU: at most 262,144 voxels and 4-px pixels; GPU:
  same voxels, 2-px pixels) and sharpens to the slider 250 ms after it
  stops. Defaults: 100 % on the GPU, 50 % on the CPU; the slider is saved.
- Surface finish list on the Masks layer row: Matte, Satin, Glossy,
  Metallic (Blinn-Phong: ambient/diffuse/specular/shininess, metal tints
  the highlight with the object colour). Normals come from the mask itself
  (central differences of the occupancy), so the CPU draws the same light
  (its surfaces hit at voxel samples, so edges are blockier). Saved.
- 3D magnifier: the Magnifier button in True 3D, or M (the Live magnifier
  key) while True 3D is shown, shows a cube (accent outline) that follows
  the pointer on the slice plane (or through the middle of the volume when
  the plane is edge-on). Inside it the volume is drawn magnified about its
  centre; outside it everything is dimmed to 35 %. Shift+wheel resizes the
  cube and Ctrl+wheel zooms inside it, as Shift/Ctrl do for the 2-D
  magnifier; the plain wheel still zooms the view. The 2-D magnifier is
  untouched.
