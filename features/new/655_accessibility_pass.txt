WHAT WAS BUILT (2026-10-04)
  Names. `spacr.qt.i18n._name_for_assistive_tech` runs at the end of every
  language pass (`retranslate_widget_tree`), which already reaches every
  module screen when it is built, every dialog when shown and every subtree
  that arrives later. A control assistive technology would announce with no
  name (icon-only buttons, fields, spin boxes, combos, sliders, text boxes)
  is named after, in order: its tooltip's first sentence, its placeholder,
  the spin box or combo it is the editor of, its settings-row label, the
  label a layout puts in front of it, the tab it is the page of, and its
  object name read as words. A table's corner button is "Select all". A
  control with no tooltip is described with its label's help. Names set by
  code are never replaced; derived ones are recomputed on every pass, so
  they follow language changes. Buttons with a caption are left to Qt,
  which names them after the caption and follows it when it changes.
  Measured with QAccessible on the 48 screens: 207 of 902 visible controls
  had no name before, 0 after.

  Keyboard. The same pass sets Tab to leave text boxes and tables (Qt's
  defaults typed a tab or stepped between cells, trapping Tab on Mask,
  Classify, Map barcodes and Regression). `a11yKeepsTab` opts a widget
  out. The CSV column field's picker button was unreachable by Tab; its
  tab order is now edit then button.

  High contrast. `HIGH_CONTRAST_PALETTE` in spacr/qt/theme.py ("high_contrast"
  in THEMES and PALETTE_THEMES), offered as "High contrast" in Preferences >
  Appearance > Theme with a tooltip sentence. Every text role clears 7:1 on
  every surface. The theme-invariant button roles (CONSTANT_ROLES) stay
  blue at 4.75-6.96:1.

  Tests: tests/qt/test_accessibility_pass.py (lint per module screen, Tab
  traversal per Core screen, helper unit tests, theme contrast and choice).
