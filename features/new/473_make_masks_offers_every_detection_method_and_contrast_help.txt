================================================================================
MAKE MASKS OFFERS EVERY DETECTION METHOD, AND WAYS TO MAKE OBJECTS EASIER TO SEE
================================================================================

Status:    OPEN, filed 2026-09-22. Not started.
Owner:     Claude (spacr/qt/screens/make_masks.py and the detection engine).
Requested: 2026-09-22, by the maintainer, in these words:

           "in the make mnasks modual, in addition to the otsu, and cellpose
           options i would like to add all the options that are available for
           organell detection. i would also like to add aoption to enhance
           contrast in the image and other strategies to potentially make
           objects easier to detect on the image."

WHAT IS THERE TODAY (nightly, 2026-09-22)
--------------------------------------------------------------------------------

* Make Masks' magnifier and whole-image detection offer these modes
  (spacr/qt/screens/make_masks.py, `_MAGNIFIER_SEGMENTERS` ~2608): "otsu",
  "cellpose", and the installable backends in `_MAGNIFIER_BACKENDS`
  (Cellpose 3 cyto3/cyto2/cyto/nuclei, DINOCell, SAMCell).
* Organelle detection already implements eight methods
  (spacr/settings_spec.py:287, `organelle_method`; engine in spacr/object.py
  ~1437; guidance per morphology in spacr/organelle_types.py, whose
  LEGAL_METHODS says which suit which shape): otsu, adaptive, log, dog,
  ridge, hysteresis, cellpose, unet.
* Make Masks can already detect on the normalised image or not (the
  "detect on the normalized image" option added 2026-09-21) and invert for
  detection (item 419 point 9c).

WHAT TO BUILD
--------------------------------------------------------------------------------

1. EVERY ORGANELLE METHOD IN MAKE MASKS. Add adaptive, log (Laplacian of
   Gaussian), dog (difference of Gaussians), ridge, hysteresis and unet to
   the Make Masks mode box beside Otsu and Cellpose, for the magnifier and for
   whole-image detection alike. REUSE the organelle engine in spacr/object.py
   rather than a second copy, so a method means the same thing in both
   places. Each method brings its own parameters (block size and offset for
   adaptive; sigma(s) for log/dog; scale and threshold for ridge; low/high
   for hysteresis; the model for unet), shown only when that method is
   chosen, with the organelle_types guidance on what each suits (spots,
   puncta, tubules/networks, blobs). The Otsu mode's smoothing / correction /
   fill-holes / split options stay as they are.
2. CONTRAST ENHANCEMENT before detection, as options the detection reads
   (and the magnifier box shows, the way it already shows the normalised
   image), chosen independently of the method:
     * percentile stretch (already there as normalisation -- keep, name it);
     * gamma correction;
     * CLAHE (contrast-limited adaptive histogram equalisation), with tile
       size and clip limit;
     * global histogram equalisation.
3. OTHER STRATEGIES TO MAKE OBJECTS EASIER TO DETECT, each an option in the
   same pre-detection chain:
     * background subtraction (rolling ball / top-hat, radius in pixels;
       spaCR already has background-removal settings for Mask -- reuse them);
     * denoising (Gaussian, median, and non-local means or bilateral where
       scikit-image provides it);
     * sharpening (unsharp mask);
     * morphological opening/closing to separate touching or join broken
       objects;
     * a distance-transform / watershed split for touching objects (Otsu
       already has "split"; offer it to the other threshold methods);
     * invert (already there; keep).
   The chain applies in a fixed, documented order (e.g. background ->
   denoise -> contrast -> sharpen -> detect -> morphology -> split), and the
   whole chain is saved with the mask's provenance so a mask can be
   regenerated.
4. SHOW WHAT THE DETECTOR SEES: the magnifier and the canvas can show the
   enhanced image (not only the raw one) so the user can judge each step; a
   one-click "compare" (raw vs enhanced) is enough.
5. PERFORMANCE: every step runs on the magnifier's box region live, as today;
   whole-image runs stay off the GUI thread with progress and cancel (item
   407's whole-image machinery). Heavy steps (non-local means, unet) say so.

WHAT TO BE CAREFUL WITH
--------------------------------------------------------------------------------

* Whether the enhancement chain also belongs in the Mask module's own
  pre-processing (so a model trained on enhanced masks sees the same input at
  inference) -- ask the maintainer before wiring it into Mask; within Make
  Masks it only changes how objects are detected for curation.
* New captions and tooltips are translated strings in nine languages: list
  them for the catalog lane rather than regenerating spacr/qt/i18n_catalogs.

DONE WHEN
--------------------------------------------------------------------------------

* Make Masks' mode box offers otsu, cellpose, the backends, and adaptive,
  log, dog, ridge, hysteresis and unet, each detecting through the same code
  as organelle detection, with its own parameters.
* Contrast enhancement (gamma, CLAHE, histogram equalisation, percentile
  stretch) and the other strategies (background subtraction, denoising,
  sharpening, morphology, split) can be switched on before detection, in a
  documented order, and the magnifier shows the enhanced image.
* Each option is tested on a real field, and the chain is recorded with the
  masks it produced.

WHAT LANDED (nightly, commits 226397ff8, 9a87d7dec, 6202379a1, 10b049b95,
e36fd3f9d, 7d74945eb)

* spacr/qt/organelle_modes.py -- the bridge. A Make Masks mode names an
  (organelle_morphology, organelle_method) pair, the parameters that pair
  reads (PARAMETERS_FOR) and the call that runs it. `segment()` reaches
  spacr.object._segment_single_image and, for unet, _segment_unet: THE SAME
  FUNCTIONS THE ORGANELLE MASK PIPELINE'S WORKERS CALL. There is no second
  implementation; tests/qt/test_make_masks_offers_every_detection_method.py
  ::test_a_method_runs_through_the_organelle_engine_and_not_a_copy holds
  that down by intercepting the engine's entry point.
  The morphology each mode runs under, and why: adaptive -> irregular (the
  branch that smooths, closes, opens, fills holes and watershed-splits,
  which is what a solid object wants; the spots branch's adaptive top-hats
  first and erases anything wider than its disk); log and dog -> spots;
  ridge, hysteresis and unet -> network. Those are the only branches that
  implement them.
* spacr/organelle_types.py -- morphologies_for_method() and
  method_guidance(), built from LEGAL_METHODS, so the sentence the Mode box
  and the Detection methods card show about a method is spaCR's own record
  of which shape it detects and not a second opinion.
* spacr/qt/detect_chain.py -- the chain, in ONE fixed order, CHAIN_ORDER:
      percentile stretch -> background -> denoise -> contrast -> sharpen
          -> detect -> morphology -> split
  The percentile stretch is the existing "Detect on the normalized image"
  and stays on the canvas, because its two levels are percentiles of the
  WHOLE FIELD and the magnifier's box is not the field. The module
  docstring argues each of the other boundaries. provenance() records only
  the steps that ran, with the order, so a mask can be regenerated.
* spacr/qt/screens/make_masks.py -- six new rows in the Mode box (Adaptive
  threshold, LoG blobs, DoG blobs, Ridge filter, Hysteresis, U-Net), all
  through one segmenter, _organelle_segmenter; two settings categories,
  "Detection methods" (the chosen mode's own parameters, the rest hidden)
  and "Image enhancement" (the chain, with the order printed on the card);
  "Show the enhanced image" on the canvas and in the magnifier's box, and
  "Compare raw and enhanced", which shows the box under the mouse when
  there is one and the whole field otherwise.
  The chain and the parameters are part of the magnifier's REQUEST KEY and
  are applied on the WORKER thread, to the box's own region, so a heavy
  step is never a frozen window; whole-image scope is item 407's machinery
  unchanged, with a ticket check before and after the detector.
  Both detect buttons read the chain, through one call:
  _detector_image() is now _MaskCanvas.detection_source().

WHAT THE NUMBERS SAY, beyond "it runs"

* THE CHAIN IS THE BIGGEST EFFECT ON THIS DATA. Gamma 0.5 more than doubles
  Otsu's F1, 0.297 -> 0.639, and histogram equalisation does nearly as well
  (0.605). Both lift the dim end of a 16-bit histogram whose vacuoles sit
  just above a bright host-cell haze, which is exactly the complaint the
  item was filed about. Neither changes a pixel on disk.
* AND IT CAN ALSO HURT. The unsharp mask halves Otsu's F1 (0.297 ->
  0.157): it puts a rim round every vacuole and a moat outside it, and the
  threshold lands on the rim. A top-hat at r40 changed nothing here and
  cost 27 s a field. The card is a set of things to TRY on the box before
  the button, which is why the magnifier shows what they did.
* HYSTERESIS IS THE BEST BARE METHOD ON VACUOLES (0.523) and the fastest
  (0.4 s a field): two percentile levels suit a bright, well-separated
  object on a dim field. Its thresholds are percentiles, so a monotone
  contrast curve cannot move them -- "hysteresis + gamma 0.5" is the same
  mask to the object, which is a true fact about the pair and not a bug.
* ADAPTIVE FINDS THE MOST VACUOLES (recall 0.649) and pays for it in false
  positives (154); one morphological closing at r3 turns that into the best
  precision in the table (0.850) at F1 0.596. That pair -- a permissive
  detector and a cleanup step -- is what the chain's post-detection half is
  for.
* THE BLOB DETECTORS ARE THE WRONG TOOL HERE AND SAY SO. LoG and DoG are
  spot detectors; a 40 px vacuole is not a spot. With the spot watershed on
  they score 0.000, because _blobs_to_labels grows a watershed over
  everything above the 20th percentile and one object swallows the field;
  with it off they stamp discs and reach 0.154 and 0.266. The Detection
  methods card's "Split touching spots" is therefore the box that matters
  most for those two, and the organelle_types guidance on the row already
  says they suit "small round spots and puncta".
* RIDGE IS THE WRONG TOOL AND SAYS SO TOO (0.133): its guidance reads
  "Suits filaments, tubules and networks", and a vacuole is neither.

That is the point of the row's guidance sentence: the box now offers eight
ways of looking, and the numbers above are what each one is for.

TIMING AND THE HEAVY MARK

Whole 1,994 px fields, CPU: Otsu with no chain 0.7 s; hysteresis 0.4 s;
adaptive 2.8 s; dog 2.0-3.3 s; ridge 3.8 s; log 6.6-7.0 s. Chain steps, on
top of a 0.7 s detection: median denoise +1.1 s, gamma +3.3 s, CLAHE
+3.5 s, top-hat r40 +26.7 s. heavy_steps() therefore warns on non-local
means, bilateral denoising, and a BACKGROUND RADIUS over 20 px -- the
radius and not the method, because a 5 px top-hat is instant. On the
magnifier's box every one of these is a small fraction of the above.

STILL OPEN

* THE MASK MODULE'S OWN PREPROCESSING IS UNTOUCHED, deliberately. The item
  says to ask the maintainer first, and the question is a real one: a model
  trained on masks curated over an enhanced image would want the same
  enhancement at inference, and that is a decision about the pipeline
  rather than about this screen. FOR THE MAINTAINER: should Mask's
  preprocessing grow the same chain, reading the same detect_chain module,
  so a mask run can be told to detect on the enhanced image?
* THE NINE TRANSLATION CATALOGS ARE NOT REGENERATED. The new captions are
  listed for the catalog lane by
  tests/qt/test_make_masks_settings_explain_themselves.py
  ::_awaiting_translation, and a second test in that file fails as soon as
  the lane has translated one, so the list empties itself. Only the English
  source layer was refreshed (tools/build_i18n_catalogs.py --sources-only),
  which the caption ratchet requires.
* U-NET IS OFFERED AND NOT MEASURED HERE: it needs a .pt/.pth checkpoint,
  and there is none in the example data. Its parameters, its heavy mark and
  its path picker are on the card; the numbers above are the seven methods
  that need nothing installed.
* The whole-image progress BAR stays indeterminate for the classical
  methods -- item 407's counter is Cellpose's tiles and a scikit-image
  filter has none. Cancel is honoured between steps. Seconds a field, so
  this is not felt; it is written down in _organelle_segmenter's docstring.
