"SHOW" OFFERS THE WELLS THE CHOSEN GUIDES ARE IN

Owner:     Qt GUI (cell table graphs, volcano selection)

--------------------------------------------------------------------------------
A. THE THREE CHOICES
--------------------------------------------------------------------------------

  1. gRNAs -- only the objects annotated with the chosen guides.
  2. gRNAs + other datapoints in selected wells -- those objects AND every
     other object in the same wells. MISSING TODAY.
  3. All datapoints -- the whole table.

The middle one is the comparison that matters, and it is the one that is not
offered: it is what makes an effect readable as an effect. A guide's cells
against every cell in the screen compares two different experiments; a
guide's cells against their own well-mates compares two populations that
shared a plate, a day, a stain and an imaging session.

--------------------------------------------------------------------------------
B. WHAT A SELECTED WELL IS
--------------------------------------------------------------------------------

A selected well is a well containing one of the guides chosen on the volcano
plot. THE VOLCANO IS THE SELECTOR -- the same click that picks a point picks
the wells -- and the user can then narrow that set: "the user should be able
to choose a selection of these wells".

So the well set has two stages: derived from the guide selection, then
editable. Which means it must be VISIBLE. A set the user is invited to narrow
and cannot see is a set they cannot narrow.

Depends on instruction 206: with one guide selectable at a time, the well set
is whatever one guide touched.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

* All three choices are offered and each draws a different population.
* Choosing the middle one plots the guides' objects and their well-mates,
  distinguishable from each other on the plot.
* The selected wells are shown, and narrowing them narrows the plot.
* Selecting different guides on the volcano changes the wells.
* Zero selected guides is handled and says so rather than drawing everything
  or nothing.

DONE 2026-08-21
--------------------------------------------------------------------------------

`spacr/well_scope.py` decides the population; the panel offers the three.

A SEPARATE BOX FROM THE CLASS FILTER. "Which objects are on the plot" and
"which of the classes on it to draw" are different questions, and one box
answering both would have a list whose entries mean two different things.

THE TWO SIDES ARE DISTINGUISHABLE. `select` marks each object `chosen gRNA`
or `well-mate` under the middle scope -- drawing them in one colour would
answer the question by hiding it, and the comparison IS the two populations
side by side.

THE WELL SET IS DERIVED THEN EDITABLE, and `None` is not `[]`. "Not narrowed
yet" and "narrowed to nothing" are different states, and the difference is
what lets a NEW guide selection re-derive rather than stay empty -- a
selection that stayed empty after the user picked a different point would
read as a broken click.

THE ORDER IS THE TABLE'S, not sorted, so a user narrowing the set sees the
wells in the order the screen was laid out.

NO SELECTION DRAWS NOTHING AND SAYS WHY. Falling back to the whole table
would look like a selection nobody made; an unknown scope raises for the
same reason, since silently drawing "all" would answer a different question
without saying so.

Instruction 206's multi-select is what makes the well set more than one
guide's wells.

--------------------------------------------------------------------------------
RE-AUDITED 2026-08-26: THE BOX IS OFFERED AND NOTHING READS IT     [OPEN]
--------------------------------------------------------------------------------

`spacr/well_scope.py` is right and is tested on its own. THE PANEL NEVER
CALLS IT.

`MeasurementComparePanel.refresh` builds the comparison from `self._objects`
directly; `scoped_objects()` has no caller anywhere in spaCR outside the
tests. Driven on a built panel with three cells' worth of well-mates:

    scope=guides   scoped_objects  2 rows   DRAWN comparison  8 rows
    scope=wells    scoped_objects  6 rows   DRAWN comparison  8 rows
    scope=all      scoped_objects  8 rows   DRAWN comparison  8 rows

So the three choices are offered and none of them changes the population --
199's fault exactly: a handler that works and a control that does not reach
it. `set_selected_guides` and `set_selected_wells` likewise have no caller
outside the tests, so the volcano selection never reaches this panel and the
derived well set is neither shown nor narrowable by a user.

WHY IT IS NOT A ONE-LINE FIX, and why it wants a decision rather than a
patch: pointing `refresh` at `scoped_objects()` makes the panel obey a scope
whose default is `guides` while nothing ever sets a guide -- so the Compare
tab would go from drawing everything to drawing nothing. The wiring and the
default belong together:

  * who calls `set_selected_guides` -- the volcano's `keys_selected` reaches
    `ResultsTable.select_keys` (206), and the montage view builds this panel
    with `picked_groups()`, so one of the two is the route;
  * what the scope defaults to before any guide is chosen;
  * where the derived well set is SHOWN, since the file's own section B says
    a set the user cannot see is a set they cannot narrow.

--------------------------------------------------------------------------------
2026-09-25 -- DECIDED AND BUILT: THE COMPARE PANEL OPENS ON THE TOP HITS
--------------------------------------------------------------------------------

Maintainer decision (2026-09-25): "the regression Compare panel opens with
the TOP HITS pre-selected (top significant guides/genes and the wells that
carry them; user can change it) -- wire scoped_objects/set_selected_guides
and show the well set."

This answers the three open questions of the 2026-08-26 re-audit:

  * WHO SETS THE GUIDES: the panel itself, on opening. The montage view
    passes its run's results path (`results=self._results_path()`);
    `spacr.well_scope._top_hits` reads the coefficient table (a CSV, or a
    run folder's results.csv / results_grna.csv / results_gene.csv), keeps
    terms with p <= 0.05, ranks by p and takes the top TOP_HITS = 5 hits
    that the object table actually carries. A guide-level term contributes
    its guide; a gene-level term every guide of that gene. With no results
    table the guides of the montage's own groups are the selection
    (`well_scope._guides_at`).
  * THE DEFAULT SCOPE: "gRNAs + other datapoints in selected wells" when
    anything is selected -- the comparison section A calls the one that
    matters -- and "All datapoints" when nothing is, so a panel with no
    guides draws exactly what it drew before rather than nothing.
  * WHERE THE WELL SET IS SHOWN: a muted line under the contrast row lists
    the gRNAs and the selected wells (first 6 / 8, with counts) and the
    well_scope description of the drawn population.

USER CAN CHANGE IT: "gRNAs…" opens a checklist of every guide in the table
(`_choose_guides` -> `set_selected_guides`, wells re-derived) and "selected
wells…" narrows the derived wells (`_choose_selected_wells` ->
`set_selected_wells`). The population box still switches scope.

`refresh` NOW DRAWS `scoped_objects()`. One exception, stated on screen:
the "against the controls" and "against every other well" contrasts need
rows outside the selected wells, so for those two the population box is set
aside and the whole table is used.

Tests: tests/test_show_offers_the_wells_the_guides_are_in.py gains
TestTheTopHits (ranking, alpha, gene terms, folder input, missing table) and
TestThePanelOpensOnTheTopHits (hits + wells selected, scope "wells", well set
shown, drawn population is the scoped one and narrows, groups fallback,
nothing-to-select stays on "all", user changes the guides).
