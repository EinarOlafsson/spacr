     in the maintainer's spirit: "If you can't train a model yourself, upload
     your images and masks here and we'll train one for you. ..." (plus what

  2. TWO WAYS IN:
       * During curation: the field on screen and its current mask, one click
         (and the whole curated queue, if the user wants).
       * A dialog with TWO path fields: an images folder and a masks folder.

and names the files; curation's one-click route sends the on-screen image

IMPLEMENTATION NOTE (2026-09-25)

Where it is
  Make Masks, bottom row, right after "Training datasets…" (away from the
  tool row and the curation Skip control other agents are changing): a
  "Contribute images and masks…" button. Tooltip (tr()):
    "If you can't train a model yourself, upload your images and masks here
    and we'll train one for you. Send the image on screen with its mask,
    every image you have curated here, or an images folder with a masks
    folder holding masks of the same names. Say what they show (organism,
    object type, stain) and they go to their own community dataset on
    Hugging Face as a pull request, which the maintainer reviews before any
    model is trained on it. They are shared under CC BY 4.0, so send only
    images you have the right to share. A careful mask makes a good model:
    every object, hugging its edge."
  The same text heads the dialog; 523's MASK_CONSCIENCE sits beside Upload.

How it works
  One click opens ContributeMasksDialog with the sources on offer as radio
  buttons:
    * "The image on screen and its mask: <file>" (default while a field is
      open): the original file plus the mask being edited (canvas, saved
      or not; what you see is what is sent).
    * "Every curated image here with its saved mask (n)": every field of
      the open folder/queue whose mask file exists (engine.mask_save_path,
      so sibling/nested layouts and multi-folder drops work), the on-screen
      one with its on-screen mask. Cellpose _seg.npy bundles are left out
      (no image file of their own).
    * "An images folder and a masks folder": two path fields with Browse….
      Matching is by name without extension (a.png pairs with a.tif; masks
      may be .tif/.png/.npy/...). Upload stays disabled until both folders
      are filled, differ, every image has exactly one same-named mask and
      the counts match; the dialog lists "No mask with the same name for:",
      "No image with the same name for:" and duplicate names.
  "What is it?" (organism, object type, stain) -> masks_dataset_target()
  -> always community_<slug> (so "plaques"/"figures" can never fall into
  Plaque Assay's repos) -> einarolafsson/community_<slug>, shown live as
  "Goes to huggingface.co/datasets/...". Notes go into contribution.json
  ("notes"); each image's meta records the typed dataset name and the mask
  file name. The last name used is remembered.
  Upload: 523's ask_community_consent (asked once, shared with Plaque
  Assay), write_contribution (masks layout; refuses any empty mask and
  names the image), then upload_with_own_login -> contribute ->
  ensure_community_repo + PR. No mask, no upload at every step.
