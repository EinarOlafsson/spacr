REQUEST (the maintainer, 2026-09-24, verbatim)
    "when in mask generation i can downloade cellpose 3 into its own
    environment fine. however after downloading the cyto2 and 3 and nucleus
    models are not available anywhere. these should each get their own row in
    the cellpose3 category. for these logic will have to be adde as cellpose4
    and 3 do not take the same input shape or give the same output shape and
    cellpose 3 models take different setings. so if one of these celpose 3
    models is chosen they will need to also get a legacy cellpose3 settings
    window with their settings and they will need their own function for
    generating the masks that takes these settings and that implements the
    cellpose3 input/output logic. everything downstream of mask generation
    should however stay the same."

WHAT TO BUILD
  * A ROW PER CELLPOSE 3 MODEL in the Cellpose 3 category -- cyto, cyto2,
    cyto3, nuclei -- reachable from Mask generation once the backend is
    installed, not only from Make Masks' Mode box.
  * A LEGACY CELLPOSE 3 SETTINGS WINDOW carrying the settings those weights
    actually take (channels as [cyto, nucleus], diameter with its size model,
    flow threshold, cellprob, resample, net average, and the normalization
    those models were trained with -- see item 446's note on percentile
    normalization), shown only when a Cellpose 3 model is chosen.
  * ITS OWN MASK FUNCTION that implements Cellpose 3's input and output
    shapes, rather than passing Cellpose-SAM's. Everything downstream of mask
    generation -- the arrays written, Measure, the database -- stays exactly
    as it is, which is the constraint the maintainer states.

DONE WHEN
Installing the Cellpose 3 backend makes cyto, cyto2, cyto3 and nuclei
selectable in Mask generation; choosing one shows its own settings; a real run
on real images writes masks that Measure reads unchanged; and a Cellpose-SAM
run is bit-identical to before.

_cellpose3_masks: INPUT -- a cell batch is [cell, nucleus]; sent as
(H, W, 2) -> channels [1, 2] = [cyto, nucleus], or the 2-D first plane ->
[0, 0] when cellpose3_add_nucleus_channel is off or there is one plane.
SETTINGS -- the object's own diameter, flow and cellprob thresholds; a blank
diameter becomes the object's magnification default, NOT 0 (507's numbers:
diameter 0 was 153 s and 7/33 matched); 0 only with cellpose3_size_model;
resample, augment, and normalize={"normalize": True, "percentile": [low,
high]}. OUTPUT -- (masks, flows, None) through parse_cellpose4_output, then
the Cellpose-SAM path's own merge/filter, counts, saving and QC.

NET AVERAGE IS NOT OFFERED: cellpose 3.1.1.3 has no net_avg. `augment` (tiles
averaged over flips) is offered instead, and its tooltip says so.

2026-09-25 (second pass) -- V2, THE LIVE PREVIEW AND THE GPU RUN

ONE ROUTE. spacr.object._prefixed_model_route(model_name, settings) is a
table of (backend, prefix reader, masks function); cellpose3: -- or
segmentation_backend=cellpose3 -- answers ('cellpose3', _cellpose3_masks).
A second prefix (525's cellpose_dino:) is one more row. V1's own dispatch
is unchanged. _cellpose3_masks gained probabilities=False, which also
returns each image's cell probability (flows[2]).

(a) PIPELINE_STYLE 'v2'. stream_masks_from_stack asks the table; a routed
model is loaded with _load_backend and segmented by _cellpose3_masks with
the run's settings (postprocess_settings, with this pass's diameter and
thresholds winning) and the object's magnification diameter as default,
batch_size max(8, n) -- all as V1. Cellpose-SAM models take the old code.
Real CPU run, same two fields and settings as the V1 CPU run above
(cell = cellpose3:cyto3, diameter 44): v2's appended mask plane is
PIXEL-IDENTICAL to V1's saved mask on both fields (57 and 23 objects, same
arrays), cyto3 37.8 s for both fields, whole v2 run 42.0 s. v2 segments
the cell object only, as it always has.

(b) THE LIVE PREVIEW. _segment_multi asks the same table; a cellpose3:
model goes through _backend_preview_pass -> _cellpose3_masks in the
backend (the worker is pooled, so a second pass does not restart it). A
cell gets [cell, nucleus] planes, both through the same PSF/enhancement
preparation; the preview's diameter and thresholds stand in for the
object's. Its RGB flow and cell probability land in 505's Flows and Cell
probability views. The model box: _is_a_real_model_name accepts
cellpose3:<cyto|cyto2|cyto3|nuclei>, a bare cellpose3: and cellpose3:<file
on disk>; _checkpoint_is_missing tests the path after the prefix (a missing
file falls back to cpsam and says so, as before); the zoo button offers
cellpose3 rows too. The timelapse preview shares those box rules, so its
segment_frame routes the same way.
