The pass runs at screen-open and works. TWO EVENT-LOOP TURNS LATER SOMETHING

The row count never moves -- 83 throughout -- so these are not lazy rows

Caught the caller by wrapping `QWidget.setToolTip` and keeping the stack:

    28x  settings_model._clear_greyed_note
           <- _apply_greyed_note <- _refresh_setting_dependencies
           <- _refresh_contextual_widgets / _refresh_after_bulk_apply

THE LINE. `retarget_field_tooltips` ends with `field.setToolTip("")` and marks
the field `apiTooltipDisplayRole = "metadata"`, but it LEAVES `apiTooltipHtml`
on the field -- that property is the SOURCE the label's copy was made from,
not a tooltip the field should show. `_clear_greyed_note` read it and called
`setToolTip` with it:

    restored = control.property("apiTooltipHtml")
    if restored:
        control.setToolTip(restored)          # <- undoes the pass

and `_apply_greyed_note` did the same when greying a row.

FIXED by `_help_lives_on_the_label`, which both note functions now ask first.

WHY THAT ONE IS NOT FORCED. It has `settingKey=None`. `_is_a_settings_field`
says outright that "carrying a `settingKey` is the definitive mark of 'this
widget is a setting's field', whatever it was built from", and that predicate
guards the pass on all forty-five screens. Widening it to catch one bespoke
list -- by adding QListWidget to the editor types, or by dropping the
settingKey gate -- puts every screen at risk to fix one row, and the last
time this item was "fixed" broadly it silently regressed two screens.

THE FIX, when someone takes it, is at the control_chart screen and not in the
predicate: give that list a `settingKey` like every other setting, or have the
screen move the help itself the way `gate_search_panel`, `umap_explorer`,
`graph_builder` and `model_zoo_picker` already do -- each calls
`retarget_field_tooltips(self)` at the end of its own __init__.

So 289 is one widget from done, and the widget is named.

The probe is `scratchpad/hover_all.py`: one process, one MainWindow, all
forty-five keys, about four minutes. Run it before claiming this closed.
