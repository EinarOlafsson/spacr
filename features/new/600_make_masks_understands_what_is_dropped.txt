--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Built. Three parts:

* spacr/drop_classification.py -- classify_drop(paths) says, with no widget
  and no question, what a drop on Make Masks is: "images", "folder",
  "nested" (images in subfolders; channel_like when the subfolders are
  named like channels -- DAPI, GFP, ch1, C01, w1... -- or hold the same
  fields), "folders" (several image folders), "images_with_masks" (a masks
  folder, files whose name says mask, or integer label TIFFs a dropped image
  claims by name, paired by stem), "spacr_output" (merged/*.npy, a
  sorted_channels folder, a merged folder itself: what it is, and which
  images to open, never a .npy) or "nothing". Everything unused is in
  .unrecognised with the reason. _accepts() is the drop handler's policy.
* spacr/qt/widgets/organize_for_measure.py -- OrganizeForMeasureDialog, the
  one popup. Source folder (typed, Browse, or a dropped folder); "Consolidate
  subfolders into filenames first" (spacr.folder_consolidation, copies);
  the regex box IS Mask generation's own metadata_type field
  (settings_model._MetadataTypeField: the grouped convention menu, example,
  Test on my folder, Which convention fits) with custom_regex, plus Sort by
  regex, Auto regex and Detect sets (three example sets confirmed with 593's
  ExampleSetsDialog); Add channel / Add mask, each mask column with its role
  and the channel it outlines; a table with a column per channel and per
  mask and a row per field. Every column takes files and folders from the
  file manager (a folder brings its images recursively, and images bring
  their saved masks into their channel's mask column) and cells dragged from
  another column; a "new channel" strip makes a column of a drop. Files sort
  themselves by name and rows are matched across columns by
  spacr.channel_sorting._match_columns (file-name tokens, then order, never
  two different image sizes; a mask column matches against its channel's
  images); empty cells show "—" and are flagged. "Teach me…" is the
  third way to fill the table: one image at a time with its thumbnail and
  "Which channel is this?" (a channel, a new channel, a mask of a channel
  with its role, skip, or stop); from the answers
  channel_sorting._teach_step learns what in the names marks each channel
  (the one place two answered names differ, the character class before it
  so an empty marker cannot swallow an unknown one), writes a regex into
  custom_regex, fills the table live, asks about the first name the regex
  cannot read, and asks once per learned marker whether it marks a channel
  or a mask or only names the field. A consolidated folder is read under
  its files' ORIGINAL names from rename_manifest.csv
  (channel_sorting._original_names), because consolidation can erase the
  channel token. Apply builds the plan
  with channel_sorting.build_plan (new masks= argument for explicit mask
  columns); incomplete rows block it and say how to fix them; RGB/z-stack
  conversion is offered; "Move and merge?" confirms. The screen applies the
  plan with 593's worker (apply_plan + merge_sorted), then opens C01.
* spacr/qt/screens/make_masks.py -- one "Organize for Measure…" button
  replaces 593's "Consolidate folders…" and "Sort into channels…". open_paths
  now classifies the drop: images -> queue (as before); one folder -> open;
  channel-like subfolders or several folders -> the popup prefilled (source
  and a channel column per folder, masks from each folder's masks/), and if
  the popup is cancelled the drop opens as it always did; other nested
  folders -> 593's consolidation question; images with masks -> opened with
  them (a masks folder named like Make Masks' masks is used as masks_dir;
  otherwise the masks are copied, after a question, to masks/<stem>.tif
  beside their images, existing masks kept, PNG masks written as TIFF);
  spaCR output -> named in the console, its images opened. Unused items are
  listed in the console. MakeMasksDropHandler.can_accept now also takes
  nested folders, spaCR output folders and .npy files so the screen can say
  what they are.
* spacr/channel_sorting.py -- "organelle" is a mask role (puncta,
  autophagy, LC3 suggest it; cyst suggests cell), the teach-mode functions
  (_diff_region, _teach_markers, _teach_regex, _teach_step, _teach_labels)
  and _original_names; images may be named by absolute path (their
  mask is then in their own folder's masks/, the regex reads the file name
  only), build_plan(masks=...), _match_columns, and the mask-role guess
  reads the folder name too (DAPI/f1.tif -> nucleus).

593's ChannelSortDialog and RegexWindow are still in
spacr/qt/widgets/channel_sort_dialog.py (their tests still pass) but Make
Masks no longer opens them.

The maintainer's folder (/home/carruthers/Downloads/enz, read only; the
run was on a copy): 84 images, all from folder consolidation. Its
rename_manifest.csv shows the originals were <field>.ext (the CYST image:
its mask has 1-5 objects) and <field>c.ext (the AUTOPHAGY image: its mask
has 30-560 puncta) in Experiment N/<strain>/ folders; ATG2 KO and ATG2' KO
are two strains, not two channels. Consolidation dropped the "c" (1.tif ->
exp_KO.tif, 1c.tif -> exp_KO_2.tif), so no regex on the current names can
tell the channels apart; on the original names "Teach me" learned
(?P<wellID>.*?\d)(?P<chanID>c|)\.(?:bmp|jpg|tif)$ from THREE answers, and
the same regex typed in custom_regex gives the identical table: 42 fields x
2 channels, none incomplete. The images are 8-bit RGB (some JPEG/BMP), so
Apply converts them to grey (originals kept). Could not be placed with a
mask: in Experiment 3 "for only ATG2 KO", 1.bmp and 1c.jpg were copied to
one stem (…ATG2 KO.bmp / …ATG2 KO.jpg), and 3.bmp and 2.jpg likewise
(…ATG2 KO_2.bmp / _2.jpg), so each pair SHARES one mask file in masks/ and
it is not knowable whose it is -- both masks are left out and named. Exp. 3
ATG2' KO 1c.tif has no mask. With cyst masks as cell and puncta masks as
organelle, 38 merged arrays (H, W, 4) were written, and spaCR Measure (CPU,
4 fields) wrote measurements.db with 4 cell, 4 cytoplasm, 164 organelle and
4 cell_organelle_summary rows.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Masks drawn on a mixed folder could only reach Measure through a chain of
questions and a separate dialog, and a folder of channel folders, a masks
folder dropped beside images, or a spaCR output folder was not understood at
all (a folder with images only in subfolders was even refused by the drop
handler).

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

* A pixel-label TIFF is taken as a mask only when a dropped image claims it
  by name: clean synthetic images look like labels too, and an existing
  test caught a drop of two images being mistaken for an image and a mask.
* The popup's consolidation runs on the GUI thread (with a wait cursor); the
  drop's consolidation question still runs off-thread as in 593.
* No thumbnails in the table (names and full paths in tooltips): the table
  is about matching, and 593's dialog read thumbnails off-thread per image.
* ChannelSortDialog/RegexWindow are not deleted, to keep this change small.
