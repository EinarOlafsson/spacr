WHAT THE STATE IS
--------------------------------------------------------------------------------

The object-type vocabulary is a FIXED FIVE, written out as a literal in many
places rather than derived from one list. Found by grep, non-exhaustive:

    spacr/measure_hooks.py:142   OBJECT_TYPES = ('cell','nucleus','pathogen',
                                                 'organelle','cytoplasm')
    spacr/feature_dict.py:1875   _ZERNIKE_OBJECTS  = (... 'organelle')
    spacr/feature_dict.py:1880   _SUMMARY_PARENTS  = ('cell','nucleus',
                                                      'pathogen','cytoplasm')
    spacr/pipeline_v2.py:613     for role in ("cell","nucleus","pathogen",
                                              "organelle")
    spacr/ml.py:4072             tables = ['cell','nucleus','pathogen',
                                           'cytoplasm']
    spacr/settings.py:1290       settings.setdefault('tables', [...])

and every `<object>_*` SETTING is spelled out four or five times over --
`organelle_channel`, `organelle_diameter`, `organelle_method`,
`organelle_morphology`, `organelle_min_area`, and so on, each declared,
typed, tooltipped and categorised individually.

So "add organelle_1" is not adding a channel. It is making the object-type
vocabulary DYNAMIC, and the reason to say so up front is that a half-done
version -- one that adds the masks but not the settings, or the settings but
not the feature_dict entries -- produces columns that silently vanish from
every model matrix (see the four prerequisites in instruction 71).

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Organelle is already the most diverse object class in the tool (instruction
72), and one organelle channel forces a choice a biologist should not have to
make: a cell stained for mitochondria AND lysosomes AND lipid droplets can
currently measure one of them per run. Running three times gives three
databases that have to be joined by hand on object identity -- which is
exactly the join the measurements database exists to have already done.

The colocalization, neighbour and per-parent summary families all become
much more useful once two organelle classes coexist in one row: "how far is
each lysosome from the nearest mitochondrion" is a question this schema
almost supports today.

   object types and every `organelle_` setting, and put the count in this

3. DERIVE, DO NOT DUPLICATE. One function should answer "what object types
   does this run have", and everything else should call it. The current
   literals are the reason this is a large change rather than a small one;
   leaving them in place and adding a sixth literal everywhere makes the next
   one worse again.

4. THE SETTINGS CANNOT BE COPIED N TIMES BY HAND. Instruction 61 closed "no
   stated default" at zero and there are guard tests on the settings table;
   twenty hand-written `organelle_2_*` entries will drift from the
   `organelle_*` ones within a release. Generate them, or make the settings
   layer index-aware, and give the generator a test.

5. COORDINATE WITH 72 AND 73. 72 gives each organelle a TYPE that presets its
   detection settings -- and a per-instance type is exactly what makes
   multiple organelles worth having (mitochondria as Tubular, lysosomes as
   Vesicular, in one run). 73 is moving settings into an advanced category
   with per-object sub-sections, and those sub-sections would now be
   per-instance. All three want the same underlying change; do 76 first or
   they will each invent their own indexing.

6. THE DATABASE. Decide whether N organelles are N tables or one table with
   an `organelle_index` column. One table is likely right -- it keeps joins
   uniform and does not multiply the schema -- but it changes what
   `object_type` means in the key columns, which `selection` and
   `anndata_export` both rely on.

HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

A run can segment and measure two or more organelle classes into one
database, each with its own channel, diameter and detection settings; every
per-object family (intensity, morphology, colocalization, neighbours) is
produced for each of them; an existing settings CSV and an existing
measurements.db still load and still mean what they meant; and no object type
is spelled as a literal in more than one place.

2026-08-12 - THE THREE QUEUED measure.py BUGS: TWO REAL, ONE DISPROVEN
--------------------------------------------------------------------------------

(i) THE ORGANELLE PLANE WAS NEVER WRITTEN BACK. Cell, nucleus and pathogen
each get `data[..., <role>_mask_dim] = <role>_mask` after filtering; organelle
did not, though its mask IS modified at the read -- `_filter_object` drops
everything under `organelle_min_size` there. So the array kept the UNFILTERED
organelle plane while the measurements used the filtered one.

The comment above that block states the invariant it exists for: "the PNG
crops and region arrays cover the same objects the measurements do".
Organelle sat outside that guarantee, so a crop could show debris the
measurement table had already dropped. Fixed, and a test now requires all
four roles to be written back.

(ii) `settings['cytoplasm_mask_dim']` RAISED KeyError, and not because the
value was None -- THE KEY NEVER EXISTED. It is in neither the measure
defaults nor `expected_types`, because the cytoplasm mask is DERIVED (cell
minus its interior objects) and appended as a new plane rather than read from
one. Every user who put "cytoplasm" in `summarize_organelles_by` hit it. The
gate is now `settings['cytoplasm']`, which is the boolean that actually
exists.

(iii) `organelle_min_size` APPLIED TWICE -- DISPROVEN, and removing the
"duplicate" would have introduced a real bug.

`_filter_object` is idempotent: measured on a mask with 9-, 25- and 100-pixel
objects at three thresholds, one pass and two give byte-identical results. So
"applied twice" costs a pass and changes nothing.

More importantly THE FIRST PASS IS LOAD-BEARING. The cytoplasm mask is built
as "cell minus every interior object" FROM the organelle mask, between the
two filter calls. Filtering only at the later site would carve sub-threshold
organelle debris out of the cytoplasm -- a silent change to a measured area.
The ordering (filter, build cytoplasm, filter again) is now asserted by a
test and explained in a comment, so nobody tidies it away.

This is the second claim from that survey to be disproven by checking rather
than assumed correct. Recorded here for the same reason as the first: an
instruction that lists a non-bug wastes the next person's afternoon.

2026-08-14 - COMPLETE: FOUR INDEPENDENT ORGANELLE SLOTS, END TO END
--------------------------------------------------------------------------------

The closed registry now exposes four stable internal roles:

    organelle, organelleb, organellec, organelled

They display as Organelle 1 through Organelle 4. Letter suffixes are
deliberate: object type and numeric label are concatenated inside prcfo, so
an underscore would split the key and a digit would make the type/label
boundary ambiguous. The schema validates those constraints at import.
Existing `organelle_*` settings and the `organelle` table remain slot 1,
unchanged; secondary slots default off.

Each slot has generated (not copied) defaults, types, tooltips, categories,
Qt/Tk labels and its own biological type preset. The mask pipeline loops the
enabled slots, passes each through one legacy-compatible scoped settings
view, writes a distinct `<role>_mask_stack`, and appends all enabled masks to
merged arrays. A versioned `.spacr_plane_layout.json` sidecar records channel
and mask order. Measure and on-demand crops consume it; explicit conflicting
mask dims and resume under a changed layout are refused before a wrong plane
can be measured.

Measurement is no longer five-positional internally. Every enabled slot gets
its own morphology, intensity, ring/outside, radial, colocalisation, spatial,
parent-link, crop and SQLite paths. The database design is N object tables
(`organelle`, `organelleb`, ...) so existing table meaning and typed object
keys remain intact. The four existing `<parent>_organelle_summary` tables
remain one-row-per-parent and widen with a separately namespaced column
family for every enabled slot; they do not multiply into N tables.
`summarize_organelles_by` now accepts str/list/None with exact membership and
controls only rollups. Raw per-object tables are written whenever a slot's
mask dim is enabled.

Cytoplasm subtracts every slot. Cell culling clears every slot. Region hooks,
resume ownership, schema contracts, table readers/mergers, feature parsing,
model feature scopes, PNG IDs, external-mask import and crop readers all use
the registry. A secondary organelle crop is keyed by its own label rather
than by the parent cell label.

The dedicated contract (`tests/test_multiple_organelles.py`) covers two-slot
segmentation layout, plane provenance/conflict and resume refusal, independent
presets, full real measurement/database output, wide summaries, cytoplasm
exclusion, feature parsing, merged-table reads, crop IDs and legacy defaults.
Related database, settings, Qt, external-mask, schema, resume and golden
pipeline suites also pass. Final focused verification: 610 passed, 1 skipped,
1 expected xfail in the settings/Qt integration suite; 142 database-contract
tests; 11 dedicated/orchestration edge tests; and the 865-test measurement,
schema, settings, crop and golden-pipeline sweep after updating obsolete bug
guards.
