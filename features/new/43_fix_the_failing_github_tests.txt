FIVE OF THE SIX FIXED, and only one was a stale test:

  * test_seg_qc_banner -- A REAL PRODUCT BUG ON PYTHON >= 3.12. `read_scorecard`
    detected a corrupted scorecard by letting CPython's csv module raise
    `_csv.Error: line contains NUL`. 3.12 STOPPED RAISING and parses the NUL
    into a FIELD NAME instead. The module's own NUL check looked only at
    `row.values()`, so a NUL in the header became a key it could not see:
    every real column went missing, every field took its default, `severity`
    fell back to "ok", and a damaged card came back as a clean verdict -- the
    exact invented verdict the function's docstring promises to refuse. Now

  * test_outlier_model (3) -- pinned numbers from a randomised estimator.
    scikit-learn 1.9 changed MinCovDet's subsampling, so the same planted
    outliers score 76-214 instead of 84-214 and the same clean 2,000 points

    exactly the nominal false-positive rate this test claims to check, so the
    newer estimator is CLOSER to the contract and the equality failed on the
    improvement. Now asserts the margins and bounds instead of the digits.

  * test_settings_full_coverage -- the test's own PREMISE expired. It asserted

    signature, so the uninspectable-callable fallback was never reached. It
    now DISCOVERS an uninspectable builtin at runtime and skips if the
    interpreter has none, which is the only version of this test that cannot
    break the same way again.

2026-08-25 - THE CI STACK IS NOT THE DEVELOPER STACK, AND ONE TEST SAID SO
--------------------------------------------------------------------------------

Fast and Minimum dependencies were down to ONE failure each, and it was the
same test both times:

    tests/test_an_object_is_measured_in_its_own_box.py
        ::test_an_intensity_percentile_keeps_the_dtype_of_its_image

FIXED, and the cause is worth more than the fix.

`measure._percentiles_of` batches the six percentile cut points into one
`np.percentile` call for integers and float64, and deliberately does NOT
batch a narrow float, because numpy computes the sequence form of a float32
input in float64 and the scalar form in float32; batching would move the
value a measured database already holds. The test asserted the resulting
column is `float32`.

That premise is TRUE ON NUMPY 2.4 AND LATER AND FALSE ON NUMPY 1.26, which
computes BOTH forms in float64. The product is right on both -- it always
takes the scalar form for a narrow float, so the number never moves -- but
the dtype is numpy's to choose, not spaCR's. The test now reads the
reference dtype off numpy instead of writing `float32`, and a second test
counts the calls, which is the batching decision itself and is the same on
every numpy.

WHY NOTHING WAS PRINTED, which is the reusable workflow's own bug: the
suite runs with `-o faulthandler_timeout=900`, and the comment above that
step claimed a hang would therefore name itself. It cannot under `-n`. The
dump is written by the WORKER, and xdist forwards a worker's output only
when the worker reports a result, so a worker that never reports never
delivers its dump. The one mechanism meant to make a hang loud is the one a
hang disables.

FIXED IN .github: a `per_test_timeout_seconds` input, 1200 on the Qt
shards. pytest-timeout's thread method does not need the wedged test to
come back to the interpreter -- a watchdog dumps every stack and ends the
worker, and xdist reports the crash against the test id. Measured on a
deliberately wedged test: the id is named, the surviving workers finish
their own files, and the session prints a summary.

    `--max-worker-restart=0` goes with it and is not optional. Without it
    xdist replaces the ended worker and hands it the SAME test, which wedges
    again: measured, a 3-second ceiling was paid NINE times. A deterministic
    hang would then cost more than the silence it replaced.

WHAT THE HANG PROBABLY IS, not yet proved and product-side:
`spacr.parameter_sweep.containment_available` (spacr/parameter_sweep.py:673)
runs `systemd-run --user --scope ... true` through
`subprocess.run(capture_output=True, timeout=10)`. That timeout kills the
direct child only and then blocks in `communicate()` until every inherited
pipe is closed, with no second bound. A scope that outlives the killed
`systemd-run` holds those pipes open, which matches both the silence and
the orphan processes. It is the only unguarded external call the test
makes. Fix shape: `Popen` with `kill()` then `wait(timeout=...)`, or read
the pipes with a bounded second wait, so the ten seconds actually bound the
call.
