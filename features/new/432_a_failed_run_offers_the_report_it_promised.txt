THE AI WAS ASKED. The paste contains

so the route fired. Test mode, the retry policy and macOS were all ruled
out. The crash left `runctx._give_up` by `raise exc`, reached
`bridge.PipelineWorker.run`'s `except Exception`, and was emitted on

`providers._stream_process` never read the exit status, so the worker

that as the reply:

  * `_ai_error_explanation` was set to that line. `ai_explanation_of` gave

    "Failed to authenticate: OAuth session expired and could not be
    refreshed" under "spaCR AI's analysis of this error".
  * The reply sat under "spaCR output", not "spaCR AI". The error flow
    draws the heading and the reply block at once. The run's closing
    lines (workspace, macro, "run closed", "✗ Failed") came before the
    CLI's first line. `_on_chunk` then opened a new reply block with no
    heading, so the "spaCR AI" heading stayed empty. Read top to bottom,
    that looks like the AI was never asked.

WHAT CHANGED

1. 'always' files. When a run fails with reporting on and the mode
   'always', `AppScreen._settle_the_report` (called from `_on_finished`)
   runs `_file_the_report_automatically`. It builds the same report "File as
   issue" builds (`build_report`), redacts it with `public_report`, and
   posts it on the background runner through
   `issue_report.file_without_review`. No preview opens and no browser
   opens. The console says, directly under "✗ Failed": "[issue] Filing a
   redacted report ...", then either "Filed on GitHub: <url>", "already has
   an open issue ... added to it: <url>", "Not filed: spaCR is not signed
   in to GitHub. Run `gh auth login` ...", or "Not filed: <why>. Press File
   as issue to try again." "File as issue" stays under the console in every
   case. 'ask' is unchanged.
2. 'always' is the default. `preferences.get_issue_prompt_mode` returns
   'always' when nothing is stored (DEFAULT_ISSUE_PROMPT_MODE), and
   `ai.settings.get_auto_file_issues` defaults to True, because without it
   the default mode would file nothing. A stored value is kept either way.
   A stored value this build cannot read reads as 'ask', not 'always'.
   The installer's consent page is unchanged: its answers are explicit
   (off -> never, on -> ask), and they still override.
3. The agreement. Terms 4.2 (`terms.TERMS_VERSION`), so every profile that
   accepted 4.1 sees the terms again at its next launch. 5.1 no longer says
   nothing is sent automatically. 5.5 says what a report publishes, where,
   under whose account, what is redacted, and that the log is never
   published. It used to say "Diagnostic Data is not published", which was
   false: the traceback and settings are Diagnostic Data under 1.6. The
   new 5.6, AUTOMATIC ERROR REPORTS, says that 'always' is the default,
   files without showing the report first, files each error once, needs a
   GitHub sign-in, and that accepting with 'always' set agrees to it. It
   also says how to change it: Help > Set spaCR up again..., the page "When
   something breaks", or "Report errors as GitHub issues" in the AI
   Console's settings. A test checks that each of those names exists in
   the code under that exact spelling. The first-run slide's blurb, the AI
   Settings caption, the Preferences "Report logs" tooltip and the two
   setting tooltips were changed to match. Each of them promised "nothing is
   sent" or "Default False".
4. One crash, one filing. Three layers:
   * a local ledger (`ai.settings.remember_auto_filed` /
     `auto_filed_url`): a fingerprint this profile filed is not filed
     again. Only reports that reached GitHub are recorded, so a signed-out
     or failed attempt is retried at the next failure;
   * `_REPORTS_BEING_FILED`: two failures before GitHub answers file once;
   * the existing open-issue search (`find_issue_by_fingerprint`, open
     issues only): a match gets a "Seen again" comment, not a new issue.
     Both paths now share `_post_report`.
   THE FINGERPRINT WAS NOT CROSS-MACHINE. It hashed each frame's whole path,
   so the same crash from two computers (different conda env, Python minor
   version, prefix or separator) had two fingerprints, and the open-issue
   search could only find duplicates from the same computer. It now keys
   each frame on its last two path components (`_frame_key`). Every
   fingerprint changes once. Open issues filed before this will not be
   matched by a client after it.
   #117 AND #121: #117 was written by hand ("Mask generation failure Apple
   M4") and carries no fingerprint, so no fingerprint dedupe could have
   matched it to #121. The ledger stops a profile filing the crash twice;
   it cannot recognise an issue somebody wrote.
5. The route_errors_through_ai tooltip said "Default False" while the getter
   defaults to True. It says "Default True". A test compares the stated
   default with the getter's for route_errors_through_ai, auto_file_issues
   and console_aware.
5b. Nothing is filed automatically until the profile has accepted terms
   4.2 (`AppScreen._the_terms_allow_automatic_filing`). 'always' is the
   default, and a default reaches profiles that never saw the agreement:
   `--no-setup`, `SPACR_NO_SETUP`, offscreen servers, a closed terms slide,
   a profile that accepted 4.1. The console says, under "✗ Failed", that
   nothing was sent and that filing starts once the terms are accepted.
   Added after the first commit on this branch, as a separate commit.
6. An AI error is never attached. The automatic path takes the analysis
   from `ai_explanation_of`, like the manual one, so a provider that failed
   leaves none (this file's fix). The report is filed at `_on_finished`,
   usually before the AI has answered. It does not wait for it.

REDACTION, CHECKED ON THIS PATH. Against what the manual path did:
  * home folder -> `~` (build_report), then `<PATH>` (preview default);
  * other absolute paths, Windows drive paths, traceback File fields ->
    `<PATH>` (preview default);
  * `.db` paths -> `<DB>`; credential shapes and secret-named settings ->
    `<REDACTED>`;
  * login name: only inside the home path. Host name: never.
The automatic body is exactly the body the preview sends by default (a test
compares them). The title is stripped too, which the preview does not do.
NEW for both paths, in `sanitize_path`: `redact_identity` replaces this
computer's login name (`getpass.getuser()`, the home folder's name) and
host name (`socket.gethostname()`, `platform.node()`, and the first dotted
label) with `<USER>` and `<HOST>` wherever they stand as whole words.
Generic names (root, runner, localhost, ...) and names under three
characters are left alone. `platform.platform()` carries no host name.
FOUND ON THE WAY: #121's body has `<details><summary>...<<PATH>` because
`strip_report_paths` read the `/` of `</summary>` and `</details>` as the
start of a path, so every section after the first stayed open. Fixed: a `/`
straight after `<` is never a path.

2026-09-25 -- FILING WAITS FOR THE AI; AN UNQUOTED PATH KEEPS NO TAIL

The two measured limits the notes above left are fixed. The installer's
default is not touched: it is the maintainer's call.

1. FILING WAITS FOR SPACR AI'S ANSWER (spacr/qt/screens/app_screen.py).
   `_file_the_report_automatically` still does its two checks first (filed
   before; in flight). Then, when the console is streaming an answer to THIS
   traceback and has none kept yet (`_the_ai_is_still_explaining`: a live
   `_ai_worker`, `_ai_error_traceback` equal to it, `ai_explanation_of`
   empty), it does not file. `_wait_for_the_ai_then_file` marks the
   fingerprint in flight, says "[issue] Waiting up to 60 s for spaCR AI's
   answer, so the report carries it…", and files on whichever comes first:
   the console's `ai_stream_finished`, or AI_ANSWER_WAIT_SECONDS (60). It
   files once per wait, and disconnects. The posting itself moved, unchanged,
   into `_post_the_report`. With no AI answering this error it files at once,
   as before.

   WHY 60 S. The wait holds the fingerprint in `_REPORTS_BEING_FILED`, whose
   entries expire after REPORT_IN_FLIGHT_SECONDS (120). 60 s of waiting plus
   the posting's own worst case (`gh auth token` 8 s, API calls 20 s each)
   stays inside it, so a second failure with the same crash during the wait
   is told "being reported already" rather than filing twice. A provider
   that is still going after a minute is not one worth holding a crash
   report for.

   console_panel.py is not edited (it is another lane's this week): the
   check reads the console's existing attributes.

2. AN UNQUOTED PATH'S LAST COMPONENT (spacr/qt/ai/issue_report.py).
   `_BARE_PATH_RE` now lets the last component, which no separator follows,
   run on over words shaped like part of a name (`_PATH_TAIL_WORD`): one
   starting with a digit (`plate 1`, `Patient 042`), one starting with a
   capital (`Lab Drive`, `plate A`), or one ending in a file extension
   (`plate a.tif`). Measured:

     \\LAB-NAS\screens\plate 1          -> <PATH>            (was '<PATH> 1')
     mask /Volumes/Lab Drive failed      -> mask <PATH> failed
     wrote /mnt/lab share/Patient 042 and stopped -> wrote <PATH> and stopped
     opening /mnt/data/x.tif failed      -> opening <PATH> failed (unchanged)

   Prose after a path on the same line is lower case, which is what keeps
   the readability the earlier note chose. WHAT IS STILL LEFT: a last
