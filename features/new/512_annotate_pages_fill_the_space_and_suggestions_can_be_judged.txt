WHAT TO BUILD
  1. THE PAGE IS WHAT FITS. The grid holds exactly as many crops as the space
     allows and never scrolls; opening the console, collapsing the settings or
     resizing the window recomputes the page and pushes the rest to the next
     one. The page counter follows.
  2. JUDGING A SUGGESTION IS ITS OWN ACTION. When Suggest has labelled a page,
     each suggested crop is marked as suggested, and the user confirms or
     rejects it with one key or click, with the instruction on screen and
     visible feedback for what was confirmed, rejected and left. What the user
     confirmed and what they rejected both reach the next round of training --
     a rejection is information, not silence -- and the round's counts are
     shown.

DONE WHEN
No page of Annotate scrolls at any window size or console state, and a user
can accept or reject every suggestion on a page without editing labels by
hand, with the counts visible.

PART 1 -- THE PAGE IS WHAT FITS (commit 4d87aaf4c, plus the crop-pane
minimum in 0d10e425c). Line numbers are from after the merge with nightly.
  * spacr/qt/screens/annotate.py:581 grid_that_fits -- plain arithmetic
    (tiles, gap, margins, always at least 1 x 1).
  * :3897 _grid_area measures the crop pane (the content stack), not the
    scroll viewport, because a viewport that has never been shown still
    reports its default size. :3922 _compute_grid_dims sizes tiles at the
    GUI scale in force. The grid's scroll bars are always off.
  * :3987 _refit_grid runs on a window resize, on the crop pane's own
    resize (console opened or a pane folded, caught in eventFilter) and on
    a GUI scale change. It keeps _offset, so the first crop on screen stays
    where it was. It reloads only when the shape changed.
  * :5301 _page_counter_text -- "Page N of M · crops a–b of T".
  * :467 CROP_PANE_MIN_HEIGHT = 140. The crop pane used to take the empty
    state's 321 px minimum, which made the screen's minimum height 828 px
    with the console open. At 1366 x 768 the window then grew past the
    bottom of the screen. Now the minimum is 647 px, or about 700 with the
    judge bar showing, and the console opens inside a 768 px window.

PART 2 -- JUDGING A SUGGESTION (commit 0d10e425c)
  * THE BADGE. The tile (:1158 set_badge, :1190 _paint_badge) draws an
    amber "?" for a suggestion still to judge, a green tick once confirmed
    and a red cross once rejected. The badge sits in the top right corner
    and its marks are drawn as lines, so a font without a tick glyph cannot
    turn it into a missing-glyph box. The colours come from :528
    badge_colors (the theme's warning, success and error colours, with the
    glyph in the theme's background colour). Each reads at 4.5:1 or better
    in both dark and light, and a test checks that. The dashed ring from
    379 stays as well.
  * THE ACTION. On a suggested crop, a click CONFIRMS and a right-click
    REJECTS (:5063 _on_thumb_left / right). On any other crop the click
    labels 1 or 2 as before. Y and N do the same for the focused crop and
    move to the next suggestion (:615 tokens, :5797 _kbd_judge). U undoes a
    judgement along with its label, because the undo entry now carries the
    verdict. "Confirm/Reject the rest of the page" judges what is left
    (:5807 _judge_page). The core is :5727 _judge. Judging is refused while
    a Suggest run is going, and the refusal says why.
  * THE INSTRUCTIONS AND COUNTS. A bar above the key legend (:3805
    _build_judge_bar, :5704 _refresh_judge_bar) shows the instruction and
    "This page: N suggested · N confirmed · N rejected · N left. Whole
    column: N left to judge · N confirmed · N rejected." The bar is hidden
    until the column holds a suggestion or a judgement. Y and N are on the
    shortcut map (spacr/qt/shortcuts.py:131). LEGEND_COMPACT/LEGEND_FULL
    were left alone because they are pinned to catalog rows.
  * THE DATABASE. The judgement is stored in "<column>_verdict": +c
    confirmed, -c rejected, NULL not judged (spacr/suggest.py:368
    verdict_column). THE MIGRATION is :382 ensure_verdict_column, called when
    a source is opened (annotate.py:5679 _ensure_verdict_column). It adds an
    INTEGER column with no default, so no row is rewritten. It is idempotent
    and tested on an old table. Writes go through the one SaveWorker
    (annotate_engine.py:1419 submit(batch, column=...)), in the same queue
    as the labels. A label that contradicts a judgement withdraws the
    judgement (annotate.py:555 verdict_contradicts, applied in :5407
    _set_annotation), so the two columns never disagree. Counts are read
    back at :5640 _recount_judgements and kept up to date after every
    change. A bulk Keep records +c (suggest.py:329); a bulk Throw records
    nothing, because "I do not want to review these" is not "these are
    wrong". Clear column clears the verdicts (annotate_engine.py:1310).
    Agreement does not offer <col>_verdict as an annotator
    (agreement.py:158).
  * THE NEXT ROUND. _SuggestWorker reads suggest.py:491
    rejected_suggestions (rejected and not relabelled since) and passes
    them as retrain_round(rejections=...) (annotate.py:910,
    active_learning.py:2525). In a two-class column a rejected 1 is fitted
    as a 2 (:2881 _rejections_as_labels). A crop labelled since the
    rejection keeps its label. With more than two classes a rejection
    cannot be fitted, and the round's notes count it. The console says how
    many rejections were handed to the fit, and the model card records
    rejections_fitted. What the user CONFIRMED is an ordinary label in the
    column, so the fit reads it as it reads any label.

NOT DONE / OPEN
  * A crop rejected in one round is suggested again by the next round,
    usually as the other class, because the fit learned from the rejection.
    It then needs judging again. Leaving it unsuggested was the
    alternative, but it would hide the model's changed opinion. Say if you
    want it the other way.
  * The KEEP-is-withheld flag for a one-class run
    (`_suggestions_are_a_ranking`) is still set from the synthetic-negative
    count. When rejections supply the other class it can withhold KEEP on
    a run that did not need to invent negatives. That errs on the safe side.
  * Only tested offscreen and with a bare screen, not inside the main
    window on a real display.

2026-09-25 -- DECISION APPLIED: A REJECTED CROP IS NOT SUGGESTED AGAIN
--------------------------------------------------------------------------------

The maintainer, 2026-09-25: "a crop the user REJECTED is not suggested again
in later Suggest rounds (it still trains as a negative example)."

This answers the first NOT DONE point above, the other way from how it was
built.

WHAT CHANGED, spacr/suggest.py suggest_from_scores: a new keyword
withhold_rejected (default True) drops every unlabelled crop whose
"<column>_verdict" is negative before the proposal is made, so
write_suggestions never writes to it. Nothing about training changed:
_SuggestWorker still reads rejected_suggestions and hands them to
retrain_round(rejections=...), where a rejected 1 is fitted as a 2. When
every open crop is a rejected one, the empty proposal's note says so ("every
crop left without a value is one whose suggestion was rejected, and a
rejected crop is not suggested again"), and the screen's existing "No
suggestions written -- {why}" line shows it. The rejection itself stays in
the verdict column (its red cross badge and the counts are unchanged); a
crop the user later labels is an ordinary label. No new UI string: the
console notice "{n} rejected suggestions were handed to this round's fit"
already has catalog rows and was left as it was.

TESTS, tests/qt/test_a_suggestion_can_be_judged.py:
  * test_a_rejected_crop_is_not_suggested_again_and_still_trains -- a
    whole Suggest round with the REAL retrain_round and database (60 crops,
    40 labelled, 6 of the 20 open ones rejected): retrain_round is handed
    exactly the six rejections; the proposal and the column hold a
