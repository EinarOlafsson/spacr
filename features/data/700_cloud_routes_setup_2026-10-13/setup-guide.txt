Recommended architecture
spaCR sends a strictly sanitized, bounded report over HTTPS to one maintainer-owned Cloudflare Worker. Its GitHub App creates/deduplicates issues; its AI binding returns model advice. End users need no GitHub or AI account. The maintainer needs GitHub and Cloudflare accounts. Public issue filing and cloud diagnosis have separate destinations/settings. No provider/private key is distributed in spaCR.

What you can set up now
1. Sign in as EinarOlafsson and open https://github.com/settings/apps/new . A separate bot account is unnecessary. GitHub's fine-grained PAT cannot grant a different personal bot write access to your repository, even as collaborator:
https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#fine-grained-personal-access-tokens-limitations
2. Choose an available App name such as spacr-first-responder; use https://github.com/EinarOlafsson/spacr as homepage. Leave OAuth/user authorization/device flow disabled and uncheck webhook Active. This service only sends requests to GitHub.
3. Set Repository permissions: Issues = Read & write. Metadata read is automatic. Leave optional Contents, Actions, Administration and other permissions unset. Choose Only on this account, then create the App.
Steps 1-3 documentation:
https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app
4. Record App ID and Client ID. In App settings, Credentials -> Key pairs -> New key downloads a private PEM. Keep it private; never paste it in chat or commit it.
https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/managing-private-keys-for-github-apps
5. App settings -> Install App -> EinarOlafsson -> Only select repositories -> spacr -> Install. Record the installation ID from the installed-app settings URL, or let the relay discover it later.
https://docs.github.com/en/apps/using-github-apps/installing-your-own-github-app
6. Create/sign in to Cloudflare at https://dash.cloudflare.com/sign-up . Keep Workers Free selected. No purchased domain is required: a workers.dev hostname suffices.
https://developers.cloudflare.com/workers/platform/pricing/
7. Workers & Pages -> Create application -> create a Worker named spacr-first-responder. A default template establishes the resource/address only; it is NOT the spaCR relay. Keep its harmless default until the tested relay code is ready.
https://developers.cloudflare.com/workers/get-started/dashboard/
8. Worker -> Bindings -> Add binding -> Workers AI, with binding name AI. This uses env.AI server-side; no additional Gemini/Groq/Claude account or inference API key is needed.
https://developers.cloudflare.com/workers-ai/configuration/bindings/
9. Create D1 database spacr-support; bind it to the Worker as DB. The application schema will be supplied with the relay for atomic quotas/deduplication; an empty database alone does not implement either.
https://developers.cloudflare.com/d1/get-started/
10. Worker -> Settings -> Variables and Secrets -> Add -> Secret: GITHUB_APP_PRIVATE_KEY. Store the private key directly there, including PEM boundaries and line breaks. The relay signer must support GitHub's PKCS#1 PEM or convert it locally to PKCS#8; do not upload it to an online converter. Add ordinary variables GITHUB_APP_CLIENT_ID, GITHUB_APP_INSTALLATION_ID and GITHUB_REPOSITORY=EinarOlafsson/spacr. These proposed names will be retained in the implementation. Never put the private key into a plain variable.
https://developers.cloudflare.com/workers/configuration/secrets/

Your custom spaCR system prompt is supported by this design; arbitrary custom trained weights are a different hosting task.
https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/
https://developers.cloudflare.com/workers-ai/models/qwen2.5-coder-32b-instruct/

Privacy

Using D1/KV/etc. can store application content, so retain minimal counters and public issue references, not raw errors. This does not promise zero operational retention.
