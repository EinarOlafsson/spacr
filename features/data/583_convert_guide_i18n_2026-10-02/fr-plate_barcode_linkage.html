Relier les codes-barres des plaques aux métadonnées des échantillons¶

Dans Mesure, activez Afficher les fonctionnalités alpha dans les préférences et ouvrez Plate Barcode Linkage (Alpha). Définissez plate_barcode_source sur une table ou sur l’URL d’un service LIMS. La liaison s’exécute après la mesure.

Une table locale CSV, TSV, Excel ou Parquet doit contenir une colonne de code-barres, une colonne de puits et les métadonnées d’échantillons à joindre. Par exemple:

barcode,well,strain,compound,concentration
BC001,A01,RH,DMSO,0
BC001,A02,RH,pyrimethamine,2

Définissez plate_barcode_column si votre colonne de code-barres porte un autre nom. plate_barcodes associe le nom d’une plaque imagée à son code-barres. Sinon, spaCR lit barcode.txt dans le dossier de la plaque ou utilise le nom de la plaque. Conservez des unités de concentration significatives dans vos métadonnées.

Association dans Convertir¶

Dans Convertir, activez Afficher les fonctionnalités alpha et choisissez un CSV local de données d’échantillons dans Association des plaques par code-barres (Alpha). Le CSV doit contenir une colonne de codes-barres, une colonne de puits et les champs d’échantillons souhaités dans le plan de plaque. L’aperçu valide l’association avant l’écriture des images. Convertir utilise les noms des plaques de sortie affichés dans son aperçu ; ils peuvent différer des noms des dossiers sources.

Attribuez les codes-barres des plaques de sortie sous la forme plate1=BC001; plate2=BC002, ou placez un fichier barcode.txt en UTF-8 à la racine de l’acquisition ou dans un dossier réel de plaque source. Un fichier contenant un seul code-barres sans affectation ne s’applique que si ce dossier contient une seule plaque source. Pour plusieurs plaques, écrivez une entrée source_plate=barcode par plaque, séparée par des retours à la ligne ou des points-virgules ; les clés sont les noms des plaques sources d’origine. Les affectations explicites dans Convertir utilisent les noms des plaques de sortie et peuvent compléter les plaques restantes. spaCR conserve les zéros initiaux, refuse les affectations ambiguës ou contradictoires et exige un code-barres pour chaque plaque de sortie.

Après une conversion complète, lisez plate_barcode_linkage/plate_map_lims.csv dans le dossier de destination. Consultez-y plate_barcode_mismatches.csv pour les puits sans correspondance et les autres divergences. Le fichier de confirmation complete.json est écrit en dernier ; son absence signifie que l’ensemble de fichiers d’association est incomplet. L’écran Convertir affiche un aperçu limité des divergences et les chemins des deux fichiers CSV. Les images originales, les fichiers de codes-barres et les plans de plaque existants de l’utilisateur restent inchangés. Ce parcours dans Convertir accepte un CSV local ; utilisez Mesure pour un service HTTP LIMS.

Lire les enregistrements d’un service LIMS¶

Utilisez une URL telle que https://lims.example/plates/{barcode}/wells. spaCR y insère le code-barres encodé. Sans {barcode}, il ajoute un paramètre de requête barcode. Si une authentification est nécessaire, placez le jeton dans une variable d’environnement et indiquez le nom de cette variable dans plate_barcode_token_env. Ne placez pas le jeton dans l’URL ni dans les paramètres.

Le service peut renvoyer une liste d’enregistrements de puits ou un objet contenant cette liste sous wells, records, results, data ou items. Les champs simples hors de la liste fournissent les valeurs de métadonnées par défaut pour ses puits:

{
  "strain": "RH",
  "wells": [{"well": "A01", "compound": "DMSO"}],
  "next": "?page=2"
}

spaCR suit next, next_url, @odata.nextLink ou links.next. Le lien peut être une chaîne URL ou un objet doté d’un champ href. Les liens relatifs sont résolus par rapport à l’URL de la réponse. Un lien absent, null ou une chaîne vide termine la liste. Les valeurs de métadonnées par défaut sont conservées pour les pages suivantes ; les champs explicites d’un puits remplacent ces valeurs. Les champs de pagination ne deviennent pas des métadonnées d’échantillons.

Chaque lien et redirection HTTP doit conserver le même schéma, le même hôte et le même port que le service initial. Des liens contradictoires ou des pages répétées constituent des erreurs. La collecte est limitée à 16 MiB par réponse, 64 MiB pour la recherche complète, 1 000 adresses de pages par code-barres et 100 000 enregistrements pour la recherche complète. Une erreur arrête la recherche de métadonnées sans renvoyer de plan de plaque partiel. Les résultats de mesure existants restent disponibles. Les protocoles de curseur propres à un fournisseur qui ne donnent pas d’URL pour la page suivante nécessitent un adaptateur distinct.

Examiner le résultat¶

Le plan rempli est écrit dans measurements/plate_map_lims.csv. Il renseigne le paramètre profiling_metadata si celui-ci est vide. Lorsque des colonnes de composé et de concentration existent, il renseigne aussi viability_plate_map si celui-ci est vide. Un plan existant fourni par l’utilisateur est comparé, et non remplacé discrètement.

Consultez measurements/plate_barcode_mismatches.csv et le journal pour repérer les codes-barres absents ou partagés, les puits sans correspondance, les enregistrements contradictoires et les divergences avec un plan existant. Résolvez ces divergences avant d’interpréter les comparaisons entre traitements.
