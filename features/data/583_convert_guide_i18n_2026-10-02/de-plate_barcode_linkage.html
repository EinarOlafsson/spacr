Plattenbarcodes mit Probenmetadaten verknüpfen¶

Aktivieren Sie in Messen die Option Alpha-Funktionen anzeigen in den Einstellungen und öffnen Sie Plate Barcode Linkage (Alpha). Setzen Sie plate_barcode_source auf eine Tabelle oder eine LIMS-Dienst-URL. Die Verknüpfung erfolgt nach der Messung.

Eine lokale CSV-, TSV-, Excel- oder Parquet-Tabelle benötigt eine Barcodespalte, eine Well-Spalte und die anzuhängenden Probenmetadaten. Zum Beispiel:

barcode,well,strain,compound,concentration
BC001,A01,RH,DMSO,0
BC001,A02,RH,pyrimethamine,2

Setzen Sie plate_barcode_column, falls Ihre Barcodespalte anders heißt. plate_barcodes ordnet dem Namen einer abgebildeten Platte deren Barcode zu. Andernfalls liest spaCR barcode.txt im Plattenordner oder verwendet den Plattennamen. Behalten Sie aussagekräftige Konzentrationseinheiten in Ihren Metadaten bei.

Verknüpfung beim Umrechnen¶

In Umrechnen aktivieren Sie Alpha-Funktionen anzeigen und wählen unter Plattenverknüpfung über Barcodes (Alpha) eine lokale CSV-Datei mit Probendatensätzen aus. Die CSV-Datei benötigt eine Barcode-Spalte, eine Well-Spalte und die gewünschten Probenfelder für den Plattenplan. Die Vorschau prüft die Verknüpfung, bevor Bilder geschrieben werden. Umrechnen verwendet die in der Vorschau angezeigten Ausgabeplattennamen; diese können von den Namen der Quellordner abweichen.

Weisen Sie den Ausgabeplatten Barcodes im Format plate1=BC001; plate2=BC002 zu oder legen Sie eine UTF-8-Datei barcode.txt im Stammordner der Aufnahme oder in einem tatsächlichen Quellplattenordner ab. Eine Datei mit nur einem Barcode ohne Zuordnung gilt nur, wenn dieser Ordner genau eine Quellplatte enthält. Für mehrere Platten schreiben Sie je einen Eintrag source_plate=barcode, getrennt durch Zeilenumbrüche oder Semikolons; die Schlüssel sind die Namen der ursprünglichen Quellplatten. Explizite Zuweisungen in Umrechnen verwenden die Namen der Ausgabeplatten und können noch fehlende Platten ergänzen. spaCR behält führende Nullen bei, lehnt mehrdeutige oder widersprüchliche Zuweisungen ab und verlangt für jede Ausgabeplatte einen Barcode.

Nach einer vollständigen Konvertierung lesen Sie plate_barcode_linkage/plate_map_lims.csv im Zielordner. Prüfen Sie dort plate_barcode_mismatches.csv auf Wells ohne Zuordnung und andere Abweichungen. Der Abschlussnachweis complete.json wird zuletzt geschrieben; fehlt er, ist das Verknüpfungspaket unvollständig. Der Bildschirm Umrechnen zeigt eine begrenzte Vorschau der Abweichungen und die Pfade zu beiden CSV-Dateien. Originalbilder, Barcode-Dateien und vorhandene benutzereigene Plattenpläne bleiben unverändert. Dieser Ablauf in Umrechnen akzeptiert eine lokale CSV-Datei; für einen HTTP LIMS-Dienst verwenden Sie Messen.

Datensätze von einem LIMS-Dienst lesen¶

Verwenden Sie eine URL wie https://lims.example/plates/{barcode}/wells. spaCR setzt den kodierten Barcode ein. Ohne {barcode} wird ein Abfrageparameter barcode angefügt. Wenn eine Authentifizierung erforderlich ist, speichern Sie das Token in einer Umgebungsvariable und tragen Sie deren Namen in plate_barcode_token_env ein. Tragen Sie das Token nicht in die URL oder die Einstellungen ein.

Der Dienst kann eine Liste von Well-Datensätzen oder ein Objekt zurückgeben, das diese Liste unter wells, records, results, data oder items enthält. Einfache Felder außerhalb der Liste liefern Metadatenvorgaben für deren Wells:

{
  "strain": "RH",
  "wells": [{"well": "A01", "compound": "DMSO"}],
  "next": "?page=2"
}

spaCR folgt next, next_url, @odata.nextLink oder links.next. Der Link kann eine URL-Zeichenfolge oder ein Objekt mit einem Feld href sein. Relative Links werden anhand der Antwort-URL aufgelöst. Ein fehlender Link, null oder eine leere Zeichenfolge beendet die Liste. Metadatenvorgaben gelten auch auf Folgeseiten; explizite Felder eines Wells überschreiben diese Vorgaben. Paginierungsfelder werden nicht zu Probenmetadaten.

Jeder Link und jede HTTP-Weiterleitung muss dasselbe Schema, denselben Host und denselben Port wie der ursprüngliche Dienst verwenden. Widersprüchliche Links und wiederholte Seiten sind Fehler. Die Erfassung ist auf 16 MiB je Antwort, 64 MiB je Abfrage, 1.000 Seitenadressen je Barcode und 100.000 Datensätze je Abfrage begrenzt. Ein Fehler beendet die Metadatenabfrage, ohne eine unvollständige Plattenzuordnung zurückzugeben. Bestehende Messergebnisse bleiben verfügbar. Herstellerspezifische Cursorprotokolle ohne URL für die nächste Seite benötigen einen separaten Adapter.

Ergebnis prüfen¶

Die ausgefüllte Zuordnung wird nach measurements/plate_map_lims.csv geschrieben. Sie füllt die Einstellung profiling_metadata, wenn diese leer ist. Sind Wirkstoff- und Konzentrationsspalten vorhanden, wird auch eine leere Einstellung viability_plate_map gefüllt. Eine bereits vorhandene benutzerdefinierte Zuordnung wird verglichen und nicht unbemerkt ersetzt.

Prüfen Sie measurements/plate_barcode_mismatches.csv und das Protokoll auf fehlende Barcodes, gemeinsam verwendete Barcodes, nicht zugeordnete Wells, widersprüchliche Datensätze und Abweichungen von einer bestehenden Zuordnung. Klären Sie diese Abweichungen, bevor Sie Behandlungsvergleiche interpretieren.
