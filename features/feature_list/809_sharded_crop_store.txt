--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

spaCR writes one PNG per cell into one directory. On Funk well A1 (1.59 M
cells, all crops stored), measured on the NAS:

- writes: about 49 files/s (0.9 MB/s), the same with 24 or 48 streams, so it
  is the NAS small-file limit;
- directory listing: 151-604 s;
- renames: about 270 ms per file in a 650 k-entry directory;
- random reads for training: 2.4-5 PNG/s (0.04-0.09 MB/s), so one epoch over a
  plate takes days.

--------------------------------------------------------------------------------
FILES PER FOLDER (maintainer, 2026-11-06)
--------------------------------------------------------------------------------

A well holds about 1.3-1.8 M cells. In the plate A stress test, one cell_png
folder of 1.59 M files took 151-604 s to list, about 270 ms per rename, and
random reads ran at 2-5 PNG/s.

1. The one-PNG-per-cell export writes one folder per field, for example
   data/<plate>/<well>/<field>/cell_png/ (or the _generate_names layout with
   a field level). At about 1,400 cells per field, each folder stays small.
   - Guard: if any folder would exceed ops_max_files_per_folder (setting,
     default 10,000), split it further.
   - png_list paths follow the per-field layout.
2. The sharded store keeps shards per well or per field range, about 2 GB
   each, with an index of member, offset, size, prcfo, site and label. The
   index and shard files also keep each directory under the same cap.
3. Tests:
   - a synthetic well with more than 10k cells per field and many fields;
     no directory exceeds the cap;
   - readers resolve paths in both layouts.

The paper run's existing A1-A3 single-folder PNGs stay as they are, as the
measured stress sample of the old layout.
