OPS SBS GENOTYPING DECODE SPEED-UP: FLOAT32 OR GPU REGISTRATION, NO STACK COPIES, DIAGNOSTICS OFF, HASH MATCHER
==============================================================================================================

Lifecycle: new
Status: IMPLEMENTED 2026-11-13 (not alpha); step 6 proof below — the sequencing field step registers with spacr.ops_cycles._FFTEngine: each reference's forward transform computed once and reused (the first channel of a cycle for its three others, the reference cycle's target for every cycle, the spot target for every spot plane); ops_registration_precision 'float32' (scipy.fft, one thread; default) or 'float64' (numpy.fft, bit for bit the arithmetic before 932); ops_registration_backend 'cpu' or 'gpu' (each cycle's transforms batched through torch.fft on a CUDA card, deterministic algorithms on while it runs, automatic CPU fallback with no card, with ops_gpu off, with several decode workers, or when the card fails mid-field). align_field translates every plane once into a preallocated float32 stack, keeps running maxima for the sbs_mean_target targets and the spot target, converts each raw plane to float32 once and keeps only shifts and targets (background mode keeps its two moves, so the stack is unchanged). The per-field diagnostics (per-plane p50/p99.9, focus variance, DAPI focus, LoG p99.9, registration log) are written to <well>/decode_diagnostics/site<NNNN>.json only with ops_field_diagnostics (off). spacr.ops_sbs.LibraryMatcher answers a read of A/C/G/T only at max_distance 1 from an index of every barcode's one-substitution neighbours (ties marked), exact by construction; reads with N or other letters and wider distances still scan. The decode report records registration: precision, backend, fields per backend used, diagnostics folder. spacr/ops_cycles.py, spacr/ops_register.py, spacr/ops_sbs.py, spacr/ops_engine.py, spacr/ops_settings.py, spacr/settings_spec.py, tests/test_sbs_genotyping_speed_932.py.

SETTINGS
ops_registration_precision ('float32'; 'float64'), ops_registration_backend
('gpu' with automatic CPU fallback; 'cpu'), ops_field_diagnostics (False).
Defaults before 932 (for the item-931 table of default changes):
ops_registration_precision 'float64', ops_registration_backend 'cpu'.
ops_field_diagnostics gets no row: spaCR's decode never wrote these
diagnostics before 932 (only the study's sample_fields.py did), so the old
behaviour is False.

PUBLIC API
spacr.ops_cycles.align_field gains precision, backend and registrations;
its gpu parameter now only gates the 'gpu' backend (before 932 it let the
background registrations reach cupy or torch through phase_correlate).
New module data FFT_PRECISIONS, FFT_BACKENDS, FFT_PRECISION, FFT_BACKEND.
No new public callable; register_cycles and phase_correlate are unchanged
(phase_correlate's read-out moved into ops_register._read_peak, shared).

DIAGNOSTICS READERS

cache (ops_decode.save_field_cache) never held them, and no QC panel,
report, notebook or GUI screen in the repository reads p50/p999,
focus_lapvar, dapi_focus, log_p999 or a registration log (searched in
spacr/, tests/, notebooks/ and docs/). Outside spaCR (searched
/mnt/firecuda2/ops_decode_yield, /mnt/firecuda2/codex/scratch-docs,
/mnt/wd4tb/ops_decode_yield and the BMCspacr reanalysis tree) the readers
are the study's own scripts: experiments.field_diag and cycle_diag.py (every
copy of src_ruleA_*, results_v3/fp_characterisation, decode_yield code
archive) and the S2-it2 cycle QC (iterations2/scripts
s2it2_cycle_qc_extract.py, _analyse.py, dev_slide_s2qc.py). Every one reads
the study's production field JSONs written by sample_fields.py, which this
item does not touch and which always writes them, so none loses its input.
They are frozen production code or another lane's live scripts and are
not edited here; a run that feeds them spaCR output must set
ops_field_diagnostics. spaCR's own reader, ops_engine._field_diagnostics_table
(the study's field_diag columns, written as
<well>/decode_diagnostics/field_diagnostics.csv and named in the decode
report), returns None without the folder and NaN for a missing key, and is
tested for both (test_a_reader_of_the_diagnostics_copes_with_their_absence).
