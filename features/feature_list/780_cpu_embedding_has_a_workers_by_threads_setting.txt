CPU EMBEDDING HAS A WORKERS x THREADS SETTING
=============================================

Lifecycle: new
Status: DONE 2026-11-06 — CPU embedding splits crops across spawn worker processes,
each with its own torch thread count (spacr.embeddings._embed_parallel); default
from spacr.embeddings._cpu_parallelism: 2 threads per worker (1 below 4 cores),
workers for half the cores, at most 4 (32 cores -> 4 x 2). Embeddings screen gains
CPU workers / Threads (0 = Auto); Overview gains overview_embedding_threads. Results
are identical to one process (tests/test_cpu_embedding_workers_by_threads.py).
Requested: maintainer via the BMC software-paper session, 2026-11-05.
Source: BBBC021 computer-vision benchmark, /nas_mnt/data/sync/papers/BMCspacr/reanalysis/bbbc021/cv/README.md.

REQUIREMENTS
CPU embedding has no workers x threads setting; 4 workers x 2 threads ran
2-8x faster than 1 x 8. Add the setting with a sensible default derived from
the core count.
