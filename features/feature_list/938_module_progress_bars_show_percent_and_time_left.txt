MODULE PROGRESS BARS SHOW PERCENT DONE AND TIME LEFT, ON THE MODULE AND ON HOME
==============================================================================

Lifecycle: new
Status: PARTIAL 2026-11-13 (items 1-4 and 6 built; item 5 audited, nine modules newly counted; acceptance measurements on a reference dataset and the 9-locale strings still owed)
Requested: maintainer, 2026-11-13 ("the progress bar in each module does not
reflect the time that is left for the analysis. This is often printed in the
console. Where possible, implement a progress bar that shows how far along the
analysis is (0-100 %) and also show an estimate for how long is left. These
progress bars should also appear on the home screen run bars that appear when
something is running.")
Owner: unassigned.
Related: spacr.utils.print_progress, spacr/qt/bridge.py (_PROGRESS_RE,
fraction), spacr/qt/widgets/home.py (RunningBanner.refresh),
spacr/qt/screens/app_screen.py (the module run bar), 935 (OPS live mode).

WHAT IS THERE NOW
- Workers print "Progress: n/total, operation_type: ..., Time/image: ...,
  Time_left: x min." (spacr.utils.print_progress, nine callers) or their own
  "Progress: n/total" lines (power, mask GPUs, watch folder).
- bridge._PROGRESS_RE reads only n/total. The time left the worker already
  printed is dropped; the module bar and the home banner show elapsed time
  and "n of total", or a busy bar when no Progress line has arrived.
- A module with several stages (for example measure: masks, then crops, then
  tables) restarts n/total per stage, so the bar runs 0-100 % more than once
  and says nothing about the whole run.

WHAT TO BUILD
1. One progress record per run: overall fraction 0-1 and seconds left (or
   unknown), carried on the run handle next to progress and elapsed.
2. Overall fraction across stages: a module declares its stages with a weight
   (measured share of run time on a reference dataset, stored beside the
   module's settings); overall = finished-stage weights + current stage
   weight x stage fraction. A module that declares no stages keeps the
   per-stage fraction and labels the stage.
3. Time left: use the worker's own estimate when it prints one
   (Time_left in print_progress; parse it in the bridge); otherwise estimate
   from the overall fraction and elapsed time (elapsed x (1 - f) / f, blended
   with the worker's figure by weight f when there is one; a smoothed rate was
   tried and dropped, see ACCEPTANCE) and shown only after the first 5 % or
   30 s, so the first number is not wild. Round for display ("about 12 min", "about
   2 h 10 min"); show "estimating..." before that and nothing when the run
   has no countable steps (keep the busy bar).
4. Show it in both places: the module run bar (percent in the bar, "about X
   left" beside it) and every home-screen running banner (same bar and text;
   RunningBanner.refresh already re-reads the handle).
5. Cover the modules whose loops print no Progress line yet: audit each GUI
   module's main loop and add print_progress (or a structured progress
   callback) where the number of units is known in advance. List the modules
   where it is not possible (unknown total) in this file, with the reason.
6. Paused time does not count toward the rate; on resume the estimate picks
   up from the last rate.

ACCEPTANCE

RESULTS.md there; two runs per size, three for mask, on a loaded machine)
- For each module with a known total: the bar moves monotonically 0 to 100 %
  over the whole run, and the time-left estimate at 50 % is within a stated
  tolerance of the real remaining time on a reference dataset (measure and
  record per module; a control row with the naive elapsed/fraction estimate).
- The home banner shows the same percent and time left as the module bar.
- Tests: bridge parsing of the Time_left field and of multi-stage progress;
  the estimator (warm-up, elapsed-based estimate, blend, pause); the banner and
  module bar text, offscreen Qt.
- Tutorials that show a running bar are re-recorded once this lands (current
  layout only).

NOTE 2026-11-13 (built)
- spacr/qt/run_progress.py: RunProgress is the per-run record (overall
  fraction 0-1, seconds left or None). parse_progress reads n/total,
  operation_type and Time_left (ignored on a 0/n line, where print_progress
  reports 0.000 min); "[mask GPUs] ... Progress:" lines get the label
  "mask GPUs". MODULE_STAGES declares weighted stages by operation_type
  pattern for mask, timelapse, measure, external_masks, classify and
  classify_merged; the overall bar never goes backwards, a skipped stage
  counts as passed, and a label the declared module does not list (the
  nested merge_<role> lines inside mask generation) does not move it. The
  weights come from reading the code, not from timing a reference dataset;
  measuring them is still owed (acceptance item 1).
- Time left: the worker's Time_left when the module declares no stages or
  is on its last declared stage; otherwise remaining fraction / an
  exponential moving average of the rate (weight 0.3, one sample per >= 2
  active seconds). Nothing before 5 % or 30 active seconds ("estimating…").
  Paused time is not active time: the record follows the run's PauseGate
  each time it is read (once a second), the estimate holds while paused and
  resumes from the last rate. Display: "less than a minute left", "about
  N min left", "about H h M min left" (five-minute steps above an hour).
- bridge.RunHandle and _ExternalJobHandle carry run_progress; fraction() is
  the overall fraction, seconds_left() is new. The module run bar shows the
  percent in the bar and "about X left" beside it (RunTimeLeft label,
  refreshed on every line and once a second); Home's RunningBanner shows the
  same bar text and time left, both through run_progress.describe_progress.
- Item 5 audit. Newly counted: convert (Converting images, through the
  existing progress callback), foreign (Importing project, existing
  callback), ops (OPS wells), spatial_masks (Segmenting tiles), spatial_map
  (Assigning spots), analyze_plaques segmentation (Segmenting plaques),
  external_masks (Writing merged arrays), motility (Tracking well groups;

MEASURED 2026-11-14: stage weights, estimator choice, 50 % error table
- Datasets: mask (one GPU worker) and measure (4 jobs) on BBBC021 plate
  Week1_22123, tiny 12 fields, medium 240 fields (measure 96); simulation
  synthetic sweep, 4 and 300 simulations; analyze_plaques and cellpose_masks on
  the first 6 / 60 images of plaque/malnio (read only). The machine was shared
  (load average 74-94), so the seconds differ from a quiet run; the shares are
  what is recorded. The bar was monotonic 0 to 100 % in every run.
- Measured weights now in MODULE_STAGES (share of run time, mean of three
  medium runs, the 3 % unprinted tail left out): mask = Preprocessing 0.121,
  Concatinating + Normalizing 0.177 (one stage: the two loops alternate per
  batch), *_mask_gen 0.671, Merging Arrays 0.031; measure = Measure and Crop
  1.0 (0.99). Stages the reference run did not print (Consolidating images,
  adjust_cell_masks, Plot mask outlines) and timelapse, external_masks,
  classify keep their guessed weights.
- Estimator comparison (mean absolute error of the time left over the medium
  runs of mask, measure and simulation; real remaining time as truth; shown
  after 5 % or 30 s in every column):
      at              naive   blend   EMA 0.05  EMA 0.1  EMA 0.3 (old)
      25 % wall clock  25 %    21 %     113 %     41 %     51 %
      50 % wall clock  35 %    35 %      46 %     41 %    181 %
      75 % wall clock  53 %    47 %      32 %     46 %    112 %
      bar reaches 50 % 43 %    42 %      37 %     43 %     95 %
  On the tiny runs the EMA columns were off by 100 % to 2000 %. The blend
  (elapsed x (1 - f) / f, with the worker's Time_left weighted by f when it is
  printed on the last stage) is as good as the naive estimate early and better
  late, and is what run_progress.py now computes; the exponential moving
  average was removed.
- 50 % error table, error of the shown time left against the real time left
  (negative = announced too early). "Implemented" is the RunProgress estimate
  replayed on the captured lines; "naive" is the control row, elapsed x
  (1 - f) / f with the same fraction; "worker" is the last printed Time_left.
      module (size)                  bar at 50 %    implemented   naive   worker
      simulation, 300 sims                 51 %         -5 %       +1 %    -48 %
      measure, 96 fields                   46 %        -10 %      +22 %    -37 %
      measure, 12 fields                   50 %        -63 %      +10 %    -89 %
      mask, 240 fields (per-batch prints)  36 %        +50 %      +63 %   -100 %
      mask, 12 fields                      30 %        -21 %     +178 %   -100 %
  and at the moment the bar first reaches 50 %: simulation -4 %, measure
  -15 %, mask +67 % (medium); the tiny rows are within the first minute and
  not meaningful.
- Stated tolerances at 50 % (medium reference runs): simulation +-15 %;
  measure +-35 %; mask +-70 % (the first batch of masks is printed only after
  the model loads and the diameters are estimated, 45 % of the run in, so the
  bar waits there); analyze_plaques: the +-15 % hoped for is NOT met, the
  replayed capture shows +60 % to +90 % at 50 % of the wall clock because the
  first image is printed only after the model loads and image sizes differ
  widely; the tolerance stays +-90 % until the load is announced.
  Short runs (under a minute) have no useful estimate.
- Defects found by the audit and fixed on 2026-11-14, each with a test:
  Time_left counted images instead of batches when the time is per batch
  (print_progress, tests/test_938_progress_regressions.py); Preprocessing

  the n_jobs setting instead of the pool (tests/test_measure_n_jobs.py); convert
  and import never printed their last step (tests/test_convert.py,
  tests/test_foreign.py); analyze_plaques segmentation prints through
  print_progress (tests/test_cov_submodules_recruitment_plaques.py); the
  cellpose mask line counts files over files (tests/test_coverage_fill_cellpose_gpu_funcs.py);
  the serial mask path prints one Progress line per batch of fields inside each

  and the Time_left of each (tests/qt/test_run_progress_938.py).
