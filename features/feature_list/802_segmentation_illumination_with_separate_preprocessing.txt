--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Segmentation-input illumination correction is prepared only when
preprocessing and masks run in one call (item 339 documents this), so with
the prep/segment split of item 801 segmentation is uncorrected.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Splitting the stages for throughput should not change the masks.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. Save the segmentation flat field during a preprocess-only run and apply
   it in a later masks-only run.
2. A test that split and combined runs give the same masks.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

preprocess=True, masks=False followed by preprocess=False, masks=True
gives masks identical to one combined call with illumination on.

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

- Off by default while alpha, so a preprocess-only run keeps its previous
  uncorrected inputs unless the setting is on. Promoting it, or making it
  the behaviour whenever illumination_correction is on, is the
  maintainer's call.
- The pipeline_style='v2' path always preprocesses and segments in one
  call and is unchanged.
