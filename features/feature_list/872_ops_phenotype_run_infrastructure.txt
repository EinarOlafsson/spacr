DECIDED WITHOUT THE MAINTAINER (2026-11-09, lane I)
- B3: a repeated channel token is refused with or without ops_ph_acquisitions
  (the spec's test asks for a clear error without the setting). The second
  acquisition's register_on file is kept under the token <channel>@<n>,
  which only the registration reads. With two or more acquisitions and
  ops_ph_secondary_channels empty, the later acquisitions' channels fill it.
- B6: not built under its own names. ops_profile_cells is already another
  setting (a folder of cell tables, in ops_tvn) and ops_nt_rows is item
  883's (lane C); interphase-only profiles are ops_pool_interphase, already
  on nightly.
- B7: the self-check reports and the run goes on; it does not stop a run.
- B10: already on nightly as item 855 (spacr.ops_clusters.benchmark_clusters,
  ops_cluster_benchmark); no second spacr.ops_benchmarks module was added.
- B11: utilisation must be 0 % (the spec), as well as no running non-display
  compute process above ops_gpu_min_process_mib; the STOP file is
  <dst_root>/STOP. The VRAM cap halves the measurement workers when
  measuring starts rather than restarting a running worker pool.
- B17: the setting is ops_tables_layout ('compartments' | 'wide'), not
  measurement_layout, so it stays with the other ops_tables_* settings.
