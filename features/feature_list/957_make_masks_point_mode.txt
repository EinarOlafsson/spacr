PROBLEM
The hand-check of the S3 nuclei needs one click per nucleus on 20 crops, saved
as X/Y points the scorer reads. Make Masks only painted masks, so the task was
planned in Fiji's multi-point tool and Analyze -> Measure.

BUILD
- spacr-make-masks --folder <dir> --points, and Make Masks' alpha button
  "Point mode..." (asks for a folder). The folder opens as a resumable
  curation queue (spacr.curation_queue): done flags in <dir>/curate_status.csv.
  A folder of bare images (no masks/) is accepted as the "images" layout;
  nested and sibling layouts work too; _seg.npy bundles are refused.
  Every image is offered in name order; the window opens on the first image
  not done. --limit, --layers, --require-*, --exclude-verdicts and
  --compute-uncertainty are refused with --points.
- Controls (spacr.qt.point_annotator.PointAnnotatorDialog): left click adds a
  point on the clicked pixel; right click removes the nearest within 8 screen
  px; U toggles unsure on the point nearest the cursor, else the last point;
  Ctrl+Z undoes add, remove and unsure; the point count and unsure count are
  shown; wheel zooms at the cursor, middle button or Shift+left drag pans (as
  in the editor), F fits, +/- zoom; Enter marks done and opens the next image
  not done; Left/Right step without marking.
- Auto-save (spacr.point_annotation.PointSession) after every change to
  <dir>/../annotations/<stem>_points.csv, stem = file name without extension
  and without a trailing _clean. Columns X, Y (float; the clicked pixel's
  column and row, origin top-left, the Fiji Measure convention), unsure (0/1),
  note. Atomic: temp file + os.replace; saving again overwrites. Marking done
  writes the file even with zero points. A Fiji Measure CSV (extra columns)
  is read back.
- Blind by default: --hide-overlays (on). Overlay folders (--overlays DIR...,
  default <dir>/../overlays when it exists; the GUI button uses that
  default) are matched by points stem (<stem>.<ext> or <stem>_*.<ext>) and
  can be shown only when every image of the folder is marked done (or at
  once with --no-hide-overlays). O cycles the overlays of an image. While an
  overlay is on screen the points cannot be changed.
- No change to brush or mask modes; no setting changes, so no
  SETTINGS_SCHEMA_VERSION bump and no DEFAULT_CHANGES row.

note and the clicked column/row exactly. Resume: 10 done after reopen, the
window reopened on crop 11, crop 1's 13 points kept, 20 done flags at the end,
overlays enabled only then.

FIX 2026-11-16 (maintainer report): `python -m spacr.cli_make_masks --folder
<dir> --points` opened Make Masks without the point window. Under -m the CLI
ran as __main__, so the point, layer and queue handovers were stored in a
second module object and the screen (which imports spacr.cli_make_masks)
found its slots empty. The __main__ block now delegates to
spacr.cli_make_masks.main, so every handover lives in one module however the
CLI is started; the spacr-make-masks console script was not affected.
tests/test_957_make_masks_handover_under_dash_m.py runs the -m path in a
subprocess (offscreen Qt, spacr.qt.run replaced by a stand-in that takes the
handovers as the screen does) for --points and for --layers: both pass with
the fix and both fail without it.
