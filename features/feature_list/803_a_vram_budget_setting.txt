--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

There is no VRAM budget; the driver caps each segment process with
torch.cuda.set_per_process_memory_fraction. Item 282 is the host memory
budget only.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Shared GPUs (one workstation, several jobs) need a hard per-job cap.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

Widened 2026-11-06 (maintainer: "can't the GPU VRAM usage be dynamically
regulated so neither process crashes?"), merging the paper session's GPU
memory governor request. spaCR GPU work never crashes on a shared card.

Where: the Cellpose wrapper(s); measure_gpu (torch and cupy/cucim); the OPS
phenotype and SBS paths; CNN inference and training loops.

1. Before each batch, read torch.cuda.mem_get_info(). If free VRAM is under
   the estimated need plus a margin, shrink the batch or wait.
2. OOM guard: on a torch or cupy OutOfMemoryError, call empty_cache() /
   free_all_blocks(), halve the batch and retry the same item. After N
   retries at batch 1, fall back to the CPU for that item. Never drop data,
   never exit.
3. Release cached memory after each item.
4. Ramp the batch back up after K clean items.
5. Optional hard ceiling: gpu_memory_fraction, applied with
   set_per_process_memory_fraction.
6. Machine-wide ledger: each spaCR GPU process records its current use and
   ceiling in a shared file (stale entries from dead PIDs ignored), so a new
   job takes only what is free and running jobs shrink when room is needed.
7. Log adapt, retry and fallback counts to the run report.

Settings:
- gpu_memory_fraction (float or None);
- gpu_memory_margin_gb (default 1.5);
- gpu_adaptive_batch (bool, default True).
Register the feature in ALPHA_FEATURES under 803.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

- A BBBC021 plate segments inside a 5 GB budget, verified with nvidia-smi
  per process.
- Tests (CPU only): simulated OOM; batch halving with retry; CPU fallback;
  ramp-up; the ledger with a dead PID.
