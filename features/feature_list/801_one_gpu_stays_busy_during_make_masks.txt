Status: DONE 2026-11-07 (alpha) — mask_workers_per_gpu (new on Make Masks, alpha: ALPHA_FEATURES[801], default 1) starts that many mask worker processes per GPU on the item-493 worker path, so one worker loads, normalises, filters and saves while another runs Cellpose; with mask_parallel off it uses the first GPU, so a single-GPU workstation runs it. Workers are named <gpu>.<n> (GPU 0.1, 0.2 in the progress line). Fewer start when the card's memory less gpu_memory_margin_gb cannot hold 5 GB per worker, or gpu_memory_fraction leaves too little; workers sharing a GPU run Cellpose-SAM under the item-803 governor (site mask_shared_gpu). --------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Preprocessing and the CPU parts of mask generation run in the same
process as Cellpose, and mask_parallel (item 493) is multi-GPU only. The
driver split prep (preprocess=True, masks=False) from segment
(preprocess=False, masks=True) and ran 2 plates at once.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

A single-GPU workstation idles the GPU for most of a screen.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. Pipeline preparation and CPU post-processing beside Cellpose on one
   GPU (a prefetch queue, or several workers per GPU under a VRAM budget,
   see 803).
2. Report GPU utilisation per plate.
3. Register any new setting in ALPHA_FEATURES under 801.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

One BBBC021 plate keeps the GPU above 80% busy during segmentation,
without the driver's split.

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

- No prefetch queue inside one process: several workers per GPU give the
  same overlap with the existing worker isolation, resume ledger and
  progress line, and the generator loop stays as it is.
- Preprocessing still runs before segmentation within a plate; the workers
  overlap preparation and post-processing of the mask batches, which is
  the segmentation stage the acceptance check measures.
- Timelapse and t_stack runs are refused on the worker path, as for
  mask_parallel.
- The 5 GB per-worker budget is the BBBC021 figure for Cellpose-SAM at
  batch size 8; other backends are budgeted the same.
- The one-plate BBBC021 GPU-utilisation check has not been run: this
  machine had no GPU to spare on 2026-11-07.
