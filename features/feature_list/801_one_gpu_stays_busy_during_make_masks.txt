Status: DONE 2026-11-07 (alpha) — mask_workers_per_gpu (new on Make Masks, alpha: ALPHA_FEATURES[801], default 1) starts that many mask worker processes per GPU on the item-493 worker path, so one worker loads, normalises, filters and saves while another runs Cellpose; with mask_parallel off it uses the first GPU, so a single-GPU workstation runs it. Workers are named <gpu>.<n> (GPU 0.1, 0.2 in the progress line). --------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

Preprocessing and the CPU parts of mask generation run in the same
process as Cellpose, and mask_parallel (item 493) is multi-GPU only. The
driver split prep (preprocess=True, masks=False) from segment
(preprocess=False, masks=True) and ran 2 plates at once.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

A single-GPU workstation idles the GPU for most of a screen.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. Pipeline preparation and CPU post-processing beside Cellpose on one
   GPU (a prefetch queue, or several workers per GPU under a VRAM budget,
   see 803).
2. Report GPU utilisation per plate.
3. Register any new setting in ALPHA_FEATURES under 801.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

One BBBC021 plate keeps the GPU above 80% busy during segmentation,
without the driver's split.

--------------------------------------------------------------------------------
DELIBERATELY NOT DONE
--------------------------------------------------------------------------------

- No prefetch queue inside one process: several workers per GPU give the
  same overlap with the existing worker isolation, resume ledger and
  progress line, and the generator loop stays as it is.
- Preprocessing still runs before segmentation within a plate; the workers
  overlap preparation and post-processing of the mask batches, which is
  the segmentation stage the acceptance check measures.
- Timelapse and t_stack runs are refused on the worker path, as for
  mask_parallel.
- The 5 GB per-worker budget is the BBBC021 figure for Cellpose-SAM at
  batch size 8; other backends are budgeted the same.
- The one-plate BBBC021 GPU-utilisation check has not been run: this
  machine had no GPU to spare on 2026-11-07.

2026-11-10: workstation re-run (RTX 3090 Ti, BBBC021 Week1_22123, 240
fields, batch size 50, Cellpose-SAM for cell and nucleus): one worker
61 % (cell) and 60 % (nucleus) busy at steady state, 644 s; two workers
81.1 % / 66.8 % steady but 72.4 % / 56.6 % over the whole role, 559 s.
The miss was start-up: each role spawned fresh workers (imports, CUDA
context, model load, a 10 s start gate) and hashed the 1.15 GB model
again. Now the workers persist: spacr/_mask_workers.py's
_MaskWorkerPool spawns each worker once per Make Masks call, keeps its
CUDA context and its loaded Cellpose-SAM model (one held model per
worker, reused when the weights file, its size and time and the
constructor keywords match) and takes role-tagged jobs for every role
and plate; only the first spawn passes the start gate, an overload
restart starts at once. A worker that finished its share of one role
starts the next role's while its peers finish, and the parent runs a
finished role's QC while the next one segments (not with seg_qc flag,
whose flags change the next role's settings; those roles run one after
another in the same workers). Each model file is hashed once per call.
gpu_utilisation.json now records, per role and GPU, started_at (epoch
seconds and started_at_iso), startup_seconds (the first finished
archive) and the start-up and steady busy percentages on both the
worker and the one-worker path, and the [gpu] line gives the steady
figure. Defaults are unchanged. Tests:
tests/test_mask_workers_persist_across_roles.py (CPU stand-ins in real
spawned workers, a fake Cellpose model in process, no GPU). The >80 %
check waits for the workstation re-run with the same three arms.
