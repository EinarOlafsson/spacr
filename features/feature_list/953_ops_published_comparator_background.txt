PROBLEM
published_clusters dropped a comparator's non-targeting rows, so
cluster_sweep scored Funk et al. 2022's published interphase clusters with a
Fisher background of 5,072 rows instead of the publication's 5,322: CORUM
23.9 % of clusters enriched (may2025 variant) instead of the published 24.3 %.

BUILD
- published_clusters(spec, control_prefix='nontargeting', keep_controls=True):
  True keeps the control rows with their published cluster ids; False is the
  old behaviour.
- score_published(..., control_prefix='nontargeting'): each comparator is
  scored on the sweep's scored genes it clusters plus its own control rows.
  The control rows enter the Fisher background of the CORUM and KEGG shares
  only (score_clusters already leaves them out of cluster counts, enrichment
  membership and STRING pairs); complex metrics and the shuffled-label control
  use the scored genes only, with the same generator draws as before.
- published_record(..., controls=None): with controls, each comparator records
  control_rows_in_background and the legend states the rule; None writes the
  old record.
- cluster_sweep_phase reads ops_cluster_published_controls (bool, default
  True, alpha) and passes ops_control_prefix through.
- _sweep_setting_list takes a single value, so ops_cluster_seeds = 42 read
  back from a settings file is one seed (it raised TypeError before).
- Not changed: the sweep's own rows (score_partitions) are scored on the
  targeting genes only, as before.

ACCEPTANCE
tests/test_ops_published_background_953_954.py: control rows kept or left
out; the CORUM share with controls equals a hand-written Fisher test with the
background grown by the control rows (and the old share without); controls
never change cluster, gene, STRING or complex counts; the shuffled control
permutes the scored genes only; the phase with False writes byte-identical
files to the pre-953 code; files stamped before 941 load False.
