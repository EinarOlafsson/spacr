RESULT
Plate A, 5,281,214 interphase cells (scratch accept_879.py with
settings_879_A_check.json), against final_pipeline.py --plates A
(final/A_check, eval/external/X_final_A_check*, eval/metrics/X_final_A_check*):
- the same 5,112 genes and 20,439 guides in the same order with the same
  cell counts; the TVN components differ by up to 1e-3 (guides 2.6e-3);
- all 31 metric rows and 7 specificity rows present with the same queries,
  pairs and complexes; mAP within 1.6e-5, AUROC 2e-5, AUPRC 7e-7, the share
  of genes with q < 0.05 within 0.0019 (about 4 of 2,079 CORUM genes), the
  fitness-matched specificity mAP within 1.8e-4 and complex top-5 within
  1/5,960; the time-split control share differs by 0.0016, which moves the
  enrichment (a ratio over a small control share) by 1.9.
The cause is not the TVN rotation: replacing the shared core by a
step-for-step single-precision port of Brieflow's tvn_on_controls left the
same 1e-3 difference (tried and reverted). TVN scales every control axis to
unit variance, so the float32 rounding of the 5.3-million-cell PCA
products (whose summation order depends on the BLAS threads) is amplified
on the weak axes, as the ops_tvn module notes describe for the PCA sample.
Bit-identical profiles would need a pinned single-threaded BLAS in both
runs; this was not attempted.

INTEGRATION NOTES (2026-11-09, integration branch)
- Registered under its own ALPHA_FEATURES[879] (the profile settings),
  [880] (ops_eval_null_size), [881] (ops_reference_dir, ops_eval_references,
  ops_eval_split) and [882] (ops_eval_heldout_folds, ops_eval_decoys,
  ops_eval_time_split) instead of the borrowed [752]. ops_profile_shrinkage,
  ops_profile_weighting and ops_profile_similarity are the settings of items
  902, 907 and 904/905 (one definition each); the profile phase accepts
  ops_profile_similarity empty, cosine or gene_cosine and always compares
  gene profiles by cosine.
- Shrinkage and weighting are no longer refused: profile_cell_tables applies
  spacr.gene_measurement_compare.shrink_gene_profiles (prior df
  ops_profile_shrinkage_prior_df) or contrastive_weighting to the gene and
  guide tables before the active-gene filter; the two together are refused
  as in the aggregate phase; evaluate scores the w_* columns of a weighted
  table. Test: tests/test_ops_profile_pipeline_879.py.
- Maintainer decision: new setting ops_deterministic_blas (default True) runs
  the profile phases with BLAS/OpenMP held to one thread (threadpoolctl when
  installed, otherwise the OMP/OPENBLAS/MKL/BLIS/VECLIB/NUMEXPR thread
  variables, restored afterwards), so a spaCR re-run of the same settings
  file writes identical genes, guides and metric tables; runtime.json
  records the setting and how the threads were pinned (blas_threads). Test:
  two runs on the fixture give bit-identical tables.
- ACCEPTED (maintainer, 2026-11-09): the difference from the reference script
  final_pipeline.py is at most 1e-3 on the profiles (TVN components; guides
  2.6e-3) with mAP within 1.6e-5, as recorded under RESULT above. It comes
  from the float32 summation order of the reference's multi-threaded PCA, is
  not a spaCR bug, and spaCR re-runs are now bit-identical with each other.
