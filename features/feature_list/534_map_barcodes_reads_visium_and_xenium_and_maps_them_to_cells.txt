WHAT TO BUILD
  1. A Spatial transcriptomics submodule under Map Barcodes with two readers:
     * Visium / Visium HD: the Space Ranger output (filtered feature-barcode
       matrix .h5, spatial/tissue_positions(.csv|.parquet),
       scalefactors_json.json, the H&E or IF image at full and hires scale;
       Visium HD's binned outputs at 2/8/16 um).
     * Xenium: the Xenium Ranger/onboard output bundle (transcripts.parquet
       with x/y/z and QV, cells.parquet, cell_boundaries / nucleus_boundaries,
       cell_feature_matrix, morphology.ome.tif / morphology_focus, and the
       experiment.xenium metadata with the pixel size).
     Read through existing libraries where they fit (spatialdata /
     spatialdata-io, scanpy/anndata) rather than hand-written parsers, loaded
     lazily so spaCR's start-up cost does not grow.
  2. REGISTRATION TO spaCR's IMAGES: put the sequencing coordinates into the
     pixel frame of the images spaCR segments: Visium spots via the
     scalefactors; Xenium microns via the morphology image's pixel size; and
     an affine (landmark or intensity-based) registration when the user's own
     microscope image of the same section is used instead of the platform's
     image. Show the overlay (spots or transcripts over the image, coloured by
     gene) in the Map Barcodes preview so the fit can be checked by eye.
  3. RELATE READS TO spaCR OBJECTS: assign each Xenium transcript to the
     spaCR cell / nucleus / pathogen / vacuole it falls in (the same
     point-in-mask logic OPS uses for reads), and each Visium spot to the
     objects it covers (with the fraction of the spot each object occupies).
     Write per-object gene counts next to the existing per-object
     measurements (same database, keyed by the object id), so morphology,
     infection state and expression sit in one table.
  4. ANALYSIS: per-object and per-region expression summaries, genes
     enriched in infected vs uninfected host cells, expression vs distance to
     the nearest parasite/vacuole, and export to AnnData (with spatial
     coordinates and spaCR's measurements in .obs) for scanpy/squidpy.

WHAT WAS BUILT (2026-09-27)
  * Map Barcodes gets a "Spatial transcriptomics" toggle and card
    (spacr/qt/screens/map_barcodes.py, _SpatialTranscriptomicsPanel):
    platform folder, platform (Detect/Visium/Visium HD/Xenium), HD bin,
    minimum QV, analysis image (platform image or the user's own), pyramid
    level, landmark table, cell/nucleus/pathogen/vacuole masks, region mask,
    measurement database, gene; "Load and register" draws spots/transcripts
    over the image coloured by the gene; "Assign and write" runs the rest.
  * Engine: private _st_* helpers in spacr/ops_engine.py (no new module).
    Direct readers: 10x feature-barcode .h5 (h5py), tissue_positions
    (.csv/.parquet/legacy list), scalefactors_json.json, hires/lowres/full
    images, Visium HD binned_outputs/square_<2|8|16>um; Xenium
    transcripts.parquet (QV filter, control probes dropped),
    experiment.xenium pixel size, cells.parquet, morphology_focus/ or
    morphology(_mip).ome.tif pyramid levels. spatialdata/spatialdata-io and
    scanpy are NOT used: they are not in the spacr env and the formats are
    simple; anndata is used only for the .h5ad export (optional, via
    spacr.anndata_export.require_anndata).
  * Registration: Visium via scalefactors, Xenium via pixel size x 2^level;
    the user's own image through a landmark affine (least squares) or, with
    no landmarks, ORB keypoints + RANSAC affine with a phase-correlation
    fallback.
  * Assignment: Xenium transcripts by point-in-mask (the OPS rule); Visium
    spots by the fraction of the spot (circle, or square HD bin) each object
    covers, counts shared out by that fraction.
  * Written to the measurement database keyed by prcfo:
    <object>_expression (wide, expr_<gene>, top 1500 genes), Xenium also
    <object>_expression_long, Visium also <object>_spot_coverage. Rows of
    the same image are replaced on rerun. The host object's table is joined
    into the AnnData .obs.
  * Analysis (results folder beside the db): infected vs uninfected
    (Mann-Whitney U on normalised log counts, BH q), expression vs distance
    to the nearest pathogen/vacuole (Spearman, BH q), region summary (by
    region mask, else by infection state), .h5ad with obsm["spatial"], and
    the overlay through spacr.plot.save_figure.

    Maintainer, 2026-10-11 (verbatim): "if you cannot find a publicly
    available dataset that is infected use a non infected xenium and visium
    dataset. This should be divided into several sub modules. A sub module
    to mask generation, and one for map barcodes. The mask gen one should
    generate the masks from the whole slide (there will be lots of overlap
    with the OPS submodule here I think, then measure should be able to
    measure the output of that normally just like the ops sub module
    output. The map barcodes sub module should be able to analyze all of
    the barcode and transcriptome data and relate it to the same
    coordinates as the images."
    Worktree claude-f534b-20261011, commits 5c5c15961 (engines),
    96b781812 (GUI), ba26fc094, 37af4f252 (+ artefacts/i18n, + this note).
    DESIGN (reuses OPS; no new module):
    - Settings: spacr/ops_settings.py register_spatial() registers
      spatial_masks and spatial_map like OPS's register() (types,
      tooltips, categories Spatial input / region & tiling / segmentation
      / mapping / infection, descriptions). Keys are all spatial_*.
    - Spatial Mask Generation, ops_engine.run_spatial_masks: the slide (or
      spatial_window, um or px, at spatial_level) is tiled with
      ops_compose.windows_over (spatial_tile_size 2048, overlap 160); each
      window reads only its TIFF tiles/strips (_st_read_window, no zarr);
      nuclei by Cellpose through OPS's _cellpose_model (cpsam; CPU unless
      spatial_gpu) or an Otsu + watershed fallback; cells = nuclei grown
      spatial_cell_expansion_um (5) with expand_labels; observations
      sewn and numbered by ops_objects.objects_in_window / sew / number,
      the OPS seam code (PlateObject now carries the kept window label).
      Every object is kept from one window that saw it whole; each window
      that keeps objects is written as a field in the Mask Generation
      layout: stack/<plate>_A01_<n>.npy, masks/{cell,nucleus}_mask_stack,
      merged/<stem>.npy = channels + cell + nucleus planes (uint16, local
      labels 1..n, nucleus label = its cell's) and
      merged/.spacr_plane_layout.json. spatial_fields (each field's
      origin on the slide, level, scale to full resolution, um/px) and
      spatial_objects (slide-wide id, prcfo, slide centroids) go to
      <dst>/measurements/measurements.db; spatial_mask_report.json like
      ops_report.json.
    - NOTE on "like the OPS output": OPS itself writes no mask files
      (ops_objects table only) and Measure has no OPS path today. So the
      fields follow the normal Mask Generation / external-mask layout,
      which Measure reads with NO special-casing (src = <dst>/merged; the
      plane-layout file sets cell/nucleus_mask_dim).
    - Spatial Map Barcodes, ops_engine.run_spatial_map: reads the whole
      Xenium bundle (QV >= spatial_min_qv, controls dropped) or one
      Visium HD bin size (2/8/16 um); puts every point in full-resolution
      slide pixels (Xenium um / experiment.xenium pixel_size; Visium HD
      pxl_col/row_in_fullres of the microscope image), then into each
      field (/ scale - origin); counts transcripts by point-in-mask and
      shares bins by covered fraction (_st_object_counts) into the planes
      in spatial_objects (cell,nucleus). Objects are owned by one field,
      so overlaps count nothing twice. Writes <object>_expression
      (+ _expression_long for Xenium, _spot_coverage for Visium HD) keyed
      by prcfo = <prcf>_o<label>, which is how io._read_and_join_tables
      keys Measure's tables (Measure writes prcf + object_label, no
      prcfo column; _st_measured composes it, which also fixes the
      silent no-join in _st_run). Pathogen options kept:
      spatial_pathogen_genes (CHIKV*), spatial_min_pathogen_transcripts;
      infection csv, infected-vs-uninfected (Mann-Whitney, BH), distance
      to the nearest infected cell over uninfected cells (Spearman),
      region summary, optional .h5ad, overlay of the field with most
      cells (save_figure). The analysis tail of _st_run is shared as
      _st_analyse. Duplicate gene names get expr_<gene>_2.
    - GUI: map_barcodes.PageFold generalises OPS's page fold (_OpsPage is
