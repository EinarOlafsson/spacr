OPS LARGE CROPPED SITES: TILED SEGMENTATION, CHUNKED MEASUREMENT, RAM CAP, EDGE POLICY, PHALLOIDIN PRESET
=========================================================================================================

Lifecycle: future
Status: PARTIAL 2026-11-11 (alpha, under ALPHA_FEATURES[921]) — CPU path built and pinned by synthetic fixture tests; the GPU tolerance check and the CP186A Well1 run are not done (no GPU at Home). New module spacr/ops_large_sites.py, run by spacr-run ops_large_sites (run_large_site_segmentation): reads a cropped well folder (<channel>/<channel>_Site_<n>.tiff, the Cell Painting Gallery's images_corrected_cropped layout, or <site>.npy stacks); plans tile size and workers from seg_max_ram_gb and refuses a cap it cannot meet (plan_site_memory); segments nuclei on DNA and cells on [Phalloidin, DNA] tile by tile with overlap (segment_tiled, tile_grid) and stitches labels by IoU, keeping the copy whose centroid is farther from an inner tile edge, relabelled in raster order (stitch_tile_labels, relabel_raster); a site no larger than one tile goes through the segmenter unchanged; pairs one nucleus per cell (spacr.ops_sample.pair_nuclei_with_cells); applies the crop-edge policy exclude / keep / own (apply_edge_policy); measures every object once and whole in row bands with a halo (measure_chunked, basic_features); estimates the plate's nucleus diameter from a first pass, clipped to [10, 80] px (estimate_nucleus_diameter); scores agreement with reference label masks (mask_agreement: F1 at IoU 0.5, median IoU, count ratio, non-edge objects only); records peak memory per site with spacr.resource_log.ResourceSampler; optional tiled-vs-untiled control on a centred region (tiling_control). Writes <seg_dst>/labels/<site>_{nuclei,cells}.npy, tables/<site>_cells.parquet, sites.csv, agreement_well.csv, tiling_control.json, resource_log/site_<n>.jsonl and settings.json. spacr/ops_large_sites.py, spacr/settings.py, spacr/cli.py, tests/test_ops_large_sites_921.py.

SETTINGS NAMES
The spec's keys are kept (seg_tile_px, seg_tile_overlap_px, seg_stitch_iou,
seg_max_ram_gb, seg_edge_policy, seg_preset, nucleus_diameter, cell_model,
cell_channels, seg_report_reference). nucleus_diameter is an existing Mask
setting, so it is read here but not registered as alpha (registering it would
hide it in Mask). Added: seg_sites_src, seg_site_channels, seg_sites, seg_dst,
seg_workers, seg_measure_band_px, seg_gpu, seg_tiling_control_px, and the
preset's seg_nucleus_channel, seg_nucleus_model, seg_nucleus_diameter_range
(prefixed because nucleus_channel is an existing setting).

MODELS
Cellpose 4 ships only cpsam; 'nuclei' and 'cyto3' resolve to cpsam through
spacr.utils._resolve_cellpose_pretrained, which says so. The cyto3 arm needs
the cellpose3 backend and is not wired in this module. Cellpose-SAM has no
size model, so the per-plate nucleus diameter is the median equivalent
diameter of a first pass without a diameter, clipped to [10, 80] px.

FAIR COMPARISON
The agreement report compares spaCR and CellProfiler on the same pixels
(same sites, same 5,500 px grid), non-edge objects only in both, with one
matching rule (IoU >= 0.5) and no tuning on the reference masks. It is
agreement, not ground truth.

FIXES AFTER THE FIRST CP186A WELL1 RUN (2026-11-12)
The WS run (100 sites, spaCR 3bc1124532) found two bugs.
- Diameter and tiling control from site 1: both came from sites[0], an
  empty well-edge site, so the diameter fell to the 10 px floor and the
  control had nothing to compare. Now seg_diameter_sites (9) sites spread
  over the well are segmented first (sample_sites); only those with at least
  seg_diameter_min_objects (50) nuclei count, the diameter is the median over
  their nuclei, and the control runs on the median-count site
  (survey_sites). nucleus_diameter.json and sites.csv
  (nucleus_diameter_sites) record the sites and the value; a well with no
  such site stops with a message. The cell path has no diameter (Cellpose-SAM
  runs at its native scale), so it had no such estimate.
- Tiled and untiled labels differed everywhere (site 76: away_identical
  0/557, at_seams_share 0.838). Cellpose normalised every tile by its own
  1st/99th percentiles, and its network tiles fell on different grids in a
  tile and in the untiled region. Now each channel is normalised once per
  site (normalize_site, Cellpose's own arithmetic) and Cellpose runs with
  normalize=False; tiles start on Cellpose's network-tile grid
  (network_tile_starts, aligned_tiling, tiling_layout: 1968 px tiles with 432
  px overlap for 2048 / 256), and the control region is sized to that grid
  (control_layout: 1968 px region, 1200 px tiles). Nuclei with a set
  diameter are resized per tile by Cellpose, so they get the normalisation
  fix only.
