PROBLEM
OPS decode thresholds were tuned inside a run (auto mode) with no
per-combination table to inspect before a full run, and the live preview
covered segmentation only.

BUILD
- Settings (alpha, all off or empty by default, no schema bump):
  ops_grid_search (bool False), ops_grid_params (grid, None),
  ops_grid_tiles (selection, None), ops_grid_tile_mode (None = stratified;
  stratified, edge_centre, user), ops_grid_n_tiles (None = 8),
  ops_grid_seed (None = 0), ops_grid_run_id (None; written by apply).
- One grid parser for the settings file, the GUI and the CLI: a dict of
  lists, a JSON object, or "key=v1,v2; key2=v3". It varies
  ops_read_threshold, ops_read_mode (log, raw), ops_prefix_min_read_quality,
  ops_prefix_max_distance, ops_quality_min_reads and ops_prefix_crosstalk.
  The full-barcode decode's keys (ops_min_fraction, ops_single_read_quality,
  ops_pixel_quality, ops_read_mismatches) and a peak width are not on this
  path and are refused with the list of keys it does vary.
- Tile picker: stratified (wells in turn, a seeded random site each),
  edge_centre (alternately the site furthest from and nearest the well
  centre, sites taken as a square raster), user (ops_grid_tiles).
- Default point: the settings as they stand. With per-well tuning (the 966
  default) the decode runs once on the chosen tiles per well and its choice
  is the default; every grid point changes only the keys the grid names.
  The run records whether the default point's counts equal the decode's own
  site_summary rows (default_matches_decode).
- Engine path: each tile's spots are found once down to the lowest grid
  threshold (_spot_candidates, _raw_candidates), each point is read, called
  and matched with _site_tuning_reads and _at_setting, and counted with
  _site_row, which run_prefix_decode now calls too. Shuffle control: the
  engine's 3 shuffled whitelists (_shuffle_frame, _called_counts).
- Parallel over tiles: n_workers processes (spawn), each tile once.
- Outputs beside the settings file (else <dst_root>/settings):
  ops_grid_<run id>.csv (per tile and pooled rows; same settings write the
  same bytes), ops_grid_<run id>_timing.csv (spot-finding seconds per tile,
  scoring seconds per point and tile), ops_grid_<run id>.png (assigned %
  against shuffle call rate, default and Pareto front), ops_grid_<run id>.json.
- run_ops on the cropped-site layout with ops_grid_search on runs only the
  prefix_grid_search phase; the phase can also be named.
- Apply: a non-default point writes its values, sets
  ops_prefix_threshold_tuning 'none', and records ops_grid_run_id,
  ops_grid_tiles and ops_grid_seed; ops_grid_search goes back off.
- GUI: spacr/qt/widgets/ops_grid_search_panel.py, a Grid search panel
  (tile pick, n tiles, seed, tiles, grid, Run grid, sortable table, plot,
  Apply to settings) for the Spots & genotyping tab of item 971's OPS Live
  preview; _attach_grid_search(live_panel, host) adds it to
  live_panel.page('spots'). Wiring into the OPS screen waits for 971.

PROOF CHECK 2026-11-17 (CPU, one process at a time; REPORT.md in
BMCspacr/reanalysis/item960_proof/). Grid: read threshold 40/80/160 x
read-quality floor 0/0.1/0.25 x mismatches 0/1, plus the default point.
- Identity: the default point equals the frozen 966 decode's own
  site_summary on Funk plate A (8 tiles over A1-A3), CP186A (8 held-out
  sites) and 8 CP186A crops (all counts, max difference 0); a fixed point
  (80, 0.1, 1) equals run_prefix_decode with tuning off on Funk and CP186A
  (counts exact, shuffle-called to 3e-8); a 2-worker rerun writes the same
  CSV bytes.
- Control: shuffle call rate at every point (3 seeds); at the default point
  seeds 0-2 lie inside the 500-permutation 95 % range (Funk 0.261 %
  [0.163, 0.379]; CP186A 0.476 % [0.336, 0.686]).
- Brieflow automated_parameter_search rerun on the same tiles, 18 points,
  scored the same way: Funk fronts within a point (Brieflow 65.26 % at
  0.560 % shuffle, spaCR 64.34 % at 0.535 %); CP186A crops spaCR 26.80 %
  vs Brieflow 22.85 % (CP-scaled thresholds). Published Brieflow values
  exist only for its default setting on other tiles (Fig. 2c, p. 3).
- Finding: on 2-3 tiles per well the per-well tuning picks the strict
  floor 0.25 on Funk (39.70 % assigned); the grid shows floor 0.1 reaches
  64.34 % at the same decoy FDR (0.019 %).
- Speed (Funk, 1 process): 3.64 s per point per tile vs Brieflow 27.5 s
  (7.6x); CP186A full sites 10.1 s (spot finding 64 s per site, read from
  the NAS).
- GUI: panel and tests done; wiring into item 971's Spots & genotyping tab
  waits for 971 on nightly (WIRING_AFTER_971.md).
