WHAT THE STATE IS
_profile_average_precision defines positives by metadata equality, one
label per profile. Gene-gene references are multi-label, so the paper's
retrieval mAP was computed outside spaCR.

WHAT TO DO
- A multi-label AP that agrees with _profile_average_precision on
  single-label data (tests_retrieval.py check 1, now a spaCR test).
- Per-gene p values from spaCR's copairs null, BH q values, normalised AP,
  bootstrap CIs.

RESULT
Funk et al. 2022 plate A, arm C0_base (scratch script
paper-items-1109/lane-d/accept_880.py): for all 17 references of
eval/per_gene/C0_base.csv.gz (CORUM, STRING >= 0.7 and >= 0.4, KEGG,
BioGRID, the six halves and the six time-split references) the genes are
the same and ap, n_pos, n_total, nap, expected_ap, p and q agree to
1.1e-16 (the CSV round trip). This holds when the similarities come from
the double-precision embedding, as evaluate.py computed them; the arm file
stores the components at single precision, and similarities rebuilt from
it move AP by up to 5e-7.
