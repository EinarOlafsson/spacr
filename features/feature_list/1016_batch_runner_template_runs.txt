REQUEST (quoted)
"The Batch Runner gets an "Import template run" button AND a drop section.
The user presses it or drops a finished run folder (for example a plate
folder whose settings/ holds gen_mask_settings.json and the measure
settings). spaCR reads every module settings snapshot the run recorded.
A second "Jobs" button and section: press it to pick a new src folder, or
drop one or more folders. Each new folder is CHECKED FOR COMPATIBILITY with
the template before it becomes a job: the file-name regex or metadata parse
matches, the same channels and planes, the same image dimensions and dtype,
plus whatever else the template settings assume. Report a mismatch in plain
words and don't add that job.
If the template has Mask and Measure, a new folder makes TWO jobs, one Mask
and one Measure, with Measure chained to that job's Mask output
(spacr.chaining).
Every job can be edited. Clicking a job (for example the Mask job of the new
plate) opens that module screen loaded with the job's settings: the template
settings with only src and the output paths changed. Every change is saved
to the job automatically, as it is made. No save button.
Any number of jobs is set up this way. Then the queue runs as today.
Reuse the existing pieces: BatchDropHandler and plate_queue
(spacr/qt/dnd_handlers.py ~3070, settings snapshots), load_settings, and the
chaining port bindings. Don't build a second settings loader."

BUILD
- spacr/batch.py (light, outside __all__, so not public API):
  read_template_run reads every
  settings snapshot of a run folder (settings/ then the folder; JSON wins
  over a CSV of the same name) with spacr.cli.load_settings_file, the loader
  the queue resolves job settings with; run bookkeeping keys starting with
  "_" are dropped; modules are put in run order from spacr.ports (producer
  before consumer).
- snapshot_files and module_for_snapshot are the one implementation of
  "which files are snapshots, which module is each"; the Plate Queue and
  Batch drop handlers (_settings_files, _module_from_settings) now call them.
- template_job_settings: the template settings with the source key
  (spacr.chaining.source_key) set to the new folder and every path inside
  the template run moved to the same place in the new folder. Nothing else
  changes.
- chained_input: a later module that reads what an earlier template module
  writes gets its input through spacr.chaining.binding_for (ROOT or PATH
  form) and depends_on that job, so Measure runs after the Mask job of the
  same folder.
- check_template_folder: plain-sentence mismatches, no job added: no images; file
  names that do not parse with the template pattern (custom_regex or
  metadata_type); channels; z planes; image size; pixel type (TIFF/NPY
  header, no pixels read); then every ERROR of validate_settings on the
  resolved job settings ("whatever else the template settings assume").
  The raw-name parse is the shared spacr.validate._raw_image_names /
  _parse_raw_names, which _scan_raw_images now uses too.
- add_template_jobs: one Job per template module, settings in its own JSON
  file under <spacr home>/batch/template_jobs/, added through Queue.add (the
  same validation as the Add job button); a folder whose jobs cannot all be
  added leaves the queue and the disk as they were.
- Batch Runner: a "Template run" section (Import template run... button,
  drop zone) and a "Jobs" section (Jobs... button, drop zone for one or more
  folders, list of template jobs). Mismatches go to the Validation problems
  pane, never a dialog. The drop zones are private subclasses of
  BatchDropHandler.
- Clicking a job opens its module screen (MainWindow.open_module) with the
  job settings applied (apply_settings_dict) and a strip under the heading:
  "Editing the Batch Runner job ... Every change is saved to the job." with
  "Back to the Batch Runner" and "Stop editing the job". Every committed
  edit reaches AppScreen._observe_settings_commit, which hands it to the job
  editor; the key is written to the job settings file at once.

TESTS

not), and the run order Mask then Measure.
