WHAT THE STATE IS
spaCR had no way to learn gene-gene links and category membership from OPS
gene profiles and to judge them on held-out genes and a 2022 time split,
with the controls (shuffled features and labels, rewired edges, decoys,
degree prior) that make the numbers interpretable.

WHAT WAS DONE
- One flat module, spacr/gene_graph.py (no spacr/ops/ package exists), with
  the entry points get_gene_graph_default_settings, build_gene_graph,
  train_gene_graph, evaluate_gene_graph, predict_gene_functions and
  run_gene_graph. Settings keys carry the gene_graph_ prefix (the spec's key
  names after the prefix), so they never collide with another module's.
- The models are plain PyTorch on the device of gene_graph_device; CUDA falls
  back to the CPU with a warning. On the CPU the trainer runs with
  torch.use_deterministic_algorithms(True) and no autocast, so a rerun is
  identical to itself. On CUDA: admission (card + cap + 0.5 <= limit held
  for admission_hold_s), set_per_process_memory_fraction(cap), YIELD with
  resume.pt (exit 75 from python -m), STOP at gene_graph_gpu_budget_h, and
  START / YIELD / FINISH / STOP lines in gene_graph_gpu_log.
- Differences from the reference that do not change its numbers: the resume
  file also stores the torch RNG state (the reference reseeded nothing on
  resume, so dropout differed after a resume); a run whose validation never
  improves keeps its last state instead of failing; empty prediction tables
  are written with their header.
