--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

The spacr conda env's xgboost 3.4.1 is a CUDA build: with
CUDA_VISIBLE_DEVICES='' it raises cudaErrorNoDevice at fit time even with
device='cpu'. The reanalysis worked around it with xgboost-cpu in a separate
venv (/mnt/wd4tb/bmc_reanalysis/venv_moa).

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

Every spaCR classifier that uses xgboost would crash on CPU-only machines,
laptops and CPU-only CI.

--------------------------------------------------------------------------------
WHAT TO DO
--------------------------------------------------------------------------------

1. Probe for a usable GPU before choosing the xgboost device, and fall back
   to a CPU fit (or a clear error naming xgboost-cpu) when none exists.
2. Pin the install profile (spacr/install_profile.py) to a CPU-capable
   xgboost where no CUDA device is present.
3. A CPU-only test of the xgboost path under CUDA_VISIBLE_DEVICES=''.

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

The regression/classify xgboost path fits under CUDA_VISIBLE_DEVICES=''
in the spacr env.
