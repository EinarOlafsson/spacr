--------------------------------------------------------------------------------
WHAT THE STATE IS
--------------------------------------------------------------------------------

`spacr.utils._get_regex` (utils.py:6131) is an if/elif chain with four arms:

    cellvoyager  (?P<plateID>.*)_(?P<wellID>.*)_T(?P<timeID>.*)F(?P<fieldID>.*)
                 L(?P<laserID>..)A(?P<AID>..)Z(?P<sliceID>.*)C(?P<chanID>.*)
    cq1          W(?P<wellID>.*)F(?P<fieldID>.*)T(?P<timeID>.*)
                 Z(?P<sliceID>.*)C(?P<chanID>.*)
    auto         renames to Yokogawa naming first, then parses
    custom       whatever the user types into custom_regex

So the two built-in conventions are the Yokogawa CV7000/CV8000 and the
Yokogawa CQ1. Everyone else is expected to write a regex by hand, in a setting
whose own tooltip warns that a filename which does not match is SKIPPED WITH A
WARNING -- a quiet way to lose half a plate.

Two properties of the current arms are worth keeping in mind while adding
more: every group is `.*`, which is greedy and will happily match the wrong
half of a name that has more underscores than the author expected; and the
pattern is built with the image extension interpolated at the end.

--------------------------------------------------------------------------------
WHY IT MATTERS
--------------------------------------------------------------------------------

A user with a Zeiss, a Nikon, a Leica or a Thermo Fisher instrument meets
spaCR's front door with a dropdown that does not name their microscope. The
failure is not loud: a mismatched regex skips files, and a partially matching
one assigns the wrong well, field or channel -- which produces a measurements
database that is wrong rather than empty.

WHAT TO DO
--------------------------------------------------------------------------------

1. RESEARCH FIRST, and record the source for every convention. For each
   vendor and instrument family, find the DEFAULT export naming, with real
   example filenames, and cite where each came from (vendor documentation,
   Bio-Formats' format pages, OME's metadata notes, open datasets on IDR or
   BioImage Archive, forum posts by users of that instrument). A regex nobody
   can trace to a real file is a guess.
   At least: Zeiss (ZEN/Axio, CZI exports and their tiled TIFF naming),
   Nikon (NIS-Elements, ND2 exports), Leica (LAS X, and the "Image_..." TIFF
   series), Thermo Fisher (CellInsight / ArrayScan, and EVOS), Yokogawa
   (CV7000/8000 and CQ1, already here), Molecular Devices (ImageXpress
   MetaXpress), PerkinElmer/Revvity (Opera Phenix, Operetta -- the r##c##f##p##
   -ch##sk##fk##fl## form), Olympus/Evident (ScanR, cellSens), GE/Cytiva
   (IN Cell Analyzer), Agilent/BioTek (Cytation, Gen5), Sartorius (Incucyte),
   Nanolive, Etaluma, and any open-source acquisition naming worth covering
   (Micro-Manager's MDA, OME-TIFF companion naming, ImageJ/Fiji defaults).

2. TURN THE if/elif CHAIN INTO A TABLE. One record per convention: key,
   display name, vendor, instrument family, the regex, at least two real
   example filenames it must parse, what each named group means, the source it
   was taken from, and whether it is CONFIRMED (matched against real files or
   vendor documentation) or PROVISIONAL (inferred from examples found online).
   The dropdown shows confirmed and provisional differently -- a user should
   know when spaCR is guessing about their instrument.

3. KEEP THE EXISTING FOUR WORKING, byte for byte. cellvoyager, cq1, auto and
   custom keep their current patterns and their current keys; old settings
   files must load unchanged.

4. GREEDINESS: prefer specific character classes over `.*` in new patterns
   (`(?P<wellID>[A-Z]\d{2})`, `(?P<fieldID>\d+)`), and add a test for each
   convention that feeds it a filename from a DIFFERENT convention and asserts
   it does not match. Two patterns that both match the same name is the defect
   that silently mislabels a plate.

5. THE UI: metadata_type becomes a grouped dropdown (by vendor), with the
   example filename shown under the choice, and a "test it on my folder"
   action that reports how many files in the chosen source parse and shows the
   first that does not. That readout is what turns a wrong guess into a
   question the user can answer before a run starts, rather than a warning
   they find afterwards.

6. AUTODETECT, if the table makes it cheap: given a folder, try every
   convention and report which one parses the most files, and how many. Offer
   it rather than apply it.

TWO CORRECTIONS TO THIS FILE'S OWN BRIEF
----------------------------------------

  * The Operetta form this file imagined as
    `...-<n>_<Well>_T####F###L##A##Z##C##.tif` DOES NOT EXIST. Every primary
    source -- PerkinElmer's own 2011 statement, a 2021 Operetta CLS upload,
    and both Bio-Formats readers -- has Operetta and Operetta CLS writing the
    same r/c/f/p-ch/sk/fk/fl form as the Phenix. That T/F/L/A/Z/C shape is
    Yokogawa's, and the two were conflated.
  * There is NO sourceable Zeiss well-plate filename. The `_A01_T0001F001L01
    A01Z01C01` names that circulate online under "well-plate naming" are
    Yokogawa's -- Novartis's readme says so outright -- and searching for a
    Zeiss one returns them.

THE DEFECT THE ITEM PREDICTED, FOUND AND FIXED WHILE WRITING THE TABLE
----------------------------------------------------------------------

EVOS reuses Cellomics' ENTIRE `<well>f<field>d<dye>` tail. So
`scan_R_p2_z1_0_B03f01d0.tif` matched BOTH `arrayscan` and `evos` -- an EVOS
plate scan silently readable as an ArrayScan plate, with the grid index eaten
as part of the plate name. `arrayscan` now opens with a negative lookahead
for the EVOS `_[RDM]_p\d+_z\d+_\d+_` tail. This is exactly the failure the
item's point 4 names, it was real, and the cross-match test is what found it.

ONE OVERLAP REMAINS AND IS ALLOWED, in the test, by name: every
`cellvoyager` name also satisfies `auto`. Both are the Yokogawa grammar
written entirely in `.*`, and neither may be tightened, because both are
pinned. Recorded rather than hidden, so that a NEW overlap fails.

THE RULE THAT IS NOT A STYLE RULE: NO OPTIONAL CAPTURING GROUPS
--------------------------------------------------------------

`_extract_filename_metadata` reads `match.group('fieldID')[0]` to decide
whether to strip zero padding. A group that did not participate returns None
and that subscript raises TypeError, which nothing up the stack catches -- it
would kill the run. A group that matched the empty string raises IndexError,
which IS caught, and silently skips the file. So every optional token in a
real convention (InCell's ` z 3 time 2 - 2636ms`, Harmony's `rc1`,
MetaXpress's GUID) is either matched-and-discarded or captured into a group
nothing reads. Tested per example, per record.

THE TRAP THE NEXT PERSON WILL WALK INTO
---------------------------------------

`spacr.qt.widgets.preview_controls._get_regex_callable` LIFTS `_get_regex`
ALONE out of utils.py with `ast` and execs it in an EMPTY NAMESPACE, so that
a dropdown does not pay the 3.2 s and 900 MB of `import spacr.utils`. That is
why the table lives in `spacr.regex_infer` (stdlib only) and why `_get_regex`
imports it ABSOLUTELY, inside its own body. A module-level constant or a
relative import would raise in that namespace, be swallowed by the caller's
`except Exception`, and the previews would quietly stop grouping files.
Measured after the change: 9 ms, 47 MB, and `spacr.utils` stays out of
sys.modules.

THE UI
------

`spacr.qt.screens.settings_model._MetadataTypeField` replaces the plain combo
on the metadata_type row:

  * vendor headings in the menu, disabled and unselectable, so it can be
    scanned by the name on the microscope; the stored value is still the key;
  * the chosen convention's own example filename under the menu, with
    "reconstructed from real files ... not from vendor documentation" beside
    a provisional one;
  * "Test on my folder" -- counts how many image names in `src` parse and
    names the FIRST that does not, sorted so two machines give the same
    answer. Reads `orig/` when spaCR has already set the originals aside;
  * "Which convention fits?" -- ranks every convention over the same folder,
    best first, and CHANGES NOTHING. `auto` and `custom` are excluded: one
    renames before it parses and the other parses whatever was last typed.

Both run on a QThread. The thread is held in a module-level set rather than
parented to the widget, because switching away from Mask mid-scan would
otherwise have Qt delete a RUNNING QThread; the readout slot is connected to
the widget as usual and Qt drops it silently if the widget has gone.
