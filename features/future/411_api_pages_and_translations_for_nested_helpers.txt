3. RENDERING -- WHY NESTED HELPERS HAVE NO PAGE TODAY, AND WHAT MUST CHANGE
================================================================================

3.1 THE ROOT CAUSE IS AUTOAPI'S PARSER, NOT A SETTING.
  * Pages come from sphinx-autoapi (docs/source/conf.py:66; 3.8.0 locally, and
    CI installs it unpinned, docs.yml:134).
  * `autoapi/_parser.py` `parse_functiondef` (~273-344) returns a function with
    no `children`. The only place it looks inside a body is `__init__`, for
    `self.` assignments. NO option, skip hook or template edit alone makes a
    nested def appear, because AutoAPI never parsed it.
  * `autoapi_options` (conf.py:105-109) is members, show-inheritance,
    show-module-summary. The skip hook `_skip_implementation_data`
    (conf.py:243-253) only hides lowercase data/attribute members.
  * The repo's own templates are docs/source/_autoapi_templates/python/module.rst
    and package.rst. `function.rst` and `method.rst` are AutoAPI's defaults,
    which have no child loop.
  * Functions are not own-page types (module.rst:136-158): a function is an
    anchor on api/spacr/<module>/index. A nested helper should be an anchor on
    the SAME page, inside or directly under its parent's entry.

3.2 PRIVATE NAMES. AutoAPI hides "_" names without `private-members`, and
  turning that on globally would publish every private TOP-LEVEL function as
  well, which nobody asked for. The helpers must come from your own inventory
  (3.3) and be emitted by your template, so the private-member rule for
  top-level objects stays exactly as it is.

3.3 A DESIGN THAT FITS THE EXISTING MACHINERY (a proposal, not a decree; if
  you find a better one, write why here before building it):
  * ONE SOURCE-DERIVED INVENTORY: an ast walk yielding
    (parent_id, helper_name, qualified_key, signature, docstring, lineno) for
    every nested def with a docstring. Keys are `spacr.mod.outer.inner`, and
    `spacr.mod.Class.method.inner` for helpers inside methods. Put it where
    both conf.py and the extractor can import it without importing spacr, so
    the docs build stays import-free: e.g. a module under tools/, or a small
    standalone file under docs/source/.
  * THE SLICE SWITCH: one committed list of modules whose helpers render,
    read by BOTH conf.py and tools/build_documentation_i18n.py. Add a test
    that the two see the same list, the way
    tests/test_api_i18n_extractor.py:1150-1172 pins AUTOAPI_IGNORE against
    conf.py's `autoapi_ignore`. A module in the list renders AND is extracted;
    one not in it does neither. Rendering and translation can never disagree
    about what exists.
  * THE TEMPLATE: hand the inventory to the Jinja environment (AutoAPI's
    `autoapi_prepare_jinja_env` hook in conf.py) and override
    python/function.rst and python/method.rst to emit a `.. py:function::`
    per helper under the parent. Only modules in the slice list emit.
  * ANCHORS MUST EQUAL KEYS. Sphinx's Python domain does not prefix a nested
    py:function with its parent function's name (only classes push a prefix).
    Emit the qualified name explicitly, then check it in the BUILT site
    (objects.inv, or the HTML ids) against the extractor keys. Write that
    check as a test that runs under SPACR_DOCS_BUILT=1, next to
    tests/test_tooltip_api_links_resolve.py.
  * DUPLICATES: the same helper name defined twice under one parent (in
    if/else branches, or redefined) gives two identical anchors. docs.yml:171
    builds with `-W`, so a duplicate object description FAILS the docs job.
    Decide a rule, e.g. the first definition renders and later ones are listed
    under it, or a `-2` suffix. Record it here and pin it with a test that
    uses a real duplicate from spacr/ if one exists.
  * THE BROWSER-SIDE LANGUAGE SWITCH finds a symbol's DOM node from its key
    (tests/test_api_i18n_frontend.py, `REAL_SYMBOL_COUNT` at :74, used at 555,
    585, 589, 665). Confirm that a nested key resolves to the nested anchor
    and not to its parent, with a real catalog, before slice 1 lands.

4. THE TRANSLATION EXTRACTOR -- WHAT MUST CHANGE
================================================================================

  * `public_docstrings()` (tools/build_documentation_i18n.py ~4071-4147) walks
    spacr/**/*.py with ast. It never enters a function body:
    `_module_scope_nodes` (~3925-3943) descends only into If/Try/With/Match,
    and classes get one level of methods (~4121-4131).
  * `_is_visible_function_name` (~3987-4000) drops "_" names apart from
    dunders. For helpers from the inventory in slice-listed modules, "_" names
    are INCLUDED (decision 5); for top-level names the rule is unchanged.
  * Keys today are `f"{module}.{node.name}"` (~4110) and
    `f"{key}.{child.name}"` (~4127). Nested keys must be the inventory's
    qualified keys, identical to the rendered anchors.
  * Blocks: `translatable_blocks()` (~4185); the field-line regex (~3823);
    `_split_long` at 1,000 characters (~4150). Field lists become their own
    blocks, so a label's `#n` counts BLOCKS, not paragraphs
    (tools/write_reviewed_api_record.py:30-33).

5.1 TOOLS

    --label <symbol>#<n>; exactly one of --translation / --translation-file;
    --name (the record file, default `hand-written`; use e.g.

  * Record layout (e.g. docs/i18n/reviewed/api/fr/2026-08-14-current-final-000-019.json):
      {"schema": 1, "language": "fr", "records": [{"label": "spacr.align.save_coordinates#4",
       "source_sha256": ..., "source": ..., "context": ..., "translation": ...}]}
  * tools/check_reviewed_api_evidence.py (main ~38-86): reports MOVED (re-bind
    the label) and STALE (retire with "retired" + "retired_reason"), and exits
    1 on either. IT SILENTLY SKIPS a record whose symbol is not in
    `public_docstrings()` (~54-55). A record written BEFORE the extractor emits
    its key is never checked, so write records only after the slice's keys
    exist.
  * `python tools/build_documentation_i18n.py --audit` is the gate; see 6.
  * Rebuilding a catalog: `--repair-api-blocks`, ONE LOCALE AT A TIME. All
    nine at once ran out of CUDA memory (comment at
    tests/test_documentation_i18n.py ~2807-2813).

5.2 TRAPS, EACH MEASURED ON THIS REPO
  1. A PLAIN API BUILD RE-DECODES UNCHANGED PARAGRAPHS of any symbol whose
     source changed. Use the no-generation repair path; generation raises by
     design. Diff the catalog after every build: a slice may change its own
     blocks and nothing else.
  2. A PLAIN BUILD ONCE IGNORED REVIEWED RECORDS entirely (fixed in
     b8666d24d, item 410). After a build, confirm your reviewed text is in the
     catalog; don't assume it.
  3. REVIEWED RECORDS ARE KEYED BY SOURCE TEXT, NOT BY SYMBOL. A record for a
     shared line such as ":param shape: ..." lands on EVERY symbol carrying
     that exact English. A French record meant for one function changed
     "touches" to "clés" in another (item 406). Before authoring, search en.json
     for the exact source text and read every symbol it will land on. Helpers
     repeat their parents' :param: lines constantly, so this will happen often.
  4. `_contextualize` REWRITES A REVIEWED TARGET, then the closing audit
     rejects the rewrite and English ships. Portuguese "poço" became "bem" in
     spacr.qt.widgets.outlier_model #27; Spanish ops_objects #7 did the same.
     When the audit rejects a reviewed block, restore the committed entry. Don't
     loosen the audit (item 406 records the defect).
  5. `--sources-only` REWRITES en.json. A repair after it must still reuse
     unchanged blocks; the fix is on nightly since 3f27b926a. Confirm your base
     has it.
  6. MACHINE DRAFTS ARE MOSTLY WRONG ON API TEXT. 615 of 788 API blocks (78%)
     from the 2026-09-15 GPU repair were bad: inserted parliamentary
     transcripts, "beef" for a digest, inverted negations. Draft however you
     like, then read EVERY block against its English before it becomes a
     record. Identifiers, parameter names, code literals, units and negations
     are where the drafts failed; check those first.
  7. ICELANDIC (is) AND HINDI (hi) HAVE NO NATIVE PROOFREADER YET. Write them
     to the same standard, but never label them native-reviewed. The maintainer
     holds that proofread.
  8. A DOCSTRING EDIT IN spacr/ MOVES THE CATALOGS: the hash test goes stale
     and all nine languages owe the changed block. If a helper's docstring is
     WRONG, fix it in its own commit, before its slice, and say so. Never edit
     a docstring to make a translation easier.
