ON 551'S SEAM. Omnipose adds a spec and a worker adapter to item 551's

  spacr/_segmentation_backends.py
    _OMNIPOSE, _OMNIPOSE_MODELS (bact_phase_omni, bact_fluor_omni,
      worm_omni, worm_bact_omni, worm_high_res_omni, cyto2_omni -- the 2-D
      boundary-field models of omnipose.core; plant_omni is 3-D and left
      out).
    The spec: omnipose==1.1.4 plus ncolor==1.5.3, torch + torchvision from
      the installer's index, Python 3.11-3.13 (ncolor and colour-science
      need 3.11), prefix "omnipose:", default bact_phase_omni, alpha.
      WHY ncolor IS PINNED: the first real install built the environment and
      then failed its self-test -- omnipose 1.1.4's misc.py does
      `from ncolor import unique_nonzero`, which ncolor 2.x (June 2026 on)
      no longer has; 1.5.3 is the last release that does. The installer
      removed the half-built environment, as it should; the second install,
      with the pin, passed.
    _worker_env: CELLPOSE_LOCAL_MODELS_PATH inside the env (models/), where
      cellpose_omni downloads bact_phase_omnitorch_0 etc.
    _OmniposeAdapter: a named model is built as Omnipose builds it
      (CellposeModel(model_type=...)); a checkpoint path gets its input
      channels and output classes read from the weights (_omnipose_shape),
      because Omnipose would otherwise build its default network and fail
      to load them; a missing path is refused (Omnipose would run cyto).
      eval: the object plane as one grey channel (channels [0, 0]),
      omni=True, Omnipose's percentile normalisation, rescale None (its
      bacterial models run at the image's own scale, so diameter is named
      "cannot honour"), flow_threshold -> flow_threshold, cellprob_threshold
      -> mask_threshold (both logits, as in Cellpose), resample -> resample.
      It returns masks and Cellpose's flows layout: RGB flow, dP and, where
      Cellpose has the cell probability, Omnipose's distance field -- so the
      Live preview's Flows and Cell probability views fill.

2026-10-02 — CURRENT-SOURCE ACCEPTANCE AND PYTHON RANGE REPAIR
    A fresh installer run on spaCR's Python 3.13 reproduced a real dependency
    failure: aicsimageio requires lxml<5, and lxml 4.9.4 cannot build against
    Python 3.13. The Omnipose spec now selects Python 3.11–3.12 rather than
    advertising 3.13. With Python 3.12.14 discovered on PATH, the normal
    isolated installer completed in 49.5 s; its self-test loaded Omnipose
    1.1.4 and CPU torch 2.14.1. Fifty-two focused backend tests pass.

    The bacteria-only benchmark no longer demands unrelated Toxoplasma model
    files from a missing mount. It ran all seven pinned upstream fields, 621
    saved reference objects, under a 4 GiB memory cap, zero swap, CPU1 and
    hidden CUDA. At IoU 0.5, Omnipose bact_phase_omni scored pooled F1 0.952,
    Cellpose 3 cyto3 scored 0.953 and cyto2 scored 0.573. At IoU 0.75 the
    corresponding scores were 0.927, 0.937 and 0.518. Omnipose mean matched
    IoU was 0.920 versus cyto3's 0.883. All 14 upstream input hashes remained
    unchanged. Receipt: features/data/553_omnipose_cpu_acceptance_2026-10-02.json.

    The reference masks are upstream Omnipose outputs, not independent hand
    labels. These numbers establish real execution and comparison, not an
    unbiased accuracy advantage. The stated DONE WHEN is met for the requested
    2-D bacteria model. GPU, 3-D plant, and broader model comparisons in the
    earlier NOT DONE list remain future extensions of this alpha backend.
