    "Also add to future features list the items in the non GPU list that would be valuable!"

EVIDENCE
    No image.sc thread; from general practice.

WHAT TO BUILD
    Link plates to sample metadata (strain, compound, concentration,
    passage, operator) by plate barcode from a CSV or a LIMS API, filling
    spaCR's plate maps automatically and checking for mismatches.

DONE WHEN
    A plate imported with a barcode gets its plate map filled from the CSV;
    a mismatch is reported.

ALPHA: 2026-09-27
    Measure > "Plate Barcode Linkage (Alpha)", ALPHA_FEATURES[583]: four
    settings, hidden unless Preferences -> Show alpha features is on.
    plate_barcode_source names a records table (CSV/TSV/Excel/Parquet with a
    barcode column, a well column and any metadata columns such as strain,
    compound, concentration, passage, operator) or an http(s) LIMS address
    answering JSON well records per barcode (?barcode=, or {barcode} in the
    address; bearer token from the environment variable named in
    plate_barcode_token_env, never stored). Each imaged plate's barcode comes
    from plate_barcodes, else barcode.txt in the plate folder, else the
    plate name. After measuring, the filled map goes to
    measurements/plate_map_lims.csv and fills a blank profiling_metadata and
    (when compound and concentration exist) a blank viability_plate_map.
    Mismatches go to measurements/plate_barcode_mismatches.csv and the log:
    barcode_not_found, barcode_shared, well_not_in_lims, well_not_imaged,
    unreadable_well, conflicting_records, and plate_map_differs (a user's
    own plate map disagreeing with the records). An unreachable LIMS is
    reported and the run goes on.
    Code: spacr/plate_qc.py (_link_plate_barcodes and helpers),
    spacr/measure.py (_run_plate_barcode_step). Tests:
    tests/test_plate_barcode_linkage.py (local CSV, fake fetcher, a LIMS
    stand-in on 127.0.0.1), tests/qt/test_plate_barcode_alpha_gate.py.
    CPU only; no real LIMS contacted.

LEFT
    No vendor-specific LIMS adapters (Benchling, LabKey, etc.). Barcodes are not read
    from image metadata or plate-reader files; the linkage runs from
    Measure only, not at import (convert) time, and there is no Qt
    plate-map view of the mismatches.

2026-10-02 — CONVERT-TIME LOCAL CSV LINKAGE (partial)
    The existing convert_folder settings entry, including spacr-run convert
    and notebook calls, now accepts an opt-in plate_barcode_source CSV with
    plate_barcodes explicitly mapping every OUTPUT plate ID to its barcode.
    plate_barcode_column selects the identifier column. Blank source preserves
    ordinary conversion. Source plate-folder names are not guessed as barcodes.
    CSV identifier text such as 00123 is retained without numeric coercion.

    Example: spacr-run convert --set src=/data/raw --set dst=/data/converted
    --set plate_barcode_source=/data/samples.csv
    --set 'plate_barcodes={"plate1":"BC001"}'
    Preview-only mode validates the linkage but writes nothing. Bad local CSV
    configuration, incomplete output-plate assignments, an existing bundle or
    an unsafe output path is refused before image conversion writes anything.
    The destination must be separate from the source tree, and source/user-map
    inputs must stay outside the destination. Metadata inputs are capped at
    16 MiB each. This path does not contact a LIMS service.

    After a complete conversion, actual converted/existing mapping rows supply
    the imported well identities to the same private join used by Measure.
    A NEW dst/plate_barcode_linkage directory contains plate_map_lims.csv and
    plate_barcode_mismatches.csv. complete.json is published atomically LAST
    and binds the input/map/output SHA256 values, explicit barcode assignments,
    file/well counts and mismatch count. This is a completion-marked bundle,
    not an atomic directory rename. A consumer must require complete.json.
    Prior bundles are never overwritten, including late publication collisions.
    Cancellation or write failure removes only this run's owned bundle files;
    converted images remain available. Incomplete conversion or changed input
    metadata produces no successful linkage bundle. Existing profiling_metadata
    and viability_plate_map files are checked read-only; settings are unchanged.

    The same existing mismatch policy applies: absent/shared barcodes, missing
    wells, unreadable well IDs, conflicting records and user-map differences
    are reported. Conflicting records retain the first record with an explicit
    diagnostic, as Measure already does. A mismatch report is not a claim that
    the sample identity is biologically verified.

    This closes the CLI/notebook import-time CSV slice only. Convert's custom
    Qt screen does not yet expose these controls; automatic barcode extraction
    from acquisition metadata, vendor LIMS adapters and a Qt mismatch view
    remain open. F583 stays partial/alpha.

    Validation: 67 named CPU checks passed in 6.26 seconds, including a real
    CLI settings-file conversion, TIFF pixel/source-byte preservation, metadata
    mismatch reports, leading-zero barcodes, preview/no-opt-in compatibility,
    malformed input preflight, existing and late bundle collisions, incomplete
    conversion, input changes, cancellation after a CSV write, final receipt
