WHAT TO BUILD
    When exporting image figures and montages, warn when panels meant for
    comparison use different display ranges, when pixels are saturated, when
    a lossy format is chosen for quantitative images, and stamp provenance
    (source files, display settings, processing steps, spaCR version) into

NOTE 2026-09-26 -- BUILT, AS AN ALPHA FEATURE

What was built (no new module; all in spacr/plot.py as private helpers)
    save_figure(..., integrity=None) runs the check before writing when it
      is switched on: integrity=True/False decides, else the environment
      variable SPACR_FIGURE_INTEGRITY=1/0, else the Preferences toggle
      (off by default). A figure with no image panel (AxesImage of at
      least 16x16 px) is written exactly as before, with no sidecar.
    Checks, per figure (_integrity_report):
      display_range -- panels in one comparison group whose low or high
        display limits spread by more than 5 % of the combined range. Group
        = an explicit compare name, else the channel label of a traced
        panel, else (untagged single-channel panels of >= 64x64 px) the
        colour map. Untagged RGB panels have their range baked in and are
        not compared.
      saturation -- warning when > 0.1 % of source pixels sit at the
        integer type's ceiling (detector saturation), or > 5 % are above
        the top of the display range (clipped). On an untagged RGB panel
        the clip measure cannot tell saturation from annotation colours, so
        it is a note there.
      duplicate -- identical displayed arrays, or thumbnails (32x32)
        correlating >= 0.97 AND 96x96 high-pass texture >= 0.2, both at the
        best of the eight flips/rotations; invariant to linear contrast.
        Same-source panels are reported as a note (declared reuse).
      lossy_format -- JPEG/WebP/GIF/HEIC/AVIF written (warning) or asked for
        and redirected to PNG/PDF (note).
      resampling -- note when a panel is written with fewer than half its
        pixels per side.
    Provenance: every panel's shape, dtype, cmap, clim, interpolation,
      display range (source units when traced), clip/saturation fractions,
      SHA-256 of the displayed array, source files (path, size, full
      SHA-256 up to 256 MiB), processing steps, and figure-level spaCR /
      matplotlib / numpy / python versions, format, DPI and the open
      run_journal run (dir, app, manifest.json path). Stamped into the
      file: PNG text chunk "spaCR provenance", PDF Subject. Written to
      <figure>.provenance.json with the written file's SHA-256. Warnings
      are printed and recorded on the open run (Run.record_warning); the
      sidecar is recorded with Run.record_output.
    Tracing: _tag_panel(artist, source, steps, display_range, channel,
      compare, raw) attaches provenance to an imshow artist. plot_image_grid
      now tags every tile (source PNG, per-channel percentile range, steps
      rescale + to_uint8), using one shared stretch helper so the figure and
      the replay run the same arithmetic. _reproduce_panel(sidecar, n)
      rebuilds a panel from its source file and says whether it is
      bit-identical to what was exported.
    The Save figure dialog (qt/widgets/save_figure_dialog.py) runs the same
      check and stamp on matplotlib figures it writes. The cell-montage
      save and every pipeline figure already go through save_figure.

2026-10-01 — METADATA-BACKED CAMERA BIT DEPTH IN MONTAGE EXPORTS
plot_image_grid reads the already-open TIFF's OME ImageDescription metadata
alongside the source pixels. For a uniquely mapped current-file/current-IFD
Pixels element, validated SignificantBits supplies the detector ceiling:
12-bit data stored as uint16 is checked at 4095; 14-bit at 16383. Source
shape and unsigned storage type must agree, and actual pixels must not exceed
the declared ceiling. No bit depth is inferred from the observed maximum.
The selected Pixels ID, IFD, significant bits, ceiling and metadata source
are recorded in panel provenance; the saturation warning names that ceiling.

The metadata parser is bounded to 1 MiB, rejects XML entity declarations,
and does not read another pixel plane or fetch external files. TiffData
mappings are checked for current-file UUID, unique IFD membership, dimension
order and coordinate bounds. Explicit IFD without PlaneCount means one plane.
When both IFD and PlaneCount are absent, the specification's default requires
the actual file IFD count; this implementation records a dtype fallback
instead of enumerating an unbounded image sequence. Mixed SamplesPerPixel
and nonzero packed-channel origins also fall back rather than guessing RGB
channel boundaries. Absent, malformed, ambiguous or contradictory metadata
keeps the prior storage-type ceiling with its reason recorded in provenance.
Ordinary exports and existing warning thresholds/counts are preserved.

Validation: all 40 new and existing figure-integrity checks passed on the
final implementation under 4 GiB, one actual CPU, zero swap and no GPU.
Actual 12/14-bit OME-TIFF -> montage -> checked PNG/sidecar exports each
produce the expected single saturation warning, retain source array/file
hashes, and replay the displayed panel exactly. Real multi-series input and
reordered IFD mappings bind to the displayed series. Tests cover UUID scope,
range/shape/type contradictions, metadata bounds/entity refusal and valid
unannotated 12-bit-valued images that must not be guessed as saturated.
All 74 existing public signature/docstring entries and the module docstring
remain unchanged. No new Qt captions or dependencies are introduced.

Primary specification checked during implementation:
https://www.openmicroscopy.org/Schemas/Documentation/Generated/OME-2016-06/ome_xsd.html
https://docs.openmicroscopy.org/ome-model/6.2.2/ome-tiff/specification.html

This is a bounded partial completion. Untraced image sites, cross-figure/
region reuse, heavy-noise repeats, splice detection and a GUI warning dialog
remain open as listed above. Camera metadata absent from source crops cannot
be reconstructed from pixel values alone.

2026-10-02 — EXACT CROSS-FIGURE REUSE IN AN OUTPUT FOLDER
Checked figure exports now compare panel byte digests with the 64 newest
small, regular provenance sidecars beside the destination. A repeated panel
in a prior figure produces a warning naming that figure and panel; declared
same-source reuse is a note. The earlier figure's file hash must still match
its sidecar before it can be used as evidence, so an overwritten/stale figure
cannot create a false repeat. The same check runs through save_figure and the
Matplotlib Save figure dialog. It scans metadata only and hashes a prior
figure only after its panel digest matches; source images are not loaded.
All 35 focused figure-integrity, alpha-gate and save-dialog tests passed
under a 2 GiB hard cap, one CPU, zero swap and offscreen Qt. Receipt:
features/data/572_cross_figure_exact_reuse_2026-10-02.json.
This is partial: approximate or region reuse across figures, untraced
panels, splice detection and GUI warning presentation remain open.
