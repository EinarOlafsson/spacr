================================================================================
A LIVE MAGNIFIER IN MAKE MASKS THAT SEGMENTS WHAT IS UNDER THE MOUSE
================================================================================

Status:    FUTURE, filed 2026-09-15. Not started. Not blocking.
Requested: 2026-09-15, by the maintainer, in these words: "if the user flips
           this on, then a box appears with the region around the mouse
           slightly magnified, and in this region the square enhanced region
           is passed through some lightweight model (there should be options)
           and a mask for the objects in that region are shown live. if the
           user clicks on the image the objects in the enhanced region are
           saved on the image, so when the user toggles this feature off, or
           clicks save, etc., the objects are in the mask for that image."
Owner:     unassigned. `spacr/qt/screens/make_masks.py` (the screen),
           `spacr/qt/mask_engine.py` (pure-Python mask editing and
           persistence), and a new inference seam for the model.

--------------------------------------------------------------------------------
WHAT IS WANTED
--------------------------------------------------------------------------------

A toggle on the Make Masks editor. While it is on:

  1. A square box follows the mouse over the image and shows the region
     around the cursor, slightly MAGNIFIED.
  2. That region -- the enhanced crop, not the whole image -- is passed
     through a LIGHTWEIGHT segmentation model, and the objects it finds are
     drawn over the box LIVE, as the mouse moves.
  3. A CLICK commits the objects currently shown in the box into the
     image's mask. They stay there when the toggle goes off, when the user
     saves, when the user moves to the next field -- they are ordinary mask
     objects from that moment on, editable and erasable like any other.

Settings the maintainer asked for, by name:

    mode          which lightweight model runs on the region ("there should
                  be options")
    size          the diameter, in image pixels, of the region of interest
    zoom          the magnification -- and the MOUSE WHEEL CHANGES IT LIVE
                  while the feature is on
    sensitivity   the model's acceptance threshold, "like cellpose cell
                  probability score"

--------------------------------------------------------------------------------
WHY
--------------------------------------------------------------------------------

Curation is where mask quality is actually decided, and today a missed
object means drawing it by hand. This turns "the model missed three cells in
the corner" into three clicks, with the model working at a magnification
where small or dim objects are visible, and with the user choosing exactly
which objects to accept. It is also the natural front end for the
curation queue in 396: fields come from the queue, and missed objects are
added here rather than by a full re-run.

--------------------------------------------------------------------------------
DESIGN NOTES -- NOT DECISIONS
--------------------------------------------------------------------------------

THE MODEL NEVER RUNS ON THE GUI THREAD. HANDOFF and 284 are unambiguous that
a module screen must stay responsive; a model call on every mouse move is
the fastest possible way to break that. Inference belongs on a worker, with
only the NEWEST request kept -- a mouse that has moved on makes every queued
region stale, so a request superseded before it starts is dropped, not run.

THE REGION IS SMALL, WHICH IS WHAT MAKES "LIVE" POSSIBLE. A 128-256 px crop
is a few milliseconds on a GPU for the models below and tolerable on a CPU.
Throttle to the worker's own pace rather than to a fixed rate, and show the
last completed result with a subtle "updating" mark rather than blanking.

CANDIDATES FOR `mode`, all already adjacent to spaCR:

    Cellpose (cyto / nuclei, the small models)  -- spaCR's existing path;
        `sensitivity` maps directly onto cellprob_threshold
    DINOCell            -- future item 404; predicts Cellpose-style flows, so
                           the same post-processing applies
    SAMCell / MobileSAM -- future item 405; prompt-free on a crop, and a
                           natural fit for a click-to-accept interaction
    classical           -- threshold + watershed, for machines with no model
                           installed; also the fallback when a model import
                           fails, so the feature never simply does nothing

MAGNIFICATION IS FOR THE EYE AND POSSIBLY FOR THE MODEL, AND THOSE ARE TWO
DIFFERENT SETTINGS. Upsampling the crop before inference helps small objects
under models trained at a fixed object diameter; showing it magnified helps
the user see them. `zoom` should control the view; whether the model sees the
zoomed or the native-resolution crop needs measuring, not assuming.

COMMITTING IS A MASK EDIT, AND IT SHOULD GO THROUGH `mask_engine`. New label
ids must not collide with existing ones; an object overlapping an existing
object needs a rule (skip, replace, or clip to background) -- and the rule
should be a visible choice, not a hidden default. One click should be one
undo step.

COORDINATES. The box, the crop, the magnified view and the mask all live in
different coordinate systems; every commit should be tested for an off-by-one
at the crop edge and at the image border, where the region is clipped.

--------------------------------------------------------------------------------
OPEN QUESTIONS FOR THE MAINTAINER
--------------------------------------------------------------------------------

  * Which models must `mode` offer on day one, and which can wait?
  * On a click, commit ALL objects in the box, or only the object under the
    cursor? (The request says all; the second is a cheap addition.)
  * Overlap with an existing object: skip, replace, or clip?

--------------------------------------------------------------------------------
HOW TO KNOW IT WORKED
--------------------------------------------------------------------------------

  * With the toggle on, moving the mouse never drops the Make Masks screen
    below its responsiveness budget (the harness from 380 measures it).
  * Clicking commits exactly the objects drawn in the box, at the right
    pixels, including a box clipped by the image border -- a test with a
    synthetic image and a stub model that returns known labels.
  * The committed objects survive toggling off, saving, and reopening the
    field.
  * Removing every model leaves the classical mode working, rather than a
    feature that silently does nothing.

--------------------------------------------------------------------------------
2026-09-14 -- A FIRST VERSION EXISTS, ON BRANCH wip/407-live-magnifier
--------------------------------------------------------------------------------

Commit b9adbacb3, not pushed, not merged. Everything below is what that
branch does and what was measured on it; none of it is on nightly.

WHAT IT DOES

  * A checkable "Magnifier" button in the tool row (beside Cellpose-SAM
    detect) and a "Live magnifier" card on the settings panel: Mode, Size
    (px), Zoom, Sensitivity, Overlap.
  * While on, a box follows the cursor: the region contrast-stretched on its
    own and drawn zoom x the canvas's display scale, with the pixel under
    the cursor kept under the cursor. The last completed result stays drawn
    where ITS region lies; the frame goes dashed with "Updating..." until
    the result for the current region arrives.
  * The wheel changes the magnifier's zoom (at the canvas's Zoom per notch)
    and not the view. Right-button sweep and Shift/Alt pan still work.
  * A click pastes the objects the box outlines into the mask through
    `mask_engine._paste_region_objects`: ids start one past the top id, one
    click is one undo step and one "magnifier" ledger entry. A click on a
    region not yet segmented PINS that request on the worker, so moving on
    cannot supersede it, and its objects go in when it arrives.
  * Committed objects are ordinary mask edits: they survive the toggle going
    off and a save. Moving to the next field without saving still discards
    them, exactly as it discards a brush stroke -- navigation was not changed.

DECISIONS TAKEN FOR THE FIRST VERSION -- THE OPEN QUESTIONS ABOVE STILL STAND

  * Modes on day one: classical and Cellpose. Classical is Otsu when the
    region is two clear populations and a noise floor (median + 4 robust
    deviations, after sigma-1 smoothing) otherwise, then a watershed; it is
    also what runs, with a status-line note, whenever a model cannot load.
    Cellpose uses the Cellpose-SAM card's model and diameter. Adding
    DINOCell or SAMCell is one function in `_MAGNIFIER_SEGMENTERS`.
  * A click commits ALL objects the box outlines. Objects touching an edge of
    the box that lies inside the image are not offered (the recrop rule: an
    object cut by the box is not that object); objects at the image border
    are.
  * Overlap is a visible choice, default Clip (keep only unlabelled pixels,
    largest piece). Skip and Replace are the other two.
  * Sensitivity reads the way the word does: higher accepts more. For
    Cellpose it is cellprob_threshold with the sign reversed.
  * Defaults: size 128 (32-512), zoom 2.0 (1-8), sensitivity 0 (-6..6).
    Nothing persists between sessions, like every other setting on the panel.
  * Zoom is for the eye only; the model sees the native-resolution crop.
    Whether upsampling helps a model was NOT measured.

EVIDENCE

  * tests/qt/test_the_live_magnifier_segments_under_the_mouse.py, 21 passed:
    exact pixels from a stub model that reads its position from coded pixel
    values, both image corners, id collision and uint8->uint16 widening, clip
    and skip on the screen and all three rules at the engine, one undo per
    click, toggle-off/save/next/prev, newest-only and pinned requests, a
    click that waits for its result, the model never on the GUI thread (26
    moves against a 1 s model, slowest move well under 0.5 s, 2-3 model calls
    instead of 26), classical with Cellpose removed from sys.modules, the
    fallback note, wheel, lens geometry and the drawn frame.
  * Existing Make Masks suites: 533 passed, 1 failed -- the catalog-row test
    below. Docstring, API-symbol and module-coverage ratchets unchanged: no
    new public symbol, no new module.
  * Classical, synthetic 128 px regions, 5 seeds each: noise and a noise +
    gradient background 0 objects at sensitivity -2/0/+2; three disks at
    amplitude 3000/600/300 over noise 150 found 3/3; 36 confluent disks
    36/36; two touching disks 2/2; dark objects 3/3. At amplitude 150 (SNR 1)
    sensitivity 0 finds 0-1 and +2 finds 4-6 fragments. ~3 ms per 128 px
    region, 41 ms for 512 px.
  * Cellpose (cpsam 4.2.1.1) on CPU only, machine shared with other runs:
    load 5.4 s, one 128 px region 51-62 s, one 256 px region ~195 s, 3/3
    objects. On CPU the Cellpose mode is NOT live; it needs a GPU.

--------------------------------------------------------------------------------
2026-09-15 -- THE MAINTAINER'S ANSWER ON CLICK BEHAVIOUR, AND A NEW MODE
--------------------------------------------------------------------------------

Asked with the question tool whether a click should add every object the box
outlines, only the object under the cursor, or both with a modifier. Answer,
verbatim:

  "All the objects in the magnified box get added with the option to exclude
  objects touching the border that may not be completely in the area and with
  an additional mode that generates object on the entire image once then the
  user goes over with the mag box and clicks objects that are to be added and
  rich clicks to remove"

WHAT THAT ASKS FOR:
  1. Keep: a click adds ALL the objects outlined in the magnified box.
  2. An OPTION (a visible setting on the Live magnifier card) to exclude
     objects that touch the box's border, because they may not be completely
     inside the area. Today this exclusion is always on for the box's inner
     edge; it becomes the user's choice.
  3. An ADDITIONAL MODE: segment the ENTIRE image once; then the magnifier box
     shows those precomputed objects as the user moves over the image; a
     left-click ADDS the object(s) clicked, a right-click REMOVES the clicked
     object from the mask.
