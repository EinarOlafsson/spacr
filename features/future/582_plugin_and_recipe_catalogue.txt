A PLUGIN AND RECIPE CATALOGUE BROWSER

Status: IMPLEMENTED AS ALPHA 2026-09-27.
Owner: unassigned. From the 2026-09-26 non-GPU list. Ships as an ALPHA feature (features/README.md, item 569): hidden unless Preferences -> Show alpha features is on.

REQUEST (the maintainer, 2026-09-26, verbatim)
    "Also add to future features list the items in the non GPU list that would be valuable!"

EVIDENCE
    No image.sc thread; from general practice.

WHAT TO BUILD
    Browse, install and update community plugins and assay templates
    (recipes) from a catalogue, napari-hub style, built on spaCR's plugin
    SDK, with versions, authors and licences shown and installs isolated
    where plugins need their own dependencies.

DONE WHEN
    A test catalogue lists plugins and recipes; one installs, loads and
    uninstalls cleanly.

ALPHA: 2026-09-27. The Preferences "Plugins" tab is built only with Show alpha
features on (ALPHA_FEATURES[582]: PluginCatalogueHelp, PluginCatalogueSource,
PluginCatalogueLoad, PluginCatalogueTable, PluginCatalogueInstall,
PluginCatalogueUninstall, PluginCatalogueStatus). The command line and the
plugin loader never consult the gate: a catalogue plugin installed while the
tab is hidden still loads.

WHAT WAS BUILT (2026-09-27)
    spacr/plugins.py (private helpers):
      _read_catalogue / _catalogue_rows - a catalogue is JSON ("plugins" and
        "recipes" lists; key, name, version, author, licence, summary,
        homepage, source, entry, api_version, requirements, app, settings,
        sha256), read from a file, its folder or an http(s) address, or
        $SPACR_PLUGIN_CATALOGUE. Rows carry installed version and status
        (available / installed / update available / incompatible SDK).
      _install_from_catalogue - a plugin is pip-installed --no-deps into
        its own folder under ~/.spacr/plugins/site/<key> ($SPACR_PLUGIN_HOME),
        its declared requirements into the same folder; the folder is appended
        to sys.path, so spaCR's own packages always win and are never upgraded.
        Installed into a staging folder, loaded and validated there, then
        swapped in: a failed install or update keeps the previous version.
        Local catalogues install offline (--no-index --find-links). Optional
        sha256 is checked. A recipe is written to recipes/<key>.json, a file
        spacr.cli.load_settings_file and the settings loaders read.
      _uninstall_from_catalogue - removes the folder or file, drops its
        modules from sys.modules and reloads the registry.
      Discovery (_installed_sources) also yields catalogue installs recorded
        in <home>/installed.json.
    spacr-plugins: new catalogue, install <key>, update <key>, uninstall <key>
      commands, with --catalogue and --json.
    Preferences > Plugins tab (alpha): catalogue field, table with type,
      name, version, installed, status, author, licence (summary as tooltip),
      Install or update and Uninstall buttons.
    Tests: tests/test_plugin_catalogue.py (a real wheel built on the spot,
      installed by pip offline, loaded, updated, uninstalled; failed update
      rollback; checksum and SDK refusal; CLI) and
      tests/qt/test_plugin_catalogue_alpha_gate.py.

WHAT IS LEFT
    - Plugins needing conflicting dependency versions still share spaCR's
      interpreter; running such a plugin's apps in a separate environment
      (as _segmentation_backends does) is not built.
    - No hosted community catalogue exists yet; the maintainer has to publish
      one (and decide on signing beyond the optional sha256).
    - Install runs on the GUI thread under a wait cursor; a worker thread with
      progress would be nicer for large plugins.
    - The recipe Open action is implemented; focused runtime verification
      is pending (see the dated note below).

2026-09-27 — INSTALLED RECIPE OPEN ACTION (focused verification passed)
    Preferences > Plugins now offers Open for installed recipes. It reads
    the installed registry's module and settings file, not a newer offered
    catalogue entry. Existing desktop navigation resolves folded modules
    and also accepts installed plugin apps added after the window opened.
    The existing settings loader applies the values without starting a run;
    unreadable settings and unsupported forms report failure in the tab.
    The dialog closes only after settings were applied successfully.

    PluginCatalogueOpen joins ALPHA_FEATURES[582]; the action also checks
    alpha and module maturity visibility. Existing translated captions are
    reused. The new method belongs to a private top-level class, excluded
    from the canonical API inventory; it is not a nested-function helper.

    Evidence: features/data/582_installed_recipe_open_2026-09-27.json.
    Static diff check and all seven catalogue cases passed in the capped
    12-check batch. Built-in and late-installed plugin forms received the
    installed values without a worker. Complete-item acceptance remains open.
    Conflicting dependency isolation, catalogue hosting/signing policy and
    background installation remain open as listed above.
