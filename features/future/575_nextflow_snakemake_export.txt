WHAT TO BUILD
    Turn a run recorded in spaCR's run journal into a Nextflow (and/or
    Snakemake) workflow that runs the same steps per plate/well on an HPC
    cluster or cloud, using spaCR's CLI and the Docker/Apptainer images.

DONE WHEN
    An exported workflow run on a small plate reproduces the GUI run's
    outputs.

ALPHA: 2026-09-27. Run History's "Export workflow…" button (object name
RunHistoryExportWorkflow, ALPHA_FEATURES[575]) is hidden unless
Preferences -> Show alpha features is on. The command line
(spacr-repro <run> --export snakemake|nextflow --out DIR [--plates ...]
[--image ...]) never consults the gate.

WHAT WAS BUILT (2026-09-27)
    spacr/cli_repro.py: _export_workflow writes a recorded run as a
    Snakemake (Snakefile + config.yaml) or Nextflow DSL2 (main.nf +
    nextflow.config with docker, apptainer and slurm profiles) workflow.
    One job per plate: each entry of the run's src becomes
    settings/<plate>.json holding the run's exact settings with src set to
    that plate, run as `spacr-run <module> --settings <file>`. A run with no
    src is one job. The image defaults to the CPU GHCR image of the spaCR
    version that ran. Tests: tests/test_workflow_export.py,
    tests/qt/test_workflow_export_alpha_gate.py.

    VALIDATED with Snakemake 9.27.0 and Nextflow 26.04.6 installed under
    /mnt/firecuda2/codex/scratch-docs/575 (CPU, no container): the
    external_masks smoke plate (packaging/docker/smoke_pipeline.py) was run
    with spacr-run, exported, and re-run by each engine. Every measurement
    table and output file matched the recorded run except run ids,
    timestamps and the key order of the png_channel_mapping dict in the
    settings copy (the journal stores settings key-sorted). A three-plate
    mask export passes `snakemake -n`, `snakemake --lint` and
    `nextflow lint` cleanly.
