WHAT TO BUILD
    A live mode that watches an acquisition folder and runs the chosen
    pipeline (mask, measure, classify) on each new field once the file is
    complete (size stable / companion files present), with a live plate view
    of results filling in during the scan and a resume-safe queue.

DONE WHEN
    Copying a plate's files into the watched folder one by one yields the
    same results as a batch run, with each field processed within a set
    delay of arriving.

ALPHA NOTE (2026-09-26)
    What was built. Make Masks has a watch mode, switched on by the setting
    watch_folder. Its code is in spacr/core.py (_watch_folder_and_analyse,
    reached from preprocess_generate_masks). The user picks the folder
    (src) and a pipeline in watch_pipeline: 'mask' runs Make Masks, and
    'mask_measure' runs Make Masks and then Measure. Measure uses the
    settings file named in watch_measure_settings, or Measure's defaults
    when that is blank.
      - A file is taken once its size and mtime have not changed for
        watch_settle_seconds and it reads whole (TIFFs are decoded in full).
        A field is taken once the number of distinct parsed channels reaches
        the number of entries in `channels`; selected channel identities are
        not yet checked (see the remaining limitation below).
        Fields are grouped by the metadata_type or custom_regex filename
        pattern, and a file whose name has no channel is a field by itself.
        Images already in the folder are analysed first.
      - Each field is copied into src/spacr_watch/fields/<field> (a copy,
        not a hard link, so the pipeline can never write through to the
        acquired files) and analysed there on its own. Its merged stacks are linked into
        src/spacr_watch/merged, and its measurement tables are appended to
        src/spacr_watch/measurements/measurements.db. The append happens
        once per field: the field is recorded in the same transaction, in
        the table spacr_watch_fields.
      - src/spacr_watch/watch_ledger.json records every field: its files
        (size and mtime), when it was first seen, when it went stable, when
        it started and finished, how long it waited and ran, its status and
        any error. The record is written atomically after every change. A
        restart skips fields marked done. A failed field is retried on the
        next start, not within the same session. A field that Stop
        interrupted is analysed again from its images.
      - GUI: progress and errors are printed to the run console
        ("watch_folder: N analysed, N waiting, N failed", one line per field
        with the time it took and how long it waited, and "watch_folder:
        ERROR <field> failed: ..."). The WatchFolderProgress label beside
        Run shows the counts.
      - Stopping: Stop is honoured between fields and while waiting, and
        the record is saved. The run ends by itself after
        watch_idle_minutes without change, when that is above 0.
    Registered as alpha: the settings watch_folder, watch_pipeline,
    watch_measure_settings, watch_settle_seconds, watch_poll_seconds and
    watch_idle_minutes, and the widget WatchFolderProgress.
    DONE WHEN, as measured. The test
    tests/test_watch_folder_and_analyse.py::
    test_files_copied_in_one_by_one_give_the_batch_runs_results runs the
    real preprocessing, merge and Measure; only the Cellpose forward pass is
    stubbed. Three wells x two channels are copied into the watched folder
    one file at a time. The merged arrays and the cell and nucleus
    measurement rows equal those of a batch run with batch_size=1. Each
    field starts within settle + poll (+1 s slack) of its last file
    arriving, plus the run time of the fields queued ahead of it.
    tests/qt/test_watch_folder_alpha_gate.py pins the alpha gate.
    Equality holds against batch_size=1 only. Preprocessing normalises
    intensities by percentiles pooled over each batch, so a batch run with a
    larger batch_size normalises differently. Each field of a watch is a
    batch of one.
    LEFT FOR LATER
      - A live plate view of the results filling in during the scan.
        Today the combined measurements.db is there to open in the
        Database Browser or to point Measure-based tools at.
      - Classify as a watch pipeline step.
      - Timelapse, z_stack and t_stack runs are refused: nothing says when a
        field's last plane or frame has arrived. This needs a companion or
        "acquisition done" marker file, or a planes-per-field setting.
      - Companion-file completeness (for example, waiting for a vendor
        metadata file) is not implemented. Completeness means all channels
        are in and every file is stable and readable.
      - Normalisation pooled across fields (batch_size > 1 parity) would
        need a running or reference-based normalisation.
      - Fields are analysed one at a time on one device. Overlapping a
        field's analysis with the next field's pickup is left for later.
      - Each field folder keeps its copy of the raw images (in orig/ when
        save_original_images is on), so the watch costs about one extra
        copy of the raw data on disk. Reclaiming it after a field succeeds
        is left for later.
      - Selected channel identities are not yet source-aware: the readiness
        check counts distinct parsed channels, not their correspondence to
        `channels`. For example, [0, 3] can become ready on C01 and C02
        before C04 arrives. A source-aware one-/zero-based channel mapping
        is required; the recursive scanner does not guess that convention.
      - The GPU acceptance run on a real acquisition has not been done; all
        tests are CPU-only.

RECURSIVE ACQUISITION FOLLOW-UP (2026-10-02, partial)
    The scanner now follows nested acquisition directories and retains relative
    paths in the resume ledger. Root-level ledger names and scientific field
    keys are unchanged. Each ready field is still copied into its isolated
    work directory using the original basenames; source images are not moved
    or altered. Filename metadata, not folder names, defines a field.

    Channel companions must belong to the same parent directory. A parsed
    field identity appearing in multiple acquisition directories, or repeated
    channel identities including numeric spellings such as C1 and C01, stays
    waiting with an actionable diagnostic. Distinct acquisitions need distinct
    filename field identities; their measurement/output identities cannot be
    safely invented from directory names. Incomplete and unreadable companions
    continue to wait, and a restart skips completed fields. A truncated TIFF
    that tifffile decodes to an empty array (without raising) now explicitly
    remains unreadable; the new acceptance test exposed this existing bug.

    Hidden entries and symbolic links are not followed. Reserved generated
    directories spacr_watch, orig, stack, masks, merged, measurements, results
    and test, plus directories ending in _mask_stack, are excluded at any
    depth to avoid analysing spaCR's own copies and outputs. Those names are
    therefore not available as acquisition subdirectory names.

    This does not establish vendor acquisition-complete semantics, timelapse
    or z-stack completeness, selected-channel identity mapping, or a real GPU
    acquisition acceptance run. F548 remains partial/alpha.

    Validation: 33 unique named CPU cases passed across the initial 31-case
    watcher/microscope cohort and a 12-case affected rerun. The initial run
    exposed the empty-TIFF bug; the affected run passes both root and nested
    incomplete-TIFF cases. Real preprocessing, merging and Measure on the
    synthetic acquisition produce identical arrays and cell/nucleus rows to
    a flat batch_size=1 run; only the Cellpose forward pass is stubbed.
    Both runs used a 4 GiB cap, CPU0, zero swap and hidden CUDA. Public API
    signatures/docstrings and translation captions are unchanged. Receipt:

CONVERT-MAP CHANNEL-POSITION GUARD (2026-10-02, partial)
    A Convert map now must declare the same complete C01..CN channel set for
    every mapped field before the watcher creates output. Convert assigns these
    one-based channel IDs; raw preprocessing sorts present planes and skips
    missing ones, which otherwise compacts a sparse field and shifts selected
    array positions. Sparse IDs and mixed per-field schemas are refused instead
    of being interpreted as a smaller complete acquisition. Separate complete
    acquisitions with different channel sets need separate watch folders.

    Selected channels must be distinct integer zero-based positions within the
    mapped schema. Negative, duplicate, noninteger, empty and out-of-range
    selections are refused. Nonconsecutive valid selections such as [0, 3]
    remain valid when every mapped field declares C01..C04. Every declared
    companion is still required, including intermediate unselected planes, so
    array positions remain attached to their assigned channel IDs.

    This is a source-map-derived guard, not a guess about raw vendor numbering.
    No-map folders retain their existing cardinality readiness behavior. The
    earlier artificial C01/C04 manifest fixture was replaced by a producer-valid
    dense C01..C04 fixture, and an actual Convert output with a sparse second
    field now verifies the refusal path. Previously generated results are not
    rewritten or claimed to have been repaired. F548 remains partial/alpha for
    raw vendor identity/completion, unsupported series and real acquisition
    acceptance. spacr/io.py is unchanged; no new settings, public API changes
    or translatable UI captions were introduced.

    Validation: 38 named CPU cases passed in 19.94 seconds: 17 new channel
    schema cases, 20 existing manifest cases, and the existing no-map real
    preprocessing/Measure one-by-one versus batch_size=1 acceptance. Valid
    four-channel real Convert TIFFs produce the same raw stacked arrays in
    batch and watched-field preprocessing, including selected first/last pixel

VERIFIED READY-TO-COPY HANDOFF (2026-10-02, partial)
    Readiness now tracks device/inode identity and ctime as well as file size
    and mtime, so replacement or rewriting that preserves size/mtime restarts
    the settle interval. A regular filename replaced by a link or nonregular
    entry between discovery and the identity check loses its stale observation.

    Each ready source is copied read-only to private field staging in cancellable
    chunks of at most 1 MiB, with a read ceiling of the observed size plus one
    byte. Descriptor identity is checked against the observed source before
    copying and again afterward; final-component links are rejected, including
    the source-open swap race. Every companion's identity is checked once more
    before analysis begins. If acquired inputs disappear, change or cannot be
    copied as the observed snapshot, only that unanalysed staging is discarded
    and the field waits for new stable observations. Completely vanished fields
    remain reported as incomplete, rather than disappearing from the result.

    Stable staged bytes receive per-file SHA256 values and source identities in
    the field ledger before analysis. Acquisition files are never written by
    this path. Real destination/pipeline failures retain failed status and the
    existing next-start retry policy; cancellation during copying records an
    interrupted field. Normal completed-field resume behavior remains unchanged.

    This guards the observed companions at the handoff. It does not provide a
    vendor acquisition-finished signal or a filesystem lock against writes
    after analysis starts, and does not fix the remaining raw channel-identity,
    z/t completeness or batch-normalisation limitations. Later modifications to
    completed fields retain the existing warning/no-automatic-reanalysis policy.
    F548 remains partial/alpha. No io.py edits, settings additions, public API
    signatures/docstrings or translatable UI captions were introduced.

    Validation: all 77 named CPU cases passed in 47.32 seconds (13 new snapshot
    cases plus the four existing watch, recursive, manifest and channel-schema
    files). Real TIFF tests cover same-size/mtime in-place mutation and inode
    replacement during copying, an earlier companion changing during a later
    copy, deletion, source-link swaps, bounded growth, cancellation, destination
    failure/retry and unchanged top-level/nested pixel/hash provenance. Existing
    real preprocessing/Measure synthetic batch parity still passes with its
    model forward pass stubbed. The run used 4 GiB, CPU0, zero swap and hidden
    CUDA. Receipt:
    features/data/548_verified_snapshot_handoff_2026-10-02.json.

PRETRAINED CV CLASSIFY WATCH STEP (2026-10-04, partial)
    The alpha watch adds watch_pipeline 'mask_measure_classify'. Each ready
    field runs Make Masks, Measure and then Classify (CV) with a previously
    trained model. watch_classify_settings names a saved Classify file with
    training and testing disabled, apply_model_to_dataset enabled and merged
    crops selected. Per-field ML or CV fitting is refused before output is
    created: a model fitted independently on each arriving field would not
    represent one plate-wide classifier.

    The settings file is loaded once and deep-copied per field. Its canonical
    values and the checkpoint's SHA256 bind the populated watch ledger to one
    recipe; changed or missing provenance refuses resume. The checkpoint is
    copied with source identity checks into private watch storage and every
    field uses that immutable copy, even when the original model file or
    settings file changes during the scan. Each field must write CV score and
    class columns into png_list before the existing closed SQLite collection
    checkpoint is captured. The same exactly-once collector appends those
    predictions to spacr_watch/measurements/measurements.db, which is the
    stable table a later live plate view can read.

    The Make Masks watch-pipeline picker exposes the Classify choice. A field
    whose prediction columns exist but contain no scored objects is rejected
    before collection, rather than being reported as classified. Focused GUI
    and recipe regressions cover both conditions.

    Ten focused tests passed, including a real preprocessing and Measure
    comparison against a batch_size=1 plate run. Only Cellpose's forward pass
    and the CV model forward pass are deterministic stand-ins in that test;
    the Classify dispatch, SQLite prediction columns and watch collection are
    exercised. This is not a GPU or real checkpoint acceptance result. The
    existing vendor completion, unsupported series and pooled normalisation
    work remains open.

POOLED NORMALISATION LATENCY LIMIT (2026-10-05, still open)
    Current Make Masks groups sorted stack fields in batches of batch_size
    after optional random shuffling. _normalize_img_batch pools every nonzero
    pixel of each selected channel across the entire batch, computes lower
    and upper percentiles, then scales each field with those shared values.
    A live field cannot know those percentiles until its future batch mates
    arrive. The existing watch analyses each field after settle plus poll;
    a fixed Convert map describes fields but does not bound when they arrive.

    Executing the actual _normalize_img_batch on a 16x16 ramp (values 1..256)
    gives 0.4979575 for the first field's pixel 128 alone. If its later batch
    mate has values 1001..1256, that same pixel becomes 0.0945924 under the
    two-field pooled percentiles. The first-field acquisition history is
    identical through its pickup deadline in both cases. Therefore an
    open-ended watch cannot publish an immutable result by that deadline and
    also equal every possible legacy batch_size>1 run. Randomized batch order
    and padding of unlike field shapes add further parity constraints.

    A future opt-in reference-calibrated mode could apply one precomputed,
    hash-bound per-channel intensity range to both batch and watch, giving
    prompt deterministic normalisation parity under that new recipe. It must
    be named as different from legacy pooled-percentile output. An opt-in
    full batch-window mode could retain legacy pooling with deterministic
    field order, but its first field may wait arbitrarily long for later
    fields. A timeout that releases a partial window would again change
    legacy batch results. Neither mode is implemented here; ordinary watch
    parity remains batch_size=1.
