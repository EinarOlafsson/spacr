WHAT TO BUILD
    General cloud access in spaCR: browse and read images, OME-Zarr plates
    and results from AWS S3 (and S3-compatible stores, Google Cloud Storage,
    Azure) via fsspec, with credentials from the standard profiles,
    streamed/cached reads, and writing results back; usable wherever a local
    folder is accepted.

DONE WHEN
    A public S3 OME-Zarr HCS plate (e.g. from IDR) opens in spaCR and runs
    through Mask and Measure without copying the whole plate locally.

ALPHA NOTE (2026-09-26)
    What was built. src of Make Masks and Measure may be a cloud address:
    s3:// (AWS and S3-compatible stores), gs://, az:// / abfs://, or
    https:// (read-only, no listing). Access goes through fsspec; the
    library for the protocol (s3fs, gcsfs, adlfs, aiohttp) is imported only
    when such an address is used, and a missing one raises an ImportError
    naming the `python -m pip install fsspec <lib>` line. Code lives in
    spacr/ome_zarr.py (no new module; the 647-module pin holds), reached from
    preprocess_generate_masks and measure_crop through
    _run_with_cloud_sources.
      - OME-Zarr (plate, well or image, NGFF 0.4 and 0.5): the reader walks
        the store through _CloudPath, so every chunk still passes
        _read_chunk_bytes. Only the wells (cloud_wells), fields per well
        (cloud_fields) and pyramid level (cloud_level) chosen are fetched,
        one channel at a time, z maximum projected, and written as
        Yokogawa-named TIFFs into <cloud_cache>/<name>-<hash>; metadata_type
        is set to cellvoyager. Files where y/x have a unit and z has none
        (IDR's) are staged: only the 2-D pixel size is recorded.
      - A cloud folder of images or merged stacks is mirrored into the same
        kind of folder. spacr_cloud_source.json records what was fetched
        (redacted addresses, sizes, ETags), so a repeated run fetches
        nothing, even after Make Masks has moved the TIFFs.
      - Measure given the same address (optionally ending /merged) uses the
        folder Make Masks staged; if there is none it says to run Make Masks
        first.
      - cloud_results (s3://, gs://, az://) copies the measurements folder to
        <cloud_results>/<source name>/measurements after the run.
      - Tables: spacr.tabular's read_table, read_database, table_columns and
        database_tables accept an address and read a cached copy, fetched
        again only when the object's size/ETag changes.
      - Credentials: never stored, printed or written. S3 uses the standard
        chain (AWS_* variables, ~/.aws, AWS_PROFILE, roles), cloud_profile
        names a profile, cloud_anonymous forces anonymous reads, and when
        no credentials exist at all the read is anonymous. cloud_endpoint
        points at an S3-compatible service. Addresses are printed and
        recorded with user info, query strings and fragments removed.
      - GUI: a cloud button in the src field of Make Masks and Measure
        (CloudSourceBrowse) opens a browser that lists a bucket on a worker
        thread, describes an OME-Zarr from its metadata, and writes the
        chosen address, cloud_anonymous and cloud_endpoint to the form.
    Alpha gate: ALPHA_FEATURES[550] lists the eight settings (cloud_anonymous,
    cloud_profile, cloud_endpoint, cloud_cache, cloud_wells, cloud_fields,
    cloud_level, cloud_results) and the CloudSourceBrowse widget.
    Tests: tests/test_cloud_storage_access.py (fsspec memory store and a
    127.0.0.1 HTTP server; chunk counts, caching, Mask/Measure sharing a
    folder, result upload, tables, install message, no secret leaks) and
    tests/qt/test_cloud_storage_alpha_gate.py (hidden/visible, dialog).
    Manual checks, 2026-09-26:
      - moto S3 server on 127.0.0.1 with fake keys from the environment:
        listing, describe, staging one field, cloud_results upload and a
        CSV read through tabular all worked; the fetch record held no key.
      - DONE-WHEN CHECK: IDR plate idr0001A/2551 (96 wells, 6 fields,
        2 channels x 16 z) opened anonymously as
        s3://idr/zarr/v0.4/idr0001A/2551.zarr with cloud_endpoint
        https://uk1s3.embassy.ebi.ac.uk. With cloud_wells A1, cloud_fields 1
        and cloud_level 1, 32 chunks (11.5 MB) were fetched; Make Masks
        (Cellpose-SAM on CPU, 732 s) found 115 cells and Measure wrote 115
        cell rows x 155 columns. Measure needed cell_min_size lowered (the
        default 8000 px filters every yeast cell at level 1).
      - Cell Painting Gallery listed anonymously
        (s3://cellpainting-gallery/cpg0016-jump, 14 sources).
    What is left.
      - Only Make Masks and Measure (and table readers) take cloud sources;
        other modules still need local folders. dry_run does not preview a
        cloud fetch; Timelapse hides the settings.
      - Whole fields are fetched at the chosen level; no tiling of very
        large fields, no streaming of chunks straight into segmentation.
      - Results upload covers the measurements folder only; write_table /
        write_database do not write to addresses.
      - Browser: HTTP cannot be listed (type the OME-Zarr address), no
        bucket list at s3:// root, no profile field in the dialog.
      - Not tested against real GCS or Azure (gcsfs/adlfs not installed
        here); only their options mapping is unit tested.
      - Suggested extra for setup.py (not added): 'cloud': ['fsspec',
        's3fs', 'gcsfs', 'adlfs', 'aiohttp'].
