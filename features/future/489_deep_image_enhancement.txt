489 — DEEP IMAGE ENHANCEMENT
===========================
Status: NOT IMPLEMENTED. Explicit user request; record added2026-09-23.

Add opt-in network-based enhancement to Make Masks, with useful choices for
different structures and acquisition noise. Research primary documentation and
suggest appropriate methods; Cellpose3 restoration is the user's starting
example. Assess available isolated Cellpose3 restoration first, then microscopy
models such as CARE/Noise2Void only when compatible trained weights and their
intended image domain can be supplied. Do not advertise an untrained network
as a ready enhancement method or a denoised image as validated new structure.

Acceptance: explicit model selection and input expectations; Compare/Apply
semantics consistent with479; inference off the GUI thread, cancellable, with
obsolete results discarded; source images preserved and applied model/version/
weights/settings recorded. Verify real image inference, contrast/shape/channel
preservation and subsequent mask input. Resource limits and GPU idle rule apply.
Coordinate settings API, tooltips, animations, translations and tutorials with
the other session. Installation must respect backend environment separation.

2026-09-24 — VERIFIED FIRST BACKEND AND GEOMETRY CONTRACT
Primary sources checked: https://cellpose.readthedocs.io/en/latest/restore.html
and https://cellpose.readthedocs.io/en/v3.1.1.1/_modules/cellpose/denoise.html .
Cellpose-SAM does not supply this restoration API; use the already isolated
Cellpose3 backend. DenoiseModel restores without segmenting, so its output can
feed the existing Make Masks Compare/Apply chain. First useful choices are
noise removal, deblurring and one-click restoration, each using cyto3 (cells)
or nuclei weights. The model needs the approximate object diameter in pixels.
Restored values are model/normalization output, not calibrated fluorescence.

Do not silently wire the upsample models into same-sized mask editing: their
output dimensions change when diameter is below the training diameter. Offer
those only with an explicit coordinate/pixel-size contract. For the first
same-grid integration, require finite float output and exact input dimensions,
process selected channels independently, and retain source arrays unchanged.
Cache models in the backend worker; use its existing serialized requests and
cancellation/process teardown. Record package, model/weight identity, diameter,
normalization, channel and device alongside the applied chain. Test real CPU
inference before claiming the backend useful; no GPU needed for that proof.

CARE (https://csbdeep.bioimagecomputing.com/doc/) and Noise2Void
(https://github.com/juglab/n2v) remain candidates for appropriately trained,
acquisition-specific models. They are not interchangeable ready-made organelle
restoration weights. No implementation or biological validation is claimed by
this research note. This work stays outside the1.5.1.0candidate.

2026-09-24 — REAL CPU RESTORATION FEASIBILITY
Cellpose3.1.1.3's denoise_nuclei, deblur_nuclei and oneclick_nuclei all ran in
the existing isolated backend environment on a128x128crop from the public
Host–Pathogen microscopy data, channel0. CPU inference took0.55/0.22/0.23s
respectively after model initialization. Each output is finite float32 and
retains128x128geometry; the original input is unchanged. Small negative values
and values above1 are legitimate outputs here, so the integration must not
cast them directly to unsigned integers. Original weights were downloaded
from Cellpose's model source; their SHA256 identities are in the receipt.
No GPU used. Diameter25px is a feasibility parameter, not estimated optical
calibration. This is not a segmentation-accuracy or biological-fidelity result,
and does not complete the Compare/Apply UI or worker integration. Receipt:
features/data/489_cellpose3_restoration_feasibility_2026-09-24.json.
