--------------------------------------------------------------------------------
WHAT IT IS FOR
--------------------------------------------------------------------------------

The zoo should answer "what can I segment this with", not "what is already on
this machine". A segmenter the user has never heard of is worth listing exactly
because they have never heard of it; a row that says "not installed -- click to
install" teaches them it exists.

--------------------------------------------------------------------------------
WHAT MAKES THIS DIFFERENT FROM A DOWNLOAD
--------------------------------------------------------------------------------

Every zoo row today downloads a FILE. These two are PACKAGES: installing one
runs pip, can pull a different torch, and can break the environment spaCR is
running in. That is the whole risk, and it is why this is filed rather than
bolted onto the download button.

  - pip install into the running interpreter does not take effect reliably
    without a restart, and a half-installed dependency set can leave spaCR
    unable to start. Decide whether install means "pip into this environment",
    "pip into an isolated venv spaCR shells out to", or "tell the user the
    command and let them run it".
  - A torch version conflict is the likely failure, not a rare one. Cellpose,
    DINOcell and SAMcell each pin their own.
  - The install must be cancellable and must report progress; pip on a slow
    link with no output is indistinguishable from a hang.
  - After a successful install the row has to become usable WITHOUT a restart,
    or say plainly that a restart is needed. Silently doing nothing is the
    failure users will report as "the button does nothing".

--------------------------------------------------------------------------------
WHAT THE ROWS NEED
--------------------------------------------------------------------------------

Status becomes a three-state, not two: installed / available to install / not
installable here (wrong Python, wrong platform, no network). The scorecard
table applies as it does to any other model -- if these projects publish
numbers, quote them WITH their source; if they do not, the cells read
"not recorded" rather than being filled in from a README's marketing.

The adapter matters as much as the install: each package has its own calling
convention, so spaCR needs a segmentation backend per package before a row can
claim the model is usable. See spacr/_segmentation_backends.py.

--------------------------------------------------------------------------------
OPEN QUESTIONS -- ANSWER BEFORE BUILDING
--------------------------------------------------------------------------------

  - Which distribution of each project is canonical -- PyPI, conda-forge, or a
    GitHub checkout? Pinned to which version?
  - Install into the live environment, or an isolated one spaCR calls out to?
    The isolated answer is safer and is more work.
  - What happens on a machine with no network, or where the user cannot write
    to site-packages?
  - Does an install that breaks the environment have an undo?
  - Do these projects' licences allow spaCR to offer them this way?

--------------------------------------------------------------------------------
WHY IT IS FILED RATHER THAN BUILT
--------------------------------------------------------------------------------

Requested 2026-09-18 alongside the Cellpose listing. The Cellpose part was a
listing change and was done immediately. This part runs a package manager
against the environment the application is running in, which is not something
to add at the end of a session -- the failure mode is a spaCR that will not
start, reported as "the model zoo broke my install".

2026-09-19 — BUILT: ONE ENVIRONMENT PER BACKEND, AND CELLPOSE 3 IN THE ZOO
--------------------------------------------------------------------------------

Decided: "Isolated env per backend! But with the addition of adding
cellpose 3 and its cyto, nucleus, and cyto2 and cyto3 models. The cellpose
3 backend will allow more models from the biomass.io to be added to the
model zoo." -- the maintainer, 2026-09-19, answering the open questions
above. ("biomass.io" is bioimage.io.)

The open questions, as that decision and the build answered them:

  - Canonical distribution: PyPI, pinned -- cellpose==3.1.1.3 (the last 3.x,
    with `packaging`, see below), dinocell==0.74, samcell==1.2.0; torch
    from the wheel index that matches spaCR's own torch build.
  - Live environment or isolated: isolated, one venv per backend under
    ~/.spacr/backends/<name> ($SPACR_BACKENDS_DIR). venv rather than conda
    because it is in the standard library on all three systems and needs
    no conda; its limit (a Python in the backend's range must already be on
    the computer) is reported as "not installable here" with the range.
  - No network, no write access: both are row states with the reason, and
    a background probe of pip's index puts "no network" on the row before
    the click.
  - Undo: Uninstall deletes the environment and everything downloaded into
    it. There is nothing in spaCR's own environment to undo.
  - Licences: on every row, read from each release on 2026-09-19 --
    Cellpose 3.1.1.3 BSD-3-Clause; DINOCell 0.74 MIT, its weights MIT;
    SAMCell 1.2.0 MIT, fine-tuning facebook/sam-vit-base (Apache-2.0); a
    bioimage.io row carries the licence its uploader chose (one of the five
    Cellpose 3 models there is CC-BY-NC-4.0).

What was built -- one commit, "423: each segmentation backend installs into
an environment of its own, and Cellpose 3 joins the zoo with its four
models and bioimage.io's":

  - spacr/_segmentation_backends.py: the specs, the environment manager
    (state, preflight, plan, install, uninstall, lock, log), the worker
    (this same file, run with `<env python> -I ... --serve <name>`, JSON
    lines over stdin/stdout, .npy files, errors verbatim, protocol 1) and
    the client (_RemoteBackend, answering Cellpose's eval; one worker per
    backend, shut down after ten idle minutes). A DINOCell or SAMCell an
    older spaCR pip-installed into spaCR's own environment still runs in
    process; a backend environment wins when both exist.
  - spacr/model_zoo.py: backend rows carry their state as `source`, the
    reason as their first note and a new `licence` field; four Cellpose 3
    model rows (kind "cellpose3"); bioimage.io models whose weights are a
    Cellpose 3 checkpoint (CellPoseWrapper, CPnetBioImageIO -- five on
    2026-09-19) are cellpose3 rows that download the file, checked against
    the manifest's SHA-256.
  - One install/uninstall dialog (model_zoo_picker.BackendInstallDialog)
    used by the Model Zoo button, the Model Zoo screen and Make Masks' Mode
    box; the two GUI-thread `subprocess.run(pip ...)` copies are gone.
  - segmentation_backend='cellpose3' reads each object's model name as
    written (cyto3, cyto2, cyto, nuclei or a checkpoint path; other names
    mean nuclei for nuclei and cyto3 otherwise); settings._get_object_settings
    no longer maps those names to cpsam under Cellpose 3. The magnifier has
    four Cellpose 3 modes.
  - A second commit: the Model Zoo screen's "Test on fields" and "Compare
    the two selected" segment a cellpose3 row in the Cellpose 3 backend.
    Both went through spaCR's Cellpose 4, which loads a Cellpose 3
    checkpoint and segments nonsense with it, and both buttons were enabled
    for a downloaded bioimage.io checkpoint.

Measured, in a sandboxed HOME on the CPU, Cellpose 3 from PyPI (the numbers
are in docs/notes/spacr/_segmentation_backends.md): cold install 258.7 s and
1.6 GB; uninstall 0.7 s; reinstall pressed in the dialog 55.4 s, the GUI
timer firing 55 times while pip ran. Driven the way a user does it: the
Model Zoo button's rows read "installed" / "not installed -- click to
install" / "needs the Cellpose 3 backend"; its Uninstall button removed the
environment; clicking the row installed it again; cyto3's "Use this model"
returned 'cyto3'; the Mode box listed the four Cellpose 3 modes and the
magnifier segmented three blobs with cellpose3:cyto3, no fallback, and a
click committed one. generate_cellpose_masks_sam with
segmentation_backend='cellpose3' found all nine discs of a 256 x 256 field
in 7.3 s; bioimage.io's "CellPose(cyto3)", fetched through the zoo, is
byte-identical to Cellpose's own cyto3 and found seven of them as a
checkpoint (training diameter, no size model).

Found by the real run, fixed: fastremap 1.20 imports `packaging` without
declaring it, so the first real segment failed with ModuleNotFoundError
after a self-test that passed -- `packaging` is now installed and the
self-test imports what the adapter imports. And Cellpose 3 handed a path
that does not exist logs a warning and runs cyto3; that is now refused.

Tests: tests/test_backends_live_in_their_own_environment.py (106, with a
