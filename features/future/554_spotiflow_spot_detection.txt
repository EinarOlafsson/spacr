    Add Spotiflow as a spot detector (puncta, foci, FISH, small parasites,
    OPS sequencing spots next to 475's SpotNet). Installed as a backend in
    an environment of its own, exactly like Cellpose 3 (item 446/503):
    spaCR's installer, the Model Zoo row, 507's install feedback, the out-

    spaCR's own environment. Spots come back as coordinates into the same
    downstream paths the native detector feeds (per-object spot counts, OPS
    read assignment).

2026-09-27 -- ALPHA: SPOTIFLOW BACKEND, OBJECT PREFIX AND OPS DETECTOR
Built on the 551-553 seam in spacr/_segmentation_backends.py; nothing added
to spaCR's own environment.
  * Spec "spotiflow": spotiflow==0.6.5 (BSD-3-Clause; models from the
    weigertlab/spotiflow-models releases, BSD-3-Clause), torch+torchvision
    from spaCR's wheel index, Python 3.10-3.13, models general, hybiss,
    synth_complex, fluo_live (2-D only). Weights go to SPOTIFLOW_CACHE_DIR
    inside the environment. Model Zoo rows (spotiflow_v1 and one per model)
    come from the spec, with 507's install offer.
  * Objects: "spotiflow:<model or folder>" in an object's model setting.
    _SpotiflowAdapter draws each spot as a disc (radius = diameter/2 when
    set, else 2 px; every spot keeps its centre pixel), so spots reach the
    same per-cell counts as any object. cellprob_threshold 0 keeps the
    model's optimised threshold, otherwise logistic -> probability; the
    heatmap fills the cell-probability slot; flow_threshold and resample
    are named as not honoured.
  * Coordinates: worker op "spotiflow_spots" (_worker_spotiflow_spots),
    host _spotiflow_spots / _spotiflow_readiness. OPS: ops_spot_detector
    'spotiflow' (alpha choice) feeds the same base calls and nucleus
    assignment as SpotNet; decodes one field at a time; refuses with the
    reason when not installed. SpotDetectorCombo gains a Spotiflow row
    (disabled with the reason until installed; a saved choice is kept).
  * Alpha: ALPHA_FEATURES[554] = choice ops_spot_detector:spotiflow and the
    five Model Zoo keys.

2026-10-02 — STRICT, SOURCE-BOUND COMPARISON RECEIPTS
The existing tools/compare_spotnet_ops.py keeps its exploratory mode and gains
an opt-in --strict mode with a new --out receipt path. Every requested detector
must be available with cached model artifacts; every requested field must
actually decode and produce spots. Missing detectors, skipped or wrong fields,
zero detections and changed inputs cannot yield a passing acceptance receipt.
The receipt binds selected image files and plane indices, the measurement
database and library, decoder/adapter/comparison sources, backend installation
markers and cached model files to streamed SHA-256 hashes. Files are checked
before and after the comparison. A database with a WAL is refused until it is
checkpointed, including databases reached through a symlink. New model-cache
artifacts appearing during the run also fail the strict check.

Strict output never replaces an existing file, symlink or hardlink. A private
sibling is flushed/fsynced and atomically published with a no-replace hardlink;
failed publication removes the temporary file. Incomplete comparisons return
a nonzero status and, when the comparison reached completion, an explicitly
failed receipt. These checks establish complete, reproducible comparisons,
not biological accuracy or superiority over the native detector.

Validation: 20 distinct named CPU checks passed under 4 GiB, CPU0 affinity,
zero swap and hidden CUDA: 18 tool/Spotiflow checks, then two added direct and
symlinked SQLite-WAL refusal checks. The new tool tests simulate inference
only; they exercise the real CLI, file hashing and receipt publication. No
backend was installed, no weights or image data downloaded, and no real
inference or GPU work was performed in this follow-up.

The historical real comparison above is retained, not represented as a new
run. Its Spotiflow environment and /mnt/wd4tb replay inputs are absent on this
host, and the old receipt does not bind image/model hashes. F554 therefore
remains partial until a strict real-input replay can be executed. Threshold/
hybiss exploration, additional puncta/FISH validation and GPU timing remain
separate follow-ups. The earlier caption debt has been covered by the current
nine-locale runtime catalog audit; no new application captions are added here.
Receipt: features/data/554_strict_comparison_2026-10-02.json.
