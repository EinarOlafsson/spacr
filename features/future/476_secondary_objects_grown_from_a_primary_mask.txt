WHAT WAS BUILT ALREADY, UNDER ITEM 473
--------------------------------------------------------------------------------

The four numbered steps above are done and shipped: Make Masks' Detection
method category offers "Maxima + propagate", which blurs, finds the local
maxima, grows a seeded watershed out of each one and stops by one of four
rules. It runs in both scopes -- the magnifier's box and the whole image --
and records its settings with the mask.

The engine is
:func:`spacr.qt.mask_engine.maxima_propagate_instances`.

WHAT IS LEFT, AND WHY IT IS A SEPARATE ITEM
--------------------------------------------------------------------------------

CellProfiler's primary/secondary pair is TWO features and Make Masks now
has one of them:

* PRIMARY objects are found from the image alone -- a nucleus channel, say.
  That is "Maxima + propagate", and it is done.
* SECONDARY objects are grown from an EXISTING mask of another object
  type: cells grown outward from the nuclei already segmented, each cell
  keeping its own nucleus's identity, so cell 7 is the cell around nucleus
  7 and the two tables join on that number.

The second is a different feature because its INPUT is different. It does
not find seeds; it is given them, as a labelled mask of another object
class, and the identity of each seed has to survive into the result -- that
is the whole point of the pair. Make Masks has no notion of "the other
object's mask" today: it edits one mask at a time.

WHAT IT WOULD REUSE
--------------------------------------------------------------------------------

The propagation itself, unchanged. :func:`maxima_propagate_instances`
already builds a marker image and grows it with
``skimage.segmentation.watershed(-image, markers, mask=...)``; a secondary
run is that call with the markers taken from the primary MASK instead of
from ``peak_local_max``, and with the resulting labels kept rather than
renumbered. The four stop rules, the hole filling and the minimum-area
filter apply as they stand.

So the work is:

1. Split the marker-building out of :func:`maxima_propagate_instances`, so
   "grow these markers by this rule" is a function of its own and the
   maxima are one way of producing markers.
2. A way for Make Masks to hold a SECOND mask -- the primary objects -- and
   a picker for which object class it is. This is the real design question
   and the reason this is not a half-hour change: the screen, the queue,
   the save path and the curation ledger are all one-mask-at-a-time today.
3. The label identity contract: a secondary object carries its primary's
   id, and a primary with no secondary and a secondary with no primary are
   both reportable states rather than silent ones.
4. Measure it the way item 473 measured the rest, on a set with both a
   nucleus and a cell ground truth.

WHAT TO BE CAREFUL WITH
--------------------------------------------------------------------------------

* CellProfiler's Propagation uses a shortest-path cost mixing local image
  differences and distance. spaCR's negative-intensity watershed is a
  different algorithm, not an equivalent lambda-zero implementation.
  The CellProfiler manual lists Watershed - Image separately from Propagation:
  https://cellprofiler-manual.s3.amazonaws.com/CPmanual/IdentifySecondaryObjects.html
  The baseline here is deliberately intensity watershed. Whether a separate
  distance/intensity growth mode is needed remains a paired-data evaluation
  question, not a claim of CellProfiler equivalence.

secondary_object_instances takes a primary mask and retains its exact IDs,
including sparse uint64 IDs, by using compact internal markers. It includes
the primary footprint before size filtering and reports missing, orphaned,
incompletely enclosed and unexpanded IDs through primary_secondary_report.
All four stop rules share the existing maxima detector's growth helper.
240 seeded-random old/new comparisons preserve labels, seed counts and

without overwriting the previous mask; the GUI storage format remains uint16.
Default editing/save behavior remains unchanged.

is claimed yet. Remaining work: primary source/class selection per field,

GUI / QUEUE MILESTONE, 2026-09-23
--------------------------------------------------------------------------------
Make Masks now offers Secondary objects from primary masks. Select primary
and secondary object classes and either a mask file for the current field or
a folder matching image stems. Background loading validates shape, integer
IDs, distinct classes and a separate output destination, then retains an
immutable snapshot and SHA256. Explicit files never carry over to another
field; folder sources resolve each queue entry independently. Stale worker
results cannot replace the newest field's primary mask.

Both whole-image and magnifier scopes retain exact primary IDs. Accepted
regions extend existing same-ID pixels under Clip/Skip without ID offsets;
different IDs obey the selected overlap rule. Secondary magnifier clicks
accept objects without the drag tool merging primary identities. Missing or
changed primary snapshots refuse detection/acceptance instead of falling back
to Otsu. Growth controls are independent of Maxima + propagate, default to a
global threshold, and include sigma, four stop rules and per-object hole fill.
Enhancement before detection remains available. Post-detection morphology
and splitting are bypassed explicitly to retain identity.

Matched, missing, orphaned, incompletely enclosed and unexpanded IDs are
visible and recorded. Save/reopen retains sparse/disconnected IDs, source
selection, classes and checksum. Readout, filtering, hole filling and small-
object removal use exact IDs. Consecutive relabeling and unpaired Recrop are
refused with explanations because those operations would break the pairing.
Primary files, including aliases, cannot be overwritten by secondary saves.

Validation: 85 focused source/identity/GUI/provenance tests; 239 existing
magnifier/drag/scope/lock regressions; final 156-test source/editor/filter/
readout/threshold batch after adding the visible secondary hole-fill control.
Dark-theme rendering inspected. All pass. Paired-data evaluation remains;
BBBC007 supplies public manually outlined nuclei and cells for that check.

PAIRED-DATA EVALUATION AND DISTANCE OPTION, 2026-09-23
--------------------------------------------------------------------------------
All four implementation requirements are now fulfilled. Reproducible driver:
tools/evaluate_secondary_bbbc007.py; evidence including source/archive hashes,
every field's exclusions and diagnostics:
features/data/476_secondary_bbbc007_2026-09-23.json.

Reference: BBBC007 v1, https://bbbc.broadinstitute.org/BBBC007, 16 DNA/actin
image pairs. These are manual nucleus/cell outlines, not automated training
labels. Enclosed four-connected interiors smaller than16pixels and regions
connected to the image border are excluded. Nuclear interiors seed detection.
Each evaluated nucleus must overlap one cell interior by more than half its
area, with one candidate nucleus per cell. Of1259nuclear interiors,1212have
unambiguous cell partners;47are unpaired, including four ambiguous cells.
All1259seed detection. White cell-outline pixels are ignored in scoring.
RGB intensity images use BT.601 luminance; all images divide by255.

Fixed settings: sigma2, hole fill on, no area filter. Results across1212pairs:

The distance baseline exposed intensity basins crossing cell boundaries, so
secondary_object_instances now also accepts growth='distance'. This floods
a flat watershed surface from primary pixels through allowed foreground,
following four-connected paths around excluded pixels. It cannot jump an
excluded barrier into an unseeded island, unlike unrestricted nearest-primary
assignment. Intensity remains the default. Both modes support the four stop
rules and keep exact IDs; neither implements CellProfiler Propagation.
The Growth selector and CpuParams.secondary_growth record the choice in both
scopes and the curation ledger. Maxima detection ignores this new setting.

No primary ID was lost or invented. The Otsu intensity/distance runs left
399/237primaries unexpanded, respectively: a common threshold can isolate
dim nuclear interiors from nearby signal. Those IDs are explicitly reported.
The five evaluated engine configurations took at most0.58sper field on this
host, with a4GiBcap and two BLAS/OMP threads. No GPU was used.

Limits: this is an exploratory comparison on one cell type with manual seeds,
not an independent validation set, an end-to-end nucleus detector score, or
the published BBBC007 adjacent-boundary metric. Distance was added after the
initial comparison; no claim of universal superiority or parameter tuning on
held-out data is made. Border/ambiguous reference exclusions are recorded.
The benchmark's first alphabetic field is rendered for inspection, not chosen
for a favourable result. Raw data remains outside the repository.
