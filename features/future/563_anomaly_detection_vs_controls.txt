WHAT TO BUILD
    Model the negative-control cell population in embedding space (kNN
    distance, normalising flow or density model) and score every cell and
    well for how unlike controls it is, to find phenotypes nobody named;
    rank wells and show example outlier cells.

DONE WHEN
    On a screen with known hits, anomaly scores rank the hits above controls
    (AUROC), and top outlier cells are shown for review.

ALPHA: 2026-09-27
    Built as an alpha option of Control Charts (hidden unless Preferences ->
    Show alpha features; ALPHA_FEATURES[563] widgets ControlChartAnomaly,
    ControlChartAnomalySection).
    - spacr/sp_stats.py: _score_anomalies models the negative-control
      objects as normal. Features (emb_ embedding columns when present,
      measurement features otherwise) are centred on each plate's controls,
      MAD-scaled and projected on the controls' principal components.
      Detectors, all classical and CPU only: robust Mahalanobis
      (MinCovDet), kNN distance to controls, isolation forest, and
      Gaussian-mixture density. Controls are scored cross-fitted (two
      halves), so the outlier threshold (control quantile, default 0.99)
      is honest. Wells are ranked by outlier fraction, and the enrichment
      over the control rate and a robust z are reported. Known hits (positive
      control, or listed wells/prc/treatments) give well and object AUROC.
      _draw_anomaly_review shows the top outlier objects (crop tiles when
      png_path points at files, else marked on control PC1/PC2), and
      _write_anomaly_report writes CSVs plus the figure through save_figure.
    - Control Charts: toggle, detector, quantile, known hits and export in
      the controls; an "Anomalies" output section with ranked wells and the
      review figure.
    - Done-when check (tests/test_anomaly_detection_vs_controls.py): on a
      synthetic 2-plate screen with 4 hit wells per plate whose phenotype
      is in half the cells, every detector gives well AUROC >= 0.95 (1.0
      observed) and ranks the 8 hit wells first. It holds under a plate offset.
      CPU only, small data; no GPU run.
    LEFT: no deep density model (normalising flow). The brief lists kNN,
    flow or density; kNN and GMM cover it on the CPU. A flow would be an
    optional extra. Not yet checked on a real screen with known hits.
    Object crops show only when the loaded table carries png_path (a
    png_list join is not done automatically). Captions await a catalog
    rebuild.

2026-09-30 -- real-screen check (CPJUMP1) and scoring improved; still alpha
Data: Cell Painting Gallery cpg0000 CPJUMP1, U2OS 48 h compound plates
BR00117010-13 (JUMP-Target-1 map). Known actives are the annotated
poscon_diverse wells (14 compounds, 2 wells per plate), negatives the DMSO
negcon wells. The published CPJUMP1 replicability list (Chandrasekaran et
al. 2024, compound_U2OS_long, corrected p < 0.05: 202 of 306 compounds;
all 14 positive controls among them) serves as a second label set.
Single cells: site 1 of 380 wells of BR00117010, 29,210 cells, 5,783
CellProfiler features. Well profiles: four plates, 1,536 wells.
Defaults (Mahalanobis, quantile 0.99, 20 components), CPU only.
Before this change, well AUROC positive controls vs DMSO was 0.76-0.84
on single cells (Mahalanobis 0.76) and 0.90-0.93 on well profiles. Two
weaknesses showed up: (1) ranking wells by outlier fraction wastes most
cells (about 77 per well, 1% tail), and ranking the same scores by median
gave 0.88-0.90; (2) a phenotype outside the controls' 20 principal
components was invisible to the detector (the off-subspace residual
alone reached 0.96 on well profiles), and Mahalanobis flagged only 16%
of positive-control wells as outliers there.
Changes in spacr/sp_stats.py (_score_anomalies, new _anomaly_halves):
wells are ranked by the mean control percentile of their objects (new
column mean_percentile, shown in the Control Charts table as "Control
percentile"); each object's score is the larger of two control
percentiles, the detector's inside the control subspace and the distance
off it; the principal components are fitted per cross-fit half; and the
control halves are split by whole wells, so no control is scored by a
model that saw its well-mates (this moved AUROCs by at most 0.02).
After, same data and defaults:
  single cells, well AUROC positive controls vs DMSO: Mahalanobis 0.880,
  kNN 0.898, isolation forest 0.898, GMM 0.888. Published actives vs
  DMSO 0.79-0.80 (was 0.62-0.65); published actives vs published
  inactives 0.78-0.79; published inactives vs DMSO 0.51-0.54, which is
  about chance, as it should be. Object AUROC 0.63-0.66: most cells in an active well
  still look like controls. The 10 top-ranked wells are all published
  actives for every detector. DMSO outlier rate 1.0% by construction,
  positive-control cells 7.6-8.5%.
  well profiles, AUROC positive controls vs DMSO 0.953-0.959; published
  actives vs inactives 0.850-0.855; Mahalanobis now flags 50% of positive
  control wells (was 16%) at the same 0.8% DMSO rate.
Tests: tests/test_anomaly_detection_vs_controls.py gains a planted
off-subspace phenotype (AUROC 1.0 now; 0.84 on the old code) and the
whole-well split. Receipt with every number, the data sources and the
script folder: features/data/563_570_real_screen_validation_2026-09-30.json.

2026-10-01 — AUTOMATIC CROP LINKS FOR OBJECT-TABLE REVIEW
Control Charts now enriches a physical object table with png_list paths in
its existing loading worker. The source database is opened read-only and
only crop identity/path columns are read. A match requires plate, row,
column, field, the selected object's own crop-mode ID, and timepoint when
present. Integer, integral-float and o-prefixed object labels are accepted;
timeID/time_id and t-prefixed integer timepoints are handled explicitly.
Missing identity values never match one another, and conflicting time aliases
or one-sided time identity do not fall back to a static join. No object rows
or measurement values are added, removed, reordered or replaced; duplicate
pandas indices and existing nonempty png_path values are preserved.

Repeated rows for the same crop path collapse safely. Different paths for
one object remain unmatched and are logged, rather than choosing a crop
arbitrarily. Unmatched objects remain in scoring. With readable paths the
existing anomaly renderer shows crop tiles; unavailable crops retain the
existing PC1/PC2 review. CSVs, external tables and named derived tables are
not guessed into a physical crop mode. This closes automatic png_list
linking for supported physical object tables, not arbitrary imported tables
or on-demand crop generation when PNG files were never written.

Validation: 21 focused real-SQLite identity/read-only checks passed under
1 GiB, plus 5 actual Control Charts load/score/crop-render and existing alpha
checks under a predeclared 4 GiB cap. Both cohorts used one actual CPU and
zero swap. Source database hashes are unchanged; the actual scoring result
keeps all input object rows and the review canvas contains crop images.
An added fixture initially triggered pandas' incompatible-dtype warning;
changing the fixture to replace its column resolved it before the final
21-check backend pass. No new scientific real-screen acceptance is claimed.
Existing public signatures/docstrings and runtime captions are unchanged.

2026-10-01 — CROP-MODE AMBIGUITY GUARD
Independent review checked the producer contract: filepaths_to_database writes
only the selected crop mode's ID column per row; schema-union appends leave
other mode IDs NULL. Imported or enriched rows may instead carry several
populated mode IDs. Those rows now remain unmatched unless an explicit
crop_mode or object_type identifies the requested mode. If both columns are
present, both must contain the same known requested mode; unknown, missing or
conflicting values cannot resolve ambiguous IDs. No role is inferred from a
filename. A nucleus crop carrying parent cell_id is never attached as a cell
crop merely because it is the only matching path. Existing nonempty paths
remain user-owned and untouched.
Thirty backend checks pass on the final follow-up under 1 GiB, one actual CPU
and zero swap, including same-path deduplication, all identity/time safeguards,
the canonical single-mode producer contract and explicit/missing/conflicting
mode metadata. No public API or runtime caption change is introduced.
