TIME-TO-EVENT ANALYSIS: KAPLAN-MEIER AND COX FOR EGRESS, LYSIS, HOST DEATH

Status: DONE (alpha) 2026-10-02 — against the original annotated-event
comparison criterion. After measuring a timelapse, Measure
follows every tracked object to an event (track end, an annotated label, a
measurement crossing a threshold, or a fold change) or to censoring at the
end of its track, and writes Kaplan-Meier curves with 95% bands, median time
to event per condition and per well, log-rank tests and a Cox model to
measurements.db, with the curves and hazard ratios drawn under
results/time_to_event. Matches lifelines on the same table (numbers below).
Hidden with Alpha features.

WHAT TO BUILD
    From timelapse tracks and detected events, compute time-to-event per
    object (time to egress, host lysis, host death, parasite division),
    Kaplan-Meier curves per condition with censoring at movie end, log-rank
    tests and Cox models with covariates; figures in the house style.

DONE WHEN
    On a timelapse with annotated events, curves and hazard ratios match
    lifelines run on the same table.

WHAT WAS BUILT (2026-09-26)
    Where: a step at the end of a Measure run (spacr/measure.py,
    _run_time_to_event_step -> _time_to_event), beside the cell-cycle step,
    run when time_to_event is on. It reads only the columns it needs from
    the object table named by time_to_event_object (cell, nucleus, pathogen,
    cytoplasm); a track is one object_label in one field, which is what the
    timelapse module's relabelling makes it. The estimators are private
    helpers in spacr/sp_stats.py (_kaplan_meier, _median_survival, _logrank,
    _cox_regression, _survival_engine).

    Events (time_to_event_mode):
      track_end    the object is gone before the movie ends (lysis, egress,
                   detachment -- and tracking loss, which the tooltip says);
                   the event is the first movie frame after its last one.
      annotated    time_to_event_column turns non-zero (or equals the
                   threshold). The column may be on the object table or an
                   Annotate column of png_list, joined per object per frame
                   through prcfo.
      above/below  the column at or past time_to_event_threshold (death dye,
                   first detection of a pathogen signal, size collapse).
      fold_change  the column at least threshold x its first-frame value
                   (division: a doubled parasite or nucleus count).
    time_to_event_persist asks for N consecutive observed frames. Objects
    already showing the event in their first frame are left out and
    counted; tracks shorter than time_to_event_min_frames are left out.
    Right-censoring: at the track's last frame, labelled movie_end or
    track_lost. Clock: from each object's first frame (origin track) or from
    the movie start for the objects present then (origin movie). A field's
    frames are the union of every object table's frames for it, so a movie
    whose objects all vanished still ends where it ends.

    Conditions: time_to_event_conditions as name=wells entries in the
    plate-map notation (well_spec.parse), else time_to_event_group (well,
    plate, row, column, field or a column). time_to_event_reference leads.
    Covariates are read at each track's first frame, before any event.

    Output tables in measurements.db: time_to_event (one row per object:
    duration, event, censoring reason, condition, well, covariates, engine),
    time_to_event_curves (KM per condition: time, at_risk, events, censored,
    survival, ci_lower, ci_upper; exponential Greenwood / log-log band),
    time_to_event_summary (per condition and per well: n, events, censored,
    median and its Brookmeyer-Crowley interval, median_reached),
    time_to_event_tests (the k-group log-rank test and each condition vs
    the reference, BH-adjusted through multiple_testing.adjust_p_values),
    time_to_event_cox (one Cox model, Efron ties: condition indicators vs
    the reference plus covariates; coef, HR, SE, 95% CI, z, p, LR test).
    Figures through spacr.plot.save_figure in the figure_style house style:
    results/time_to_event/kaplan_meier.pdf (step curves, shaded bands,
    censoring ticks, n/events in the legend, log-rank p in the title; the
    first 12 conditions) and hazard_ratios.pdf (log-scale forest plot).

    Engine: lifelines when it can be imported, otherwise the built-in
    estimators (numpy KM and log-rank; statsmodels PHReg with Efron ties and
    Newton steps for Cox). lifelines is NOT a spaCR dependency and was not
    added; the built-in engine is what runs in a stock install. Every table
    records which engine ran.

WHAT IS LEFT
    - Real data (2026-09-30, below): annotated LNCaP death movies and CTC
      HeLa divisions agree with the ground truth; still no Toxoplasma
      egress or host-lysis movie with hand-annotated event frames.
    - Objects in one well are not independent. The log-rank tests and Cox
      SEs treat them as if they were, so p-values are optimistic when wells
      differ (the step's docstring says so; per-well medians are written
      so the wells can be compared). Cluster-robust SEs by well (lifelines
      cluster_col, statsmodels PHReg groups=) or a well frailty are the
      next step.
    - No standalone re-run: changing a threshold means re-running Measure.
      A "re-analyse measurements.db" entry (like analyze_host_pathogen)
      would need a public function and so the API pins.
    - Division as an event uses fold_change on a count column; true lineage
      division (a track splitting into daughters) would read the tracker's
      parent links, which the measured tables do not carry.
    - No delayed entry (left truncation): with origin movie, late arrivals
      are dropped rather than entered at their first frame.
    - Competing risks (death vs egress from the same host) are not modelled:
      a run analyses one event definition, and an object that meets a
      different event first stays at risk or is censored when its track
      ends. Cumulative incidence (Aalen-Johansen) would be the fix.
    - Optional dependency for the maintainer: lifelines (pip install
      lifelines) switches the engine; not needed for the feature.

2026-09-30 -- Real-data validation (CPU; scripts in /mnt/wd4tb/scratch/571/scripts;
lifelines 0.30.3 in the scratch venv as the independent reference)
    1. Annotated deaths, Vicar et al. 2020 (Sci Rep 10:1566; Zenodo 2601562
       masks + death table, 4531900 fluorescence): LNCaP under staurosporine,
       doxorubicin and black phosphorus, 7 fields each, 467/439 frames at
       3 min, 581 tracked cells, 451 annotated deaths. The published death
       frames were written to measurements.db:cell as an annotated column
       and the step run with origin movie, 0.05 h per frame, doxorubicin as
       reference. Against lifelines on the annotation table itself:
         KM curves identical (max |diff| 0) in all three conditions;
         medians 15.35 / 21.20 / 7.45 h; log-rank (3 groups) p 1.09e-19 in
         both; Cox HR staurosporine 1.897 (1.504-2.392), black phosphorus
         3.185 (2.475-4.099) in both; every per-cell event frame equal.
       Found and fixed: the staurosporine median came out 15.45 h instead
       of 15.35 h because the KM product there is 0.5000000000000001; the
       median search (sp_stats._first_time_at_or_below) now allows 1e-9.
       The source table has two inconsistent rows (a death frame after the
       movie's end; a survivor with a death frame); the step censors the
       first, and the annotation column must mark only deaths.
    2. Divisions, Cell Tracking Challenge Fluo-N2DL-HeLa (2 movies, 92 frames
       at 30 min, 306 GT divisions in man_track.txt). Time from a track's
       first frame to its division, GT lineage vs spaCR (trackpy on the
       silver-truth masks + item 567's held-out detected mitoses, through
       timelapse._event_timing). Before: median 27.0 h vs GT 35.0 h, max
       curve gap 0.11, log-rank p 8e-4 -- trackpy carries one daughter on
       under the mother's id, so a spaCR track held several cell cycles and
       only its first division counted. Fixed: _event_timing splits a track
       at every detected mitosis (_event_cycles), one row per cell cycle.
       After: 917 cycles / 314 divisions vs GT 939 / 306; median 35.0 vs
       35.0 h; max curve gap 0.043; log-rank GT vs spaCR p 0.73 (movie 1
       25.5 vs 26.5 h, p 0.86; movie 2 median not reached in either, p 0.77).
    3. Measurement-threshold events are only as good as the marker: on the
       same LNCaP cells, fold_change of the caspase-3/7 mean (1.3/1.5/2.0x,
       10 frames) does not reproduce the annotated deaths (HR staurosporine
       vs doxorubicin 11.7 / 6.3 / 6.9, against 2.08 from the annotations
       of the same two conditions; 20 % of cells within 10 frames), because
       surviving cells also gain caspase signal over the movie. The step's
       arithmetic is right; an event definition has to be checked against
       annotated cells before it is trusted.
    4. Deaths detected by item 567 (held out by field, 15-min frames) give
       Kaplan-Meier curves consistent with the annotated ones: median 21.5
       vs 21.25 h (doxorubicin), 14.25 vs 15.25 h (staurosporine), max
       curve gap 0.09 / 0.08, log-rank detected vs annotated p 0.32 / 0.49,
       HR 2.48 (1.96-3.16) vs 2.08 (1.65-2.62).
    Tests added: tests/test_time_to_event.py (median at one half up to
    round-off) and tests/test_event_detection_on_tracks.py (cell cycles,
    death once per track). Status stays alpha: the per-well dependence,
    competing risks and left truncation listed above are untouched.
