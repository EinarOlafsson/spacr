WHAT IS THERE TODAY (nightly, 2026-09-22)
--------------------------------------------------------------------------------

* Home has four sections (spacr/qt/app.py, SECTION_ORDER ~497): Core, Data,
  Tools and Assays. Assays holds exactly four modules (~1062-1065):
  `analyze_plaques` (Plaque Assay), `recruitment`, `invasion`, `replication`.
* Their icons are spacr/resources/icons/{analyze_plaques,recruitment,invasion,
  replication}.png; `replication.png` is the one this item's Toxoplasma page
  takes as its own.
* Every Home tile is a module screen. What this item introduces is a NEW KIND
  OF SCREEN: an organism page that is a description plus a grid of module
  tiles, sitting between Home and the assay modules.

WHAT TO BE CAREFUL WITH
--------------------------------------------------------------------------------

* A "Coming soon" tile is a promise. Either it carries a date or it says
  plainly that it is not built; the maintainer decides the wording.
* The organism pages hold prose about biology. It should be short, sourced and
  correct, and say where the numbers come from; the maintainer is the
  authority on what it claims.
* This is a new screen KIND, so it needs its own place in the Home registry,
  the API pages, the tutorials (see item 472's map of what feeds what) and the
  walkthroughs.

2026-09-22 — STARPLAST FIRST TILE, ISOLATED INSTALLATION AND LATER LAUNCH
--------------------------------------------------------------------------------
Starplast is now the first Toxoplasma tile, explicitly alpha, using Home's
AppTile. Toxoplasma therefore has nine tiles; the other organisms retain eight.
It is an external application, not an analysis registry key or mask backend.
The first click offers Install and open with alpha, approximately2GB Linux
CUDA-wheel downloads plus application/data/dependencies, and at least12GB free
disk warnings. Installation is deferred until that button is pressed.

The environment is ~/.spacr/apps/starplast, configurable with SPACR_APPS_DIR.
Source selection prefers SPACR_STARPLAST_SOURCE or a sibling local Starplast
checkout, otherwise its official GitHub main branch. The dialog also offers
a checkout chooser. Public PyPI metadata and the tested GitHub archive returned
404 during this session; authenticated Git works, so local-source support is
necessary on this machine. Local sources use git archive HEAD in a temporary
folder: no editable install or build artifacts touch the original checkout.

The installer discovers an appropriate Python, uses that to create a venv,
runs all pip commands through the venv interpreter, and marks success only
after importing the application and checking its bundled data. It keeps logs,
rejects unowned target folders and concurrent installs, and removes its own
partial environment on failure/cancellation. Installation runs on a Qt thread;
Cancel stops subprocess descendants, and failed installs can be retried.

Later clicks launch the environment's python -I -m starplast directly. Python
and pip target variables and host Qt plugin/library paths are isolated; PyQt6
stays in the child process. Child failures show the launch-log location. The
Starplast process is independent of spaCR's window lifetime.
