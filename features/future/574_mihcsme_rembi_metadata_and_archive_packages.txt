METADATA AND ARCHIVE PACKAGES: MIHCSME/REMBI, IDR AND BIOIMAGE ARCHIVE

Status: IMPLEMENTED AS ALPHA 2026-09-27.
Owner: unassigned. From the 2026-09-26 non-GPU list. Ships as an ALPHA feature (features/README.md, item 569): hidden unless Preferences -> Show alpha features is on.

REQUEST (the maintainer, 2026-09-26, verbatim)
    "Also add to future features list the items in the non GPU list that would be valuable!"

EVIDENCE
    https://forum.image.sc/t/sharing-the-datasets-minimal-meta-information/116212

WHAT TO BUILD
    Capture MIHCSME/REMBI metadata for a screen (assay, reagents, imaging,
    analysis) from spaCR's settings and plate maps plus a short form, and
    assemble a submission package (files, metadata spreadsheets, checksums)
    for the Image Data Resource or the BioImage Archive.

DONE WHEN
    A package for an example screen validates against the IDR/BioStudies
    templates.

ALPHA: 2026-09-27. Built behind Preferences -> Show alpha features, registered
    as ALPHA_FEATURES[574] = {'widgets': ('ReportArchivePackage',)}.
    Tools -> Report has an "Archive package..." button. It opens a short form
    (title, description, authors, email, affiliation, organism, cell line,
    screen technology/type, imaging method, microscope, protocols, keywords,
    license, release date, optional plate map), with the fields spaCR can
    fill already filled from the saved settings (experiment -> title,
    metadata_type -> microscope, channels, models, magnification). It writes
    <out>/<title>/ with:
      idr/         study.txt, screenA-library.txt (one row per plate/well,
                   organism with NCBITaxon, cell line, channels, plate-map
                   columns as Characteristics [..]), screenA-processed.txt
                   (object counts per well from pivoted_counts),
                   screenA-plates.txt
      biostudies/  <title>.pagetab.tsv (Submission, Study, Author,
                   Organization, and the REMBI Biosample/Specimen/Image
                   acquisition/Image analysis sections) and file_list.tsv
      mihcsme/     Investigation/Study/Assay/AssayConditions sheets (TSV)
                   and mihcsme.xlsx (needs openpyxl, optional)
      checksums.md5 (md5sum -c format), README.txt, archive_manifest.json
    Images stay where they are unless "Copy the images" is ticked. Nothing
    is uploaded and the run folder is never written to. After writing, the
    package is checked by spacr.report._validate_archive_package (required
    IDR study keys and library columns, well spelling, plates on the plate
    list, PageTab sections and required attributes, file list present and
    unique, MIHCSME required keys, every checksum re-hashed). Code:
    spacr/report.py (_write_archive_package and helpers),
    spacr/tabular.py (_write_workbook), spacr/qt/screens/report.py.
    CPU check on the example plate (~/.cache/spacr/example_data/plate1,
    208 CellVoyager planes, 4 wells): package written and validated in 13 s,
    no problems.
    Tests: tests/test_archive_package.py,
    tests/qt/test_archive_package_alpha_gate.py.

LEFT
    - The "templates" checked are spaCR's encoding of the IDR study/library
      templates, the BioStudies PageTab/REMBI sections and the MIHCSME
      sheets. Not yet run through IDR's own curation checks (idr-metadata
      pyidr) or a BioStudies test submission (no network writes allowed).
    - Term accessions beyond the organism (EFO screen type, FBbi imaging
      method) are left for the curators; no ontology lookup.
    - One screen per package; multi-screen studies are not assembled.
    - Command-line and Notebook entry points were added on 2026-10-01;
      see the headless workflow evidence below.
    - openpyxl is optional; without it only the MIHCSME TSVs are written.


2026-10-01 — PRESERVE RUNS AND EXISTING PACKAGE DESTINATIONS
Commit c78a89c59 enforces the existing promise that exports do not write into
the run folder. A package path equal to or inside the resolved source folder
(including parent/leaf symlink aliases) is rejected before any directory or
metadata is written. Existing package directories, files and dangling symlinks
are refused with a request to choose another output folder or title. New
sibling package exports retain their normal behavior. Fifteen focused new
and existing archive checks passed under 1 GiB memory, zero swap and a
100% CPU quota; they verify source bytes, existing notes, symlink retention
and successful ordinary export. Independent code review found no remaining
issue in this guard. No API signatures/docstrings or captions changed.
Curator/service template acceptance and other broader alpha requirements
listed above remain open; this is an output-preservation fix.


2026-10-01 — CHECKED LOCAL CLI AND NOTEBOOK WORKFLOW
The headless command `spacr-run archive-package --src RUN --out OUT
--metadata FILE` accepts a UTF-8 JSON form; `--metadata-json JSON` provides
an equivalent inline form for Python callers. Saved settings and existing
archive defaults fill omitted fields. Duplicate/unknown fields, non-text
values, missing required metadata, unreadable files and bad source folders
produce actionable nonzero exits before output is written. `--copy-images`
opts into copying the images; otherwise their original locations are used.
The existing backend still refuses output inside the source run and existing
package destinations. No source files are written and nothing is uploaded.

The command checks the completed package with the existing local template
and checksum validator. Failed post-write checks return nonzero and identify
the retained package for inspection; success explicitly says archive curator
or service approval is still needed. `spacr-run --help` links to the command's
own lightweight help. No new Python public API signatures or docstrings are
introduced. The measurement Notebook now includes an explicit opt-in cell
using `spacr.cli.main` and editable metadata; running the Notebook unchanged
does not export a package.

Validation: 31 named CLI/backend/destination checks passed under a 1 GiB cap,
one CPU and zero swap. These include real small-screen packages with and
without copied images, saved-setting defaults, malformed/duplicate/oversize
JSON, metadata failures, source/destination preservation, real checksum
corruption, import-light help and execution of the actual Notebook cell.
Three existing CLI import/help/list checks and three focused Notebook layout
checks also passed. The generator now prefers its marked run cell over an
optional appendix; insertion points are unchanged for all 31 original
Notebooks. New cell IDs, JSON structure and Python syntax were checked;
formal nbformat schema validation was unavailable because nbformat is not
installed in this environment. External IDR/BioStudies template acceptance,
ontology enrichment and multi-screen studies remain open. This feature
remains alpha.


2026-10-02 — UNMODIFIED OFFICIAL IDR PARSER REPRODUCTION; PARTIAL
The documented offline IDR study_parser (idr-utils revision
45ec7dcc02ced093532dd47f6bba9cba70e4f9fd) rejected an actual private CLI
example package because Study Publication Title was absent, although spaCR's
local checks passed. The exporter now emits the official template's row with
an unknown blank value; the local validator requires row presence without
inventing a publication. The missing-versus-blank regression and existing
archive/CLI/destination checks pass: 32 tests under 1 GiB, CPU0, zero swap.
Existing public signatures and docstrings are unchanged.

The same untouched official parser now proceeds to the next real blocker:
Unmatched name spacr-example-screen/screenA. It expects curator-assigned IDR
accession/study naming, whereas the submission template explicitly leaves
those assignments blank. No accession was fabricated and nothing was
submitted or uploaded. The official BioStudies PageTab specification was
inspected but no service or full library/curation acceptance is claimed.
F574 remains partial. Pinned sources, unchanged-image proof, both official
failures, corrected metadata and resource/test evidence are recorded in
features/data/574_official_idr_probe_2026-10-02.json.

2026-10-03 — OFFLINE TERM ACCESSIONS
The IDR study file now carries "Screen Imaging Method Term Accession" and
"Screen Type Term Accession" from a small offline table (_ARCHIVE_TERMS in
spacr/report.py: fluorescence/confocal/spinning-disk microscopy -> FBbi,
primary/secondary screen -> EFO). Unknown terms stay blank for curators.
Accessions should be confirmed by IDR curators. Test:
test_known_screen_terms_get_their_accessions. Still open: multi-screen
studies (code), curator checks (external).
