WHAT IS BUILT
--------------------------------------------------------------------------------

SpotNet (DeepCell, Laubscher et al., Cell Systems 2024) finds fluorescent
SPOTS -- single molecules, FISH puncta, sequencing-by-synthesis signals -- and
returns coordinates, not masks. It is listed in the Model Zoo as the backend
`spotnet`, installing into an environment of its own like the others, with a
worker operation `detect_spots` that returns `[[y, x], ...]`.

THREE THINGS THE ROW HAS TO SAY, and does:

  * ITS LICENCE IS NOT SPACR'S. DeepCell's models and training data are a
    modified Apache licence, NON-COMMERCIAL ACADEMIC USE ONLY.
  * ITS WEIGHTS NEED AN ACCOUNT. They come from users.deepcell.org with a free
    token, read from DEEPCELL_ACCESS_TOKEN.
  * IT NEEDS AN OLDER PYTHON. deepcell-spots 0.4.2 declares >=3.7,<3.11, so a
    spaCR on Python 3.11 or newer cannot build the environment and the row
    says "not installable here" with that reason. (spaCR's own developer
    machine runs 3.12, so this backend is UNTESTED end to end here: the spec,
    the row and the refusal are tested; a real install and a real detection
    are not.)

WHAT IS NOT BUILT, AND WHERE IT WOULD GO
--------------------------------------------------------------------------------

  * OPS SPOT DETECTION. spaCR's optical pooled screening already finds
    sequencing spots per cycle (spacr/ops_engine.py); SpotNet could be an
    alternative detector there, chosen by a setting, with the cycle's spots
    coming back as coordinates. That is where it would earn its place, and it
    needs a measurement against spaCR's own detector on a real well before
    anyone should prefer it.
  * FISH / SMFISH COUNTING as a measurement: spots per cell from a channel,
    written beside the other per-object measurements.
  * A PYTHON THAT CAN INSTALL IT. Either spaCR finds an older interpreter for
    that one environment (the installer already looks for one and says so), or
    the backend waits for deepcell-spots to admit a newer Python.

DONE WHEN
--------------------------------------------------------------------------------

  * A real install on a Python 3.10 machine, a real detection on a real
    image, and the result compared with spaCR's own spot detection on the
    same field.
  * If it wins, a setting that chooses it in OPS, and its licence stated
    where a user selects it.

2026-09-23 — BATCH COORDINATES AND REAL INSTALL BOOTSTRAP REPAIRED
The pinned0.4.2 postprocessor returns a NumPy array with one leading image
axis, including shape(1,0) for no spots. The old worker only removed that
axis from lists/tuples, so actual NumPy batches failed for zero, one, two and
five spots. It now unwraps exactly one image, returns [] for empty detections,
preserves floating-point coordinates, and rejects malformed/nonfinite output.
Image shape, finite intensity and threshold validation precede weight loading.
Receipt: features/data/475_worker_coordinate_contract_2026-09-23.json;
these are API-contract fixtures, not trained-model detections or ground truth.

A compatible Python3.10.20 DOES exist locally in the hugmunn environment.
Putting its bin folder on PATH lets the ordinary installer create a separate
private environment; nothing installs into hugmunn or spaCR. The first real
attempt exposed missing Torch/torchvision bootstrap declarations: deepcell-

now lets the existing CPU/CUDA index choice work. That original attempt was

2026-09-25 -- TOKEN FILE, REAL INSTALL IN ~/.spacr, OPS SETTING, NATIVE BASELINE

The Model Zoo row gains a note saying where the token goes and whether one

PATH (nothing installed into hugmunn or spaCR), CPU Torch index: finished
first try in 170.6 s into ~/.spacr/backends/spotnet, 3,165,129,138 bytes.
deepcell-spots 0.4.2, deepcell 0.12.10, TensorFlow 2.8.4, Keras 2.8.0,

OPS SETTING. ops_spot_detector, "OPS decoding": 'native' (default) or
'spotnet'. SpotNet sees one image per field (each cycle's brightest base
channel, scaled by its 99.9th percentile, averaged over cycles), threshold
0.95; its positions are rounded, deduplicated and go through the same
margin, bases, calls and assignment to nuclei (ops_read_threshold does not
apply). It decodes fields one at a time (one SpotNet worker). A run asking
for SpotNet when the environment or token is missing is refused before
anything is written, with the reason; never silently swapped. In the GUI
the SpotNet row is disabled with that reason, and the tooltip states the
NON-COMMERCIAL ACADEMIC USE ONLY licence where it is chosen.

COMPARISON. tools/compare_spotnet_ops.py decodes named fields with both
detectors against a plate run's stored objects and placements. Native half,
real, plate 20200202_6W-LaC024A well A1 sites 331+332 (the two local
fields): 22,733 spots, 17,668 owned reads, 3,476 objects assigned, 95.3 %
of those exact library barcodes, 27 s on CPU. Receipt:
features/data/475_real_install_and_native_baseline_2026-09-25.json.

WHAT REMAINS. No ~/.spacr/deepcell_token exists here. With one in place
(or DEEPCELL_ACCESS_TOKEN set), run tools/compare_spotnet_ops.py with the
arguments in its docstring: it fetches SpotNet's weights into the
environment and adds SpotNet's spots, owned reads, assignment rate,
seconds, and the 2 px match fractions both ways. Only then can SpotNet be
recommended, or not; native stays the default until it is. The three new
GUI captions await catalog entries from the translation lane.

Match within 2 px (owned reads): 69.3 % of native's reads have a SpotNet
read nearby; 79.6 % of SpotNet's have a native read nearby. SpotNet's
barcodes are as pure, but it finds fewer reads and assigns 27 % fewer
nuclei, about 25x slower on CPU. On this evidence native stays the default
and SpotNet stays opt-in. Caveats: two fields, no ground truth, SpotNet
fed one composite image per field (brightest base channel, cycle-averaged)
at its default 0.95 threshold -- a lower threshold or per-cycle detection
could change the count, and is the next thing to try if anyone wants it.
GPU: SpotNet's TensorFlow 2.8.4 finds no CUDA 11 runtime in its
environment (libcudart.so.11.0 absent), so its detection is CPU either
way; a gpu_turn.sh run for the native side was queued behind other
sessions. Receipt: 475_real_install_and_native_baseline_2026-09-25.json.
