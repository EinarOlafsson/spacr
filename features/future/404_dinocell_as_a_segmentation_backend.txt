--------------------------------------------------------------------------------
WHAT DINOCELL IS, READ FROM THE REPOSITORY 2026-09-14
--------------------------------------------------------------------------------

An automated cell-segmentation model for LIVE CELL microscopy. A DINOv2 ViT
encoder pretrained on 1.2B images, domain-adapted on 130k unlabelled cell
images. MIT licence. `pip install dinocell`. A Python entry point
`segment(img_path)` returning `output_segmentations`, and a CLI
`dinocell segment image.png --output results/`.

THE DETAIL THAT MAKES THIS CHEAP RATHER THAN A REWRITE: it predicts
CELLPOSE-STYLE FLOWS rather than binary masks. spaCR's whole mask path already
consumes Cellpose flows, so a backend that emits them plugs into what exists
instead of needing a second post-processing pipeline beside it.

Its README claims it outperforms Cellpose-SAM and SAMCell on both held-out
test sets and zero-shot cross-dataset evaluation, and claims zero-shot
generalisation to novel cell types and microscopes. THOSE ARE ITS CLAIMS AND
NOT MEASUREMENTS OF OURS -- see below.

NOT STATED IN THE REPOSITORY and needing a look before anyone builds: the
image modality it expects, channel count, whether it is 2-D only, and where
its checkpoints come from. The README does not say.

--------------------------------------------------------------------------------
WHY IT IS WORTH HAVING
--------------------------------------------------------------------------------

Every model in the zoo today is Cellpose or a YOLO detector, and all three
entries are Toxoplasma-specific (`toxoplasma_pv_v1`, `toxoplasma_plaque_v1`,
`toxoplasma_well_detector_v1`). A model whose selling point is zero-shot
generalisation to cell types it has not seen is the opposite of that, and is
what a user with an unfamiliar assay actually needs on day one.

Live-cell microscopy is also exactly where spaCR is weakest: the Cellpose
models in the zoo are trained on fluorescence, and timelapse work is often
label-free.

--------------------------------------------------------------------------------
WHAT TO BUILD
--------------------------------------------------------------------------------

  * A `kind` FOR IT IN THE MODEL ZOO. `ModelEntry.kind` is already the
    discriminator -- 'cellpose' and 'detector' both exist -- so this is an
    addition to an existing mechanism rather than a new one. If its flows are
    genuinely Cellpose-shaped it may not even need a separate mask path.
  * AN OPTIONAL DEPENDENCY, not a core one. `dinocell` pulls a ViT and its
    weights; a user who never opens it must not pay for it. spaCR's
    lazy-import discipline (item 282) is the standard to meet, and
    `tests/test_perf_guard.py` is what enforces it.
  * A SCORECARD BEFORE A RECOMMENDATION. `spacr/scorecard.py` exists and
    scores a segmentation against ground truth with Dice, IoU, boundary F1
    and AUPRC. Item 370 asks that every published model carry one. A vendor's
    benchmark is not evidence about a user's images, and the whole point of
    370 is that the comparison is run on OUR held-out set, not quoted.

--------------------------------------------------------------------------------
HOW IT WILL BE CHECKED
--------------------------------------------------------------------------------

DINOCell segments a spaCR project end to end through the ordinary Mask path,
with no import of `dinocell` in a process that does not use it -- proved the
way 282 proves it, by asserting the module is absent from `sys.modules` after
the Qt launch path. And a scorecard on THE SET 370 AUTHORISED -- with
`toxoplasma_pv_v1` re-scored on that same set in the same run, because the
published 0.867 was measured on something else and two numbers from two sets
are not a comparison.

NOT BLOCKED ANY MORE, as of 2026-09-14. 370 asked whether a labelled held-out
set existed and the maintainer answered "Label a new set for the purpose", so
the set is authorised and its requirements are written down in 370's last
section -- including that it be WIDER THAN TOXOPLASMA, which exists because of
this item and 405. Read that before scoring anything.

The order is unchanged and still matters: the INTEGRATION can land before a
single field is labelled, the RECOMMENDATION cannot. "DINOCell generalises
zero-shot" is the vendor's claim, and until it is measured on our set it stays
the vendor's claim in this file's own words.

BUILD IT WITH 405, NOT AFTER IT. Both were approved in one sentence and both
extend `ModelEntry.kind`. DINOCell emits Cellpose-style flows and may need no
new mask path at all; SAMCell emits masks through its own pipeline and is the
one that decides whether a second path is needed. Settle THAT question once,
across both, before writing either -- two backends added a month apart is how
one mechanism becomes two.
