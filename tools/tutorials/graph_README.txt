Graph Builder — real measurement-table practice
==============================================

Unzip this archive. Open Graph Builder from Home, choose Load table, select
measurements.db and choose the cell table. This is a byte-identical copy of
the measurement database from the downloaded Annotate example used in the
recording, not synthetic measurements and not a new segmentation run.
The database has 2,341 cell rows. Image paths in other tables may refer to the
original example's location; this archive deliberately does not bundle images.

Drag cell_area onto X, then cell_channel_1_mean_intensity onto Y. Drag columnID
onto Colour and rowID onto Row facet. The labels describe acquisition metadata,
not an inferred treatment, validated class or independent biological replicate.
The area and intensity values keep their stored units: this download does not
calibrate pixels to micrometres or normalize intensities.

Add cell_area in Local Data Filter and set its minimum to 21925. This keeps
1,171 rows in this source; Clear all restores 2,341. The cutoff is the rounded-up
median used to illustrate filtering, NOT a recommended biological threshold.
Removing a facet's channel changes the layout, not the measurement database.

The recorded build has an unresolved selection bug. A genuine rectangular
brush publishes object keys internally but leaves the visible selection empty
and Open selection in Annotate disabled. The tutorial DOES NOT claim that the
handoff works, patch it, or create annotations by another route. A plain click
clears the published selection too. The number of keys in the verification
receipt describes the recorded mouse rectangle, not a universal target count.

There is no chart/specification-export button in this recorded screen. This
archive is an external tutorial download, NOT an export generated by Graph
Builder. Keep the source, chosen columns, filters and application version when
describing a graph. Other views may share filter/selection state; recheck the
visible population rather than assuming it is the whole table.

API orientation: spacr.qt.screens.graph_builder.read_table reads a CSV/TSV or
SQLite table; GraphBuilderScreen supplies the native UI. GraphSpec in
spacr.qt.widgets.graph_spec describes channels, facets and plotting policy;
spacr.selection distinguishes declarative filters from explicit object keys.
These APIs do not establish statistical significance or fix the GUI handoff.

No AI service, new image-analysis pipeline or model was run for this lesson.
The source_manifest.json records the unchanged database hash and actual native
chart checks. The original failed-handoff evidence remains preserved separately.

Updated lesson authoring: condition columns (N625)
------------------------------------------------
The source lesson and capture inputs now add an illustrative annotation
exercise after the existing chart, filter and brush checks. This section does
not assert that narration, screenshots, video or this download were rebuilt
or published. The recorded-build limitations above remain historical evidence.

In Annotate conditions, create these ordered outputs through the controls:
1. genotype, Rules: Exact values on columnID; WildType for c1,c2,c3 and
   mutant for c7,c4,c5,c6 in a separate box.
2. replicate, Rules: two boxes named replicate1, on rowID: r1,r4,r5,r6
   and r7,r9,r10 respectively. Same-label boxes union without a conflict.
3. condition, Combine columns: append genotype then replicate, separator _.
Preview and Apply. These names are illustrative, not verified genotypes or
independent biological replicates. This actual source contains only c1/c2
and r5/r12: all 2,341 cells receive WildType, mutant matches zero, and r12
keeps replicate and condition blank. Missing components never become text
like None or nan. Exact matching distinguishes c1 from c10.

The current UI offers Save chart, Export table and Save annotated table for
SQLite sources; Apply changes the working table only. Saving an annotated
table requires a new name and retains the source table. The annotation
exercise does not claim to exercise those persistence buttons or repair the
separate brush-to-Annotate handoff.

Capture authoring uses capture_graph_annotations.py with actual keyboard and
button interactions. graph_evidence.py independently checks every output row,
source column, index and recipe box. Run the named annotation-control and
graph-evidence tests offscreen before native recapture. Existing native chart
and brush checks still run first and retain their original acceptance gates.
